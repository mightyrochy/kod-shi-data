# Спільна робота Codex і Claude Code

## Межі та джерело рішень

- Читай `CLAUDE.md`: продуктові рішення, перевірки та єдиний перелік проблем
  `аудит/БЕКЛОГ.md` чинні й для Codex. У `аудит/ПЕРЕДАЧА.md` шукай лише потрібні
  поточному завданню записи; історичні доручення самостійно не відновлюй.
- Власник 03.10.2026 дозволив самостійну технічну роботу та запуск виконавців.
  Звертайся до нього щодо концептуальних рішень або перешкод, які він вирішить
  суттєво швидше (наприклад, вхід до облікового запису).
- Головний керівник проєкту — Claude Opus 5.5, max effort. Поки його ліміт
  вичерпано, Codex готує інтеграцію й виконує вже погоджені завдання; нові
  продуктові рішення оформлює для керівника. Не змінюй їх мовчки.

## Виконавці та контекст

- Для реалізації кооперації та звичайних Codex-завдань запускай окремого
  виконавця `gpt-6.1-sol` з effort `high`; для вузьких проб — `medium`.
  Використовуй Standard speed. Astra потрібна для складних незалежних розборів,
  а не для регулярного очікування чи збору стану.
- Кожне окреме завдання починай у свіжій сесії з коротким дорученням: мета,
  дозволені файли, критерії приймання, перевірки, обмеження та відповідальний.
  Незалежні задачі можуть виконуватися паралельно в окремих копіях репозиторію.
- Передавай справи на завершенні завдання або пакета рішень. Довжина контексту
  є приводом оцінити передачу, а не підставою втратити незавершену роботу.
- Передача: commit/гілка, виконане, перевірки та їхні обмеження, відкриті
  питання, наступний крок і посилання на докази. Повні логи читай за потреби.
- Після двох невдалих цілеспрямованих спроб передай проблему з доказами
  координатору. Не запускай нескінченні повтори чи самонагадування.

## Витрати й перевірки

- Підписки Claude та ChatGPT мають окремі ліміти. Підсумовуй їх використання
  окремо; кількість токенів CLI не дорівнює відсотку тижневого ліміту.
- `ZHYVA=sonnet` та `claude -p` витрачають Claude навіть при запуску Codex.
  Перед живими Claude-пробами підтверджуй доступний запас. Невідомий або
  застарілий залишок не є нулем витрат і не є дозволом на автоматичний запуск.
- Перевірки продукту — за `CLAUDE.md` п.15. Збережені відповіді та заглушки
  не доводять якість нової поведінки моделі. Інфраструктурні зміни перевіряй
  вузькими пробами; не запускай для них повну продуктову матрицю.
- Автоматично не перемикайся на платний API і не запускай `workflow_dispatch`.
  Не публікуй локальні логи, облікові дані або незавершені чужі зміни.
- Локальні сервери використовуй через наявні клієнти; перед GPU-роботою
  перевіряй зайнятість. Без інтернету зберігай контрольні точки, без циклів
  повторних хмарних запитів. По завершенні зупиняй запущені тобою фонові роботи.
