# Спільна робота Codex і Claude Code

## Джерело правил

- Правила перевірок і роботи з репозиторієм містить `CLAUDE.md`, рішення
  власника про продукт — `аудит/ПРОДУКТ.md`; сталі мітки `п.N` в обох чинні й
  для Codex.
- Codex не змінює `CLAUDE.md` і `аудит/ПРОДУКТ.md`. Зміни правил проводить
  менеджер Claude після рішення власника.

## Ролі

- Менеджер Claude керує роботою, перевіряє результат і зливає PR.
- Codex працює як виконавець або незалежний рев'юер.
- Codex не приймає і не зливає власну роботу.

## Наряд і робота

- Наряд Codex надходить коментарем, який починається з `@codex`, у чернетці PR
  з гілкою `codex/<id>`. Звичайні коментарі без згадки не є новим нарядом.
- Працюй лише в межах доручення та в гілці цього PR. Зі своєї задачі ти не
  пушиш (у клоні нема remote: `git push` — «No configured push destination»,
  тест #950, 11.10): результат — коментар `ДЛЯ CLAUDE: ПАТЧ <SHA бази>` з
  виводом `git diff <база>..HEAD` у блоці ```diff (видалені файли — переліком
  шляхів). Патч застосовує й пушить у гілку PR супровід Claude. Коміт і
  `make_pr` не потрібні: результат — лише diff у коментарі.
- Задача віддає один коментар; патч у ньому — до ~8 тис. знаків (більші досі не
  доходили, межу не встановлено). Більший — `ДЛЯ CLAUDE: ЗАБЛОКОВАНО: патч ~N
  тис. знаків`, супровід поділить наряд.
- Кожна згадка `@codex` — нова задача зі свіжим клоном: твоїх попередніх
  комітів у ній нема. На прохання надіслати патч ще раз — виконай наряд заново
  й виведи diff.
- Якщо роботу неможливо завершити, напиши
  `ДЛЯ CLAUDE: ЗАБЛОКОВАНО: …`; окрему важливу знахідку передай як
  `ДЛЯ CLAUDE: ЗНАХІДКА: …`.
- Виправлення після перевірки приходять так само: коментар з `@codex` на
  початку, одне доручення на коментар. `ДЛЯ CODEX: …` без згадки — лише
  інформація, нічого не запускає. Після виправлень знову надішли патч.

## Дошка й обмеження

- `аудит/БЕКЛОГ.md` — єдиний перелік відкритих проблем. PR закриває свій рядок
  позначкою `ЗАКРИТО #PR`, кожна нова знахідка — окремим рядком; ти пишеш їх
  словами в коментарі, а в дошку (і в регенеровані файли, як-от `*.schema.json`)
  їх вносить супровід — у патч Codex дошка не йде.
- Не використовуй платні API, не роби покупок, не запускай `workflow_dispatch`
  і auto-merge, не створюй та не проси нові секрети.
- Живі продуктові прогони виконуй на ноутбуці з LM Studio через
  `аудит/проби/рв6_стенд.js` і `MODEL=<ід>`, а не через `claude -p`.
