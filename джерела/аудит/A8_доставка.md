# A8 · шар доставки: build_артефакт.py, показ.html, worker_джерело.js, наскрізь.js

## ЗНАЙДЕНО 40 · Продукт не можна було зібрати ЖОДНИМ задокументованим способом

Це найдорожче в аудиті. Решта знахідок про якість суджень; ця — про те, чи
покращення взагалі можуть доїхати до людини.

У файлі **два** збирачі:

| функція | читає шаблон | у репозиторії | викликається |
|---|---|---|---|
| `зібрати` | `шаблон_артефакта.html` | **НЕМА** | з `__main__` — єдиний вхід CLI |
| `зібрати_показ` | `показ.html` | **Є** | **нізвідки** |

Перевірено прогоном:

```
$ python3 build_артефакт.py . /tmp/проба.html
FileNotFoundError: './шаблон_артефакта.html'

>>> build_артефакт.зібрати_показ(".", "/tmp/проба_показу.html")
  показ: розвилка ок, модулів 17
✓ показ зібрано · html 591 КБ · zip 255 КБ
```

Тобто збирач, який працює, існував і був недосяжний, а недосяжний був
задокументований. Обхід усього дерева (`.py`, `.md`, `.yml`, CI): `зібрати_показ`
не кличе **ніхто**.

**Полагоджено**: CLI дістав режими `показ` (типовий), `показ-повний`, `артефакт`,
`лайт`; докстрінг тепер називає обидва збирачі й каже, якого шаблону кожен
потребує і який із них у репозиторії є.

## ЗНАЙДЕНО 41 · Відмова вела по файл, якого в репозиторії нема

`_фід_вантажу` беззастережно відмовляв від «повний»:

> «каталог_повний.xml більше не існує — жниварка v4.0 віддає два:
> ЛЮСТЕРКО_КАТАЛОГ=жіночий … ЛЮСТЕРКО_КАТАЛОГ=чоловічий»

а порада для «жіночий» слала `curl …/каталог_жіночий.xml.gz`. Виміряно на самому
репозиторії:

```
$ git ls-files | grep каталог
каталог_повний.xml.gz        ← Є (3.8 МБ, відстежується)
каталог_жіночий.xml.gz       ← НЕМА
```

І `КАТАЛОГ_ВАНТАЖУ` за замовчуванням — саме «жіночий». Тобто код відмовляв від
єдиного каталогу, що в репозиторії є, і слав по той, якого нема, ще й типовим
шляхом. **Полагоджено**: «повний» законний, поки файл на диску; відмова настає
лише тоді, коли його справді нема, і веде по `.gz`, який у репозиторії Є.

## ЗНАЙДЕНО 42 · Гейт чистоти називав не той файл, який міряв

```python
_пом = _чк.класифікувати(фід_дж)[4]          # міряє _імя_фіду
raise SystemExit("лайт: каталог_стенд.xml БРУДНИЙ …")   # називає зашите ім'я
```

Виміряно: на `каталог_повний.xml` повідомлення казало «каталог_стенд.xml
БРУДНИЙ», указуючи не на той файл, який треба чистити. **Полагоджено**: імʼя
береться з виміряного, і команда відновлення тепер із правильною сигнатурою
(`почистити(вхід, вихід)` — два аргументи).

## ВИМІР: повна збірка ПРАЦЮЄ, але не публікується

Після чистки каталогу (`почистити` зняв **304 помилки слота** і 24 подвійні
екранування, видалив 21 позицію) повна єдина сторінка збирається:

```
вантаж: фід ← каталог_повний.xml (43 752 КБ, чистий)
показ: розвилка ок, модулів 28
✓ html 5 831 КБ · zip 4 184 КБ · 10 749 речей
```

**Але 5.8 МБ не опублікується.** Докстрінг самого файлу фіксує вимір
28.08.2026: «повна збірка 1182 КБ не публікується — File is too large; лайт
761 КБ проходить». Гейт розміру показу стоїть на 6 МБ — це запобіжник від
абсурду, не межа публікації, і він пропустив збірку, вп'ятеро більшу за ту, що
вже відмовилися приймати.

Отже придатний до публікації шлях один: **`показ` — 591 КБ**. Це треба сказати
прямо, а не лишати «повний» у меню як рівноправний вибір (той самий дефект,
який зонд 8 уже ловив на «стягнутиКаталог»).
