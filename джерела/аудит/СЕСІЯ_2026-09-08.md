## Знайдено шлях знахідки до споживача
```
модуль-правило: dict(правило, сила, сила_нп, суть, чому, ремонт, речі, …)
   ↓ bridge._стислі_знахідки лишає: правило, сила, сила_нп, суть, речі

```
Звідси: **у кожного речення `суть` рівно один читач — модель**, і людини в цій

## Полагоджено

### 1. K-COMP-01: вердикт «ціле», вказівка в протилежний бік
```
before  образ 1 (ранг 0.833, РОЗЛАД)         · позиція … 0.44 від оптимуму [0.25]
        образ 2 (ранг 0.167, НАДКООРДИНАЦІЯ) · позиція … 0.44 від оптимуму [0.25]
after   · розлад: 0.44 від оптимуму — звести кольори [0.25]

```
Третій образ мовчить правильно: ранг 0.500 — вершина кривої, сила 0.0.

### 2. Найсильніший вирок системи про мову йшов у нікуди
`hard` означає «текст не видається жінці, поки модель не перепише». Зміряно:
R-NVB-02 `hard` є у вердикті — і його нема ні в `знахідки`, ні в жодному з трьох
промптів. Показ читає `мова.порушення` лише в гілці `!ітерацій`, тобто для рук
БЕЗ каталогу. Те саме з реєстрами.
Під'єднано тим самим швом, що чеклісти 07.09 («рахувались і не читались ніким»).

### 3. `hard`-правило знімалося словом із чужого речення
Стем «хром» у списку осей стояв без межі слова й збігався з «моно**хром**ія».
```
підпис «тепла нейтраль»   -> R-TYP-05
підпис «тиха монохромія»  -> ЖОДНОГО    ← підпис ІНШОГО образу знімав правило
```
На реальному шляху моста: було 1 порушення, стало 2. `\b` на кирилиці в Python
`re` працює (перевірено окремо; у GNU grep — ні).

### 4. Речення знахідки — вхід у гіперграф, а не текст
```python
# graph._вузли_знахідки
текст = " ".join(str(з.get(k) or "") for k in ("суть", "чому")).lower()
for зт in ЗОНИ_ТІЛА:
    if ("«%s»" % зт) in текст or (" %s " % зт) in ...: вузли.add(зт)
```
Слово-зона в реченні додає ребру вузол тіла; вузол керує рядком «вузьке місце»
в промпті й вибором слота у вітрині ремонту. Спіймано живим: суть K-OUT-10 із
«на довжині «коліно»» виростила вузли з `['верхній_шар']` до
`['верхній_шар', 'коліно']`.
Друге сполучення: `outfit._репліка` ріже `суть.split(" — ")[0]` — тире як
ЗВʼЯЗКА зносило присудок.
**Висновок: «правка лише тексту» в цій системі не існує як безпечна категорія.**

### 5. Перевернутий знак: ремонт вели в протилежний бік
`outer.край_см` віддає висоту **від підлоги** (вимір: пальто до коліна 47.9,
сукня максі 10.1), тож Δ > 0 = «край верхнього шару ВИЩЕ» = пальто КОРОТШЕ.
```
було  if Δ > 0: «верхній шар ДОВШИЙ» → «ВКОРОТИТИ верхній шар»
      тобто вже коротшому пальту радили вкоротитись іще
стало пальто ДОВШЕ  → «краї майже збігаються (7.0 см) — вкоротити верхній шар»
      пальто КОРОТШЕ → «… — змінити низ: подовжити верхній шар нічим не можна»
```
Тексти ремонтів були правильні — стояли не з того боку. Свідок, що це не
конвенція модуля: K-OUT-05 у тому ж файлі читає ту саму величину правильно.
Гейт не ловив: у зимовому образі |Δ| = 14.3 ≥ смуги 10.0, входу нема.

# ЧОГО ЦЯ СЕСІЯ НЕ ДОВЕЛА

- **Не доведено, що бодай одне правило ПРАВЕ.** Міряли, чи воно ДІЄ. Поріг може
  бути хибним у правила з вердиктом «ціле».
- **«Без сліду» не означає «мертве».** Сім правил ожили від правки батареї, не
  коду; п'ять «воскресли» від правки лічби. Скільки таких лишилось — прилад
  сказати не може за означенням.
- **Не доведено, що виправлені речення ДОБРІ.** Доведено, що вони розрізняють
  ситуації, які раніше зливались, і називають напрям. Чи модель від цього складе
  кращий образ — покаже прогін із живою моделлю, якого тут не було.
- **Жодного вердикту людини.** Усе виміряне — сантехніка: чи доходить, чи не
  падає, чи називає себе, чи можна за сказаним щось зробити. Чи образ добрий,
  скаже носій.
