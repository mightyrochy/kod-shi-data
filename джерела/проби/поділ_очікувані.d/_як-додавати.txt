# ЦЕ ОДИН ФАЙЛ РЕЄСТРУ ПОДІЛУ. Реєстр — тека `поділ_очікувані.d/`, і `поділ_спільне.очікувані` читає
# ОБ'ЄДНАННЯ всіх `*.txt` у ній. Один запис — один рядок:
#     <модуль-до-поділу> | <новий_модуль>::<ім'я> | <sha> [<sha> …] [| нота]
# Порожній рядок і рядок із «#» — не запис; журнал цього рядка дошки теж тут, рядками «#». Проба бере
# МНОЖИНУ ключів, тож порядок файлів, порядок рядків і повторений ключ на вердикт не впливають.
# ЯК ДОДАВАТИ: заведи (або редагуй) ЛИШЕ СВІЙ файл `рядок-NNN.txt` — тоді дві гілки ніколи не правлять
# той самий файл і не конфліктують ніде, у тому числі на кнопці «Merge» GitHub. ЧУЖІ ФАЙЛИ НЕ ЧІПАТИ:
# щоб дописати sha до чужої пари, НЕ прав її рядок — постав СВІЙ рядок із тим самим ключем у своєму
# файлі (дублікат ключа нешкідливий: проба бере множину).
#
# ЧОМУ ТЕКА, А НЕ ОДИН ФАЙЛ. До 24.09.2026 реєстр був одним файлом `поділ_очікувані.txt` із
# `merge=union` у `.gitattributes`. Union діє лише на ЛОКАЛЬНИХ злиттях: серверне злиття GitHub
# драйвера з `.gitattributes` не бере, і кнопка «Merge» давала конфлікт — #251 зливався локально
# чисто, а GitHub показував `mergeable: false, dirty`. Тека знімає це без жодного драйвера:
# різні файли конфліктувати не можуть ні локально, ні на сервері.
