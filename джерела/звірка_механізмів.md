# Звірка механізмів: корпус проти коду, правило за правилом

Метод: `звірка.py K-XXX-NN` друкує блок теми (що правило МАЄ робити) і код навколо
точки емісії (що воно РОБИТЬ). Вердикт ставиться читанням.

Вердикти: **ЗБІГ** · **ЧАСТКОВО** (реалізована частина механізму) ·
**ПІДМІНА** (код робить інше) · **НЕМА ВХОДУ** · **ВІДСУТНЄ**.

Черга: спершу 52 правила, що спрацьовують на реальному каталозі (360 образів,
4 сценарії) — хибний механізм там шкодить сьогодні. Далі решта.

## E2-1. Системна причина для аксесуарного шару: ціле відро знахідок не збирається

`accessory.перевірити` віддає знахідки шістьма відрами:

```
ворота          → pipeline збирає ✓
преференції     → pipeline збирає ✓
без_входу       → pipeline збирає ✓
питання         → НЕ ЗБИРАЄТЬСЯ ✗
без_відповіді   → НЕ ЗБИРАЄТЬСЯ ✗
канал_3 (команди розкладки) → НЕ ЗБИРАЄТЬСЯ ✗
```

`pipeline._усі_зн` (рядки 311–313) бере рівно пʼять списків: `ворота`,
`преференції`, `надточний_збіг`, `віднімання`, `без_входу`. Відра `питання`,
`без_відповіді` і `канал_3` лишаються всередині `вих["аксесуари"]` і далі нікуди
не йдуть.

**Що саме туди потрапляє.** `accessory.py:2086`:
`питання = [з for з in _усі_ворота if з.get("сила") == "питання"]` — тобто
**КОЖНА воротна знахідка, яка чесно вийшла «питанням» через брак входу**. Плюс
рядок 2121 додає туди ж `_місця_зн` (K-ACC-12) і питальну гілку K-ACC-07.

**Чому це порушення корпусу, а не деталь.** `_усі_зн` — це вхід мовного гейта,
чеклістів K-SYS-08/09 і **блоку припущень K-IO-03**, який корпус дає силою
`hard`: «Every assumption goes explicitly into an assumptions block». Правило,
що видало «питання» через відсутній вхід, — це рівно припущення, і K-IO-05
вимагає записати зниження. Аксесуарний шар цього не отримує: його питання
губляться на межі модулів.

**Наслідок для звірки.** Частина з 22 «мовчазних» правил `accessory.py`
насправді СПРАЦЬОВУЄ — але у відрі, якого ніхто не читає. Мій лічильник
спрацювань їх не бачив із тієї ж причини, з якої їх не бачить стиліст.

**Другий дефект того самого місця.** K-ACC-07 сам каже, чого йому бракує:
«передати `спец` і `запити` у `accessory.перевірити`». `pipeline` їх передає —
`спец=kw.get("спец"), запити=kw.get("запити")` — але `сцен` у мосту будується з
`_ПОЛЯ_СЦЕНАРІЮ`, де ні `спец`, ні `запити` нема. Отже вони завжди `None`,
правило завжди йде в `elif`-гілку, видає «питання» — і воно гине у відрі.
Два незалежні розриви на одному шляху.
