# Перевірки PR моделлю Gemini у Colab — результат (наряд `аудит/наряди/colab-перевірка.md`)

Виконано 2026-10-26 16:24–16:30 UTC, ноутбучна сесія claude-sonnet-5-5. Крок 1 дав стоп: шлях `colab exec` → `google.colab.ai` закрито,
кроки 2–5 (пілот, суд, ліміти) не виконувались — моделі недосяжні без браузера.

## Вхід
- Colab CLI (`google-colab-cli`) у WSL (Ubuntu, користувач rochy), `--auth oauth2`, токен власника в `~/.config/colab-cli/token.json` (не читався).
- Строк життя токена CLI не виміряно (`colab usage` і `colab new` пройшли без запитів у 16:24 UTC).

## CU до / після
- До: `colab usage` → Current balance 200.00 compute units, Active assignments 0.
- Рантайм: `colab new -s rev` (CPU, READY), ~6 хв, rate 0.08/hr; після `colab stop -s rev` → 200.00 CU, Active assignments 0,
  `colab sessions` → «No active sessions found on server». Списано < 0.01 CU (залишок на екрані — 200.00).

## Крок 1 — `ai.list_models()` у VM через `colab exec`
Команда: `colab exec -s rev -f lm.py` з `from google.colab import ai; print(ai.list_models())`. Вивід (дослівно, суть):

    File ".../google/colab/ai.py", line 132, in list_models: model_proxy_token = _get_model_proxy_token()
    File ".../google/colab/ai.py", line 113, in _get_model_proxy_token: model_proxy_token = _userdata.get('MODEL_PROXY_API_KEY')
    File ".../google/colab/userdata.py", line 66, in get: raise TimeoutException(key)
    TimeoutException: Requesting secret MODEL_PROXY_API_KEY timed out. Secrets can only be fetched when running from the Colab UI.

Механізм (з вихідного коду `ai.py` у VM): токен проксі береться з env `MODEL_PROXY_API_KEY` або з `userdata.get`, що питає
браузерний фронтенд Colab; env-змінних проксі у VM нема, крім `MODEL_PROXY_HOST` (= `mp.kaggle.net`). `GET {host}/models` без токена
з VM → HTTP 401 (порожнє тіло). Перелік моделей отримати не вдалося, модель не обрано.

## Висновок
Шлях «Gemini через `colab exec`» без браузера закрито (за наказом наряду крок 1 → «лише в браузері»). Таблиця за PR (#1833, #1819,
#1835), не-JSON, час/виклики на перевірку, ліміти год/доба, CU на перевірку, прогноз перевірок на добу — не виміряно (моделі нема).
Мірило (≥ 5 перевірок на добу, знайдені блокувальні вади) — не досягнуто: 0 виконаних перевірок.

Лишається одна неперевірена гілка, поза межами наряду (браузерну автоматизацію акаунта власника наряд забороняє): `colab url --open`
прикріпляє веб-інтерфейс Colab до сесії CLI, і тоді `userdata.get` міг би відповісти; потрібна жива людина з відкритою вкладкою на
всю перевірку, тож це не автономний шлях. Рішення — за менеджером.
