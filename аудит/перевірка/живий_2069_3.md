# План приймання жнив після перевірки #2069

Об'єкт: нова пачка 5.3-Б у `gemini/перевірка-2069-4` замість #2069 та #2105. Перевірена інтегрована голова коду — `878370b0985c18988fdda88ef6ba7a8bffe5dc59`: `main` `39989dd42a49625c74c1593aaafc249f44fc54c0` + доробка `af743cd654d7b0cdbc9432e0018b8518f62bf649`, реалізація `a73b2ff3b32f5d13d303b1bfb98971acee0522d3`. Звіт — `перевірка_2069_4.md`. Перед прийманням усунути 10682 (неповне охоплення спільним читачем/писачем) і перевірити голову доробки; поточний вердикт — ДОРОБИТИ. Офлайн-повтор 10661 пройдено, але зовнішнього приймання ще немає. Рядки доробок, зокрема 10636–10637, 10661 та 10678, до приймання лишаються не вище ЧАСТКОВО. Перед запуском зафіксувати фактичний повний SHA призначеної голови й перевірити її відмінності від цієї бази.

Це прогін відновлюваного обходу крамниць, без мовної моделі й моделі-стилістки. Реєстр `аудит/проби/живі_сцени.txt` описує образи; жодна його сцена не вимірює HTTP жниварки, JSONL чи checkpoint. Прогін образів, фото образів і `FOTO=1` цього питання не перевіряють. Потрібна окрема сесія жнив на ноутбуці, призначена диспетчером; цей план не запускає жнив і не змінює черги обгортки.

ДО: точний `a136a841db8fed6703c17866166514729f2875eb`, локальне відтворення `докази_2069_3/ДО.txt`. Новий товар після кінця: 0 HTTP і старі три адреси; очищення JSONL: 0 адрес і хибний підтверджений кінець. Повторювати цей ДО живцем не потрібно; його межа — керовані HTTP-відповіді, а не зовнішня крамниця.

ДО для 10661 — `7a3173e767b403ffcee0030dea4a721cb4dd156b`, нові докази `докази_2069_4/ДО.txt` → `ПІСЛЯ.txt`: власна матриця 14/29 → 29/29, код 1 → 0. Пошкодження на межі означає фактичне видалення останнього цілого запису; окремо перевірено цілий останній запис без LF. Цей доказ не є зовнішнім HTTP-прийманням.

Для обох сімейств Woo та Shopify використовувати окрему копію журналу поза git для кожного випадку. Джерело має дозволяти перевірити зміну переліку адрес між двома дозволеними проходами. Зміна справжнього каталогу крамниці не доручається. Якщо нового товару в дозволеному джерелі немає, цей випадок позначити «не виміряно», а не «пройдено». Не замінювати живий доказ повтором офлайн-фікстури.

- Новий товар після кінця → чи нові жнива побачили адресу, якої не було в завершеному проході → прямий запуск виконавця за рецептом, без `--оновити-перелік` → ДО з `ДО.txt` → новий прохід звернувся до першої сторінки й зберіг нову адресу; SHA256 відповідає JSONL, кінець лише після порожньої відповіді HTTP 200.
- Очищений журнал → чи цілі кешовані сторінки відбудовують усі раніше збережені адреси → спорожнити JSONL у копії завершеного проходу, зберігши checkpoint і кеш → ДО з `ДО.txt` → повернулися всі адреси без HTTP збережених сторінок; неповний журнал не оголошено завершеним.
- Обрізаний журнал → чи відбудовано втрачені цілі записи й запис посеред рядка → дві окремі копії: обрізати на межі запису та посеред запису → ДО з `ДО.txt` → цілих сусідів збережено, кожна втрачена адреса знову має читабельний результат; кеш не перезапитується, битий старий рядок явно діагностовано.
- Обрив під час сторінки → чи повтор починає з першого незавершеного результату → перервати прямий процес після збереження відповіді сторінки й частини карток, повторити на тому самому журналі → офлайн-ДО та ПІСЛЯ в `ДО.txt`, `ПІСЛЯ.txt` → збережено попередні картки, завершено решту; HTTP лише незбережених сторінок, без повтору вже збереженої.
- Відбудова підсумку → чи завершений цикл не запускається знову через втрату `обхід_стан.tsv` → після завершення прибрати лише TSV з копії й двічі запустити `обхід.py` → офлайн-ПІСЛЯ `два обходи` → TSV правдиво відновлено з JSONL і кінця, обидва повтори без HTTP; прямі нові жнива та продовження обходу мають різне призначення.
- Ізоляція крамниць після обриву зведення → чи виправлення 10661 не зупиняє здорову крамницю → обірвати UTF-8 хвіст TSV в окремій копії, повторити обхід із двома крамницями → ДО `повтор_2053.txt`: двічі `UnicodeDecodeError`, запусків 0 → здорову крамницю виконано, збережені цілі записи доступні, пошкоджений результат має причину або повторно виконаний.
- Ізоляція після обриву стану та JSONL → чи здорова крамниця виконується за пошкодженого сусіда → для кожного формату окрема копія з обривом UTF-8, серединою запису, втратою останнього цілого запису й відсутнім останнім LF; двічі повторити обхід → ДО й ПІСЛЯ у `докази_2069_4/` → здоровий домен виконано, збережені адреси доступні, пошкодження діагностовано, другий повтор без зайвого HTTP.
- Дописування після обриву → чи новий цілий результат відокремлено від старого хвоста → окремо обірвати зведення, JSONL і TSV стану; дати справжньому виконавцю дописати результат, а обходу замінити стан → власні проби `докази_2069_4/ПІСЛЯ.txt` → читач бачить новий цілий результат та збережені сусідні записи, фізичний курсор не пропускає наступний підсумок і не видає його двічі.

Докази: повний SHA фактичної голови, домени й рецепти, час UTC, команда кожного запуску, HTTP-адреси/сторінки, перелік адрес JSONL до й після, SHA256 та checkpoint, підсумок TSV і названі причини. Сирі тіла й робочі журнали лишити поза git; у звіт — числа й відбитки, достатні для звірки. Не використовувати платні API, нові секрети, `workflow_dispatch` чи сторонні зміни каталогу.

Оцінка: окрема сесія жнив, без моделі; час зовнішніх відповідей тут не виміряно. Успіх тільки за фактичними результатами всіх названих випадків; відсутнє джерело чи незадіяний крок — «не виміряно». Запуск і CI голови перед злиттям — диспетчерові.
