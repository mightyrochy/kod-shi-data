## Що змінено

Причина — змішування точки кольору з інтервалом у читачах. Для візуалізації тепер є спільний
`джерела/прилади/колір_звіту.py`: вимір дає збережений hex або hex власної Lab-точки,
інтервал — тип і всі межі через `колір_річ.межі_кольору`, невідоме — None.
Центр вікна не обчислюється; навіть залишковий hex або Lab інтервалу не перетворюється на вимір.

Виправлені читачі:

| Файл у `джерела/проби/` | Зміна |
|---|---|
| `поверхня_212.py` | Обидві колонки споживача й основний колір приймають точку, інтервал і невідоме; аркуш друкує межі L*, C*, h, без плашки інтервалу. Нема слова й виміру — немає білої плашки. |
| `шлях_речі_вимір_проти_слова.py` | Вимір, кластери, другий колір і запис пулу підписуються спільним читачем. |
| `foto_rechi_152.py` | ΔE00 і точкове членство лише за двома результатами `точка_кольору`; відсутня точка названа «без входу», порожня вибірка не стає нульовою ΔE. |
| `пул_порядок_500_2030.py` | Порівняння ΔE76 читає точку через API; окремо друкує число пар без виміру. |
| `колір_центр_вікна_хрома.py` | Сусідній вимір збагачення читається через API, без обов’язкового hex. |
| `поділ_жнива_офлайн.py` | Історичне порівняння точкових алгоритмів бере лише справжні точки та друкує обсяг записів без виміру; Lab-точці не потрібен збережений hex. |

`поверхня_показ_212.py` та `швидкість_поверхні_1993.py` імпортують той самий `споживачеві`, тому
одержують межі без окремої копії виправлення. Формат другого елемента `споживачеві` тепер
`hex | {колір_тип, межі} | null`; ці читачі зберігають його в JSON і не розбирають як hex.

Інвентар пошуку — [2075-2/читачі-hex.json](2075-2/читачі-hex.json), відтворення —
`python -X utf8 аудит/перевірка/2075-2/інвентар.py`: 52 файли, 93 прямі читання hex після виправлення.
Оглянуто верхній рівень `джерела/` поза `status.МОДУЛІ_ПРОДУКТУ`, `прилади/`, `проби/`, `лабораторія/`
і `аудит/проби/`. Це інвентар кандидатів, а не лічильник дефектів.
Залишені читання належать фіксованим hex-фікстурам (`gate_e2e`, `pair_test`, `проба_правила`),
побудованим зразкам палітри, піксельним сегментам або явно відібраним вимірам з перевіркою наявності hex.
Наприклад, `leks_bezhevyi_59.py` перевіряє hex регулярним виразом; `khvylia2_*`, `mokko_kolir.py`,
`хакі_*`, `колір_hex_вікна.py` мають відбір hex-вимірів; `знімок_змісту.py` перевіряє наявність ключа.
`прилади/вимір_поверхні_212.py` читає явно закріплений історичний алгоритм `9dd9f675`, а не типізоване
зведення нинішньої голови; його колонку ДО не підмінено новим алгоритмом. У `аудит/проби/` прямих
обов’язкових читань hex типізованої речі не знайдено.
