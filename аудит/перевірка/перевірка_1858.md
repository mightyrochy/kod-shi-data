## Доведені вади

**10006 — після реального циклу OFF → новий boot немає BOOT.** `Get-NextMarker` у `claude_run.ps1:251` пропускає будь-який наявний state до перевірки FreshBoot на `:258`. Проба `off-first` створила OFF і один ВИМКНЕНО; потім збережено state/позначку, змінено тільки boot `b1 → b2`, прибрано файл заглушки shutdown й повторено Main. Exit 0, кількість вихідних файлів **1 → 1**, кількість викликів shutdown цього проходу **0**, BOOT **0**. Окрема `boot-new` без попереднього state дає BOOT: штатний K6b перевіряє цей інший випадок, а не ту саму вже виконану позначку після перезавантаження. Потрібне повідомлення BOOT для збереженої OFF-позначки, без другого вимкнення.

**10007 — EOF обходить поріг завислості.** `claude_run.ps1:456` виходить з циклу при EOF, а `:466` замінює контроль подій фіксованим `WaitForExit(300000)`. Заглушка `fake_events.py`, сценарій closed: прочитати stdin, віддати одну system-подію з flush, закрити fd 1/2, спати 7 с, вийти з кодом 3. `HangMinutes=0.025` (1.5 с), але отримано **EXIT за 8.27 с**, а не HANG після тиші. За стандартного порога 120 хв цей самий шлях обриває ще живий процес через 5 хв; на ньому також немає Update-Status. Потрібно стежити за часом останньої події до завершення процесу і після EOF, без окремої абсолютної межі.

**10008 — не-JSON рахується подією.** У `claude_run.ps1:457` таймер скидається до розбору типу, `:461` записує events.tsv навіть з порожнім типом. Заглушка noise: одна system-подія, потім 10 не-JSON рядків кожні 0.5 с, exit 3. За порога 1.5 с отримано **EXIT за 6.33 с**, хоча валідних подій понад 5 с немає; кожен шумовий рядок продовжує очікування. Додаткова killed-заглушка завершила процес через `os._exit(9)` посеред роботи: **EXIT, один рядок**, не тиша.
