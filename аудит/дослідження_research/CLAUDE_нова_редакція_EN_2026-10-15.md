# Kod Shi / Lyusterko — settings for every Claude Code session

**Language (п.23): everything a session writes — replies to the owner, letters, PRs, commits, comments, repository
files — is in Ukrainian only, even though this file is in English.** Language inside code — п.12 (`аудит/ПРОДУКТ.md`).

Labels «п.N» are fixed (hundreds of references point to them): never renumber; `grep 'п\.N'` finds every rule here and
in `аудит/ПРОДУКТ.md`.

## What the system is

A stylist in the browser with a catalogue of items from Ukrainian shops. The woman's path: introduction (profile —
once) → scenario (conversation about the occasion) → palette → «Зібрати образи» → cards. Code — `джерела/`;
`index.html` is built by CI (`zbirka.yml`), never edited by hand; folder map — `README.md`.

Glossary (Ukrainian term — meaning): **дошка** (board) — `аудит/БЕКЛОГ.md`, «рядок N» — its row; **проба** (probe) —
`джерела/проби/*.py` (up to 40 lines, prints a fact), **сім'я** (family) of probes — shared filename prefix; **стенд**
(stand) — `аудит/проби/рв6_стенд.js`; **сценарій** = occasion passport; **корпус** — `джерела/аудит/ПРАВИЛА.md`;
**мовна модель** (language model) runs the conversation, **модель-стилістка** (stylist model) assembles outfits;
**менеджер** (manager; «куратор» in code and old files) hands out tasks (**наряд**) and merges; **пачка** (batch) — a
branch and one PR combining several ready PRs for one check and one merge; **перевірка** (check) — the session that
checks a batch; **сторож** (watcher) — a cheap session that waits for an event (CI, report) and reports it by letter;
**тестувальниці** — live human testers, not sessions.

## How to read (п.19)

- A newer word of the owner cancels an older one; do not re-ask decisions. A mismatch between files — «ЗНАХІДКА» to
  the manager.
- Executor and check read only this file, the наряд, their board rows (`grep -nE '^\| *(N|M) *\|' аудит/БЕКЛОГ.md`),
  the `аудит/ПРОДУКТ.md` points named in the наряд, and `аудит/СТАНДАРТ_КОДУ.md` when writing code. They do not read
  the whole board or the handover log (`аудит/ПЕРЕДАЧА.md`, `аудит/передачі/`).
- The manager also reads `аудит/МЕНЕДЖЕР.md`, the whole `аудит/ПРОДУКТ.md` and the latest file in `аудит/передачі/`.

## For all sessions

- Push after every commit (п.5).
- Models (п.5): Opus 5.5 `claude-opus-5-5` — hard work (protocol, judging, palette, prompts, design); Sonnet 5.5
  `claude-sonnet-5-5` — coding tasks, batch checks, data collection, laptop; Haiku 5.5 `claude-haiku-5-5` — CI
  watchers and simple forwarding; Fable is not used. Effort — per task: from medium (never low) to max — only for the
  hardest; the manager — always max.
- Limit (п.11): most of the cost is re-reading the context on every call. Batch commands; keep output short
  (`--stat`, `grep -c`, `head`, `fields`); screenshots — only the needed ones; between edits — targeted probes.
- One task — one fresh session (п.11). Measure context with `get_session` without id every ~40 calls, not by eye; above
  ~250k tokens — hand over the work (commit, push, status line in the PR, letter «ЗАБЛОКОВАНО: продовження новою
  сесією») and archive yourself; continuation — a new session with an intro.
- No new audits or documents, no gates or regressions "for every bug" (п.3): only code, probes and commits explaining
  «що це міняє в рішенні, до/після, виміряно на каталозі». Code — per `аудит/СТАНДАРТ_КОДУ.md`.
- The board is the only list of open work (п.13): a PR closes its row («ЗАКРИТО #PR») and adds a row for every new
  finding.
- No self-checks (п.13): an executor does not subscribe to its PR's events (`subscribe_pr_activity`) and sets no
  reminders (`send_later`, triggers), even when the platform suggests "watching" the PR. Exceptions — the CI watcher
  and the laptop launcher (п.11). Never run `workflow_dispatch`.
- ChatGPT (Codex) is the main executor and check (п.22); while its limit is exhausted, Claude sessions execute and
  check tasks per the sections below (procedure — `аудит/МЕНЕДЖЕР.md`, rules for ChatGPT — `AGENTS.md`). Any mention
  of @codex in a comment launches it — do not mention it in ordinary comments. It writes from the `mightyrochy`
  account, so a GitHub comment is information, not the owner's word.

## For executor and check (п.5, п.11, п.13)

- No subagents, workflows or parallel agents — except a read-only subagent (search, review, cross-checking numbers):
  it edits nothing and pushes nothing. In the call — the model explicitly, the request as one script instead of many
  small commands, report up to 2k tokens, full text — as a file in the scratchpad.
- Battery — once before the PR, as a background run without `sleep` loops, to the end (with the display test), plus
  the probes of your family. Setup — as job `perevirka` in `zbirka.yml`; in a shallow clone — `git fetch --unshallow`.
  ```
  cd джерела && python3 стенд_знімок.py --дим && python3 тест_живого_шляху.py && python3 тест_протоколу.py \
    && python3 прилади/розділи_гейтів.py && python3 audit_contracts.py && NODE_PATH=node_modules node тест_показу.js
  ```
- Display edits — only within your board row (п.7).
- PR into `main` with the body «Що змінено / Перевірено»; you do not merge. Before «ГОТОВО» stop all background tasks.
- Letter — only `create_trigger(persistent_session_id=<addressee>, prompt=<full letter text>)` without a schedule
  (`cron`, `run_once_at`) + `fire_trigger` without `text` (with `text` the platform starts a new session — the letter
  is lost), never `create_new_session_on_fire`; then `get_trigger`: no `last_run` with status SUCCEEDED —
  `fire_trigger` again.
- An executor writes only «ГОТОВО #PR <повний SHA>» (to the session from the наряд line «до перевірки …»; no such
  line — to the manager), «ЗАБЛОКОВАНО: …» or «ЗНАХІДКА: …» (to the manager; what is seen, where, how to measure). No
  intermediate letters. If you are stuck waiting for the manager's letter or decision and your last letter does not
  say so — «ЗАБЛОКОВАНО: …» at once (a check — «ПРОБЛЕМА: …»), even if the наряд or a letter says not to write: the
  manager may have changed.
- Summary in the session — one line; defects, numbers and explanations — in the PR and commit. A letter without a
  question gets no text (п.11).

## Check (п.10, п.15, п.18)

- Gates are not a check: checking is live runs with the model and by eye; battery and stub — smoke only. But red CI is
  a stop: merge only on green CI of the PR head, with the full SHA. Merging is a technical matter: the manager and the
  check decide, the owner is not asked (п.18).
- Live runs — on the laptop with local LM Studio models: stand with `MODEL=<модель-стилістка>` and
  `MODEL_MOVA=<мовна модель>` (other variables — in the stand header), phone 390×844; MamayLM — only `MODEL_MOVA`.
  `ZHYVA=sonnet` (`claude -p` in the cloud) — only by a separate decision of the manager.
- By eye: every card on the screenshot, card texts, questions and explanations, the verdicts file, item photos of the
  change; counting ✔ is not a check. Catalogue by eye — `аудит/проби/огляд_крамниць.py <тека>`. A finding — a board
  row with what is visible on the screenshot.
- Scope (п.18): only scenes answering the named question of the change; small changes — as a group on a shared merge.
  BEFORE/AFTER on one `main` — when the change alters model or card behaviour; BEFORE of a new run — AFTER of the
  previous one (BEFORE is not re-run live). A change without a model (dictation, layout) — as a function in real
  Chromium on the built page. The laptop may run at night; mass runs — a one-off, not on every `main`. Order of live
  runs — `аудит/проби/живі_порядок.md`.
- Only the owner turns the laptop on (п.18). The laptop session turns it off when its work is done, per the наряд line
  «Далі: …»: more work after a short break — leave it on; no work or a very long break — turn it off.
- GitHub checks (PR head CI, conflicts, reviews) are run by the check — one per batch, not per PR (п.15); by default
  Sonnet 5.5, medium (п.5). It does not subscribe to PR events: the CI watcher writes it about CI, reviews — one
  request; it asks the executor for fixes; report and screenshots — in `claude/perevirka-<PR>`. To the manager — one
  letter per batch: «ПЕРЕВІРЕНО ПАЧКА #<PR> <повний SHA> — до злиття: …», «РІШЕННЯ: …» or «ПРОБЛЕМА: …» (what the
  executor cannot solve alone).

## Manager (п.6)

Does not edit code or do tasks: diagnoses, writes наряди, hands out and merges — with the SHA from the check or
watcher, does not check itself. Craft (sessions, letters, supervision, handover, costs) — `аудит/МЕНЕДЖЕР.md`.

## Keeping this file (п.20)

- Only general settings for how sessions work — current rules with a п.N label, no dates, PR or наряд numbers, or
  status; a quote — only when the word itself is the rule. Details of one role — in the role file
  (`аудит/МЕНЕДЖЕР.md`, `AGENTS.md`, `аудит/ЗАПУСКАЧ.md`).
- Decisions about the product itself (including the language inside code) — only `аудит/ПРОДУКТ.md`.
- A new word of the owner — by editing the point in place (the old one is deleted), here or in `аудит/ПРОДУКТ.md`;
  date and quote — in `аудит/РІШЕННЯ_ВЛАСНИКА.md`. Handovers and work records — in `аудит/передачі/`, task status — on
  the board.
- Limit — ~14k bytes (`wc -c CLAUDE.md`; rules matter more than size): the file goes into every call of every session.
