Наряд БЮДЖЕТ-ПУЛУ на слово власника 15.10 ~07:30 UTC про дослідження #1042 («"бюджет 120 тис. символів знімає ще

## Підсумок для власника

**Головне.** Бюджет міряє символи, а час і ціну виклику визначають **токени**. Сьогодні 120 тис. символів пулу — це
~44 тис. токенів пулу й ~49–50 тис. токенів усього промпту руки 1 (і стільки ж руки 2). Тому «влізти більше речей у
120 тис. символів» і «дати більше речей за той самий час» — різні речі: коротші ключі при тих самих 120 тис. символів
дають +14–20 % речей, але й +12–13 % токенів, тобто довший і дорожчий виклик, а на ноутбуці (qwen, контекст 57 344
у режимі двох моделей) промпт уже не влазить. Чесне порівняння — **при тих самих токенах**.

**Порада.** (1) **Т з бюджетом на ті самі токени** — найбільший виграш (+25 % речей) без жодного сповільнення й без
втрати жодного факту речі; але спершу живий ДО/ПІСЛЯ: одна сцена на ноутбуці (qwen 9B) і одна в хмарі, бо чи читає
мала модель колонки так само надійно, як ключі, — не виміряно. Якщо таблиця читається гірше — **К2** (+5 %, без
ризику). (2) **Підлога аксесуарів — ваше слово** (вона ваша, 31.08): зараз 10 слотів аксесуарів забирають 41 % місць
пулу й 34 % його токенів; 10 замість 20 віддає ці місця одягу, взуттю й сумкам за ту саму ціну. (3) **Бюджет не
піднімати**, поки стилістка живе на ноутбуці: 150 тис. уже не влазить у контекст qwen у режимі двох моделей. Для хмари
150 тис. — питання ціни (+22 % входу рук 1–2), а не швидкості (оцінка — нижче). (4) Хоч би який запис обрали, бюджет
треба перерахувати під нього (або міряти токенами): та сама цифра в символах на іншому записі — інша ціна й час.

Сукні цей бюджет майже не рятує: їх у пулі 23–43 при будь-якому варіанті, бо після вікон палітри лишається 108–185
суконь (#1042) і семплер ділить решту пропорційно наявному. Те, що звужує сукні, — вікна, а не бюджет.

## 1. Звідки 120 тис. і для кого вона однакова

- **Де.** Показ шле `бюджет_символів: БЮДЖЕТ_СИМВОЛІВ_П = 120000` (`джерела/показ.html:11480`), Python бере його в
  `міст_пакет._пакет_у_бюджет` (за замовчуванням `_БЮДЖЕТ_СИМВОЛІВ = 120_000`, `міст_пакет.py:566`). Міряється лише
  поле `pool` того самого тексту, що йде моделі (`пакет_моделі.вага_пулу`, ПР-10): інструкції, людина, правила (~18 тис.
  символів, ~5 тис. токенів) — поза бюджетом. Пошук — найбільше n речей, чий пул ще влазить (січна + бінарний), речі
  обирає `семплер.вибрати` (страти, підлога 20 на слот, сід).
- **Чому таке число.** Історія в коментарях: 02.09 бюджет був 60 тис. через 429 безкоштовного тарифу (чотири руки
  одночасно), 04.09 тариф платний — повернули 120 тис. «як кап проти патологічного каталогу, не судження про якість»;
  коментар у коді прямо каже «число не каліброване». Не під час і не під вікно моделі його ставили. Worker ріже вхід над
  400 тис. символів (`worker.js:50`).
- **Хмара й ноутбук — та сама цифра.** Показ шле 120 тис. для будь-якої моделі (`gemini-3.8-flash` типово, `ТИПОВА_МОДЕЛЬ_П`);
  стенд ноутбука ходить тим самим мостом. Тобто одна межа в символах для моделі з контекстом у сотні тисяч токенів і для
  qwen 3.5 9B із контекстом 57 344 (дві моделі через проксі) чи 81 920 (одна) — `аудит/МЕНЕДЖЕР.md`.

## 2. Як кодується річ і що з неї модель бере

Річ пулу — JSON-об'єкт (`пакет_моделі._річ_пулу` → `дріт_моделі.річ`), порожні поля не пишуться, типові значення
(`in_arc`, `branch`, `L_from`, `hem_from`) — у `pool_keys`. Приклад (офіс):
`{"n":"#61·17","name":"Блуза плісе cірий","price":1900,"type":"blouse","cut":"fitted","fabric":["polyester"],
"length":"waist","color":"grey","hex":"#b5aaab","family":"neutral_achromatic","L":[71,71],"hem_cm":[101,107],
"formality":["everyday","neat"],"register":"preppy"}`.

Офіс, 463 речі, 120 тис. символів: **258 символів і 95 токенів Qwen на річ** (Gemma 3 — 94). Частки токенів пулу:

| поле | токенів | примітка |
|---|---|---|
| `name` (слова крамниці) | 20,6 % | 38 символів → 16,6 токена: кирилиця ~2,3 симв./токен; не чіпається (п.12) |
| `n` («#67·33») | 12,4 % | номер + код крамниці; цифри Qwen рахує по одній |
| `hex` | 11,8 % | |
| `L` | 10,5 % | у 382 з 463 речей `[a,a]` — те саме число двічі |
| `family` | 9,3 % | |
| `fabric` | 8,9 % | 132 речі — `"unknown"`; список з одного — у дужках |
| `price` | 8,5 % | |
| `color`, `type`, `formality`, `hem_cm`, `register`, `length`, `cut`… | решта | |
| **імена ключів разом** | 38 % (і 38 % символів) | англійське слово-ключ — 1 токен, скорочення («family»→«fm») — теж 1–2: короткі ключі економлять символи, а не токени; токени економить лише відмова від повтору ключа (таблиця) |

**Що повторюється.** Імена ключів — у кожній речі (14 ключів у середньому); `L` двічі одне число; списки з одного
значення; `"fabric":"unknown"` у 28 % речей; однакові коди (`neutral_achromatic`, `everyday`) сотнями разів.

**Що модель справді використовує** (35 записаних відповідей складання qwen 3.5 9B, `аудит/живі_11`, `живі_12`,
`живий_пачка2`, 2 093 посилання на речі пулу): речі називає лише `n`; у поясненнях — тканина (385 згадок), ошатність
(273), світлота/контраст (159), hex (126), довжина/поділ (111), візерунок (68), реєстр (65), каблук (22), блиск (17),
**ціна — 0** (і правила задачі ціну не згадують). Беруть речі рівномірно по всьому пулу: за децилями позиції
246 / 226 / 180 / 219 / 198 / 234 / 253 / 226 / 190 / 121 (останній дециль — дрібні аксесуари). Тобто «губитись
у середині» модель на ~460 речах не помітно; на 600+ — не виміряно. Ціну не пропоную знімати: п.9, «ціна — лишаємо так».

## 3. Варіанти економії (виміряно: `проби/бюджет_пулу_запис.py`)

Варіанти — лише форма, факти ті самі; слова крамниці (назва, колір крамниці) йдуть як є, код їх не читає й не складає (п.12).
- **К1** — короткі ключі для всіх речей (`дріт_моделі.КОРОТКІ_КЛЮЧІ` + `name`→`nm`, `shop_color`→`cs`), легенда в `pool_keys`.
- **К2** — К1 + `L`/`hem_cm` `[a,a]`→`a`, список з одного → значення, `fabric:"unknown"` → типове «absent = unknown».
- **Т** — К2 таблицею: `{"cols":[…],"rows":[[…],…]}`, колонки — ключі ≥25 % речей, рідкі — об'єктом у кінці рядка.

| побачення 19:00, дощ, smart_casual | 461 | 530 | 549 | 656 | 95,5 → 91,6 → 76,5 | 49,5 → 56,0 → 55,8 |
| весілля гостею 17:00 | 451 | 519 | 537 | 637 | 96,7 → 92,1 → 77,3 | 49,3 → 55,4 → 55,0 |

Промпт у всіх цих стовпцях — 49,1–50,0 тис. токенів Qwen (Gemma 3 — 48,4–50,3 тис.), тобто час і ціна ті самі.

**Порядок семплера (підлога).** `семплер.ПІДЛОГА_СЛОТА = 20` — рішення власника 31.08: кожен із 17 слотів дістає
щонайменше 20 місць, решта ділиться пропорційно наявному. На 460 місцях підлоги з'їдають ~320, і 10 слотів аксесуарів
(пояс, головний убір, шарф, прикраси, сережки, намисто, кольє, браслет, каблучка, брошка) мають 180–196 місць — 41 %
пулу й 34 % його токенів, тоді як верх+низ+сукня+комплект+верхній шар — 179–204. Підлога 10 (запис як є): одяг
192–241, взуття+сумки 58–146, аксесуари 133–144, сукні 23–33 — при тих самих токенах. Це не межа пулу й не наказ
промпту, але число — ваше.

**Що ще розглянуто й не раджу.** Довідник кодів сімей (`neutral_achromatic`→`f0`): −1 токен на річ, зате дві назви
одного факту в одному промпті (сім'ї стоять і в палітрі людини) — код уже двічі ловив, що модель читає це як два різні
факти. `hex` без «#»: −1 токен на річ. Номер без коду крамниці («#67» замість «#67·33»): ~−4 токени на річ (−4 %), але
код крамниці — контрольна пара, яка ловить чужу річ у відповіді (Т-7, 25.09). Зняти ціну чи сім'ю — −7…−8 % токенів,
але це втрата факту (і ціна — п.9).

- **Виміряно, але грубо (ноутбук):** 603 записані виклики qwen + MamayLM (`живі_11`, `живі_12`, `живий_пачка2`):

## 5. Проба й відтворення

`cd джерела && QWEN_TOKENIZER=<tokenizer.json Qwen3.5-9B> python3 проби/бюджет_пулу_запис.py [бюджет …]` — шість сцен
#1042 × ДО / К2 / Т при кожному бюджеті: речей, символів на річ, токенів промпту й пулу, одяг / сукні / взуття+сумки /
аксесуари. `PIDLOHA=10` — підлога семплера. «Ті самі токени»: бюджет 105 000–106 000 для К2 і Т. Без токенізатора —
лише символи й речі. Токенізатор: `https://huggingface.co/Qwen/Qwen3.5-9B/resolve/main/tokenizer.json`, `pip install tokenizers`.
Сцени — з `проби/пул_свобода_смуги.py` (та сама лічба місць у пулі, `стеля.K`).
