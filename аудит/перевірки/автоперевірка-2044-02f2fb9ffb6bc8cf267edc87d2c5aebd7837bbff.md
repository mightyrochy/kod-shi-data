## Доведені зауваження

### 1. Рядок металу безумовно відкидає кольори-інтервали (Р2)

Місце: `джерела/фід_добір.py:153–154`, `описує_річ`; викликач `джерела/композитор_слоти.py:720`. Після створення інтервалу функція перевіряє метал лише точкою, а за відсутності точки повертає `False`. Усі інтервали відкидаються ще до перевірки перетину вікон, незалежно від їхніх меж і свідка металу. Це зміна відбору поза заявленими змінами фото.

Власна проба `проби.py <дерево> метал-каталог <знімок>` на повному каталозі: золотий рядок із чинної `palettes.ЗОЛОТО` пропускає **91 → 16** речей, з них інтервали **75 → 0**. Власна проба `добір-металу` викликає штатну `кандидати_на_слот` на двох справжніх записах і золотому та нейтральному рядках:

```text
ДО: Кандидати: ['ж-07620@jecomestudio.com', 'ж-07619@gepur.com']
ПІСЛЯ: Кандидати: ['ж-07619@gepur.com']
Нота: None
```

Золото зникає без повідомлення, бо срібло заповнює слот і запасний шлях «жодне вікно не влучило» не діє. Потрібно провести інтервали металу через API меж і узгоджену політику невизначеності, не повертати їм вигадану точку. Під час правки звірити також `_нота_рідшого_золота`: її умова на межі пропускає інтервал до `tuple(точка_кольору(r))`; поточний відсів вище маскує цю незавершеність. Окремою досяжною аварією її тут не оголошено.

### 2. Носій сім'ї є в каталозі, але зникає з того самого пулу й площ схеми (Р2)

Місце зміни: `джерела/палітра_схеми.py:625` (`_lab_речі`); читачі `площі_схеми` :649–660, `_великі_у_пулі` :770, `слова_у_речах` :978. Допоміжна функція тепер повертає лише точку; ці споживачі продовжують передавати її у `сім_я_схеми`, хоча ця API вміє довести сім'ю за повним інтервалом. Лише `_великі_у_каталозі` виправлено на передачу запису.

Власна проба `проби.py <дерево> сімя`: синя сорочка з повним вікном лексикону й сім'єю `{роль: основа, дуга: [210, 340]}`. У базі — старий формат із походженням та центром; у голові — той самий інтервал із `lab=None`. API `сім_я_схеми(r, [family])` в обох деревах доводить `основа`.

```text
ДО: У каталозі: 1; У тому самому пулі: {'верх': 1}
ПІСЛЯ: У каталозі: 1; У тому самому пулі: {}
ДО: площі/носії основи: слоти ['верх'], речі ['blue']; невиміряні 0
ПІСЛЯ: площі/носії основи: слоти [], речі []; невиміряні 1
```

Наслідок: суд і повідомлення великої схеми втрачають доведеного носія, лічба асортименту й пулу суперечить сама собі, слова носіїв теж губляться. Потрібно зберегти типізований запис до API сім'ї у всіх цих читачах.

## Очі та межі

Переглянуто всі чотири `аудит/перевірка/2.13_тип_кольору/кадри_*.jpg` очима. Червоні сукні Vilni узгоджуються з повернутим виміром; кремові сукні 25union лишають інтервали при темному фото-вимірі. Помилки завантаження й відсутні кадри на аркушах видимі. Пудровий комплект `ж-04274@wearme.ua` та невідповідність рожевого виміру смугастій сорочці `ж-11918@theoriginals.com.ua` підтверджують уже відомий рядок 9700; новими вадами їх не пораховано.

Очного результату ≥38/40 змінених речей у PR немає: звіт доробки прямо каже «нового очного мірила ≥38/40 не заявлено». Звіт перевірки #1927-2 оголосив повне доведення мірила без нового аркуша з оцінкою кожної зміни. Нове рішення про вибір фото реально змінює основний колір речей, тому вимога п.18 продукту залишається невиконаною (відома межа 9701).

ЖИВИЙ ПІСЛЯ залишається потрібним для `ж-00378@vilni.store` та `ж-00260@25union.com.ua`. Статичний рендер і проби не доводять поведінку живої стилістки; платних API не викликано. Номерів нових рядків процесний наряд не виділив; дві нові вади передано цим звітом для реєстрації диспетчером.
