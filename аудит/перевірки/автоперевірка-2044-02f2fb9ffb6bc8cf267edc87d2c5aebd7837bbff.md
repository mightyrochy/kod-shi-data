## Доведені зауваження

### 1. Рядок металу безумовно відкидає кольори-інтервали (Р2)

Місце: `джерела/фід_добір.py:155–157`, `описує_річ`; викликач `джерела/композитор_слоти.py:720`. Після створення інтервалу функція перевіряє метал лише точкою, а за відсутності точки повертає `False`. Усі інтервали відкидаються ще до перевірки перетину вікон, незалежно від їхніх меж і свідка металу. Це зміна відбору поза заявленими змінами фото.

Мінімальний доказ без невизначеності: власна проба `метал-вікно` подає інтервал `L=[74,76], C=[34,36], h=[84,86]`, повністю всередині чинного золотого рядка. `palettes.метал_меж` в обох деревах повертає **так**, але `описує_річ` дає **True → False**. Отже причина — не обережність щодо широкого невизначеного слова, а втрата будь-якого інтервалу в цій гілці.

Власна проба `проби.py <дерево> метал-каталог <знімок>` на повному каталозі: золотий рядок із чинної `palettes.ЗОЛОТО` пропускає **91 → 16** речей, з них інтервали **75 → 0**. Власна проба `добір-металу` викликає штатну `кандидати_на_слот` на двох справжніх записах і золотому та нейтральному рядках:

```text
ДО: Кандидати: ['ж-07620@jecomestudio.com', 'ж-07619@gepur.com']
ПІСЛЯ: Кандидати: ['ж-07619@gepur.com']
Нота: None
```

Золото зникає без повідомлення, бо срібло заповнює слот і запасний шлях «жодне вікно не влучило» не діє. Це вимір масштабу зміни; він не доводить, що кожен із 75 широких інтервалів має лишитися певним золотом — потрібна узгоджена політика невизначеності. Мінімальний приклад вище доводить помилку і для цілком певного металу. Потрібно провести інтервали через API меж, не повертати їм вигадану точку. Під час правки звірити також `_нота_рідшого_золота`: її умова на межі пропускає інтервал до `tuple(точка_кольору(r))`; поточний відсів вище маскує цю незавершеність. Окремою досяжною аварією її тут не оголошено.

### 2. Носій сім'ї є в каталозі, але зникає з того самого пулу й площ схеми (Р2)

Допоміжна функція тепер повертає лише точку; ці споживачі продовжують передавати її у `сім_я_схеми`, хоча ця API вміє довести сім'ю за повним інтервалом. Лише `_великі_у_каталозі` виправлено на передачу запису.

Власна проба `проби.py <дерево> сімя`: синя сорочка з повним вікном лексикону й сім'єю `{роль: основа, дуга: [210, 340]}`. У базі — старий формат із походженням та центром; у голові — той самий інтервал із `lab=None`. API `сім_я_схеми(r, [family])` в обох деревах доводить `основа`.

### 3. Металева прикраса стає «самотнім колірним акцентом» (Р2)

Місце: `джерела/суд_від_моделі.py:1266` (`_метал_точки`); споживач — `бюджет_і_відлуння`. На відмові API від точки допоміжна функція повертає `None` і втрачає факт металу. [Зауваження рецензента](https://github.com/mightyrochy/kod-shi-data/pull/2044#discussion_r4397997209) підтверджено власною пробою `проби.py <дерево> метал-суд` без підмін суду:

```text
ДО: Колір металу: True; Знахідки: []
ПІСЛЯ: Колір металу: True
Знахідки: [('K-COL-05', 'orphan_accent', 'повторити цей колір у другій рознесеній зоні (взуття ↔ сумка ↔ шарф ↔ прикраси) АБО оголосити цю зону фокусом АБО прибрати')]
```

Вхід — золоте намисто (`метал=золото`) з інтервалом «золотий»; у базі — старий формат із центром і походженням, у голові — той самий інтервал без Lab. `palettes.колір_металу` в обох випадках доводить метал; на голові жінці їде хибна порада повторити колір чи прибрати прикрасу. Потрібно зберегти визначення металу за повним записом/межами, не вимагати точки.

### 4. Кандидат з доведеним членством палітрі не доходить до пошуку заміни (Р2)

Місце: `джерела/оцінка_образу.py:974`, `зміни_кроками`. Фільтр точки стоїть перед `річ_з_фото.членство_вікна`, хоча ця API підтримує інтервали. [Зауваження рецензента](https://github.com/mightyrochy/kod-shi-data/pull/2044#discussion_r4397997216) підтверджено власною пробою `проби.py <дерево> заміна`:

```text
ДО й ПІСЛЯ: Справжнє членство: ('так', 1.0)
ДО: Викликів членства в штатному генераторі: 1 [('так', 1.0)]
ПІСЛЯ: Результат: ([], {'цілі': ['old'], 'сума_до': 1, 'спроби': [], 'крамниця': {'пул_рук': True, 'чому': None, 'кандидатів': {'верх': 1}}})
```

Межі проби явні: на межі каталогу `_крамниця` подає контрольований готовий пул з одним кандидатом; штатні підготовка цілі, цикл відбору й справжня API членства збережені. Проба зупиняється при першому досягненні членства у базі; подальший суд та вітрина не запускаються й поліпшення образу не заявлено. На голові генератор завершується сам: кандидат відкинутий, до членства не доходить. Потрібно допускати записи з межами до вже наявної перевірки вікна.
