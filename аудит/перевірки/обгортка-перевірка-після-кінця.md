## Обхід кодом застосованого `wrapper_chain.ps1` (`Get-ChainBusySlots` :408, `Get-ChainBranchWork` :436)

Усе читання чужого стану лежить під одним `try { … } catch { Write-WrapperLog "стан смуги <назва> недоступний: <тип>: <повідомлення>" }` на смугу; `''` (звичайна перевірка) — поведінка до латки. Шляхи:

- `Test-Path slots` / `Get-ChildItem slots` (`-ErrorAction Stop`): UnauthorizedAccessException, PathTooLong, ArgumentException — у catch смуги.
- Замок: `File.Open(…,'None')`. UnauthorizedAccess — не IOException, проходить до catch смуги, зайнятістю не вважається. IOException: лише HResult&0xffff = 32 (sharing violation) = зайнято; FileNotFound (HResult 2) і DirectoryNotFound (3) внутрішній catch перекидає `throw`, зовнішній `catch [FileNotFound]/[DirectoryNotFound]` дає `continue` (слот звільнено); решта IOException (33, 206 тощо) — у catch смуги. Шлях перекидання перевірено за порядком catch у PowerShell.
- JSON слота: `ReadAllText` (UnauthorizedAccess → смуга; FNF/DNF → continue), `ConvertFrom-Json -ErrorAction Stop` (некоректний → смуга), порожній/чужий формат → `throw 'CHAIN_LANE_STATE'` → смуга.
- Claude: `state/branch-*.txt`, `.git`-файл копії, `HEAD` — `Test-Path -ErrorAction Stop` і `ReadAllText`, будь-який виняток (UnauthorizedAccess, IOException, ArgumentException на недопустимому шляху, FNF у вікні між Test-Path і читанням) — у catch смуги.

## Вади знайдено: 3 (дрібні, на наступний наряд ділянки, не доробка)

1. **Гранулярність catch — смуга, не слот** (`wrapper_chain.ps1:448–474`): `@(Get-ChainBusySlots …)` збирає всі слоти до повернення, тож виняток на одному слоті (напр. JSON одного слота нечитний) відкидає й уже прочитані придатні слоти тієї ж смуги; PR цієї смуги перевіряється як звичайно, хоч інший слот міг справді писати в його гілку. Наслідок — зайва проміжна перевірка в рідкісному збігу відмови й справжньої роботи; не падіння. Узгоджено з нарядом («для цієї смуги поведінка до латки»).
2. **Мовчазне «нема slots»**: якщо права забороняють проходити в батьківську теку (`claude-run`), `Test-Path -ErrorAction Stop` у PowerShell повертає False без винятку (поведінка Test-Path) — смуга пропускається без рядка «стан смуги … недоступний». Стенд перевіряє лише відмову на самій `slots` (та на JSON/замку/гілці/.git/HEAD). Наслідок — нема рядка журналу для цього випадку; поведінка та сама. Припущення (PS 5.1/7), живо не відтворено.
3. **Стенд не вправляє IOException ≠ 32 і PathNotFound/DirectoryNotFound на замку** (`сценарії_кінець_роботи.ps1`): ACL-випадки, пошкоджений JSON і гонка зниклого JSON (11566а) покриті, інші гілки catch — лише очима (вище). Не виміряно стендом.
