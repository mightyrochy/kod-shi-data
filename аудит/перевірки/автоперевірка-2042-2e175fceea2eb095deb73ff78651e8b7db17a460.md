## Доведені зауваження

### З1 · P1 · Обірваний UTF-8 однієї крамниці зупиняє весь обхід

Місце: `zhnyvarka/обхід.py:31` (`результати`, читання всього JSONL як UTF-8), виклик до запуску процесів — `обхід.py:218`. Перехоплення `JSONDecodeError` всередині циклу не охоплює помилки декодування самого файла.

Відтворення: у `сирі/hang.com.jsonl` записано байти `b'{"url":"https://hang.com/p1","note":"\xd0'`, тобто останній кириличний символ обірвано після першого байта. Викликано справжній `обхід.main` для `hang.com,ok.com`; межу запуску процесів замінено лічильником, мережа не потрібна.

Дослівний вивід доказу:

```text
UTF8: UnicodeDecodeError; запуски=[]; стан_записано=False
```

Наслідок: `main()` обривається ще під час збирання стану ДО циклу; здорова `ok.com` не стартує, новий стан обходу не записано. Повтор на тому самому файлі знову падає. Це порушує мірило ізоляції завислої/обірваної крамниці та відновлення після обриву.

### З2 · P2 · Після обірваного рядка нова картка губиться, а крамниця вважається завершеною

Місце в новому обході: `zhnyvarka/обхід.py:76–85` — за відсутності читабельних записів `є_картки` й `виконано_в_журналі` довіряють лічильникам зведення; `обхід.py:199–201` потім виключає завершену крамницю. У JSON-шляху `zhnyvarka/виконавець.py:610` підтверджується кінець пагінації.

Причина на шляху мірила: наявний записувач `_пиши` (`виконавець.py:432–435`) дописує новий JSON без відновлення межі обірваного останнього рядка. `_журнал` ігнорує некоректний рядок, залишаючи його у файлі. Сам записувач існував до цього PR; новий обхід приймає результат такого повтору за збережену завершену крамницю.

Відтворення для кожного з `woo` і `shopify`: файл `сирі/json.test.jsonl` містить незавершений рядок `{"url":` без переносу. Справжній шлях `main → _магазин → _json_сімейство → _пиши → стан_рядка` отримує через заглушку HTTP одну придатну річ, потім порожню сторінку. Новий повний JSON склеюється з уламком. Далі виконано ще один обхід того самого журналу.

Дослівний вивід:

```text
JSONL/woo: запити=2; стан=CATALOG; готово=1; лишилось=0; читабельних_карток=0; хибних_рядків=1; повторних_запитів=0

```

Наслідок: втрачено єдину нову картку, але збережено `CATALOG`, `готово=1`, `лишилось=0`; повтор не робить жодного запиту. Це окрема від З1 вада: UTF-8 тут коректний, винятку немає. Потрібно відновлювати межу записів перед дописуванням і підтверджувати збережений результат за журналом. Зв'язок із пізнішою доробкою читача не перевірено.
