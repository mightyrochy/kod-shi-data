## Перевірені мірила

**Застосований результат.** На тимчасовому дереві бази виконано `git -c core.autocrlf=false apply --check checkout.patch`, потім `git -c core.autocrlf=false apply checkout.patch`. Обидва отримані файли побайтово тотожні blob перевіреної голови. Зміна режиму нового shell-файлу з `100644` у латці на `100755` у PR не змінює його виконання через `bash`. Явне вимкнення `autocrlf` потрібне для відтворення Linux на цьому Windows: початкова локальна спроба зі стандартним налаштуванням дала CRLF, після чого перевірку повторено з LF. Це властивість локального застосування, а не розбіжність латки.

Огляд усього диффу: усі чотири `fetch-depth: 0` замінені, відразу після кожного викликається однаковий скрипт; `persist-credentials: false`, матриця десяти шматків, перевірки, пороги й часові межі збережені. `git grep -n 'fetch-depth: 0' refs/review/2970 -- .github/workflows` не знаходить місць. Скрипт одержує точні SHA голови й бази та `origin/main` явними refspec, з `--no-tags --no-recurse-submodules`; у неглибокому дереві додає `--unshallow`. Старі бази проб і повна історія правил лишаються доступними; токен не записується в локальну конфігурацію.

**Повтор фікстури виконавця.** Переглянуто й виконано `перевірити.py` з зафіксованого SHA джерела: PR merge, PR head, push, порожня база, нульова база й тестовий токен; кожен сценарій на неглибокому та вже повному дереві. `bash -n` проходить. ДО отримано чужу гілку, її commit/blob і тег; ПІСЛЯ в усіх 12 повторах — 0 чужих гілок, 0 чужих commit/blob, 0 тегів; незмінена голова, точна база, `origin/main`, спільний предок і давній файл доступні. Заголовка автентифікації в `.git/config` немає.

**Додаткові проби цієї сесії.** Саме скрипт голови виконано після просування main відносно точної бази PR, без `GITHUB_SHA` та `BASE_REF`, після перемотування main назад. Пройдено 3/3: HEAD збережено, `origin/main` оновлюється, сторонніх remote refs і тегів немає.
