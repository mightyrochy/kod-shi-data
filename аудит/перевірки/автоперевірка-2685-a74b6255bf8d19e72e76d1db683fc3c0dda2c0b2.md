- `аудит/адаптери/gemini/перевірка/сценарії_claude.sh:21,26`, `сценарії_доставки.sh:15`,
  `сценарії_прогону.sh` (формування `GA`): фікстура не має `poll_minutes` з джерелом, виклик не задає `PollMinutes`.
  Нові `claude_run.ps1:1237–1245`, `gemini_run.ps1:1302–1308` закономірно виходять до кінця воркера, але старі

  о 14:10:10 — `ГОТОВО` воркера; звірка стенда вже отримала порожній рядок. Сам вихід без джерела відповідає наряду;
  зламане приймання через неузгоджені фікстури.

### 12205: сигнал GPU не відновлюється після проміжної причини, яка минає сама

Місце: `аудит/адаптери/gemini/queue_lanes.ps1:1299–1304`, `Update-HoldSignals`.
`sent` переноситься з минулого стану навіть коли поточна причина — замок іншого наряду, для якого повідомлення
правильно пригнічується. Наступне утримання тим самим стороннім процесом порівнюється зі старим `sent` і мовчить.
Це суперечить повтору при зміні причини, описаному в самій функції; зміна `Reason` у стані відбулася двічі.

Виконано окрему пробу на справжніх функціях голови, зі свіжою тимчасовою текою стану; підмінено лише доставку:

```powershell
. (Join-Path $SourceDir 'queue_lanes.ps1')
$script:StateDir = $StateRoot
[void][IO.Directory]::CreateDirectory($script:StateDir)
$script:sentLines = New-Object System.Collections.ArrayList
$send = { param($line) [void]$script:sentLines.Add($line); $true }
foreach ($reason in @('процес chrome.exe', 'замок GPU іншого наряду', 'процес chrome.exe')) {
    $held = @{GPU = @{Reason = $reason; Markers = @('gemini-queue/п/gpt-6/1/gpu')}}
    Update-HoldSignals $held $send
    Write-Output ('причина=' + $reason + '; надіслано=' + $script:sentLines.Count)
}
```

Команда: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ../tmp/hold-transition.ps1
-SourceDir ../tmp/review-2685/аудит/адаптери/gemini -StateRoot ../tmp/hold-transition-state`.
Код 0; дослівний вивід:

```text
причина=процес chrome.exe; надіслано=1
причина=замок GPU іншого наряду; надіслано=1
причина=процес chrome.exe; надіслано=1
{"GPU":{"since":1793535292,"reason":"процес chrome.exe","sent":"процес chrome.exe"}}
```

Після третього проходу очікується другий сигнал, а є лише перший. Диспетчер не дізнається, що зовнішнє блокування
повернулося після роботи власної черги. Наявна проба `сценарії_простій_ресурсу.ps1` між причинами викликає
`Update-HoldSignals @{}` й видаляє стан; послідовності без порожнього проходу вона не перевіряє.
Це незавершене виправлення того самого механізму рядка 12205, а не новий номер дошки.
