## Доведені зауваження

### 1. Висока: синхронне зависання не дає запустити справні наступні крамниці

Місце: `zhnyvarka/обхід.py:180–190, 212–221`, `zhnyvarka/виконавець.py:438–463`.

Усі крамниці виконує один дочірній процес. Його межа часу прибирає зависання, але вбиває також роботу решти. Крамниці, які ще чекали семафора, отримують `TIMEOUT` без спроби; оскільки приросту немає, `наступні` порожній і другий дозволений цикл не запускається. При повторенні того самого порядку справна крамниця знову лишається за завислою.

Відтворення на перевіреній голові, без мережі:

```text
python zhnyvarka/обхід.py --журнал <нова_тека_поза_репозиторієм> --магазини hang.com,ok.com --секунд-на-магазин 1 --секунд-на-цикл 3 --циклів 2 --паралельно 1 --заглушка синхронний_блок
цикл 1: код -1 · крамниць 2 → лишилось продовжувати 0
```

Збережений результат: `hang.com=WAIT/TIMEOUT, готово=0, лишилось=1`; **`ok.com=WAIT/TIMEOUT, готово=0, лишилось=1`**. Файла `сирі/ok.com.jsonl` немає. Очікуване мірило для справної `ok.com` — `CATALOG` незалежно від зависання попередньої.

Приладом поряд зі звітом повторено той самий порядок на тому самому журналі: `Повтор того самого порядку: цикл 1: код -1 · крамниць 2 → лишилось продовжувати 0`; `ok.com після повтору: WAIT TIMEOUT`.

Авторська проба маскує цей випадок: передає `ok.com,hang.com` та `--паралельно 2`, тому справна крамниця встигає записати результат до синхронного блокування. Це не доводить проходження решти черги після завислої. Потрібна межа відмови, за якої наступні крамниці справді виконуються, та доказ на порядку «зависла → справна».

### 2. Висока: нуль невідомого залишку назавжди вилучає WAIT з повтору

Місце: `zhnyvarka/обхід.py:78–82, 158–160, 199–203`; джерело стану порожньої розвідки — `zhnyvarka/журнал_проходу.py:85–98`.

За відсутності sqlite-черги лише слова `стеля`/`бюджет` дають залишок 1; виняток до створення черги та таймаут закриття дають 0. Для створеної порожньої черги береться `count(*) - DONE = 0`, хоча `мета.відомо=0` прямо означає невідомий перелік. Наступний запуск фільтрує за `лишилось > 0`, тож навіть явні `WAIT/EXCEPTION`, `WAIT/TIMEOUT`, `WAIT/EMPTY_SOURCE` більше не пробуються. Відсутність доведеного переліку хибно прирівняно до завершення.
