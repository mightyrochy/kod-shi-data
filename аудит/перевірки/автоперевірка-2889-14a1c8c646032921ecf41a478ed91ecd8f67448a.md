## Доведена вада: невідомий перелік прирівняно до порожнього

Місце: `аудит/адаптери/gemini/queue_lanes.ps1:647`, споживачі
`Start-GpuModels:685` і `Complete-GpuModels:671–679` на призначеній голові.
Сила: Р2. Одна причина, а не дві окремі знахідки.

`Get-LmsInstances` при `WebExceptionStatus.ConnectFailure` повертає порожній потік.
Відсутність HTTP-сервера не встановлює стан моделей у пам'яті. Документація окремо описує
[завантаження в пам'ять](https://lmstudio.ai/docs/cli/local-models/load) та
[увімкнення HTTP-доступу до завантажених моделей](https://lmstudio.ai/docs/cli/serve/server-start).
Проба не використовує справжню модель: зберігає стан підробного Studio й перенаправляє
той самий HTTP-клієнт на незайнятий порт, отримуючи **справжній ConnectFailure**.
Функції з голови PR, перехоплення винятку та запис/стирання знімка не підмінено.

Фактично виконано `python ../tmp/перевірка_http_2889.py` на експорті голови;
у цій копії шлях `source` був указаний прямо. У збереженій пробі той самий шлях
передається параметром `--source-dir`, логіку не змінено. Відтворення:

```powershell
python аудит/перевірки/автоперевірка-2889-14a1c8c646032921ecf41a478ed91ecd8f67448a/http_probe.py --source-dir аудит/адаптери/gemini
```

Якщо звіт перебуває в іншому дереві, перший шлях указує на файл цього звіту,
а `--source-dir` — на експорт `14a1c8c646032921ecf41a478ed91ecd8f67448a`.
Фактично виконана команда завершилася кодом 0: всі чотири твердження про відтворення помилки підтвердилися.
Дослівний stdout:

```text
gemini/server-off-at-start: before=[]; loaded={}; unloads=[{"instance_id": "owner-id"}]; відтворено=True
gemini/server-off-at-cleanup: lease_exists=False; loaded={"owner-id": "owner-model", "job-id": "job-model"}; відтворено=True
claude/server-off-at-start: before=[]; loaded={}; unloads=[{"instance_id": "owner-id"}]; відтворено=True
claude/server-off-at-cleanup: lease_exists=False; loaded={"owner-id": "owner-model", "job-id": "job-model"}; відтворено=True
```

1. HTTP недоступний при старті, але `owner-id` уже існує. `Start-GpuModels` пише
   `before=[]`. Після відновлення HTTP наступний `Repair-GpuModels` виконує POST unload
   саме для `owner-id`. Початкова модель втрачена на обох смугах.
2. При старті HTTP доступний, знімок правильно містить `owner-id`; додається `job-id`.
   Під час прибирання HTTP недоступний. Обидва GET перетворюються на порожню множину,
   і `Complete-GpuModels` видаляє знімок без жодного unload. `job-id` лишається;
   наступний прохід після відновлення HTTP вже не має запису для повтору.

Для доробки потрібен відомий стан моделей незалежно від HTTP або збереження стану
«невідомо»: без достовірного початкового переліку не можна записувати порожній `before`,
без достовірного кінцевого переліку — стирати знімок. Реалізацію ця перевірка не змінювала.
