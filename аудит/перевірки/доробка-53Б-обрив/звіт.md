Причину виправлено в усіх знайдених читачах/писачах стану обходу (`rg -n
'обхід_стан|прочитати_чергу' --glob '*.py'`): `main` узгоджує підсумок із журналами до
пропуску завершених крамниць, TSV має спільного стійкого читача для обходу та приладу
`каталог_обхід_стан.py`. Запис використовує окремий тимчасовий файл у тому самому
каталозі, flush/fsync, закриття й os.replace; при звичайному винятку тимчасовий файл
видаляється. Перевірка HTTP 200, адреси й SHA256 тіла спільна для стартового
підрахунку DONE та відновлення ЖурналПроходу. Сам читач SQLite працює read-only;
переведення пошкодженої адреси в PENDING робить виконавець при відновленні журналу.

Три старі фікстури уточнено за новим мірилом: DONE має справжнє тіло; відома завершена
черга пропускається вже на першому запуску; новий JSON-прохід явно скидає його маркер
завершення. Видалення TSV відтепер відновлює підсумок і не починає нові жнива.
Змінені модулі zhnyvarka не належать до історичних модулів проб поділу;
неправдивих записів у `поділ_очікувані.d` не додано.
