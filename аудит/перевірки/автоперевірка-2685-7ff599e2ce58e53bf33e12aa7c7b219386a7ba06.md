## Доведені зауваження

### Стенди читають результат до завершення worker

Місце зміни: `аудит/адаптери/gemini/claude_run.ps1:1237–1244`, аналогічно `gemini_run.ps1:1302–1308`; споживач — `перевірка/сценарії_claude.sh:19–27`. `setup` цього стенда пише v1 без `poll_minutes`, а `cr` не передає `PollMinutes`. Після зміни планувальник запускає worker, журналює відмову й повертає керування; наступне твердження читає ще не створені гілку, журнал і вихідний рядок. Сам worker успішно закінчує пізніше. Це не доказ поломки його результату, але доведена поломка приймального стенда й порушення мірила «проби зелені».

Команда на призначеній голові:

```powershell
python -X utf8 аудит/проби/доробка_менше_прогонів.py --дерево ../tmp/pr2685 --журнали ../tmp/review2685-logs
```

Дослівний підсумок завершеного складника:

```text
ПІДСУМОК сценарії_claude.sh: ✓ 19 / ✗ 47; код стенда 1; код логу 0
```

Лічильник Python-оркестратора дав 46 провалених тверджень; shell рахує ще й останній рядок `ЗБІЙ ✗`. Приклад журналу `k1/cr/claude-run.log` (місцевий час журналу; ідентифікатори скорочено знаком `…`):

2026-11-01 12:54:17 [35232] позначка …: старт …, claude -p …
2026-11-01 12:54:18 [35232] рядок … : GEMINI ОБГОРТКА: ГОТОВО claude/проба-рушія-claude 07db514a0f5016d20ed5f9b429c70e9ee7fdd611 МОДЕЛЬ cc-claude-sonnet-5-5-medium

Потрібно узгодити фікстури й очікування стендів із новим договором: період у даних із джерелом або явний параметр стенда; окремо перевіряти свідомий вихід за відсутності періоду. Повертати типове значення коду для зазеленення не слід.

Інший прояв неузгоджених фікстур того самого приймання: `перевірка/сценарії_ланцюга.ps1:40–46` створює PR перед першим `Invoke-WrapperChain`, але новий `wrapper_chain.ps1:366–376` добирає лише PR після `installed_utc` або спостережену зміну SHA. ### Завелике число слотів обходить відмову кривим даним

Місце: `аудит/адаптери/gemini/queue_lanes.ps1:203–208, 238`. `ConvertTo-LimitNumber` пропускає ціле додатне `2147483648`, але `Get-Limits` приводить його до `[int]` без перевірки представності. Наслідок — виняток замість рядка відмови з назвою `slots.claude`; читання конфігу переривається. Це регресія захисту даних після зняття `Ceil`, а не вимога повернути штучну стелю слотів.

Відтворення: підвантажити `queue_lanes.ps1`, установити `$script:Bound=@{}`, підмінити тільки `Invoke-Git` відповіддю `Code=0; Out=<JSON>` і викликати `Get-Limits` за `$ErrorActionPreference='Stop'`:

```json
{"v":2,"slots":{"claude":{"n":2147483648,"джерело":"власник 01.11 2147483648"}}}
```

Той самий тимчасовий скрипт запущено Windows PowerShell 5.1 з `-NoProfile -ExecutionPolicy Bypass -File ../tmp/review2685-probe.ps1 -SourceDir <тека обгортки>` на базі й голові. Дослівні результати:

```text

велике n: ВИНЯТОК Cannot convert value "2147483648" to type "System.Int32". Error: "Value was either too large or too small for an Int32."
```

Виправлення на шляху мірила — відмова непредставному типу даних із назвою поля, без обрізання й без падіння всього читача.

### Сторожі приймають джерело без виміру

Місце: `аудит/адаптери/gemini/queue_lanes.ps1:231`, `wrapper_health.ps1:124`. Для всіх полів, крім механізмів, викликається загальна перевірка джерела; вона приймає `власник 01.11` без числа й без виміру. Рішення менеджера 01.11 та змінений опис у `НАЛАШТУВАННЯ.md` вимагають для трьох сторожів саме вимір найбільшого проміжку здорового прогону. Наслідок — ці поля можуть знову ввімкнути стоп без потрібного виміру. Це давня властивість загального розбору, яка лишилась у зміненому читачі; прилад п.4 її не оцінює. Сама ця знахідка не є підставою нового кола доробки приладу.

Той самий скрипт, підміна відповіді `Invoke-Git`:

```json
{"v":2,"slots":{},"claude_hang_minutes":{"n":1,"джерело":"власник 01.11"},"codex_stall_minutes":{"n":2,"джерело":"власник 01.11"},"agy_turn_minutes":{"n":3,"джерело":"власник 01.11"}}
```

```text
сторожі без виміру: hang=1 stall=2 turn=3
```

Формат власника для слотів і вимога виміру для сторожів потребують різного розбору. Нових номерів не вигадано: три знахідки збережено також коментарями в окремому фрагменті дошки; диспетчер має надати номери й перетворити їх на рядки перед PR звіту.

## Межі й відомі рядки

Перевірка чужої реалізації, іншим постачальником. Зміни UI, каталогу й моделі-стилістки відсутні: знімки 390×844 та фото речей тут не застосовні. Живий запуск справжніх рушіїв, платні API, вимір журналів здорового ноутбука й установлення обгортки не виконувались; це відомі незавершені 12200, 12201, 12204, а не доведена цим звітом готовність продукту. Сцени `ЖИВИЙ ПІСЛЯ` продукту не додаються.

Виконавець заявив 8 вад, але фрагмент містить 9 рядків: 12200–12208. Усі прочитані; нового незаписаного факту з цього розходження не виведено. 12205 — відбір причин у `Test-HoldNeedsAction` застосовано; 12206 — один BOM; 12207 — `START` та відсутність `_M0` застосовано; 12208 — старі описи `ЧЕРГА.md` свідомо лишені на окремий крок правил. Відома 12204 не закрита цим звітом. Вхід зауважень Codex — `[]`, розбирати зауважень нема.

Перший незавершений запуск із кирилицею в шляху журналів зупинено разом із деревом процесів: заглушки потребують ASCII. Його результати відкинуто. Зарахований запуск має ASCII-шлях, незмінені `NODE_OPTIONS`/`PYTHONPATH`, `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=core.autocrlf`, `GIT_CONFIG_VALUE_0=false`. Це параметри середовища проб, без правок реалізації чи гейтів.
