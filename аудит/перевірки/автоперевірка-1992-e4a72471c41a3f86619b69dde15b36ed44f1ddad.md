## P1 — залишок JSON-крамниці після помилки запиту дорівнює нулю

**Місце:** [zhnyvarka/обхід.py:101](https://github.com/mightyrochy/kod-shi-data/blob/e4a72471c41a3f86619b69dde15b36ed44f1ddad/zhnyvarka/%D0%BE%D0%B1%D1%85%D1%96%D0%B4.py#L101),
стартовий фільтр там само, рядки 206–208. Джерело нотатки —
`zhnyvarka/виконавець.py:582–597`, `_json_сімейство()`.

**Умова:** звичайний запит першої сторінки Shopify/Woo отримує таймаут раніше, ніж вичерпано
загальний бюджет крамниці. `_json_сімейство()` ловить виняток і повертає нотатку
`стор. 1: … Timeout 90000ms exceeded. …`. SQLite-черги для цього сімейства немає.

**Причина й наслідок:** `стан_рядка()` передає до `залишок()` резерв лише за словами
`стеля` або `бюджет`. Звичайний таймаут запиту цих слів не містить, тому стан записується
як `WAIT/TIMEOUT`, але `лишилось=0`. Стартовий фільтр наступного запуску відкидає крамницю.
Тимчасова недоступність до отримання першої адреси стає постійною відмовою обходу, доки
не втрутитися в журнал. Це порушує мірило повтору після обриву та вимогу не втрачати
невідомий перелік адрес. Проба `_перелік.py` перевіряє цю вимогу лише для SQLite.

**Відтворення без мережі:** зберегти наступний код у тимчасовий `доказ.py` поза репозиторієм
і виконати `python доказ.py <корінь дерева e4a72471c41a3f86619b69dde15b36ed44f1ddad>`.
На Windows використано `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`.
Підмінено браузерний контекст, HTTP-виклик і запуск процесу при повторі; шлях
`_магазин → _жнива → _json_сімейство`, запис і читання зведення, обчислення та запис
стану, а також стартовий фільтр — справжні функції перевіреної голови.

```python
import asyncio
import sys
import tempfile
from pathlib import Path
from types import SimpleNamespace
from unittest.mock import AsyncMock, Mock, patch

sys.path.insert(0, str(Path(sys.argv[1]) / "zhnyvarka"))
import виконавець
import обхід

with tempfile.TemporaryDirectory(prefix="review-1992-json-") as journal:
    worker = виконавець.Виконавець(SimpleNamespace(журнал=journal, стеля=300,
        секунд_на_магазин=10, без_огляду=True))
    worker._get = AsyncMock(side_effect=TimeoutError("Timeout 90000ms exceeded."))
    recipe = dict(домен="test.com", старт="https://test.com", транспорт="http",
        сімейство="shopify", пошук="/products.json?page={n}&per_page=100", мова="/")
    browser = Mock(new_context=AsyncMock(return_value=Mock(close=AsyncMock())))
    asyncio.run(worker._магазин(browser, recipe, asyncio.Semaphore(1)))
    rows, _ = обхід.останні_рядки(worker.зведення, 0)
    row = rows["test.com"]
    state = обхід.стан_рядка("test.com", row, 1, journal)
    print("Нотатка виконавця:", row["нотатка"])
    print("Стан після помилки:", state)
    обхід.записати(journal, {"test.com": state})
    with patch.object(обхід.subprocess, "Popen") as launch:
        обхід.main(["--журнал", journal, "--магазини", "test.com", "--циклів", "1"])
        print("Запусків при повторному обході:", launch.call_count)
        assert state["причина_код"] == "TIMEOUT" and state["лишилось"] == 0
        assert launch.call_count == 0
    print("ВАДУ ВІДТВОРЕНО: тимчасова помилка назавжди вилучає JSON-крамницю з повтору")
```

Запусків при повторному обході: 0

**Приймання доробки:** незавершений JSON-перелік після помилки залишається доступним
повторному обходу; доведене вичерпання JSON-переліку не спричиняє зайвих перезапусків.
Потрібно також врахувати вже записаний помилковий `WAIT/TIMEOUT` із нульовим залишком.
