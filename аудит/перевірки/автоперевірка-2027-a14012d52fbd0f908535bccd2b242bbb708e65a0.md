## ЗНАХІДКА поза змінами PR: статичний скан пропускає виклик через `**`

Місце: `джерела/досяжність.py:233` визначає коментар як рядок, що починається
з `*`; рядок 252 вилучає такий рядок із пошуку згадок. Тому реальний виклик
`_клас_кадру(o, фото)` в `джерела/міст_опис.py:438`, який починається з
`**({...})`, теж вилучається. Статичний режим хибно називає вкладену
`показ.<locals>._клас_кадру` з рядка 265 «ніхто».

Відтворення: наведена команда `досяжність.py --без-прогону` повернула одну
таку мітку. `git grep -n '_клас_кадру' cc1e060ddd75f1e5fe734e7b007ed996cd2d69f6
-- '*.py' '*.js' '*.html'` показав те саме означення 265 і той самий виклик 438
у базі. `git diff <база> <голова> -- джерела/міст_опис.py` порожній.

Прицільна проба прочитала AST бази й голови, перевірила фільтр коментарів
для рядка виклику та прогнала записаний виклик `bridge.виклик('показ', …)`
із `знімок_входи_сід3.jsonl.gz` під профайлером тільки для цього імені.
Код виходу 0, дослівний результат:

```json
{
  "голова_виклики_ast": [438],
  "база_виклики_ast": [438],
  "файл_тотожний_базі": true,
  "помилково_коментар": [{"рядок": 438, "коментар": true}],
```

Наслідок доведений: статичний режим дає хибну мітку «ніхто» для функції,
яка має виклик у коді й виконується на записаному шляху. Це не доведена
регресія PR: обидва файли не входять у його зміни, функція тотожна базовій.
Реалізацію не правлено. Повний профільний повтор після цієї прицільної проби
зупинено; його «НІХТО = 0» не заявляється. Сам офлайн-ланцюжок окремо
пройдено 6/6 у батареї, повний знімок мосту — 124/124.
