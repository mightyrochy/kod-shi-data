## Що не виміряно (нема `pwsh`; Linux-контейнер)

`pwsh` відсутній (спроба поставити його з релізу PowerShell відхилена запобіжником, не обходив). Тому **не виміряно**: `сценарії_кінець_роботи.ps1` (ДО 3 → ПІСЛЯ 1; обидва випадки Codex/`agy`: heartbeat без `lanes` при зайнятому замку, старий `busy` після звільнення й ГОТОВО), `heartbeat-fixed.ps1`, `heartbeat.ps1` перевірки #2423, `slots-8` і решта shell-стендів, що запускають worker'и (усі 12 `сценарії_*.sh` падають 127/без worker'а — це відсутність `pwsh`, а не вада латки; числа `✓/✗` цих запусків не беру), 879 тверджень виконавця. Для цих стендів — лише оцінка коду очима:

- `Get-ChainBusySlots` (`wrapper_chain.ps1:408–424`) читає `slots/<смуга>-N.json`, вважає слот активним лише коли замок `.lock` не відкривається з `FileShare.None` (`IOException`), валідує `slug`/`marker` за форматом `gemini_run.ps1:1208–1210` і `claude_run.ps1:976–989`. Heartbeat не читається ні для пропуску, ні для дозволу: випадки 1 і 2 з перевірки #2423 за коду відпадають за конструкцією (старий `busy` при вільному замку → `Get-ChainBranchWork` порожній → перевірка ставиться; heartbeat без `lanes` при зайнятому замку → слот видно через JSON+замок → пропуск з рядком журналу).
- Гілка `gemini/<slug>` для `codex|agy`; для `claude/…` — `claude/<slug>`, `state/branch-<hash>.txt` і HEAD копії (звичайний `.git` і worktree-файл `gitdir:`) — стенд містить окремі твердження для обох форм. Хмарний PR без слота → `Get-ChainBranchWork` повертає `''`, рядок журналу «активної смуги нема» → шлях як до латки (стенд твердить 1 → 1). `eligible` зберігається в `heads` до пропуску (рядок `Write-FileAtomic $statePath` стоїть перед пропуском), тож перевірка кінцевої голови після звільнення слота можлива.
- Знятий із `сценарії_кінець_роботи.ps1` рядок успішного «ПІДСУМОК: ✗ 0»: тепер `ПІДСУМОК` друкується лише при `$bad` — відповідає замітці #2423 (`запустити_стенд.sh` рахує будь-яке `✗` як провал). Підтверджено читанням і командою `запустити_стенд.sh`.
