База ДО — точна голова `gemini/доробка-53Б-обрив`,
`4d9184708f0d7c177f69bc2f22c496c23562b8e9`. Вибрана обгорткою гілка вже
містила `main` `1d8a21abdb9d9feec9e7e3b6a840ab66f24e92b5`; попередню
доробку приєднано звичайним merge. Після `git fetch origin main` цей main
залишився свіжим. Гілка — `gemini/доробка-53Б-журнал`.
Перевірений код — `ba210be441b1bae5858fd88cf1c1edb4ea837d0b`; наступний
коміт додає звіт, виводи й рядки дошки та видаляє виконаний наряд.

## Що змінено

Спільний читач `журнал_карток.прочитати` читає JSONL у двійковому режимі й
декодує кожен запис окремо. Неповний JSON, обірваний UTF-8 і запис без адреси
не доводять завершення; цілі сусідні записи зберігаються. Читач використовують
обхід, виконавець, перевірка DONE у SQLite та огляд фото. Підсумок пошкодженої
крамниці має код `JOURNAL_CORRUPT`, інші крамниці й наступний запуск працюють.
Дописування відділяє нову картку від обірваного хвоста. Історія пошкодження
залишається в JSONL; код причини не приховується після відновлення картки.

JSON-прохід атомарно зберігає повну сторінку перед записами карток, а позицію
та мовний префікс — після обробки сторінки. Межа 120 сторінок діє на один
запуск. Частково оброблена сторінка береться зі збереженої відповіді, прийняті
картки пропускаються. Рецепт підписує кеш, явний новий прохід скидає старі
сторінки. Завершення містить SHA256 JSONL: подальше пошкодження чи втрата
журналу вимагає відновлення зі збережених відповідей.

## ДО → ПІСЛЯ

Ті самі нові проби виконуються на історичних модулях і на голові гілки.
`каталог_зависла_крамниця_журнал_до.py` вивантажує лише потрібні історичні
модулі поза робочим деревом, не перемикаючи гілки.

| Мірило | ДО | ПІСЛЯ |
|---|---|---|
| Кожен байтовий обрив JSON-запису в хвості й середині | 158/158 сценаріїв не проходять мірило | 0/158 помилкових; цілі сусіди збережені, `JOURNAL_CORRUPT`, дві крамниці й повтор працюють |
| Незмінний woo і shopify: 121 непорожня сторінка й порожня 122 | 240 запитів, максимум 120, готово 120→120, `NO_PROGRESS` | 122 запити загалом; повтор лише `[121, 122]`, готово 120→121, залишок 0 |
| Обрив після першої речі з трьох на сторінці | Повторно запитується вже збережена сторінка 1 | Готово 1→3; запит лише сторінки 2 |

## Команди й докази

Середовище: Windows, Python 3.12.10, Node 22.23.3;
`PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`. Команди з кореня:

```powershell
python джерела/проби/каталог_зависла_крамниця_журнал_до.py
python джерела/проби/каталог_зависла_крамниця_журнал.py
python джерела/проби/каталог_зависла_крамниця_журнал_json.py
python джерела/проби/каталог_зависла_крамниця_журнал_sqlite.py
python аудит/перевірки/доробка-53Б-журнал/відтворення.py .
Get-ChildItem джерела/проби/каталог_зависла_крамниця*.py | Sort-Object Name | ForEach-Object { python $_.FullName; if ($LASTEXITCODE) { throw $_.Name } }
python джерела/прилади/згорнути_дошку.py --лише-перевірити
```

Оригінальний доказ `6ad83f10` збережено без зміни логіки в
`автоперевірка_доказ.py`, первісний ДО — `ДО.txt`. Він повертав код 0 навіть
при знайдених вадах, а його порожній Mock запуску після попередньої доробки
створював сторонній `ValueError` розпакування замість результату процесів.
`відтворення.py` узгоджує тільки цю межу: повертає `{домен: (0, False)}`,
друкує збережений стан і завершується кодом 1, якщо лишився виняток або не
досягнута сторінка 121. На базі відтворює З2 й З4, на голові має код 0.
Докази — `ДО_мірила.txt`, `ПІСЛЯ_доказ.txt`.
З1 (недостворена SQLite) й З3 (обірваний TSV) на базі вже не спричиняють
винятку: це видно з виводу того самого узгодженого доказу. Їх удруге не
лагодили; первісні повідомлення `ValueError` походили від старого Mock.

Сім'я має 27 файлів. Повний прогін — `проби.txt`; останню помилку
допоміжного історичного відтворення усунуто вибіркою лише модулів верхнього
рівня й повторено окремо (`історична_повтор.txt`, код 0). Фікстура відомого
переліку тепер зберігає справжній запис картки разом із DONE. Початкова
перевірка JSON-стану знову зелена: явний новий прохід скидає попередній кеш.

Батарея `аудит/КОД.md` запускається з `джерела`: дим, живий шлях, протокол,
`прилади/розділи_гейтів.py`, `audit_contracts.py`, показ із
`NODE_PATH=node_modules`. Повний вивід і коди — `батарея.txt`.
Усі шість команд мають код 0: живий шлях 6/6, гейти 574/574 без входу 0,
контракти цілі, показ — 793 звірки у 69 розділах. Похідний `worker.js`
відновлено після батареї. Виводи приведено до UTF-8, прибрано пробіли наприкінці рядків. Синтаксис модулів і межа 40 рядків у пробах
перевірені; дошка — 0 помилок.
