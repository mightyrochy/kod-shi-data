## 16605 — місцеве трасування на Windows

На незміненій голові, Python 3.12/Windows:

```text
python -X utf8 -W ignore джерела/прилади/тест_річ_запис_її_річ.py
..F.F..FF
FAILED (failures=4)
```

Місце: `джерела/прилади/річ_запис_її_річ.py:142–147`. `self.джерела = str(джерела) + '/'` дає префікс із кінцевим `/`, тоді як `co_filename` має `\`; `startswith` відкидає кадри продукту. Позитивні мутанти завершуються «залежить від уривка, але кадру, що його записав, нема — трасування неповне». Це успадкована вада приладу, Linux CI PR вона не червонить. Окреме виправлення потрібне для справжнього приймання незміненої голови на Windows.

Для історичної та додаткової місцевої проби **лише в тимчасових деревах** зроблено дві заміни:

```python
"str(джерела) + '/'" → "джерела.as_posix() + '/'"
"ф = кадр.f_code.co_filename" → "ф = кадр.f_code.co_filename.replace(chr(92), '/')"
```

Обидва боки історичної проби отримали один і той самий адаптер. Це адаптоване виконання; його не видаємо за зелений запуск незміненої голови. Після проб тимчасовий прилад голови повернуто до вихідного тексту.

На голові з цією нормалізацією та без інших змін повторено команду всього файла:

```text

OK
```

Це підтверджує, що всі мутанти стають на чинний код і всі перевірки проходять після усунення відмінності шляхів; зелений запуск незміненої голови засвідчує окремо Linux CI.
