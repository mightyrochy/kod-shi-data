## Що змінилося й де розійшлася лічба

Спільний модуль `zhnyvarka/ідентичність_сторінки.py` дістає id з `productID`
або `productId`, полів кошика `product_id` / `id_product` / `add-to-cart`,
`data-product-id` / `data-product_id`, типізованого Product у JSON платформи,
далі зі `sku`. DOM обмежений власним блоком товару; вкладені Product
відсікаються, різні id одного рівня доказу не замінюються першим знайденим.

Адресований Product мусить називати поточну адресу або єдину `rel=canonical`
сторінки на тому самому домені. Це дістає sku зі сторінок із мовним префіксом,
коли схема називає їхню канонічну адресу. Явно чужа адреса й зовнішній
канонічний домен не приймаються. Для JSON платформи потрібен Product з власною
адресою чи власним слагом; id сусідніх товарів не підходять.

Збережені HTML показали, зокрема: COOSH — `Product.id` і власний `slug` у JSON;
MustHave — `data-product_id` поля розміру; Twice — `id_product` форми;
The Originals — sku Product на канонічній адресі. Домени в коді не перелічуються.
Оновлювач і відбиток рецепта жниварки включають новий модуль.

Запасний цифровий id тепер береться лише зі шляху URL. `sc_content` не є id.
Два повтори regex запасного id у `жниварка.py` замінені викликом спільного
модуля: **2 → 0** поза ним. Читач `доказ_варіанта`, вимоги свідчення одного
кольору, відсутності кількох кольорів і власної галереї не змінені.

`лічба.tsv` зберігає класифікацію початкового виміру. Первинна причина — перша
перешкода в його порядку; `порівняння.tsv` також рахує всі появи «нема_id» з
перетинами. Тому перенесення запису з «нема_id» в «нема свідчення одного
кольору» не означає нового прийнятого доказу. Окремі колонки
`без_id_у_записі_*` перевіряють саме канонічне поле: старий класифікатор причин
ще бачить цифровий хвіст повного URL, зокрема мітки переходу, а новий писач
цього не робить. Доведені записи завжди визначає незмінений читач кожного кадру.

## Повтор

З кореня репозиторію, PowerShell; сховище тільки читається:

```powershell
$сховище = 'C:/Users/gemini/gemini-data/кадр_варіант_кв1_канал_1411/системні_CA'
python -X utf8 аудит/проби/кадр_варіант_кв1_писач_1511/повтор.py `
  --дерево . --знімок "$сховище/каталог_записи_06_11.jsonl.gz" `
  --сховище $сховище --вихід ../tmp/писач_повний --без-мережі --процесів 12
python -X utf8 аудит/проби/кадр_варіант_кв1_писач_1511/звірити.py `
  --після ../tmp/писач_повний
python -X utf8 аудит/проби/кадр_варіант_кв1_писач_1511/перевірки.py ../tmp/перевірки
```

`повтор.py` виконує `оцінити_окремо` й `підсумок` попереднього `вимір.py` на
поточній голові дерева: новий писач → канонічний запис → чинний читач усіх кадрів.
Умови непридатної відповіді, класифікація та лічба лишилися ті самі; HTTP-транспорт
не створюється. Локальна черга не прив'язана до темпу крамниць, а повний архів
пишеться один раз після всіх записів. Мережевих режимів і часткової розвідки немає.
Для локальної черги
обрано 12 процесів: вимір ноутбука показав 32 логічні процесори й близько 7 ГіБ
вільної пам'яті; це не змінює обчислення запису й не створює HTTP-запитів.

Цей прогін продовжено з 10 128 проміжних результатів того самого SHA коду
`bad83927c24971d0ca213d0f658347dcfb2ea2b1`. Додатковий аргумент фактичної команди:
`--продовжити ../tmp/писач_остаточно/результати.jsonl.gz`. Для кожного такого рядка
звірено SHA, id та адресу зі знімком; дублі заборонені. Кількість і SHA-256
проміжного архіву записані в маніфесті. Команда вище без цього аргументу повторює
весь розбір із HTML заново; збереження проміжних обчислень не потрібне для повтору.

`звірити.py` звіряє всі id та адреси, незмінність кодів і кінцевих адрес
відповідей, повторно викликає читач для кожного кадру й перевіряє збереження
попередніх доказів. `зміни_id.tsv` містить усі переходи id; `результати.jsonl.gz`
зберігає записи й докази для повторної звірки без дублювання великих полів
`факти` та `канонічний`. Повні поля відтворює команда повтору; відбитки повного
й стислого архівів розрізнено у `звірка.json`.
