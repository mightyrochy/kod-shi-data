на диску 4+ (lapa, gemma-4-e4b/12b, mamaylm…), завантажених нема. У LM Studio `autoStartOnLaunch: true`
(`~/.lmstudio/.internal/http-server-config.json`), але самого застосунку при вході не запускає ніщо: у
`HKCU\...\Run`, теці Startup і Планувальнику LM Studio нема; ключа «запуск при вході» ні в `settings.json`, ні в `lms`
(`lms --help`, `lms server --help`) нема — штатний перемикач лише в інтерфейсі застосунку.

**Що змінено (п.2).** Задачу Планувальника `LMStudio-server-start` (користувач `Admin`, тригер «при вході», рівень
Limited, без адміністратора): `C:\Users\Admin\.lmstudio\bin\lms.exe server start`. Порт, `parallel`, контекст,
моделі, Avast, інший автозапуск — не чіпано. Знімається: `Unregister-ScheduledTask LMStudio-server-start`.

**Перевірка (п.3).** Задачу запущено вручну (`Start-ScheduledTask`): `LastTaskResult 0`; `lms server status` — працює на
1234; `GET /v1/models` з `Admin` — 200. З облікового запису `gemini` не перевіряв (перемкнутись не можна); порт
loopback, спільний для користувачів. Реальний вхід (перезавантаження) не відтворювався — задача перевірена запуском.
