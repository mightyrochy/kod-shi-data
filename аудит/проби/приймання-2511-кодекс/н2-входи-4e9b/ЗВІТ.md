# Н2. Входи правил та передача заяв

Голова #4678 `4e9b6de1160fc46290e8b7a356efc58d07ee2b9a`, база `39fc66fc7ad8ce705a248c77f0175f2ae708a4c2`. **Покриття описами підтверджено. Семантичне приймання відкрито.** У 61/61 пунктів п’яти груп є режим, опис полів і посилання на джерело. 64 — число різних кодів у цих пунктах. Для 19 пунктів `немає_каналу` незмінно дає `немає_входу`. Всі 19 полів та Git blob ID семи змінених файлів є в manifest.json. Два з цих 19 заперечує справжній суд на входах, уже доступних Н2.

## Що втрачає продукт

Один штатний суд на кожен синтетичний образ. Ч2 прочитав типи та виміряні кольори, Ч3 зібрав пул, Ч5 розібрав вибрані номери, Ч6 викликав звичайний суд. Спостерігач зберіг його справжню відповідь і без змін повернув викликачеві. Однакові записи у двох місцях відповіді зведено за кодом. Рядки таблиці показують ДО на базі, джерело в тому самому виклику і ПІСЛЯ на голові.

У K-COL-05 гілка відлуння читає тони та зони, без площі (`джерела/суд_від_моделі.py:1031–1040, 1162–1174, 1771–1780`). Н2 встановлює дозвіл першою згадкою коду з `single_focus` (`ядро/дані/чеклісти.json:12,83`, `ядро/знання.py:240–248`), згодом відкидає реальну заяву (`ядро/знання.py:383–389`). У K-COL-01 поріг перевіряє чинна функція перебору (`колір_світлота.py:314–364`), але її результат взагалі не може пройти постійний стан з `чеклісти.json:23`. Для K-ACC-10 обидві поверхні відомі, проте правило зупиняється раніше на декларації (`аксесуари_структура.py:667–672`, `чеклісти.json:444,556`). У поточному порядку `правила_чекліста` обходить accessories **перед** context. Запис у JSON має інший порядок. Перестановка не розв’язує суперечності входів.

Дві додаткові розбіжності видно вже на тих самих даних. `genre_dominant` просить поле речі «реєстр», хоча виробник виводить непорожній вектор із типів речей, а пункт старого суду пройдено (`знання.py:190–193`, `перевірка_образу.py:559–570`, `суд_чеклісти.py:447–449`). Для B4 три однакові волокна дають у старому суді провал, заміна лише волокна сумки — прохід. У Н2 в обох випадках `plainness.texture_adds = суджено, результат 0`. Число лічить лише заяви зі списку кодів, який для B4 порожній (`чеклісти.json:259–267`, `знання.py:252–262`, старий розрахунок `суд_чеклісти.py:1049–1066`). Таке поле не дозволяє відрізнити ці два результати. Заяви з новим кодом для нього не встановлено.

## Мірило наступної доробки

Чинний Н2-автор прив’язує допуск до гілки та її фактичних входів, а причину браку в кожному пункті — до входу саме цього пункту. Для червоної сумки очікується одна адресна `accent_orphan` у Вироці, для сірої — нуль. Для однакових вагомих поверхонь потрібна адресна `one_lightness_level_reads_flat`, для розбіжних варіантів перебору зберігається невизначеність. Для двох червоних поверхонь K-ACC-10 й A12 зберігають брак `заявлена_колона`. Ті самі приклади мають працювати при перестановці описів. Чекліст далі має три стани. Припис наряду, рядки 45–53, лишає йому власну перевірку входів і один виклик суду, з якого беруть лише заяви. Копіювання старого чекліста як результату не задовольняє договір.
