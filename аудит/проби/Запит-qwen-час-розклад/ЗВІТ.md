Для медіани це твердження не підтверджено: 280 → 287, **+2,5 %**; p90 1570 → 2707, +72,4 %. Метрику в листі не названо, тому єдиного точного «+40 %» записи не доводять. **«Повільна відеокарта 11–17.11» не виміряно як стан GPU.** Ефективна швидкість qwen за повним часом виклику справді нижча 13–16.11, ніж 07.11. Немає сцен за 11–12, 17–18.11 та часу до першого токена; без журналу LM Studio не відокремити генерацію від завантаження моделі й обробки входу. Порівняння з 18.11 неможливе на цій базі.

## Відтворення й джерела

З кореня репозиторію, після викладення архівів `автоживий-*`, `Е1-нічний-живий-*`, `нічні/` через sparse-checkout:

```text
python -I аудит/проби/Запит-qwen-час-розклад/зібрати.py
python джерела/прилади/згорнути_дошку.py --лише-перевірити
```

- [таблиці.md](таблиці.md): медіана/p90/n усіх полів за прогоном, датою UTC та кожною записаною моделлю; перемикання кожної сцени; повний перелік відсутніх полів із номерами викликів; види викликів і їхній порядок до/з 15.11.
- [виклики.csv](виклики.csv): один рядок на номер виклику в сцені, точний вид, модель, HTTP, токени, час, швидкість, джерело токенів і номер рядка логу.
- [сцени.csv](сцени.csv), [виключені.csv](виключені.csv): повна інвентаризація включених і виключених сцен; [джерела.csv](джерела.csv): SHA256 використаних результатів, логів, проксі й файлів обміну.
- [зведення.json](зведення.json): числові підсумки; [пари.csv](пари.csv): пари однакових сцен для розкладу подовження; [злиття.md](злиття.md): перелік злиттів, команда й часові межі.

Модель — `запит.model` файлу `VIDPOVIDI/обмін/0000N.json` (запасне поле `відповідь.headers.x-model`); напис «ЖИВА МОДЕЛЬ qwen» не використано для приписування всіх викликів qwen. Токени — `відповідь.body.usage.input_tokens/output_tokens` або `prompt_tokens/completion_tokens`. Для логів без обміну підсумок має власні поля токенів, але повтори запису виключено з виміру моделей.

Час — рядок `↔ модель #N … → T с`, запасний — відповідний рядок підсумку «ЖИВА МОДЕЛЬ». Нумерований лог і підсумок звірено за всією послідовністю назв і тривалостей; токени звірено з обміном. **Незіставлених підсумків 0; дублів номерів і нерозібраних рядків `↔ модель #N` 0.** Варіант із вкладеними дужками `фото N (не дійшло M)` також розібрано.

Швидкість = вихідні токени / повний час виклику для HTTP 200. Це ефективна швидкість відповіді разом із затримками, а не вимір генерації GPU. Статистики кожного поля використовують лише наявні значення; `n` наведено окремо. p90 — найближчий ранг `ceil(0,9*n)`; медіана звичайна. Нулі токенів при HTTP 501/503/504 не підміняють відсутній usage.

Точна назва з файлів — **`qwen/qwen3.5-9b`**. Порівняно всі датовані виклики з usage, незалежно від завершення всієї сцени:

Перший `ПАКЕТ_V1→ОБРАЗИ_V1` у сцені: **1379 → 2538,5** (49 → 38 викликів); другий — **1450 → 2231,5** (49 → 38). Треті й четверті виклики та всі точні види — у `таблиці.md`. У записі є окремі назви `ВЕРДИКТ_V1→ОБРАЗИ_V1`, `ПОВНОТА→ДОПОВНЕННЯ_V1`; вони не злиті з початковим збиранням. Другий `ПАКЕТ` не оголошено мережевим повтором: у сцені буває інша рука. Слово «ремонт» безпосередньо є у `мовний шар: ремонт поради` — це MamayLM, у статистику qwen його не додано. Це суміш видів і сцен, не контрольований дослід однакових входів. Частка важких видів змінюється; зростання середнього не доводить однакового збільшення кожної відповіді.

Перший наступний наявний прогін зі збільшеною медіаною `ПАКЕТ` — **`Е1-нічний-живий-20261115`**, збірка `ef60e250a98cdb05d7f31fdf62bd296971807e94`: 2219 токенів проти 1507 у попередньому `Е1-нічний-живий-20261113`, збірка `c3d18d313e88a6199c3211d7984a492c4073a7a1`. Між початками цих прогонів, **13.11 22:42:49 UTC → 15.11 10:25:23 UTC**, у main **160 заголовків злиттів PR**: повний перелік SHA, дат і назв у `злиття.md`. ## Швидкість і перемикання

| дата початку сцени UTC | qwen, медіана / p90 т./с (n) | перемикань на сцену, медіана / p90 | сума перемикань на сцену, медіана / p90 с (n сцен) |
|---|---|---|---|
| 07.11 | 43,69 / 68,70 (705) | 9 / 11 | 52,33 / 81,32 (49) |
| 13.11 | 9,28 / 50,00 (29) | 5 / 13 | 199,36 / 619,76 (5) |
| 14.11 | 12,24 / 40,43 (131) | 4 / 7 | 177,22 / 379,29 (36) |
| 15.11 | 32,05 / 47,83 (357) | 8 / 9 | 377,70 / 652,38 (25) |
| 16.11 | 33,77 / 48,53 (292) | 9 / 11 | 370,92 / 461,86 (20) |
| 11–12, 17–18.11 | не виміряно: немає сцен | не виміряно | не виміряно |

Підтверджено падіння **ефективної швидкості виклику** в наявних датах: 43,69 → 9,28–33,77 т./с. Стан GPU та весь інтервал 11–17 проти 18.11 — не виміряно. Час перемикань є у **136 із 157 сцен** (у тому числі одна без дати); для кожної наведено число й суму в `таблиці.md`. У решти **21** немає проксі: 16 хмарних, 4 відтворення обміну, 1 `…-функція/ж9`.

Перемикання — саме завершені рядки `перемикання #N → … · T мс`, включно з початковим завантаженням #1. Число змін після початкового завантаження — на один менше, коли є #1. Це сума записаних подій, не оцінка всіх очікувань: незавершене завантаження може не залишити такого рядка. Додавати суму перемикань третім доданком до «виклики + поза моделлю» не можна — спільні межі для такого додавання не виміряні.

## Яку частку подовження дає довший виклик

Для розкладу взято **8 пар** тієї самої сцени й того самого режиму у `Е1-нічний-живий-20261107` та `Е1-нічний-живий-20261115`; усі пари названо в `пари.csv`. Є тривалість сцени, час усіх викликів, кроки; виключено обірвані сцени, хмарний паралельний прогін, сцени без полів і запит понад 3000 с. Решта спроб лишається в загальних таблицях. Ця парна вибірка вужча за #4278 і не описує всі сцени.

| середній час на сцену в парних записах | ДО, с | ПІСЛЯ, с | приріст, с | частка приросту сцени |
|---|---|---|---|---|
| сцена | 511,48 | 1422,66 | 911,19 | 100 % |
| усі виклики моделей | 424,94 | 983,91 | 558,98 | 61,3 % |
| з них qwen | 251,95 | 703,44 | 451,49 | 49,5 % |
| поза моделлю | 86,54 | 438,75 | 352,21 | 38,7 % |

Щоб відокремити тривалість **одного** виклику від їхнього числа, для кожної пари й моделі розкладено `T = N*d` симетрично: внесок довшого виклику `(Nдо+Nпісля)/2 * (dпісля−dдо)`, внесок числа `(dдо+dпісля)/2 * (Nпісля−Nдо)`. Сума точно дорівнює зміні часу запитів. Усереднено вже ці внески, а не добуток загальних медіан:

- довший виклик qwen: **+418,00 с, 45,9 %** приросту сцени;
- довший виклик MamayLM: **+117,25 с, 12,9 %**;
- зміна числа викликів обох моделей: **+23,72 с, 2,6 %**;
- поза моделлю: **+352,21 с, 38,7 %**.

Отже, **довші виклики разом — 58,7 % подовження** у цих 8 парах. Це арифметичний розклад записаного часу, не доведення апаратної причини. Середній записаний час перемикань тих самих пар: **62,67 → 425,00 с**; це окремий діагностичний показник, не додатковий відсоток у сумі.

Поруч із цим [#4278](../Автоживий-час-сцени-розклад/ЗВІТ.md) для своєї ширшої вибірки повних сцен дає **25,3 % часу поза моделлю у «повному» та 28,9 % у «повному +фото»**. Це частки всього часу, а 38,7 % вище — частка його **приросту**. Для самих 8 пар частка поза моделлю у всьому часі становить **16,9 % → 30,8 %**; знаменники явно різні.

## Не виміряно й де взяти відсутнє

Повний перелік «поле — прогін/сцена — номери» містить `таблиці.md`, розділ «Відсутні поля»; порожнє поле не замінено нулем.

- **TTFT: 0 із 3759 спроб моделей.** У всіх зазначених прогонах немає явного часу до першого токена. Потрібні історичні журнали LM Studio з полем TTFT/позначками першого токена; за їх відсутності цей вимір для минулих запусків не відновити. Поточний `lms log stream` не відтворює минуле сам по собі.
- **Usage восьми HTTP 503/504** відсутній: `Е1-нічний-живий-20261113` — `ж3_зима #8`, `ж4_клуб_приховати #31`, `ж7_звичайний_день_кеди #15–16`; `Е1-нічний-живий-20261115` — `ж1_екскурсія_бруківка #12`, `ж4_робота_спідниця_фото #8`; `Е1-нічний-живий-20261116` — `ж1_екскурсія_бруківка #33–34`. Час HTTP є; вихідна відповідь моделі й usage — у журналі LM Studio/проксі ноутбука, якщо запит узагалі дійшов. Неуспішне завантаження не означає згенеровані 0 токенів.
- **Приміряння `gemini-nano-banana-2.1` не виконувалось:** 9 відмов 501, usage немає; 4 без часу — `Е1-нічний-живий-20261116/ж1_оціни_образ_6б #40,43–45`. Швидкості цієї моделі з цих записів узяти ніде; журнал обгортки уточнює лише відмову.
- **`…-функція/ж9 #1–8`:** немає обміну, відповідей, тривалості, токенів і моделі по виклику; не можна робити висновок про живу генерацію з одного рядка `↔`. Потрібні журнал обгортки та джерело цих відповідей. **72 спроби `повтор_обміну_1800`** — явне відтворення, не пропущені 72 живі генерації.
- **Дві сцени без `результат.json`:** немає точного початку/кінця/тривалості сцени; потрібен журнал обгортки відповідних запусків. Саме це не дає додати 14395-секундний таймаут у частки часу сцени.
- **Стан GPU та дні 11–12, 17–18.11:** потрібні збережені журнали LM Studio, обгортки та знімки GPU на час запусків. За самим відношенням виходу до часу HTTP причину «повільна відеокарта» не встановлено.

Знахідки для правки: **16617** — сцени без завершального результату; **16618** — відсутня історична телеметрія для твердження про GPU (продовження теми 16553). Вад знайдено: 2; продукт, стенд, обгортку й чужий звіт не змінено.
