Каталог — усі 27 525 речей очищеного `каталог_повний.xml`, фото не завантажувалися.
Пари принтів та гранична сітка — наявна проба `джерела/проби/е3_принти_набори.py`;

Режим ДО читає з Git лише чотири змінені модулі в TMP задачі; всі решта файлів обох прогонів однакові.
Клонів дерева немає. Вхід каталогу зберігається лише в TMP і створюється заново командою `каталог`.
Батареї слід запускати послідовно, до кінця, без мережевих викликів моделей. Їхні окремі коди виходу й
послідовність ваг емітованих знахідок записуються у `до-батарея.json` та `після-батарея.json`;
журнали — поруч. Ці режими не є незалежною перевіркою чи живим прийманням.
Обгортки записують виклики емітерів у процесі проби; підпроцеси стандартних гейтів перевіряються їхніми
кодами виходу. Предметні перевірки K-MUA-01 (§85) і P-PRT-03 (§114) кличуть емітери в основному процесі.

**Поточний результат батарей — НЕ ВИМІРЯНО.** Початковий запуск ДО було надмірно розширено на всі `pal_*`
й `col_*`; його припинено на `pal_K-PAL-01.py`, щоб завершити хід із блокером 16754. Перед зупинкою
дим, живий шлях, протокол, гейти й аудит контрактів завершилися з кодом 0. Трасу ваг, накопичену в пам'яті,
не збережено. Чергу ПІСЛЯ зупинено до запуску. Журнал `до-батарея.log` — саме цього незавершеного запуску.
JSON станів мають `завершено=false`; `звірити_батареї.py` повертає 2 й записує явне «НЕ ВИМІРЯНО».

Скрипт для наступного запуску виправлено: предметні проби взято зі спільного записувача принтів
`джерела/проби/виконання/е3_принти_батарея.py`, стан зберігається після кожного скрипта, завершення явне,
стандартна батарея запускається лише ПІСЛЯ. Цей виправлений порядок не проганяли (16756).
Звірювач порівнює ваги спільних предметних скриптів; додаткові стандартні скрипти ПІСЛЯ перевіряє кодами виходу.
Після каталожних знімків перейменовано два параметри приватних функцій: формули й позиційні виклики
збережено; після перейменування повторено `py_compile` й прилад, але не всю каталожну матрицю.

`прилад-до.txt` і `прилад-після.txt` — вивід незміненого приладу; повтор після злиття свіжого main
`e685cae42b36c6d5e505edb47951340fc9da6e62` дав ту саму мультимножину рядків (порядок двох рядків п3
не стабільний). `місця.json` — звірка мультимножин «файл · пункт · функція».
`невдала-проба-прямого-перенесення.txt` — невдалий проміжний варіант, **не результат голови**:
константи в спільному емітері давали нові п5; константа K-COL-10 — нове п2 іншого емітера.
