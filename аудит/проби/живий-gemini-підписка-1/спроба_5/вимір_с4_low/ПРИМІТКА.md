# Два проходи Low з виявленим збоєм транспорту

Обидва проходи природно завершилися, 17 слів уведено, 4 розбіжності натискань. 53 звернення мають HTTP 200. Але в запиті №16 (рука 1 першого проходу) модель передала read_file буквальні імена @01.jpg та інші з @; міст мав лише імена без @. Прочитано 0 із 7 доступних фото, було 7 помилок file does not exist. HTTP 200 сам цього не доводить. Повна лічба — читання_фото.json. Цей прохід не прийнятий як основний візуальний вимір.

Міст виправлений будовою: @NN.ext і NN.ext — дві назви одних байтів; оригінальний текст застосунку незмінний. Архів зберігає канонічний файл з SHA256. У ../контроль_посилання_low/ той самий первісний запит сторінки пройшов через новий міст: 7 доступних фото, 7 read_file DONE, 0 помилок; одне фото повернуло URLError. Контрольні два проходи для основних даних починаються в ../../gemini-3.8-flash/.

Квота групи за ці дві спроби: 77 → 74 % тижня, 61 → 48 % п’яти годин. Це спільний показник, а не доведені витрати лише цього процесу. Усі байти 32 завантажених фото збережено з первісним SHA256. Новий основний прогін потрібен через непрочитані фото, а не для заміни невдалих відповідей моделі. Старі дані лишаються як є.
