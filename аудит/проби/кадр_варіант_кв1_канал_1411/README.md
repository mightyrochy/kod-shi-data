## Вхід і спосіб

Знімок 06.11 — `каталог_записи_v1.jsonl.gz`, SHA-256
`463268ea374a2d61192f6aee87b2f7513111ff37fd73614b9aa5fd555c0e28cc`.
Рівно 13 882 записи мають системний параметр `канал=картка`; це 34 крамниці.
Інші канали не входять у лічбу. Вихідний id і адреса кожного запису збережені.

`вимір.py` використовує `Транспорт` голови PR: три крамниці одночасно, по три
картки пачкою, пауза 0.8 с на домен, штатні повтори, перевірка `robots.txt`.
Крамниці починаються за спаданням довжини черги; порядок записів усередині крамниці
той самий, що у знімку. Стелі кількості чи часу немає. HTML розбирають три окремі
процеси; це не збільшує мережевої паралельності.

Кожна отримана сторінка проходить `факти_з_картки`, `_власник_сторінки`,
`канонічний_запис` і `доказ_варіанта` голови PR. Читач перевіряє **кожен**
кадр очищеної галереї. Доведеним рахується запис з непорожньою галереєю, для якої
всі ці докази прийняті. Сам факт запису JSON-доказу не зараховується як успіх.

Це вимір каналу жниварки «картка»: писач тут `_власник_сторінки`, джерело
`картка:один_колір`. Прийняте читачем джерело `ricamare:сторінка` виведене
окремою колонкою; спеціалізований адаптер RicaMare до цього каналу не домішується.

## Як читати дані

`лічба.tsv` містить один рядок на крамницю та підсумок `РАЗОМ`.
Основні категорії взаємно виключні: доведено за джерелом, невідомо за першою
причиною, без відповіді, збій розбору, не виміряно. Їхня сума дорівнює кількості
записів. `оброблено` — допоміжна колонка, у цю суму вдруге не входить.
Колонка статусів містить фактичні статуси відповідей, включно з 200.

Коли причин «невідомо» кілька, порядок основної причини: кілька кольорів JSON-LD,
кілька свотчів, кілька значень вибору, нема Product, нема id, нема кадрів,
нема свідчення одного кольору, читач відхилив доказ. Усі супутні причини збережено
в `результати.jsonl.gz`; їхня лічба з перетинами — у `звірка.json`.
Неуспішний HTTP, порожнє тіло, заслон чи відмова robots — окрема категорія
«без відповіді», а не «невідомо». Статус 0 означає локальну/транспортну відмову,
не HTTP-статус сервера; подробиці є у записі результату.

`порівняння.tsv` розкладає свіжі результати за старими групами:
7 530 без свотча, з id й кадрами; 4 484 зі свотчем; 1 868 без id.
Отже, стара пара 7 530 / 6 352 відтворюється точно. Вона не доводила власника:
варіантів JSON-LD, вибору кольору й кількості свотчів старий запис не містить.
Крім того, наступна доробка писача вимагає явного свідчення одного кольору;
сама відсутність списків кольору більше не є доказом. На старому знімку читач
голови PR приймає власника у **0 з 13 882** записів.

## Збережені відповіді та повтор

Постійне сховище ноутбука поза продуктовими файлами:

`C:/Users/gemini/gemini-data/кадр_варіант_кв1_канал_1411/системні_CA/`

`відповіді/<id>.json.gz` — адреса, час UTC і повна відповідь штатного транспорту
з HTML; `robots/<домен>.json.gz` — відповіді robots; `маніфест.json.gz` — SHA коду,
відбиток знімка й кількість завершених записів. Невдалі початкові спроби до
налаштування системних CA збережені в батьківській теці окремо, до фінальних
чисел не входять. `результати.jsonl.gz` у цьому PR зберігає нові факти, канонічний
запис, нормалізований запис для читача й докази кожного кадру; це також резервна
копія результатів, незалежна від подальшої наявності робочої теки.

Для кроку перезбору результат можна читати без мережі: знайти рядок за `ід`,
перевірити `стан`, узяти `канонічний` (свіжі поля жниварки), `факти` або `запис`
(`id`, `url`, `фото`, `параметри.id_магазину`, `параметри.власник_кадру`). Старі
записи не втрачаються й не замінюються рядками, де сторінка не відповіла.

Повтор лічби на кеші з кореня репозиторію (PowerShell):

```powershell
python -X utf8 аудит/проби/кадр_варіант_кв1_канал_1411/вимір.py `
  --дерево ../код-3747 --знімок каталог_записи_v1.jsonl.gz `
  --сховище C:/Users/gemini/gemini-data/кадр_варіант_кв1_канал_1411/системні_CA `
  --без-мережі
python -X utf8 аудит/проби/кадр_варіант_кв1_канал_1411/звірити.py `
  --дерево ../код-3747 --знімок каталог_записи_v1.jsonl.gz
```

Початковий обхід — та сама перша команда з `--системні-ca` замість
`--без-мережі`. Перед новим отриманням сторінок потрібна порожня тека сховища:
наявні відповіді скрипт завжди повторно використовує, включно з невдалими.
Відсутні відповіді в режимі без мережі лишаються «не виміряно», не стають
вигаданими мережевими відмовами. `--розвідка` бере лише першу адресу кожної
крамниці та не є повним виміром.

## Середовище та межа доказу

Версії — `середовище.json`. Початковий транспорт на всіх 34 перевірених
крамницях давав `SSLError`, код 0: certifi не містив довіреного локального
видавця сертифіката. Додавання вже довірених CA Windows до certifi дало HTTP 200
на тих самих 34 адресах. Перевірка TLS залишається увімкненою; нові довірені
центри, секрети чи обхід заслонів не додавались.

Це власний вимір доказу платформи, не незалежна перевірка й не живе приймання
кореня. Фото не завантажувались і піксельний розкид галереї не вимірювався;
продуктовий каталог, виміри кольору й факти власника не перезбирались.
