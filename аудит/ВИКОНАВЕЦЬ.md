# Виконавець — один договір для будь-якої моделі

Один наряд — одна гілка, одна PR-чернетка в `main`. Claude, ChatGPT і Gemini працюють за тим самим договором — робота не
стоїть, коли в одного постачальника скінчився ліміт. Глибину перевірки визначає `аудит/ПЕРЕВІРКА.md`.

## Читаєш (п.19)

`AGENTS.md` (Claude має його в контексті), цей файл, наряд, свої рядки дошки (`grep -rnE '^\| *(N|M) *\|'
аудит/БЕКЛОГ.md аудит/дошка`), названі в наряді пункти `аудит/ПРОДУКТ.md`, `аудит/СТАНДАРТ_КОДУ.md` для коду. Дошку
цілою, картину й передачі не читаєш.

## Робиш

- Корінь (п.3): перш ніж правити — де ще діє та сама причина; ширша за наряд — «ЗНАХІДКА» з доказом; корінь із наряду —
  «Корені вад» картини, лише названий пункт.
- Гілка — від свіжого `main` (`claude/…`, `codex/…`, `gemini/…`), ніколи від незлитого PR: після сквошу — конфлікт і
  окрема сесія злиття. Неглибокий клон — `git fetch --unshallow`.
- Правки показу — лише в межах свого рядка дошки (п.7). Зміна AST модуля — запис у
  `джерела/проби/поділ_очікувані.d/рядок-<N>.txt` у тому самому PR — інакше CI пачки червоний на «пробах поділу»; для
  функції, якої нема в базі поділу (`pipeline.py@ac8c2ca`), запис зайвий — «не справдився» теж червонить CI.
- Дошка — за п.13 (`AGENTS.md`), номери нових рядків — з наряду.
- Батарея — раз перед PR, фоном без `sleep`-циклів, до кінця (з тестом показу), плюс проби своєї сім'ї; підготовка — як
  job `perevirka` у `zbirka.yml`. Нема середовища — досить зеленого CI голови: там ті самі команди.
  ```
  cd джерела && python3 стенд_знімок.py --дим && python3 тест_живого_шляху.py && python3 тест_протоколу.py \
    && python3 прилади/розділи_гейтів.py && python3 audit_contracts.py && NODE_PATH=node_modules node тест_показу.js
  ```
- PR-чернетка в `main` — рецензенти оглядають лише не-чернетку, тож огляд один, на PR пачки. Тіло «Що змінено /
  Перевірено»: що це міняє в рішенні, ДО → ПІСЛЯ, виміряно на каталозі; потрібен живий прогін — рядок `ЖИВИЙ ПІСЛЯ:
  <сцена> — <питання>`. Наряд із файлу `аудит/наряди/` — PR видаляє цей файл: у черзі лишається лише незроблене. Перед
  «ГОТОВО» зупини всі фонові завдання.

## Пишеш

- Лише «ГОТОВО #PR <повний SHA>» (перевірці з рядка «до перевірки …», нема рядка — диспетчерові), «ЗАБЛОКОВАНО: …» чи
  «ЗНАХІДКА: …» (диспетчерові; що видно, де, як виміряти). Знахідка, що потребує рішення, — і рядок дошки, і одразу
  лист: рядок сам нікуди не доходить. Проміжних листів нема. Спосіб — `AGENTS.md`, «Листи».
- Лист перевірки чи диспетчера про твій PR (виправлення, «злий main») — частина наряду.
- Стоїш, чекаючи листа, події чи рішення, а твій останній лист цього не каже, — одразу диспетчерові «ЗАБЛОКОВАНО: чекаю
  <подія> від <хто>» (і перевірці), навіть коли наряд чи лист велять не писати: чекання поза реєстром диспетчера нікому
  не належить, а адресат міг змінитися.

## Не робиш

- Не правиш `аудит/БЕКЛОГ.md`, правил, картини, стану й `аудит/ПРОДУКТ.md`, коли наряд прямо цього не доручає: їх ведуть
  менеджер, диспетчер і CI.
- Нового поза нарядом не починаєш — «ЗНАХІДКА»: незавершене накопичується, а наряд стоїть.
