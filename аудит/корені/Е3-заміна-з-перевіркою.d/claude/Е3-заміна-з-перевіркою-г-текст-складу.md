### Крок «г» 2026-11-16 UTC — текст картки для складу, який код вирішив (гілка `claude/Е3-заміна-з-перевіркою-г-текст-складу`)

**Зроблено — будова.** Проза відповіді опису, що запропонувала заміну з фото, більше не текст картки за жодного
рішення коду. Після рішення (прийнято, відмова, нема запасної, модель лишила річ, другий виклик упав) показ
(`показ/збирання_руки.js`, блок «ТЕКСТ КАРТКИ — ДЛЯ СКЛАДУ, ЯКИЙ КОД ВИРІШИВ») просить опис наново для вирішеного
складу: з новою річчю чи з тією, що лишилась. У вході опису — `рішення_заміни` (`протокол.py`, ОПИС_V1), у промпті —
поле «swap_decided» (`дріт_моделі.опис`), і збирач прибирає «swap» зі скелета відповіді (`вихід_без`), тож модель
заміни вдруге не пропонує; відповідь, що все ж несе `заміна`, не дійде на картку (виняток, картка без опису). Рядок
картки пише один писар — `заміна_з_фото.текст_складу`: прийнято — `card_item_swapped`; річ лишилась — `card_incomplete`
з новою заявою `photo_item_unfit_no_swap` (річ, підстава кодом; для `day` — ще й факти дня). Доти цей шлях був лише для
`day` (`бракує_для_дня`, заява `photo_item_not_for_day_no_spare` — замінено). Коли річ лишилась, той самий рядок іде й у
«missing» нового опису (`міст_опис._з_рішенням_заміни`). Без рядка лишаються: річ не в образі, її річ, підстава не з
переліку. Окремі гілки kept/refused у `міст_відповіді.від_моделі` злито в один шлях
(`заміна_з_фото.вирішити`/`запасні`); `розбір_відповідей.без_прози_заміни` видалено — її робить будова. Опис поля
`заміна.чому` називає коди переліку схеми: «colour», «kind», «occasion», «day»; схему не розширено.
