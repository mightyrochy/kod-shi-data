## 3. Покоління відповіді (7311)

**Чому це крок 4.1, а не латка 3.4.** Доки Python синхронний у головному потоці, вікно для гонки вузьке: дотик чипа
чекає кінця `runPythonAsync`, а продовження після `await містП` — мікрозадача, що виконується раніше за дотик. У
воркері кожне `await містП` — справжнє вікно в секунди (палітри 0,2–0,4 с, вибір палітри 10 с, збір 47 с): жінка
торкається чипа, сценарій змінюється, і стара відповідь приходить у новий стан. Тож запис після `await` без звірки
(7311 — `оновитиПалітруП`; той самий шаблон — `оновитиПомадиП`, §1) з рідкісної гонки стає звичайним шляхом.

**Як у прототипі** (`міст_воркер_клієнт.js`): кожен виклик несе `н` (номер) і `пок` (покоління); воркер їх лише
повертає. Виклик із `ключем` робить попередні виклики з тим самим ключем застарілими; їхня відповідь не віддається
продовженню — проміс відхиляється помилкою з `застаріло: true`, тож запис `ПАЛІТРА`, DOM і нот не виконується. Для
записів після другого `await` (модель, мовний шар) викликач звіряє `чинне(ключ, пок)`. Без ключа (`мова`, `вердикт`,
руки збору) виклик ніщо не відміняє, але відповідь однаково дістається своєму входу за `н`: `виклик_а` поступається,
і короткий виклик слідом закінчується раніше.

Виміряно в справжньому воркері (кожен прогін ПІСЛЯ): три виклики `палітри` поспіль з одним ключем —
`застаріло, застаріло, прийнято`, остання чинна; «суд» оцінки (`виклик_а`) і `мова` слідом — послано «оцінка, мова»,
прийшло «мова, оцінка», обидві відповіді дісталися своїм входам.

**Одна форма замість чотирьох.** Звірки, що вже є (`чинний()` заміни, `ж()`/`номер` оцінки, `ОЦ.перелік !== п`,
`ВИБІР_СТИЛІСТКИ_П.ключ === ключ`), — те саме правило, записане чотири рази; у 4.1-Б вони переходять на ключ моста
там, де звіряють лише відповідь моста, а `ж()` оцінки лишається (вона звіряє й виклики моделі між кроками).

## 4. План 4.1-Б кроками на межі коміту

Порядок: Б-1 → Б-2 → (Б-3 + Б-4 одним PR, окремими комітами: без Б-4 стенд знімає стан раніше за кінець роботи) → Б-5.
Кожен крок: знімок 0.2 тотожний (`знімок_мосту.py --діф`), батарея з тестом показу, проби своєї сім'ї.

**Б-1 (Р1). Дані аргументом, ще в головному потоці; шов транспорту.** `містП` кличе `_vyklyk(ім, рядок)` /
`_vyklyk_a` з глобалей Pyodide (як у прототипі) замість коду з літералом; доступ до Python — одна функція
`транспортМостуП(ім, рядок, асинх) → рядок`, яку підміняють `наскрізь.js` (замість регулярки по коду) і тест
`тест_показу.js` 2е (замість «літерал, не глобальна» — «кожна відповідь свого входу»). Паралельні руки безпечні: вхід
— аргумент виклику, спільної глобалі нема (причина коментаря 11865 зберігається). ДО → ПІСЛЯ: код Python за сцену
1,98 МБ → 0 (виміряно, режим «аргумент»); Python той самий (80,1 → 80,5 с, у шумі); знімок тотожний. Увага: синхронний
виклик функції не віддає подію між викликами (у послідовному відтворенні — одна задача на 62 с), тож Б-1 сам замерзання
не знімає — лише готує Б-3.

**Б-2 (Р1). Покоління в `містП(ім, дані, {ключ})`.** Ключі: `оновитиПалітруП` — «палітри» і `чинне` перед нотами після
другого `await` (7311); `оновитиПомадиП` — «помади»; `стилісткаОбираєП` — ключ моста замість `ВИБІР_СТИЛІСТКИ_П.ключ`.
`замінитиРічП` (`чинний()` звіряє ще й позицію картки) і `ж()` оцінки (звіряє й виклики моделі) лишаються. Застаріла
відповідь — `catch` з `е.застаріло` → тихий вихід, без запису стану й без тексту жінці. ДО → ПІСЛЯ: проба на заглушці —
два дотики чипа, поки міст рахує палітру: `ПАЛІТРА` і ноти від останнього входу (ДО — від того, що прийшов останнім).
Закриває 7311 і рядок 8410.

**Б-3 (Р2). Воркер у продукті.** Тіло воркера — рядок у `index.html` (сторінка одна): `new Worker(URL.createObjectURL(new
Blob([…])))`. `importScripts` з jsdelivr у Blob-воркері працює, і `page.route` стенда перехоплює запити воркера
(перевірено: `pyodide.js` і `pyodide-lock.json` віддано з диска). Що міняється:
- `містП` = клієнт прототипу (той самий контракт; `н`, `пок`, `мс_python` у відповіді); `підняти_міст_показу` = підйом
  воркера (рядок base64 `МОДУЛІ_ПОКАЗУ` іде повідомленням, `atob` і `unpackArchive` — у воркері);
- `<script defer pyodide.js>`, `дочекатисьЗавантажувачаПП` і `підняти_pyodide_показу` зі сторінки знімаються;
- рядок стану й сторож тиші: воркер обгортає свій `fetch` і шле `{тип: 'рух', файлів, байтів}` → `ОСТАННІЙ_РУХ_П`,
  `ЗАВАНТАЖЕНО_П`, тексти ті самі (обгортка `window.fetch` сторінки воркерових запитів не бачить);
- глобаль `pyodide_показу` зникає → `МІСТ_ГОТОВИЙ_П` (так/ні) для стенда й проб;
- повідомлення-прилад `{тип: 'прилад', файли, код}` — `FS.writeFile` і `runPythonAsync` у воркері для стенда
  (`ПРАВИЛО_РУКИ2`, рядок 152); продукт його не шле;
- запасного шляху в головному потоці нема (звіт #1415: запасний шлях Main — 0 виконань); збій підйому — той самий
  `mirror_failed`.

Що стає async: для викликачів — нічого, усі 59 місць уже `await`. Нове — між `await` тепер виконуються дотики й таймери:
після Б-2 це безпечно для палітри й помад; решта місць пишуть свій запис чи свою ланку (§1). Виклики, що прийдуть під
час збору (мовний шар чату), стають у чергу воркера за Python збору — доти сторінка в цей час не відповідала зовсім.
Картки всі разом (п.21): рендер іде після `Promise.all` чотирьох рук (15154) — воркер цього не чіпає.

**Б-4 (Р1, прилад). Стенд чекає кінцевий стан, не таймер.** Доти таймер стенда часто «перечікував» синхронний Python;
