## Метод і межі

Два окремі браузерні контексти: ДО і ПІСЛЯ. `measure.cjs` — чотири екрани, реальні дотики, Tab і AX-дерево статусів; `extended.cjs` — додаткові родини чипів і дії профілю. `modal.cjs` — попередні сценарії фокусу аркуша, збереження inert і повернення. Фото профілю не аналізуються: використано наявні числові кольори й виміри фікстури 4942. Архівна картка — синтетичний контейнер IndexedDB, не запис власника; слова архівного прогону скопійовано без змін. Джерело `аудит/живі_12/Б/09_ж1_весілля_гостя/вердикти.txt` у базі має перевірений SHA-256 `13016ccc59428cf321f93a2b9bf615aca64683964bd738bf4bece43dc87497c0`. Це перевірка UI, не якості фото, моделей чи живого збирання. Живих API-викликів: 0; мережу сторінки перехоплено, Pyodide і шрифти читаються з локального кеша.

## Одне мірило наряду — native ДО → ПІСЛЯ

| Цільова звірка | ДО | ПІСЛЯ |
|---|---:|---:|
| Провали стану після реального дотику, 134 випадки | 134 | 0 |
| Невидимий фокус на реальному Tab, 271 дія | 12 | 0 |
| Стадії збирання з постійною доступною областю live | 0/16 | 16/16 |
| Завершення і відмова збирання доступні як статус | 0/2 | 2/2 |
| Сталий підпис чату замість лише placeholder | немає | `aria-label` |

AX-ім’я чату ДО — довгий змінний placeholder «Напиши, як подрузі…». ПІСЛЯ — «Куди ти збираєшся?» зі сталого `aria-label`, попри зміну placeholder. Розкладка, назви та видимі тексти не мінялись (п.7). ARIA-стан синхронізується з чинним внутрішнім вибором і класом, без читання значення людського напису; нових словників не додано (п.12). Шлях збоїв збережено (п.14 стандарту).

Лічба дотиків: нагода 8, відчуття погоди 5, опади 4, макіяж 4, прикраси 6, мета 4, гама 4, основа 38, схема 7, вердикт 3, «для мене» 3, аспекти 11, самозвіт 12, опади оцінки 4, помади 21. Після кожного дотику звірено весь відповідний ряд станів із `aria-pressed`. Чипи швидкої відповіді виконують одноразове надсилання і не видають себе за перемикач вибору. Enter самозвіту перевірено окремо; ДО він не змінював вибір, ПІСЛЯ змінює.

Відновлений вердикт з наявної фікстури теж перевірено окремим відкриттям через бібліотеку: 17 чипів мають узгоджений стан, включно з обраним. Native-відмова перевірена реальним натисканням «Зібрати образи» без токена; зовнішня модель не запускалась.

Усі 16 кодів стадій із `НАПИС_СТАДІЇ_П` перевірено через чинну `малюватиПоступП`: в AX-дереві область має role=status і live=polite, у DOM aria-atomic=true, кожний текст змінюється. Завершення дає чинне «Готово». Згорнуте «Службове» більше не ховає повідомлення від читача екрана. Звуковий вивід конкретного читача екрана не вимірювався.

## axe-core A/AA

| Екран | A ДО → ПІСЛЯ | AA ДО → ПІСЛЯ |
|---|---:|---:|
| Знайомство | 0 → 0 | 0 → 0 |
| Сценарій | 0 → 0 | 0 → 0 |
| Палітра з наявним повним профілем | 0 → 0 | 0 → 0 |
| Архівна картка-фікстура | 0 → 0 | 1 → 1 |

На картці те саме правило `color-contrast`: лічильник оцінених образів угорі й унизу має 3,7:1. Контраст ≥4,5:1 і цілі дотику — наступний наряд після злиття цього. На всіх чотирьох екранах color-contrast також має incomplete: загальне 0 AA не заявляється. Окремі три модальні аркуші (нагода, профіль, обхвати), а також темний профіль — 0 автоматичних A/AA, з обмеженням incomplete.

Попередня native-проба модальних аркушів пройшла assertions Tab/Shift+Tab, Escape/Готово/заслона, повернення на видимий відкривач і точного відновлення початкового inert. Функції `відкритиАркуш`, `закритиАркуш` і `привʼязатиГолос` збігаються з базою текстово; диктування з ручним виправленням (#992, рядок 5205) не змінювалося.
