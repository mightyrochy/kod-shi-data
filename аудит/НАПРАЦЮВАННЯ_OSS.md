## 0. Одним абзацом

«Open Source Stylist» — дослідницька лабораторія перевдягання людини на фото
(ComfyUI + Qwen-Image-Edit + SAM/GroundingDINO, RTX 4090 16 ГБ). Наскрізного

речі семантичним парсером ATR (ONNX, CPU), вимір кольору в Lab з CIEDE2000,

конвеєр майже без переробки. Результатів для каталогу «Код Ші» там **нема
жодного** — жоден файл не згадує ні id оферів, ні наш фід.

### Головна користь

Не код, а **вимірювана заміна здогадки**. Зараз колір речі приходить або зі
слова крамниці, або з ока VLM. У `джерела/аудит/ЗБАГАЧЕННЯ_ЗВІТ.md` видно, чого
воно варте: те саме слово — 34.7 %, та сама сім'я тону — 46.0 %. Тобто в
половині випадків ми не знаємо кольору речі. ATR-маска + середнє Lab по масці
дають **число з фотографії**, яке можна звірити з обома джерелами й показати
розбіжність, а не вибирати навмання.

Друге за вагою — **`dominance`**. Це відповідь на питання, якого ми собі не
ставили: «чи річ взагалі є на цьому фото». На фото-таблиці розмірів, логотипі
чи крупному плані тканини `dominance` завалиться, і річ чесно піде в «не
виміряно» замість того, щоб отримати колір фону.

### Чого не брати

- Усе, що потребує ComfyUI (GroundingDINO + SAM): служба не піднята, ваги
  3–4 ГБ, на 10 тис. фото це години GPU. ATR на CPU дешевший і на **фото речі
  на моделі точніший** — див. нижче.
- FitDiT, Leffa try-on, Qwen-Image-Edit, дошки, ремонт — це генерація, не вимір.
- Пороги ΔE 3/5: вони калібровані на парах «те саме фото зі зсувом тону», а не
  на «фото крамниці проти нашого виміру». Брати як орієнтир, не як правило.

### Одна перевірена чужа помилка, яку варто не повторити

`experiments/015_isolation_compare/conclusion.md` (вердикт власника того
проєкту, з плитками на руках):

- **ATR** на фото речі **на моделі** — найчистіший: він семантичний, тому
  зберігає ґудзики й розріз і викидає саму модель.
- **GroundingDINO+SAM** кращий на крупному плані взуття, де ATR (парсер цілого
  тіла) розсипається на друзки (1.6 % площі замість очікуваних десятків).
- **rembg / BiRefNet (матування) — не той інструмент** для фото на моделі: вони
  відділяють передній план від фону, тож на моделі лишають **усю людину**,
  а не річ.

Останній пункт для нас важливий: спокуса взяти «видалювач фону» замість парсера
велика, і вона хибна.

## 6. Як запустити (найкоротший шлях до маски)

Без ComfyUI, без GPU, з глобального python:

```python
import sys
sys.path.insert(0, r"C:\Users\Admin\Open Source Stylist")
from system.segmentation.parsing import garment_mask   # читає LEFFA_PATH або C:/Users/Admin/Leffa

mask, dominance = garment_mask("фото.jpg", "dress")    # регіони: upper skirt pants dress belt shoes …
# mask — uint8, 255 = річ, розмір як у фото; dominance — частка речі серед розпарсеного
```

Далі колір:

```python
from system.gates.color import _load_lab
lab = _load_lab("фото.jpg")
середнє = lab[mask > 127].mean(axis=0)     # L 0–100, a/b ±128
частка  = (mask > 127).sum() / mask.size
```

Перше звертання створює дві ONNX-сесії по 254 МБ — кілька секунд і близько
600 МБ пам'яті; сесія кешується в модулі, тож для пакетного прогону парсер
створюється один раз.

Решту запусків (дошки, генерація, ворота) тут не наводжу: вони потребують
піднятого ComfyUI і до нашого конвеєра не входять.

## 7. Три найкорисніші файли

1. **`system/segmentation/parsing.py`** — маска речі й `dominance`. ONNX на CPU,
   імпорт перевірено, ваги на місці. Без нього немає чого міряти.
2. **`system/gates/color.py`** — Lab у правильних діапазонах, CIEDE2000, хрома,
   кут тону, поріг надійності тону біля сірого. Готовий вимірювач.
3. **`system/gates/texture.py`** — банк Ґабора на смузі 4–8 px, свідомо мимо
   шуму JPEG. Півкроку до абсолютної міри «гладке / фактурне».
