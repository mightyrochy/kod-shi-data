# Витрати ChatGPT (Codex) і оптимізація його роботи — дослідження 18.10.2026

Наряд диспетчера за словом власника 18.10: «дослідити використання токенів кодексом, наскільки оптимізована його робота».
Лише читання: код і PR не правилися. Дані — (а) знімки панелі ChatGPT, які власник приклав 18.10 («дані, які намалював сам
ChatGPT»); (б) git/GitHub: 173 PR гілок `codex/*` (#598–#1460), `#963`, `аудит/РІШЕННЯ_ВЛАСНИКА.md`, `аудит/витрати/аналіз_1518.md`.
Токенів у репозиторії нема ніде; є лише **% тижневого ліміту** з панелі. Усе, що не виміряно, позначено «невідомо».

## 3. Марнотратство — виміряне

1. **Astra — найбільша стаття (36,4 % за моделлю)**, хоча `AGENTS.md` дозволяє її лише для кольору й фото речей та «незалежної
   думки під складне питання» (слово власника 11.10). Окрема перевірка на пачку — 32 коментарі «ПЕРЕВІРЕНО ПАЧКА» в #963 за
   12–18.10; скільки з них Astra max, невідомо.
2. **Субагенти 34,7 %**: правило «одночасно ≥ 4 виконавці, один файл — паралельно на різних ділянках, пачка з 2–3 PR»
   (`AGENTS.md`) плодить холодні старти й конфлікти. Доказ конфліктів — merge-коміти в самих гілках: у 14 відкритих `codex/*`
   їх **66** (#1445 — 16 із 24 перших-батьківських комітів; #1444 — 7 із 8; #1440/#1441 — по 6; #1450, #1453, #1454 — по 5).
   Кожне оновлення гілки від `main` — новий CI й нове авто-рев'ю.
3. **Дублі й повтори.** Номер рядка дошки в назвах кількох PR: 4944 — 9 PR (#974, #994, #999, #1000, #1005, #1038, #1049,
   #1058, #1327); 7483 — 4 PR (#1449 план, #1450, #1453, #1454); 3350 — #1047, #1059, #1079; 5191 — #995, #999, #1037;
   #1458/#1459 — обидва 7611. #1422 і #1423 створені ~16 хв після #1417 і #1416 (ті самі П2 і П1) і закриті за ~1 хв.
   Закрито без довезення — 22 PR, 41 комміт, ≈ 17,9 тис. рядків (з них 10 тис. — #1369).
4. **Авто-рев'ю 12,1 % + 0,4 %**: 351 PR за 30 днів проти 173 PR Codex за 3–18.10 — тобто він переглядає й чужі PR (дошка,
   стан, пачки Claude) і кожну пачку заново (її складники вже переглянуті). Дав 441 знахідку; у `main` 41 коміт посилається на
   відгук Codex (P1/P2) — частка влучних знахідок серед 441 невідома.
5. **Читання на старті.** Для Codex-виконавця: `CLAUDE.md` 15 818 Б (понад власну межу ~15 000 Б) + `AGENTS.md` 10 299 Б
   + `аудит/ПЕРЕВІРКА.md` 12 510 Б + `аудит/ПРОДУКТ.md` 40 863 Б ≈ **79 КБ ≈ 20 тис. токенів** (оцінка ~4 Б/токен для кирилиці)
   на кожному холодному старті; половина `CLAUDE.md` — розділи ролей Claude (листи, перевірка, правила ведення), виконавцю
   Codex непотрібні. Правила «Як читати» (п.19: лише свої рядки дошки, ПРОДУКТ — лише названі пункти) у `AGENTS.md` **нема** —
   там лише посилання на `CLAUDE.md`. `аудит/БЕКЛОГ.md` — 2,9 МБ (≈ 700 тис. токенів, цілим не читається); `КАРТИНА.md`
   21 КБ. Чи читає Codex їх цілком — невідомо (нема журналів сесій), але нічого в `AGENTS.md` цьому не перешкоджає.
6. **Чат власника 20,9 % (Remote Android)** — координатор живе в одному довгому чаті: кожна нова відповідь перечитує весь
   контекст (так само, як у Claude: 59 % грошей координаторів — перезапис кешу й малі ходи, `аналіз_1518.md`).
7. **gpt-5.6-sol 22,3 %** — стара модель, хоча правило — «Sol 6.1 medium». Хто її викликає (рев'ю, середовище, чат), невідомо.

## Метод (для повтору)

`git fetch origin '+refs/pull/*/head:refs/remotes/pr/*'` + `--unshallow`; список `codex/*` — пошук GitHub `head:codex/`
(173); «довезено» — голова PR є предком `origin/main` або голови злитого PR; обсяг — `git log --first-parent --no-merges
--numstat` від останнього коміту `main` до створення PR. Слабкі місця: типи за назвою; рядки не включають merge-коміти;
розбивка панелі — по одному числу 86,5 % у трьох зрізах.
