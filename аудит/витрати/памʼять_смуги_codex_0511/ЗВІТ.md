## Межі доступу й висновку

- `Win32_Service` повернув `0x80041003 Access denied`. Читання не повторювали,
  прав не підвищували. Системну групу побудовано за сеансом 0, доступним шляхом
  Windows і системними назвами; це наближення, не повна інвентаризація служб.
- У 317 процесів недоступний шлях виконуваного файла. LM Studio визначається за
  доступними шляхами, назвами `LM Studio`, `llmster`, `lms` та їхнім деревом.
  Процеси без цих ознак можуть лишитися в «решті». Системні застосунки без
  доступного шляху й поза сеансом 0 також можуть потрапити туди.
- Для 319 PID `Get-Process` або час створення недоступні: збережено лічильники
  `Win32_Process.WorkingSetSize` / `PrivatePageCount` з початкового переліку.
  Це позначено в кожному рядку та списку запасного джерела. Решта — `WorkingSet64`
  / `PrivateMemorySize64`. Обхід усіх процесів тривав 2,65 с, він не атомарний.
- Зв’язок із сесією — дерево PPID із перевіркою часу створення проти повторного
  використання PID. Уже осиротілі процеси чи відсутні проміжні предки не можуть
  бути надійно приписані сесії й лишаються в інших групах.
- Клас процесних лічильників `Win32_PerfRawData_PerfProc_Process` і клас пам’яті
  `Win32_PerfFormattedData_PerfOS_Memory` не повернули рядків. Приватний робочий
  набір і окремі складники системної фізичної RAM цим методом не отримані.

Висновок з наявного обсягу: у цей момент п’ять самих сесій займають 0,625 GiB
робочого набору, усі їхні дочірні — 1,033 GiB; до повної смуги бракує п’яти слотів.
Причина історичних 95 % RAM за 19 слотів **не визначена**. Гіпотезу про одночасні
важкі прогони цей знімок не доводить: не виміряно повну смугу, часові піки,
осиротілі дерева та фізичну пам’ять усіх складників Windows. Екстраполяції на
10 або 19 сесій й рішення про підвищення межі немає.

## Повтор і перевірка

Скрипт: [вимір.ps1](вимір.ps1), UTF-8 з BOM, Windows PowerShell. Запускається на
передньому плані з кореня репозиторію:

```powershell
& "./аудит/витрати/памʼять_смуги_codex_0511/вимір.ps1"
```

Кожен виклик зберігає окремий JSON із записувачем, UTC, усіма PID, групами, слотами
та ознакою `повна_смуга`. Для завершення потрібні щонайменше п’ять знімків з
`повна_смуга=true`, інтервали між початками ≥300 с (загалом ≥20 хв), без зниження
межі для створення формальної «повноти». Після цього обчислити часові середні й
максимуми окремо для codex, інструментів прогону й службових дочірніх та доповнити
облік фізичної пам’яті системи доступним дозволеним виміром.

ДО → ПІСЛЯ: розкладки поточного стану не було → один початковий знімок 5/10,
360 процесів і відтворюваний скрипт. Знімків повної смуги: **0 із потрібних 5**.

з п’ятьма зайнятими слотами, слотів без живої обгортки чи codex — 0.
