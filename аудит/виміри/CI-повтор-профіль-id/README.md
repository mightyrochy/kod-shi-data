# CI: відтворюваність id профілю

База виміру — `main` 0ac30d57bd6c18911178195b53f8a5e0744b79cb. Записи — десять сцен
`аудит/проби/нічні/20261107`, без змін у записаному обміні та паспортах.
Штамп збірки ДО — 022e30fbddabd3397e64d87a781abcfa2035a0f2: цей підготовчий коміт
додає лише докази й команду виміру; `джерела/` і `аудит/проби/` тотожні базовому main.

## Причина

`джерела/показ/профілі.js:новийІд` читає `Math.random`. Під час ініціалізації
`завантажитиПрофілі` створює перший профіль; `profiles` у запиті мовної моделі несе його id.
Стенд `рв6_стенд.js` встановлює свій `Math.random` лише після `goto` і підйому сторінки.
Початковий профіль на той час уже записаний в IndexedDB.

`записаний_обмін.js:ключЗапиту` рекурсивно сортує ключі об'єктів і рахує SHA-256 усього JSON.
`ЗаписанийОбмін.взяти` шукає невикористаний запис із тим самим ключем. Жодного виключення для id
чи іншого поля нема. Відмінний id робить різними навіть запити одного коду з одним сідом.

## Чому зелений main і червоний PR

- [main 978b1154, прогін 43072202884](https://github.com/mightyrochy/kod-shi-data/actions/runs/43072202884):
  обидві джоби успішні, але журнал частини 1 містить п'ять `REPLAY_STALE` на виклику 1, код стенда 3.
  Зелений статус не доводить відтворення записаних відповідей.
- [PR #3518, прогін 43072088918](https://github.com/mightyrochy/kod-shi-data/actions/runs/43072088918):
  обидві джоби червоні. Частина 1 бере ті самі п'ять сцен, має той самий вид застарівання без регресій,
  а `живий_після_CI.js` завершується кодом 1: немає погодження `ЖИВИЙ ПІСЛЯ`.
- `живий_після_CI.js` приймає рядок із тіла PR; для push у main — з повідомлення точного коміту
  або тіла пов'язаного з ним злитого PR. У [PR #3512](https://github.com/mightyrochy/kod-shi-data/pull/3512),
  злитому як 978b1154, такі рядки є. Перевірка погодження перевіряє наявність рядка, а не відповідність
  кожній застарілій сцені. Це пояснює статуси, але не є предметом цієї правки.
- `.github/workflows/zbirka.yml` викликає `приймання_записів.js` з частинами 0/2 та 1/2.
  `свіжіЗаписи` бере останній `повтор.json` для кожного id із `аудит/проби/нічні/`, упорядковуючи теки;
  `REPLAY_BASE_ROOT` додає або заміняє записи точного базового main. Архів `б1/ДО-2710` обирається лише
  з `REPLAY_ARCHIVE=1`, якого ці джоби не задають. На 978b1154 та базі цього наряду вибрані записи 20261107.
  Розподіл — за індексом у переліку modulo 2. Частина 1: `ж1_екскурсія_бруківка`,
  `ж2_новорічна_мороз`, `ж3_прогулянка_кофта`, `ж4_робота_срібні_сережки`, `ж7_робота_можливо_дощ`;
  частина 0 — решта п'ять сцен.

Повні журнали GitHub частини 1: `main-978b1154-job1.txt.gz`, `pr3518-job1.txt.gz`.

## Відтворення виміру

Зібрати повний показ командою `python джерела/build_артефакт.py джерела <збірка>/index.html показ-повний`
з `LYUSTERKO_CATALOG=повний`, `LYUSTERKO_PYC_PYTHON=<CPython 3.12.1>`,
`NODE_PATH=<залежності Node>` і `PYTHONUTF8=1`.

До зміни коду виконати:

```
node аудит/виміри/CI-повтор-профіль-id/вимір.js до <збірка-ДО> <кеш-Pyodide-0.26.4> <тимчасовий-вихід>
```

Після зміни коду зібрати показ повторно та виконати ту саму команду з `після` і новою текою збірки.
Скрипт запускає штатне приймання двічі, усі десять сцен кожного разу; перевіряє код 3 і виклик 1,
порівнює повну серіалізацію запитів побайтно та окремо показує розбіжності із записаним запитом.
Шлях `:json` у результаті означає розібраний JSON усередині текстового поля; побайтне порівняння
працює з незміненим запитом, без такої нормалізації.

`вимір-до.json` і `вимір-після.json` — числа та шляхи розбіжностей;
`запити-*.json.gz` — усі двадцять повних запитів кожного виміру;
`стенд-*.txt.gz` — журнали приймання й усіх його дочірніх запусків.

## Результат ДО → ПІСЛЯ

| Мірило | ДО | ПІСЛЯ |
|---|---:|---:|
| Сцен із різними першими запитами у двох повторах | 10/10 | 0/10 |
| Запусків із `REPLAY_STALE`, виклик 1, код 3 | 20/20 | 20/20 |

Єдина розбіжність кожної пари ДО — `.messages.0.content.0.text:json.profiles.0.id`.
ПІСЛЯ всі десять пар побайтно однакові; значення першого id — `пф-3-1`.
`новийІд` читає одне явне джерело стенда. Стенд встановлює його через `addInitScript`
до створення початкового профілю; id залежить від сіда й номера створення профілю.
Лічильник у sessionStorage переживає перезавантаження сторінки.

В обох вимірах перші записані запити відрізняються від поточних у `profiles`, `task.input`,
`task.codes`, `task.answer_schema` і `task.answer`. Тому старі записи й після правки застарілі.
Вимір охоплює перший запит, на якому суворий повтор зупиняє сцену; завершення сцен ним не доведено.
Перезапис має виконати жива черга. Записи, порівняння запитів, прилади й храповик не змінено.

Середовище виміру: Windows, Node 22.23.4, Python 3.12.10; компілятор вантажу — CPython 3.12.1,
Pyodide 0.26.4 із `C:/Users/gemini/pyodide`, залежності Node —
`C:/Users/gemini/kod-shi-test-node/node_modules`: Playwright 1.64.1, jsdom 30.1.3,
fake-indexeddb 6.2.6. Збирач перевіряє jsdom у локальній теці
`джерела/node_modules`, тому автоматичну перевірку показу пропущено; її виконання
зафіксовано окремими записами у `перевірки.json` для шаблону і зібраного HTML.

## Батарея й межа перевірки

Після `npm ci --ignore-scripts --no-audit --no-fund` із `джерела/package-lock.json`
виконано всю батарею `аудит/КОД.md` до кінця: димовий стенд, живий шлях (6/6),
протокол, гейти (582/0, без входу 0), `audit_contracts`, показ (991 звірка у 76 розділах).
Усі шість команд мають код 0. Окремий прогін зібраного HTML також має 991 звірку,
76 розділів і код 0. Дошка, синтаксис обох JS-файлів, `git diff --check`, проби
записаного обміну та храповика — код 0. Команди й коди всіх 15 перевірок — у
`перевірки.json`, журнали — однойменні `*.txt.gz` (текст після розпакування — UTF-8).

Додаткова проба `перевірити_нову_базу.js` локально **не зелена**: у Node 22.23.4 процес
аварійно завершився з кодом 3221226505 без тексту; цільовий повтор на наявному Node 24.22.1
дав код 1 і показав `AssertionError` у рядку 91: `path.relative` повертає Windows-шлях із
`\\`, а очікування містить `/`. Повтор не змінював проби, інструментів чи порівняння запитів.
Результати — `нова_база.txt.gz`, `нова_база-node24.json`, `нова_база-node24.txt.gz`.

Ця проба, `нова_база.js`, `приймання_записів.js`, `храповик_записів.js`, `записаний_обмін.js`
і її фікстура 20261028 не відрізняються від 978b1154. У збереженому журналі Ubuntu
`main-978b1154-job1.txt.gz` є `нова база: 5 груп перевірок зелені`.
Компонент і надалі має пройти CI голови на Ubuntu; локальний прогін на Windows його не замінює.
Окремого Linux-прогону в цій сесії не було: `wsl --list --quiet` не повернув дистрибутивів.

Рядки 14590–14591 залишені відкритими. Наряд прибрано з черги після досягнення мірила 0/10;
старі записи очікують живого перезапису, незалежна перевірка належить перевірці й диспетчерові.
