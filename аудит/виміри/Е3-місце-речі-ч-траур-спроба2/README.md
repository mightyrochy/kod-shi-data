## Чому блокер поза змінами трауру

На `б1_концерт_стримано` старий перший обмін не має `profiles`; у чинному мовному запиті цей список є, а також
відрізняються `task.input`, `task.codes`, `task.answer_schema`. Це видно при розборі JSON із поля
`messages[0].content[0].text` старого `VIDPOVIDI/обмін/00001.json` і збережених помилок повтору.

У всіх десяти парах поточні запити голови й `main` після розбору вкладеного JSON відрізняються лише
`profiles[0].id`. Випадковий id створює `джерела/показ/профілі.js:51`; у першій парі це `пф-2301bz` та `пф-ph4vsa`.
Тому хеші запитів двох запусків різні. Входи прогонів не нормалізувалися й не підмінялися: це лише аналіз доказів.
Сумісний повтор має врахувати й відтворюваність цих id; одного твердження «перезаписано» для доказу недостатньо.

`conversation_tools.py` (опис `profiles` — рядки 133–134), `мовний_шар.py`, `показ/профілі.js`,
`аудит/проби/записаний_обмін.js` та `рв6_стенд.js` тотожні `main` побайтно. Збій відбувається на першому мовному
запиті, до збирання речей і виконання траурної логіки. Для цієї голови доведено несумісність старих записів із
поточним `main`; це не доказ проходження пізніших кроків трауру.

## Відтворення

Використано команди приймання й Pyodide з `.github/workflows/zbirka.yml`, із парним `REPLAY_BASE_BUILD` та
`REPLAY_BASE_ROOT`. Локальна ОС — Windows, Node 22.23.4, збирач CPython 3.12.10 (у CI 3.11), окремий компілятор
байткоду CPython 3.12.1, Pyodide 0.26.4. Це локальний повтор, не запуск GitHub Actions.

Підготовка: `npm ci --ignore-scripts --no-audit --no-fund` у `джерела/`, кеш
`аудит/проби/стенд_pyodide_кеш.sh`, worktree бази всередині тимчасової теки задачі. Обидві збірки виконано так:

```powershell
$env:PYTHONUTF8='1'
$env:NODE_PATH=(Join-Path (Get-Location) 'джерела/node_modules')
$env:LYUSTERKO_CATALOG='повний'
$env:LYUSTERKO_PYC_PYTHON="$env:TEMP/python-3.12.1/python.exe"
New-Item -ItemType Directory -Force -Path "$env:TEMP/pokaz","$env:TEMP/main-pokaz" | Out-Null
python -X utf8 джерела/build_артефакт.py джерела "$env:TEMP/pokaz/index.html" показ-повний
python -X utf8 "$env:TEMP/main-replay/джерела/build_артефакт.py" "$env:TEMP/main-replay/джерела" "$env:TEMP/main-pokaz/index.html" показ-повний
$env:REPLAY_BASE_BUILD="$env:TEMP/main-pokaz"
$env:REPLAY_BASE_ROOT="$env:TEMP/main-replay"
node аудит/проби/приймання_записів.js "$env:TEMP/pokaz" "$env:TEMP/pyodide" "$env:TEMP/replay-0" 0 2
node аудит/проби/приймання_записів.js "$env:TEMP/pokaz" "$env:TEMP/pyodide" "$env:TEMP/replay-1" 1 2
```

Обидва збирачі завершилися з кодом 0; журнали — `збірка-голова.log.gz`, `збірка-main.log.gz`.
На голові виконано 991 звірку показу в 76 розділах, усе зелене. У worktree бази збирач пропустив jsdom-перевірку
через відсутність локального `node_modules`; сторінка бази пройшла димову перевірку вантажу та використана всіма
десятьма браузерними запусками Pyodide.

`звірки_Е1.js`, `перевірити_записаний_обмін.js`, `перевірити_храповик.js` завершилися з кодом 0.
Додаткова `перевірити_нову_базу.js` завершилася нативним кодом Windows `-1073740791` без текстового пояснення;
її проходження локально не доведено. Стенд не змінювали. На початку підготовки бракувало компілятора 3.12.1,
а перша збірка голови не записалася через нестворену вихідну теку; ці помилки підготовки виправлено до наведених
остаточних збірок і повторів.

Що лишилось: диспетчерові — придатні записи й відтворюваний вхід профілів; після цього — повтор обох частин CI,
незалежна перевірка та живе мірило кореня. Корінь, наряд і рядки 14503–14505 залишаються відкритими.
