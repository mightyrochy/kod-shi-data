# Е1: режим сцени з питання плану

База — `fedeab0f789b7189b1be6a0211d5dfcad6d66c9d`, зміна приладу — `a6fe74deb2`.

`записати_сцену.py --режим` передає явний режим до `сцена_реєстру`; без параметра використовується поле реєстру.
Режими, як і раніше, розбирає лише `змінні_режиму`, у синтаксисі `РЕЖИМ_РЕЄСТРУ`. Реєстр не змінено.
Невідомий режим дає причину відмови до створення теки результату й запуску моделей.

Сталого запускача нічного JSON-плану раніше не було: прогін `439529075c6318f9737558bda659a143d628c36b` записано
окремими командами з `КОМАНДИ.md`. Додано `аудит/проби/записати_план.py`: читає поле
`question` між першими двома стрілками, готує й перевіряє всі команди до першої сцени, явно передає `--режим`.
Питання без поля режиму використовує реєстр. Кілька питань однієї сцени покриває один прогін потрібної довжини,
з фото й оцінкою, коли вони названі. Команди, час і коди виходу зберігає `done.txt`; усі дочірні процеси чекає до кінця.
Постійний наряд `аудит/наряди/автоживий.md` указує цей запускач. Закритих тек адаптера й `.github/` не змінено.

| сцена | ДО, поле реєстру | ПІСЛЯ, явний режим |
|---|---|---|
| `ж4_робота` | `DO=palitra FOTO=0` | `повне +фото`: `OTSINKA=0 FOTO=1`, без `DO` |
| `ж1_свято_тріада` | `DO=palitra FOTO=0` | `повне`: `OTSINKA=0 FOTO=0`, без `DO` |

Усі 120 сцен без параметра мають тотожний базі результат або ту саму відмову; розбіжностей 0.
Відтворення повного порівняння й звірки старого плану:

```powershell
python аудит/виміри/Е1-режим-сцени-з-плану/звірити_режими.py
python аудит/проби/записати_сцену.py --лише-змінні --сцена ж4_робота --режим 'повне +фото'
python аудит/проби/записати_сцену.py --лише-змінні --сцена ж1_свято_тріада --режим повне
python аудит/проби/записати_план.py аудит/виміри/Е1-режим-сцени-з-плану/план_мірила.json збірка кеш тимчасовий-вихід --лише-змінні
python джерела/проби/запис_сцени_режим.py
python аудит/проби/тест_записати_план.py
python джерела/прилади/згорнути_дошку.py --лише-перевірити
git diff --check
```

Для Windows Python запущено з `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`; для перевірки показу використано
`NODE_PATH=C:\Users\gemini\kod-shi-test-node\node_modules`. Решту середовища обгортки збережено.
Команди повної батареї, коди виходу й тривалість — `перевірки.json`, stdout/stderr — у відповідних `.log`.
Проба реєстру звіряє 120 сцен; п'ять перевірок запускача проходять реальний CLI без моделей, перевіряють
запасний режим реєстру, відмову всього плану до першої сцени, об'єднання питань і журнал послідовного запуску.

## Знахідка поза канонічним мірилом

Вад знайдено: 2, №13163 і №13164. У збереженому нічному плані за 05.11 на `439529075c6318f9737558bda659a143d628c36b`
усі 29 сцен містять 64 явно названі поля режиму; 36 полів виходять за синтаксис реєстру. Наприклад,
`повне, OTSINKA=0` або `повне +фото (OTSINKA=0 FOTO=1 ODNOCHASNO=1; руки 1–2; після перезбору каталогу)`.
Повний перелік із PR, сценами й причинами — `синтаксис_плану_0511.json`; рядок дошки —
`аудит/дошка/gemini/Е1-режим-сцени-з-плану.md`. Диспетчерові перед повтором потрібен план із канонічними полями режиму;
додаткові умови питання не слід змішувати з цим полем. Старий план не переписано й не видано за придатний до запуску.

№13164: протокольний стенд завершується кодом 1 на `тест_протоколу.py:1013`, індексує порожній `_вб8["ід"]`.
Повтор із кодом стенда з бази `fedeab0f789b7189b1be6a0211d5dfcad6d66c9d` відтворив той самий `IndexError`.
Перед повтором побайтово звірено текст стенда та список змін `джерела/` і каталогів: змінено лише
`джерела/проби/запис_сцени_режим.py`, яку протокольний стенд не імпортує; решта імпортів читається з тих самих
незмінених файлів. Команда базового виконання й cwd — у `протокол_база.json`, результат — `3-до-тест_протоколу.log`.
Порожній вибір і його причину в продукті цей наряд не досліджує; повну батарею не названо зеленою.

Нічний прогін наживо цей наряд не виконує: повтор за 05.11 після злиття ставить диспетчер.
