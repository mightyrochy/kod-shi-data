# Gemini без руки — разове налаштування власника (М.2)

Після цього наряд Gemini йде сам: диспетчер ставить позначку черги, ноутбук проганяє `agy` під `gemini`, публікує гілку
`gemini/<наряд>` і пише диспетчерові рядок. Рук на прогін — 0. Час — 40–60 хв, з них ~20 — проба наприкінці.
Ноутбук має бути ввімкнений; кроки 3–5 — у «PowerShell (від імені адміністратора)» під твоїм обліковим записом.

## Як це працює (прочитати, 3 хв)

| хто | що робить | ключі |
|---|---|---|
| диспетчер (хмара) | гілка-позначка `gemini-queue/<наряд>/<модель>/<спроба>` на коміт `main`; текст наряду — `аудит/наряди/<наряд>.md` у `main` | свої |
| задача `gemini-run`, користувач `gemini`, раз на 2 хв, без межі часу | перевірка ізоляції → `git fetch` без входу → смуги Codex і `agy`: до N нарядів у кожній водночас («Смуги й черга» нижче) → `agy`/Codex до звіту → бандл і стан у `C:\Users\Public\gemini\out\` | **нема** |
| задача `claude-run`, ти, раз на 2 хв, без межі часу | смуга Claude: позначки `cc-…` → `claude -p` у робочій копії слота твого клону → рядок кінця в теці вихідних; стан ноутбука — тіло issue #1856 («Рушій Claude» нижче) | Claude, git і `gh` — твої |
| задача `gemini-publish`, ти, раз на 1 хв | бандл → перевірки (лише `gemini/*`, без `.github/` і файлів обгортки, fast-forward) → `git push` → `claude -p … --cloud <диспетчер>` | git і Claude — твої |

Межі (18.10): повні права — лише під `gemini`; під `gemini` нема входу ні в GitHub, ні в Claude; обгортка ізоляції не
створює й не змінює. Задача під тобою з теки `gemini` лише читає файли, нічого звідти не запускає; її скрипт лежить у
твоєму профілі, а не в клоні; після встановлення самооновлення цей файл лише вибирає версію з `active.txt`.

## 2. Файли обгортки (5 хв)

Той самий PowerShell під тобою (не від адміністратора):

```powershell
$base = 'https://raw.githubusercontent.com/mightyrochy/kod-shi-data/main/аудит/адаптери/gemini'
$pub = "$env:USERPROFILE\gemini-publish"; New-Item -ItemType Directory -Force $pub | Out-Null
Invoke-WebRequest "$base/gemini_publish.ps1" -OutFile "$pub\gemini_publish.ps1" -UseBasicParsing
Invoke-WebRequest "$base/gemini_run.ps1" -OutFile "$env:TEMP\gemini_run.ps1" -UseBasicParsing
Invoke-WebRequest "$base/queue_lanes.ps1" -OutFile "$env:TEMP\queue_lanes.ps1" -UseBasicParsing
Invoke-WebRequest "$base/wrapper_health.ps1" -OutFile "$pub\wrapper_health.ps1" -UseBasicParsing
Invoke-WebRequest "$base/wrapper_health.ps1" -OutFile "$env:TEMP\wrapper_health.ps1" -UseBasicParsing
Get-FileHash "$pub\wrapper_health.ps1", "$env:TEMP\wrapper_health.ps1", "$env:TEMP\queue_lanes.ps1" | Format-List Hash, Path
Get-FileHash "$pub\gemini_publish.ps1", "$env:TEMP\gemini_run.ps1" | Format-List Hash, Path
```

Хеші мають збігтися з таблицею внизу цього файлу (у PR — так само). Не збіглися — зупинись і напиши диспетчерові.
Оновлення обгортки згодом — той самий крок і крок 3 (копія `gemini_run.ps1`).

## 3. Тека обгортки `gemini` лише для читання (5 хв, від адміністратора)

`gemini` запускає свою копію, але змінити її не може — інакше агент міг би вимкнути межі часу.

```powershell
$run = 'C:\ProgramData\gemini-wrapper'
New-Item -ItemType Directory -Force $run | Out-Null
Copy-Item "$env:TEMP\gemini_run.ps1" "$run\gemini_run.ps1" -Force
Copy-Item "$env:TEMP\queue_lanes.ps1" "$run\queue_lanes.ps1" -Force
Copy-Item "$env:TEMP\wrapper_health.ps1" "$run\wrapper_health.ps1" -Force
icacls $run /inheritance:r /grant:r "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F" "${env:USERNAME}:(OI)(CI)F" "gemini:(OI)(CI)RX"
```

`1_адмін.ps1` рахує sha256 уже скопійованих `gemini_run.ps1`, `queue_lanes.ps1` і `wrapper_health.ps1` у ProgramData (не `$env:TEMP`, який пише звичайний користувач); розбіжність — копію видаляє й зупиняється (9742).

Теку обміну `C:\Users\Public\gemini\out` створить сама обгортка під `gemini` (крок 4) — тоді вона її власниця.

## 4. Перевірка під `gemini` (10 хв)

Зміна користувача (Win+L → `gemini`; так, як ти робив 19.10), звичайний PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\ProgramData\gemini-wrapper\gemini_run.ps1
Get-Content C:\Users\Public\gemini\out\heartbeat.json      # має бути "isolation":"OK"
Add-Content C:\ProgramData\gemini-wrapper\gemini_run.ps1 '#' # має бути відмова в доступі
agy models                                                  # список моделей (диспетчерові не треба — обгортка сама)
```

- `isolation` не `OK` — код скаже, що не так: `WHOAMI` (не той користувач), `NET_SESSION` (у `gemini` права
  адміністратора), `PROFILES` (бачить твій профіль), `DRIVES` (бачить інший диск), `ENV` (змінна з KEY/TOKEN/SECRET/
  PASSWORD). Виправ ізоляцію за описом 19.10, далі не йди.
- Помилка `origin клону … не https://github.com/mightyrochy/kod-shi-data` у `C:\Users\gemini\gemini-runs\wrapper.log`
  — клон не той; клон за `GEMINI.md`.
- У `gemini` нема пароля (входить без нього) — задай його тут же: Ctrl+Alt+Del → «Змінити пароль». Саме так, а не
  `net user` з твого облікового запису: скидання пароля адміністратором стирає збережений вхід `agy`.

Повернись до свого користувача й перевір, що задача під тобою прочитає теку обміну:

```powershell
Get-Content C:\Users\Public\gemini\out\heartbeat.json
```

Відмова в доступі — від адміністратора: `icacls C:\Users\Public\gemini /grant "${env:USERNAME}:(OI)(CI)RX" /T`.

## 5. Дві задачі планувальника (10 хв, від адміністратора)

```powershell
$set = @{ MultipleInstances = 'IgnoreNew'; AllowStartIfOnBatteries = $true; DontStopIfGoingOnBatteries = $true; StartWhenAvailable = $true }

# право «Вхід як пакетне завдання» для gemini: без нього задача не стартує (0x80070569); на Windows Home нема secpol.msc
$sid = ([System.Security.Principal.NTAccount]"$env:COMPUTERNAME\gemini").Translate([System.Security.Principal.SecurityIdentifier]).Value
$d = "$env:TEMP\batchright"; New-Item -ItemType Directory -Force $d | Out-Null
secedit /export /cfg "$d\cur.inf" /areas USER_RIGHTS | Out-Null
$line = Get-Content "$d\cur.inf" | Where-Object { $_ -match '^SeBatchLogonRight' }
$old = if ($line) { ($line -split '=', 2)[1].Trim() } else { '' }
$new = if (-not $old) { "*$sid" } elseif ($old -match [regex]::Escape($sid)) { $old } else { "$old,*$sid" }
'[Unicode]','Unicode=yes','[Version]','signature="$CHICAGO$"','Revision=1','[Privilege Rights]',"SeBatchLogonRight = $new" | Set-Content -Encoding Unicode "$d\new.inf"
secedit /configure /db "$d\new.sdb" /cfg "$d\new.inf" /areas USER_RIGHTS

# під gemini: раз на 2 хв, без межі часу задачі — запуск є планувальником смуг і живе, доки йдуть його наряди
$a = New-ScheduledTaskAction -Execute 'powershell.exe' -Argument '-NoProfile -NonInteractive -ExecutionPolicy Bypass -File C:\ProgramData\gemini-wrapper\gemini_run.ps1'
$t = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(2) -RepetitionInterval (New-TimeSpan -Minutes 2)
$s = New-ScheduledTaskSettingsSet @set -ExecutionTimeLimit ([TimeSpan]::Zero)
$c = Get-Credential -UserName "$env:COMPUTERNAME\gemini" -Message 'Пароль користувача gemini'
Register-ScheduledTask -TaskName 'gemini-run' -Action $a -Trigger $t -Settings $s -User $c.UserName -Password $c.GetNetworkCredential().Password -RunLevel Limited

# під тобою: раз на 1 хв (кінець прогону доходить за ≤ 2 хв), до 30 хв, поки ти увійшов у Windows (блокування екрана не заважає): задача з паролем
# акаунта Microsoft не приймає (0x8007052E); conhost --headless ховає вікно
$a2 = New-ScheduledTaskAction -Execute 'conhost.exe' -Argument "--headless powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File `"$env:USERPROFILE\gemini-publish\gemini_publish.ps1`""
$t2 = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(2) -RepetitionInterval (New-TimeSpan -Minutes 1)
$s2 = New-ScheduledTaskSettingsSet @set -ExecutionTimeLimit (New-TimeSpan -Minutes 30)
$p2 = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType Interactive -RunLevel Limited
Register-ScheduledTask -TaskName 'gemini-publish' -Action $a2 -Trigger $t2 -Settings $s2 -Principal $p2

Get-ScheduledTask gemini-run, gemini-publish | ForEach-Object { $_.TaskName, $_.Principal.LogonType, $_.Triggers[0].Repetition.Interval, $_.Triggers[0].Repetition.Duration }
```

Очікувано: `Password` і `Interactive`, `PT15M`/`PT1M`, тривалість порожня («безстроково»). Тривалість не порожня —
у «Планувальнику завдань» відкрий задачу → «Тригери» → «Змінити» → «протягом: Безстроково». Пароль задачі —
локальний (зберігає Windows), не секрет сесій.

## Рушії черги (М.9-В)

Рушій обирає **назва моделі в позначці** `gemini-queue/<наряд>/<модель>/<спроба>` (дозволені літери, цифри, `.`, `-`):

| модель у позначці | рушій | запуск (кожен хід — окремий процес; текст ходу — файл `turnN.md`) |
|---|---|---|
| `gpt-<модель>[-none\|-minimal\|-low\|-medium\|-high\|-xhigh\|-max\|-ultra]`, напр. `gpt-6.1-sol-high`, `gpt-6.1-sol-max` | локальний Codex | `codex exec -C <клон> -m <модель> [-c model_reasoning_effort=<рівень>] --json -o <файл> --dangerously-bypass-approvals-and-sandbox "<прочитай файл…>"` |
| інша, напр. `gemini-3.8-flash-high` | `agy` (як було) | без змін |

Gemini CLI не ставимо (рішення диспетчера 25.10: для Google One його замінено Antigravity CLI з 18.06.2026; другий рушій Gemini — наявний `agy`).

- Codex — під тим самим ізольованим користувачем `gemini`, той самий клон, ті самі перевірки перед пушем (`gemini_publish.ps1`
  не змінювався по суті): гілка `gemini/<наряд>`, без `.github/` і `аудит/адаптери/`, fast-forward. Звіт — той самий рядок
  `НОУТБУК ГОТОВО gemini/<наряд> <SHA40>`. Догонка несе повний текст наряду (нової розмови рушій не пам'ятає).
- `--dangerously-bypass-approvals-and-sandbox` у Codex — лише тому, що ізоляція ОС (користувач без прав і входів, перевірка
  `Test-Isolation` перед кожним прогоном) уже стоїть; документація Codex дозволяє цей прапор лише в ізольованому середовищі.
- **Codex вмикається ключем (9738).** Рішення власника 25.10: Codex під `gemini` — з основним акаунтом ChatGPT власника, ризик
  прийнято (ізоляцію рушіїв веде М.9-Г). Рушій вмикає явний ключ `-EnableCodex` в аргументах задачі `gemini-run`
  (`… gemini_run.ps1 -EnableCodex`); його дописує `m9v/1_адмін.ps1 -EnableCodex`, без ключа аргументи, як були. Без ключа Codex не кличеться: позначка `gpt-…` дає `ENGINE_MISSING`, каскад іде лише `agy`
  (`-CodexFallbackModel` без ключа ігнорується). Токен Codex — `~/.codex/auth.json` профілю `gemini`: секрет у межі цього
  користувача; `gemini_publish.ps1` не пускає його в репозиторій (код `SECRET`, 9739). Вхід — `codex login --device-auth`.
- **Вибір за квотою.** Параметр `-CodexFallbackModel <gpt-модель[-зусилля]>` (за замовчуванням порожній — вимкнено; діє лише з `-EnableCodex`): коли група
  моделі `agy` на 0 %, наряд іде в Codex з цією моделлю (`engine=codex` у стані, рядок «рушій: …» у журналі). Квоту Codex без ходу
  не прочитати, тож його 429 ловить обгортка (`QUOTA`); обидва недоступні — `QUOTA_ZERO`/`QUOTA`, позначка лишається. Моделі
  Codex — `аудит/МОДЕЛІ.md`; хмарний Codex з GitHub — лише GPT-5.6 Sol, локальний — gpt-6.1-sol чи Astra.
- **Codex без меж (власник 26.10).** Суфікс-зусилля позначки `gpt-…` іде в `-c model_reasoning_effort=<рівень>` дослівно, `max` теж; перелік
  суфіксів — у `$script:CodexEfforts` (`gemini_run.ps1`). Рівня, якого `codex exec` не приймає, обгортка не підміняє нижчим: вона віддає
  `ЗАБЛОКОВАНО <гілка> EFFORT_INVALID` (один виклик, без догонки; розпізнається і конфігураційна відмова `model_reasoning_effort`, і відповідь
  сервера `Invalid value … Supported values are: …` без назви параметра — за надісланим зусиллям чи переліком зусиль; клас відмови
  шукається в тексті, розкодованому з екранування JSON (`\u0027` → `'`), бо рядки подій `--json` приходять екранованими; `codex-cli 0.164.0`
  називає прийнятими `none…xhigh, max`, `ultra` відмовляє), а диспетчер бачить найвище прийняте зусилля з виводу `codex exec`.
  Межі часу всього прогону для Codex нема (`-TotalMinutes` на нього не діє, для `agy` — як було): зупиняє лише завислість —
  нових подій `--json` нема довше за `-CodexStallMinutes` (за замовчуванням 60 хв) → `ЗАБЛОКОВАНО <гілка> STALL`. Час і тип кожної
  події пише `gemini-runs\<id>\codex.events.tsv` — за ним поріг вивіряють; 60 хв узято з запасом, бо часових міток старих
  прогонів не збереглося. Роль агента — з рядка `Роль — ВИКОНАВЕЦЬ|ПЕРЕВІРКА …` наряду (з першої колонки, слово ролі не продовжується літерою; кінець
  тексту без переносу допустимий; рядки в огороджених блоках ```/~~~ — приклад, їх пропущено); нема рядка — виконавець. Захист не змінено: агент обгортки файлів `аудит/адаптери/gemini/` не міняє.
- Рушія нема на ноутбуці — код `ENGINE_MISSING` (рядок `ЗАБЛОКОВАНО … ENGINE_MISSING`), а не збій обгортки.
- Нові коди помилок: `QUOTA` (429, `usage limit`, `rate limit`), `AUTH` (`not logged in`, `please log in`).

### Пули й каскад (М.9-В, доповнення «Gemini на повну»)

**Безпечність `/usage`.** Офіційний changelog agy, v1.1.11 (7.08.2026): у print mode `-p "/usage"`, `/quota`, `/credits`, `/model`,
`/effort`, `/skills` дають по одному запису з табами на рядок «without starting an agent turn, spending quota, or leaving a
conversation behind». Тому обгортка читає `agy --version` і кличе `/usage` **лише на версії ≥ 1.1.11** (константа
`$script:UsageMinVersion`); версія нижча чи не розпізнана — `/usage` не кликати, квота невідома, наряд іде далі (429 ловить
`Get-ErrorCode`). Джерела: https://antigravity.google/docs/changelog/ (запис v1.1.11), https://antigravity.google/docs/cli/features/ (`/usage`,
alias `/quota`), https://antigravity.google/docs/cli/headless/ (команди, що відповідають самі, дають текстовий звіт, не потік подій).

**Розбір.** Колонок документація не наводить: перший рядок з табами — заголовок (без цифр; `Remaining %`/`Used %`/`Resets in`
розпізнаються за назвою, час скидання — `2h 17m` або дата), далі записи. Живий формат agy 1.4.7 — без заголовка: таблиця читається, лише коли
кожен рядок має назву групи, `NN%` передостанньою колонкою й ISO-час останньою (вікно — друга колонка, якщо є). Інша таблиця без заголовка — квота
«невідома»: рядок «квота: /usage — таблиця без розпізнаного заголовка» і початок виводу в `wrapper.log`, у рядку ПУЛИ — позначка `Q=?`, каскад за пулом
не вмикається (наряд іде на моделі позначки). Версію agy беремо
лише з рядка з назвою `agy` (`agy 1.1.11`); число з іншого місця не береться, нерозпізнана версія — `/usage` не кличеться. Вивід-JSON старих збірок теж приймається.

**Пули для диспетчера.** Щоразу, коли `agy` є, `gemini-run` пише `pools.json` у теку вихідних (версія agy; групи: ASCII-код, % залишку, хв до
скидання; назви `agy models` лише родин `gemini-`/`claude-`/`gpt-`, до 6). `gemini-publish` перевіряє його заново за шаблонами й кладе у вихідні рядок
`GEMINI ОБГОРТКА: ПУЛИ V=<версія|-> (G=<ГРУПА>:<0-100>:<хв|->){0,6} (Q=?)? M=<модель>(,<модель>){0,5}`, де `<модель>` — `^(gemini|claude|gpt)-[a-z0-9.-]{1,36}$` (9740: вільний текст із `pools.json`, який пише `gemini`, у хмару не йде), рядок ≤300 знаків — не частіше за раз на 3 год і лише
коли рядок змінився. Обрано окремий рядок, а не heartbeat: heartbeat у хмару не йде, а рядок `ГОТОВО` виходить лише коли є наряд.
Фактична модель наряду — суфікс ` МОДЕЛЬ <модель>` у рядку `ГОТОВО`.

**Каскад за залишком пулу** (константи в `gemini_run.ps1`, не конфіг): клас за назвою позначки — `flash` → «код», `pro` → «проєктування».
Модель позначки з пулом на 0 % → наступна того ж класу; усі на 0 % і `-CodexFallbackModel` не задано — `QUOTA_ZERO`.

| клас | порядок |
|---|---|
| код (`…flash…`) | модель позначки → Codex (`-CodexFallbackModel`) |
| проєктування (`…pro…`) | модель позначки → `claude-opus-5-5-high` (через `agy`; пропускається, якщо її нема в `agy models`) → Codex |
| інша `agy`-модель | модель позначки → Codex |
| `gpt-…` | без каскаду (Codex) |

Невідома квота (старий agy, нерозпізнаний вивід) не блокує кандидата. Крок каскаду лишає рядок «каскад: …» і «рушій: …» у `wrapper.log`.

### Межа довіри наряду

До сесій Claude — лише рядки, які обгортка обчислила сама: номери, SHA, стани, коди причин, адреси. Вільного тексту агента,
коментаря чи файлу — ні (урок 8940: текст агента пройшов через `models` стану). Тека вихідних — у профілі власника, не
`C:\Users\Public`: ізольовані користувачі в неї не пишуть. Пуш — лише в `refs/heads/gemini/*` і `refs/heads/codex/*`;
`.github/` і `аудит/адаптери/` у диффі — відмова, як у М.2. `gh` і `claude` — наявні входи власника на ноутбуці. Один секрет усе ж є: токен Codex (`~/.codex/auth.json`) у профілі `gemini` після
`codex login --device-auth` (9738) — він лишається в межі користувача `gemini`, а `gemini_publish.ps1` відмовляє `SECRET` для шляхів
`auth.json`, `.codex/`, `.config/gh/` і вмісту, схожого на токен (`eyJ…`, `sk-`, `ghp_`, `refresh_token`), у кожному коміті (9739). Знахідки — `аудит/дошка/<гілка>.md`, номери — від диспетчера.

## Смуги й черга (М.9-Е)

Смуга на рушій — Codex, `agy`, Claude Code; смуги йдуть водночас, у смузі — до N нарядів водночас. Планувальників два
(облікові записи розведено): `gemini-run` під `gemini` веде смуги Codex і `agy`, `claude-run` під тобою — смугу Claude.
Спільне — модуль `queue_lanes.ps1` (поруч зі скриптом, під хешем). Запуск задачі — планувальник: опитує чергу раз на
`poll_minutes` (≤ 5 хв), доки йде хоч один його наряд; без нарядів виходить, задача стартує знову за 5 хв.

- **Межі** — `смуги.json` у цій теці; читає з `origin/main` (після `git fetch`, не з робочої копії агента) кожен прохід, тож
  зміна в `main` міняє паралельність без перевстановлення копій. Кількість слотів задає `смуги.json`; межа 0–64 у `queue_lanes.ps1` захищає від помилки в даних,
  а не визначає місткість ноутбука. Інші стелі коду:
  `poll_minutes` 1–5, `usage_minutes` 5–60, `quota_wait_minutes` 15–1440, `agy_total_minutes` 30–600, `agy_turn_minutes`
  10–600, `codex_stall_minutes` 10–240, `claude_hang_minutes` 30–240; значення поза межами обрізаються. Параметр задачі
  (рука власника) сильніший за файл. Формат v2 (ядро, «Межа роботи»): кожна межа — `{"n": число, "джерело": "…"}`,
  джерело — «власник ДД.ММ …» чи «вимір: …» з датою ДД.ММ і числом. Межа без джерела (порожнє, не за форматом), файл v1,
  кривий чи невідомий — береться попереднє прийняте значення (`state\limits.json` кожного облікового запису; нема — з
  коду), а в #1856 — рядок «межа без джерела: <поле>»; узяття це не зупиняє. Формат звіряє `перевірка/перевірити_хеші.py`.
- **Наряд — окремий процес** того самого скрипта (`-WorkerFile`) зі своїм слотом (замок `slots\<смуга>-<k>.lock` на весь
  прогін) і текою запуску. Копія задачі — тека `gemini-runs\w\<прогін>`, `claude-run\w\<прогін>` (`New-TaskCopy`):
  `repo` — git worktree клону (спільні об'єкти) без тек-архівів `аудит/` (від третього рівня, ≥ 8 МіБ відстежуваних
  файлів; тека, названа в наряді, лишається; іншу сесія додає `git sparse-checkout add`), `tmp` — `TEMP`/`TMP` процесу й
  нащадків; шлях — у промпті. Копія є лише після звірки голови й прибирається після доставки; з комітами поза
  `origin` (Gemini — поза гілками) лишається з `kept.txt`. Перший прохід планувальника прибирає копії незайнятих слотів
  і давні `w\<слот>`.
  Узяття позначки атомарне (`state\<ключ>.claim`, CreateNew): дві смуги чи два слоти одну не візьмуть; один наряд
  (назва) двома слотами водночас — ні.
- **Порядок** — умови в назві позначки (`ЧЕРГА.md`): пріоритет, строк, далі час першої появи позначки на ноутбуці.
- **Квота.** `agy`: `/usage` — не частіше за `usage_minutes` (кеш `usage.json`) і заново, коли минув час чекання;
  живий формат agy 1.4.7 — без заголовка, рядок на вікно (тиждень, 5 год), скидання ISO UTC; група моделі — за власним
  словом («Gemini 4 Argon» ↔ `gemini-4-argon-*`), інакше група родини («Gemini Models», «Claude and GPT models»). Група на
  0 % до старту — позначка чекає скидання, спроба не спалена; посеред прогону (429, Codex, Claude) — так само, з головою
  гілки для продовження, до 5 повернень. Відмова до старту наряду (робоча копія, запуск процесу) рахується тим самим лічильником
  і тією самою межею: позначка повертається в чергу, а на межі закінчується `ЗАБЛОКОВАНО <гілка> CRASH`. Рядок диспетчерові — `ЗАБЛОКОВАНО <гілка> QUOTA0_<ГРУПА>_M<хв>`, раз на чекання.
- **GPU** — замок `C:\Users\Public\gemini\lanes\gpu.lock` (пишуть INTERACTIVE і BATCH), спільний для обох облікових
  записів: GPU-наряд тримає його весь прогін, другий GPU-наряд чекає в черзі.

## Рушій Claude (задача `claude-run`)

Третій рушій: наряд ноутбука веде Claude Code без вікна (`claude -p`) **під тобою**, з наявними входами Claude, git і
`gh` — нового входу нема. Скрипт — `%USERPROFILE%\claude-run\claude_run.ps1` (у профілі, не в клоні: після встановлення самооновлення файл вибирає перевірену версію; злиття до встановлення його не
міняє). Ставить `m9v/0_власник.ps1` (крок 1 `m9v/ЩО_НАТИСНУТИ.md`) тими самими `$base`, `$set` і `$p`, що й `gemini-watch`:

```powershell
$cr = "$env:USERPROFILE\claude-run"; New-Item -ItemType Directory -Force $cr | Out-Null
Invoke-WebRequest "$base/claude_run.ps1" -OutFile "$cr\claude_run.ps1" -UseBasicParsing
Invoke-WebRequest "$base/queue_lanes.ps1" -OutFile "$cr\queue_lanes.ps1" -UseBasicParsing
Invoke-WebRequest "$base/wrapper_health.ps1" -OutFile "$cr\wrapper_health.ps1" -UseBasicParsing
Get-FileHash "$cr\claude_run.ps1", "$cr\queue_lanes.ps1", "$cr\wrapper_health.ps1" | Format-List Hash, Path
$a = New-ScheduledTaskAction -Execute 'conhost.exe' -Argument "--headless powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File `"$cr\claude_run.ps1`""
$t = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(1) -RepetitionInterval (New-TimeSpan -Minutes 2)
$s = New-ScheduledTaskSettingsSet @set -ExecutionTimeLimit ([TimeSpan]::Zero)
Register-ScheduledTask -TaskName 'claude-run' -Action $a -Trigger $t -Settings $s -Principal $p -Force | Out-Null
```

Межі часу задачі нема (`ExecutionTimeLimit` 0, `IgnoreNew`): водночас один планувальник, нарядів — до N слотів смуги
Claude («Смуги й черга» вище).

| позначка | що робить `claude-run` |
|---|---|
| `gemini-queue/<наряд>/cc-<модель>[-<зусилля>]/<спроба>[/<умови>]`, напр. `cc-claude-sonnet-5-5-medium` | `claude -p --model <модель> [--effort <зусилля>] --permission-mode auto --output-format stream-json --verbose` у копії задачі `%USERPROFILE%\claude-run\w\<прогін>\repo` (git worktree клону `%USERPROFILE%\kod-shi-data` без тек-архівів; «Наряд — окремий процес» вище); зусилля — останній сегмент, якщо він `none\|minimal\|low\|medium\|high\|xhigh\|max\|ultra` |
| `gemini-queue/ВИМКНИ-НОУТБУК/cc-off/<спроба>` | коли рушії не працюють — рядок `ВИМКНЕНО <SHA позначки>`, чекання доставки (до 10 хв) і `shutdown /s /t 60` |

- **Черга.** Порядок і слоти — «Смуги й черга» вище; узята — файл стану в `%USERPROFILE%\claude-run\state`, вдруге не
  береться (доробка — `<спроба>+1`). `gemini-run` позначок `cc-` не бере й узятими не позначає: смуги Gemini (під `gemini`)
  і Claude (під тобою) йдуть водночас; GPU-наряд — один на ноутбуці (замок).
- **Квота.** Відмова за квотою (`usage limit`, `hit your limit`, 429) — не кінець: позначка чекає скидання (час — `resetsAt`
  події `rate_limit_event` stream-json, яку `claude` 2.1 друкує на кожному прогоні; нема — `quota_wait_minutes`), рядок
  `ЗАБЛОКОВАНО claude/<наряд> QUOTA0_CLAUDE_M<хв>`, після скидання її бере ця ж смуга, сесія продовжує гілку наряду.
- **Звіт** — один окремий рядок у полі `result` події `result`. Дозволено збалансоване оформлення
  жирним, inline-бектиками чи лапками і крапку в кінці; після рядка може бути підсумок. Цитати `>`,
  блоки коду, цитований наряд і позначені приклади не є звітом; кілька звітів неоднозначні.
  Гілка й SHA, як раніше, звіряються з `git ls-remote`.
- **Промпт** (`Get-Prompt`) — «Середовище й кроки ноутбука — `аудит/НОУТБУК.md`» з каналом результату (останній рядок
  відповіді `НОУТБУК ГОТОВО <гілка> <SHA40>` чи `НОУТБУК ЗАБЛОКОВАНО: …`); повний текст `аудит/наряди/<наряд>.md` з
  коміту позначки; тека задачі (`repo`, `tmp`, клонів поза нею не робити); «Продовжуй з гілки `<гілка>`», коли гілка
  попередньої спроби є на `origin`; останній рядок — «ноутбук не вимикай — вимикає лише обгортка за позначкою». Гілку `claude/…` і PR-чернетку сесія пушить сама.
- **Завислість — єдина межа часу:** жодної події stream-json `HangMinutes` = 120 хв — `HANG`, дерево процесів `claude`
  зупинено. Подія — рядок stdout, що розбирається як JSON з полем `type`; інший рядок таймера не скидає (лише
  `claude.jsonl`). Поріг і стан діють, доки процес живий, і після закриття stdout. Часи подій — `runs\<id>\events.tsv`:
  за ними поріг вивіряють після прогонів.
- **Кінець** — один рядок у теці вихідних (доставляє `gemini-publish`): `GEMINI ОБГОРТКА: ГОТОВО claude/<наряд> <SHA40> МОДЕЛЬ
  cc-…` — лише коли `git ls-remote origin` має саме цей SHA на гілці зі звіту; інакше `GEMINI ОБГОРТКА: ЗАБЛОКОВАНО
  claude/<наряд> <КОД>`:

| код | що |
|---|---|
| `NOT_ON_MAIN` | коміт позначки не в `origin/main` — наряд не взято |
| `CLAUDE_NOT_LAPTOP` | позначка `cc-…` без умови `gpu` і не з переліку `claude_laptop` у `смуги.json` — Claude на ноутбуці лише для того, що без ноутбука неможливо (власник 26.10, 29.10); копії й слота нема, наряд — хмарній сесії. Для `автоперевірка-*` рядок не будить: ланцюг сам знімає позначку й дає іншого рецензента |
| `NO_TASK_FILE` | на коміті позначки нема `аудит/наряди/<наряд>.md` |
| `MODEL_INVALID` | `claude` не прийняв модель (`There's an issue with the selected model`) |
| `EFFORT_INVALID` | `claude` не прийняв зусилля (`Unknown --effort value` — він узяв би типове; це підміна, процес зупинено) |
| `ENGINE_MISSING` | `claude` не знайдено |
| `HANG` | завислість (вище) |
| `AUTH` / `QUOTA` | вхід Claude (`Not logged in`, 401) / ліміт понад 5 повернень у чергу (`usage limit`, 429, `overloaded`) |
| `QUOTA0_CLAUDE_M<хв>` | ліміт Claude: позначка чекає скидання (хв), потім її візьме ця ж смуга — нової позначки не треба |
| `EXIT` | `claude` вийшов з помилкою без звіту |
| `NO_PUSH` / `BAD_BRANCH` | звіт ГОТОВО, а SHA на `origin` інший / гілка не `claude/…` |
| `BLOCKED` | звіт сесії `НОУТБУК ЗАБЛОКОВАНО` (причина — у її PR чи гілці) |
| `NO_REPORT` | останній рядок відповіді — не звіт |
| `INTERRUPTED` | прохід перервано (вимкнення, зупинка задачі): наступний прохід зупиняє залишений `claude` і пише код |
| `BOOT` | позначка вимкнення вже стояла до першого проходу після ввімкнення — не вимикаю (постав `<спроба>+1`); виконана позначка після нового ввімкнення — теж один `BOOT`: ноутбук знову працює |
| `COPY_KEPT` | другий рядок після кінцевого: голова копії задачі несе коміти, яких нема на `origin`, — тека `claude-run\w\<прогін>` лишається з `kept.txt`, решта прибирається |
| `CRASH` / `LINE_REJECTED` | збій запуску `claude` / рядок не за шаблоном (тоді лише `claude-run.log`) |

- **Стан ноутбука** — тіло issue #1856, одне місце, читається одним викликом (`issue_read`). `claude-run` переписує його
  (`gh api -X PATCH`) щопроходу, не частіше за 5 хв: оновлено (UTC), фаза `claude-run`, задачі планувальника (востаннє

### Межа довіри рушія Claude

- Наряд — лише файл `аудит/наряди/<наряд>.md` з коміту позначки, що є в `origin/main`; позначка вибирає лише наряд, модель
  і спробу (перевірені шаблоном `[a-z0-9.-]`, у `claude` — окремими аргументами).
- Дозволи — класифікатор `--permission-mode auto`; обходу дозволів нема.
- Обгортка не пушить і не входить: лише `git fetch` `main` і `gemini-queue/*` з порожнім `credential.helper` і без гачків;
  позначок не пушить. Пише сесія — твоїми входами, як нинішні ноутбучні сесії; ширшого доступу, ніж у них, нема.
- Хто ставить позначку: будь-хто з правом пуш у репозиторій — акаунт `mightyrochy` (сесії Claude й Codex пишуть з нього);
  коміт позначки має бути в `main`, тобто наряд пройшов злиття диспетчером.
- До диспетчера — лише обчислене: SHA з `origin`, код, назва моделі з позначки; тексту сесії в рядку нема.

## Тека вихідних і квота (М.9-А)

**Тека вихідних** — `%USERPROFILE%\gemini-outbox` (поруч із `gemini-publish`, у профілі власника; не `C:\Users\Public`).
Один файл — один рядок, UTF-8 без BOM, ім'я `<yyyyMMdd-HHmmss>-<12 hex>.txt`. Писати лише так: тимчасове ім'я з крапкою
спереду, потім перейменування:

```powershell
$n = '{0}-{1}.txt' -f (Get-Date -Format 'yyyyMMdd-HHmmss'), ([guid]::NewGuid().ToString('N').Substring(0,12))
$f = Join-Path "$env:USERPROFILE\gemini-outbox" $n
[IO.File]::WriteAllText("$f.tmp", "$line`n", (New-Object Text.UTF8Encoding $false)); Rename-Item "$f.tmp" $n
```

`gemini-publish` щохвилини доставляє файли через `claude -p --cloud` (3 спроби за прохід, до 60 за все; стан
«надіслано / спроби» — `state\o-<id>.json`) і переносить у `done\`. Пересилається лише рядок, що повністю збігся з
шаблоном (мітка великими літерами; гілка й наряд — за `SlugPattern` обгортки; код — `[A-Z0-9_]{2,40}`):
`GEMINI ОБГОРТКА: ГОТОВО <гілка> <SHA40>( КВОТА <ГРУПА> <0-100>)?`, `GEMINI ОБГОРТКА: ЗАБЛОКОВАНО <гілка> <КОД>`, `GEMINI ОБГОРТКА: ВИМКНЕНО <SHA40>`, `СПОСТЕРІГАЧ КОМЕНТАР|CI|ПЕРЕНЕСЕНО|НЕ ПЕРЕНЕСЕНО …`. Інше йде в `quarantine\`, а
диспетчер бачить лише `GEMINI ОБГОРТКА: КАРАНТИН ВИХІДНИХ <id> <код>` (до 3 на добу; тексту файлу там нема).

Кінець прогону обгортка пише в теку сама: `ГОТОВО <гілка> <SHA>` для опублікованого, інакше
`ЗАБЛОКОВАНО <гілка> <КОД>` (`NOT_FF`, `PUSH_FAILED`, `NO_REPORT`, `MODEL_INVALID`, `INTERRUPTED_PUBLISHED`, `QUOTA`, `EFFORT_INVALID`, `STALL`, `ISOLATION_FAILED`, `STATE_INVALID` — для двох останніх гілка `gemini/невідомо` —, …).

**Квота.** Перед нарядом `gemini-run` викликає `agy -p "/usage"` (0 ходів; безпечність і версійна брама — розділ «Пули й каскад» нижче). Група моделі наряду з 0 % —
наряд не береться, диспетчер отримує `ЗАБЛОКОВАНО <гілка> QUOTA0_<ГРУПА>_M<хв до скидання>`; позначка чекає скидання
(`WAIT` у стані), після нього її бере та сама смуга, нової позначки не треба, спроба не спалена. Залишок групи після прогону — суфікс ` КВОТА <ГРУПА> <0-100>` рядка ГОТОВО й `publish.log`. Не розібрали вивід чи `agy` не відповів —
наряд іде, початок виводу — в `wrapper.log`.

## Тривоги, запасний канал і свіжість

`wrapper_health.ps1` — спільний модуль обох планувальників і публікатора, поруч із кожною копією скриптів, під SHA-256.
Під час оновлення разом із файлами М.9-Е копіюється й цей модуль; кроки `m9v/0_власник.ps1` і `1_адмін.ps1` перевіряють
його хеш. Робочі копії агента не виконуються під власником; права ProgramData та перевірки публікації зберігаються.

Службовий рядок: `GEMINI ОБГОРТКА: ТРИВОГА <КОД> <ДЕТАЛЬ>`. Допустимі пари: `AUTH AGY|CODEX|CLAUDE|CLOUD`,
`ISOLATION WHOAMI|NET_SESSION|PROFILES|DRIVES|ENV`, `DISK FULL`, `ENGINE AGY|CODEX|CLAUDE`. Деталь — перелік коду,
виводу рушія в ній немає. Gemini пише їх у `out/alerts`; власник читає лише файли за форматом і заново перевіряє пару; позначку прийняття зберігає у себе, теку обміну не змінює.
Повтор пари — після 3600 секунд, збережених у файлі UTC, також після перезапуску й між паралельними процесами.

`gemini_publish.ps1`: тільки булеве `"ok":true` з кодом виходу 0 підтверджує Claude. Без підтвердження 10 хвилин від
першого очікування (час збережено в UTC) той самий рядок іде через `gh api POST` коментарем у #1690; 401 вмикає резерв
негайно і створює окрему тривогу `AUTH CLOUD`. Підтвердження gh — успішний код та додатний id коментаря. Текст JSON
передається stdin. Звичайний збій Claude зупиняє нові звернення до нього до наступного проходу, але не затримує готовий резерв інших рядків. Бюджети незалежні: `MaxSendAttempts` для Claude і `MaxFallbackAttempts` (12) для gh. Вичерпані спроби
лишаться в стані рядка, `publish.log` і `delivery.json`; підсумок видно в стані ноутбука. Повторний прийнятий рядок
не відправляється; мережевий збій після прийняття сервером, але до відповіді клієнту, може спричинити повтор коментаря.

Обидві задачі записують `read_utc` з `Z`; службові очікування викликають серцебиття раз на хвилину, публікація стану
в #1856 — щонайбільше раз на 4 хвилини між спробами. Вік Gemini показано окремо: робота Claude не освіжає зупиненого
джерела. Понад 5 хвилин без оновлення — стан застарів. Квота `agy` береться з JSON `command.data.groups[].buckets[]`
(`remaining_fraction`, `reset_time`, назва групи від батьківського об'єкта); час зчитування квоти окремий від heartbeat.
Старі відповіді CLI читаються сумісним розбором; нерозпізнане лишається невідомим.

Стенд: `powershell -NoProfile -ExecutionPolicy Bypass -File аудит/адаптери/gemini/перевірка/сценарії_здоровя.ps1`.
Перевірка зупинки джерела і годинного придушення пересуває час у фікстурі, реальні задачі ноутбука не зупиняє.

Після оновлення обидві задачі запускаються раз на 2 хвилини й у простої; під час довгого наряду серцебиття підтримує планувальник. Це залишає запас до межі свіжості 5 хвилин.

## Самооновлення й автоматичний наступний крок

Після злиття цієї зміни сесія застосування під обліковим записом власника один раз виконує
`powershell -NoProfile -ExecutionPolicy Bypass -File аудит/адаптери/gemini/m9v/3_самооновлення.ps1` із клона main.
Потрібні вже наявні права запису власника в ProgramData; підвищення прав, пароль, нові ключі й зміна ACL не потрібні.
Скрипт зберігає початкові файли як `.before-update`, ставить перевірену версію та замінює чотири входи задач
малими читачами `C:\ProgramData\gemini-wrapper\active.txt`. Параметри наявних задач зберігаються.
До цього одноразового кроку старі встановлені копії самі нової можливості отримати не можуть.

Щохвилинний gemini-publish після fetch бере лише повний SHA `origin/main`, створює git archive з LF,
звіряє кожен виконуваний файл із `m9v/хеші.psd1`, запускає `wrapper_probe.ps1` окремим процесом і ще раз звіряє
байти. Кандидат та версії лежать під захищеним коренем: gemini має лише RX. Інші групи з правами запису та
reparse point — відмова. Проба перевіряє синтаксис усіх модулів і розбір позначки/автонарядів без мережі й GPU;
це дим, повні стенди лишаються в CI. Лише успіх перемикає pointer атомарним File.Replace. Живі процеси
продовжують читати власну попередню теку версії. Головні цикли claude-run і gemini-run перед кожним проходом звіряють `active.txt` зі своєю текою
(`Get-VersionSwitch`): інша версія — чистий вихід без нових позначок, наряди доробляють окремими процесами під
замками слотів, нову версію запускає планувальник за 2 хв; журнал і рядок #1856 — «версія: <стара> → <нова>». Попередні версії автоматично не видаляються.
Незмінне дерево обгортки не створює ще одну копію через сторонній коміт main.

Успіх: `GEMINI ОБГОРТКА: ОНОВЛЕНО <SHA40> СЕКУНД <N>`; N — секунди від часу останнього коміту першого батьківського ланцюга origin/main,
який змінив обгортку (не вимір точної миті натискання Merge у GitHub). Відмова: `ОНОВЛЕННЯ <SHA> UPDATE_<КОД>`;
старий pointer лишається. Повтор тієї самої відмови не дублює рядок. Встановлені копії й задачі сесія під gemini
не змінює; одноразовий крок виконує сесія застосування під власником після незалежної перевірки латок.

`ланцюг.json` читається тільки з origin/main. Підтверджений результат DONE публікатора зберігає квитанцію
створення PR-чернетки; збій gh не губить її. Наступний прохід створює чернетку з повідомлення останнього коміту
або знаходить уже створену. Спецзгадка легасі-Codex з повідомлення не переноситься. Native Claude вже створює свій PR.
Живий відкритий PR рушія власника з цього самого репозиторію на main отримує позначку перевірки конкретного SHA:
`автоперевірка-<PR>-<SHA40>`. Для Claude — GPT, для codex — Claude, для Gemini з невідомим каскадом — обидва:
назва гілки не доводить, який постачальник фактично виконав наряд. Автозвіти виключено, циклу перевірок немає.
Чужий автор, форк, інша база й некоректна назва відкидаються. Перевіряються всі сторінки API.
PR із `[НЕ ЗЛИВАТИ]` у назві пропускається. Документний PR — лише `аудит/` поза `аудит/адаптери/`
й `аудит/проби/` — теж не отримує автоперевірки. Повний список змінених файлів читається через REST
`pulls/<PR>/files?per_page=100&page=<N>`; при перейменуванні враховується і попередній шлях.
Збій будь-якої сторінки або порожня відповідь не записується як виконана перевірка: наступний прохід повторює читання.

`review_hours` у `ланцюг.json` — ціле число 1–168, типово 24; у старому конфігу без поля також 24.
Перший прохід нової версії зберігає `installed_utc` і базову лінію `heads` у `chain.json`,
не ставлячи перевірок на весь старий архів. PR допускається, якщо створений після цієї межі,
його SHA змінився після вже збереженого знімка або час committer точного SHA потрапляє у
включне UTC-вікно `[зараз − review_hours, зараз]`. `updated_at` PR не використовується: його змінюють і коментарі.
Початкове рішення зберігається з SHA, а зміна голови відкриває нову перевірку. Втрата локального стану
починає нову базову лінію; сталі віддалені позначки та lease захищають від повторного запуску старих спроб.

У вільному слоті безпосередньо перед моделлю процес наряду звіряє `автоперевірка-<PR>-<SHA40>` через
публічний GET `/repos/mightyrochy/kod-shi-data/pulls/<PR>` без входу й нових секретів. Планувальники
не роблять REST-запитів під час обходу черги: вимкнена смуга, зайняті слоти й незавершений WAIT не витрачають їх.
PR закритий, SHA змінився, автор/база/репозиторій не відповідають договору або гілка є автозвітом —
`DONE … STALE` і один `GEMINI ОБГОРТКА: ЗАБЛОКОВАНО <гілка> STALE`, без моделі.
Це стосується й уже поставлених позначок. До постановки кожен прохід ланцюга знімає з `origin` позначки
`автоперевірка-*`, яких смуги не мають брати (`Remove-DeadReviewMarkers`): PR не відкритий чи не перевіряється, голова
змінилась, PR без коду, друга позначка тієї самої голови (лишається одна — постачальника не на квоті); зняття — під
lease на SHA позначки, кожне — рядок `publish.log` «ланцюг: <позначка> знято — <причина>».

`review-api.json` та `review-api.lock` у спільному `$LaneDir` обмежують усі три смуги сукупно
30 запитами за рухомі 3600 секунд. Запит резервується під файловим замком до мережі; збій і перезапуск
не обнуляють витраченого бюджету. Успішний LIVE не кешується: кожен запуск перевіряє свіжий стан.
Нема доступу до замка, пошкоджений бюджет, мережевий збій, 403/429, неповна відповідь чи вичерпана межа —
`REVIEW_API` і повернення в WAIT на 120 секунд без збільшення retakes, кінцевого звіту чи виклику моделі.
Мережева відмова також ставить спільну паузу 120 секунд. Голова продовження Codex/agy зберігається.
Нових секретів, ACL і встановлених копій ця зміна не потребує.

Закриття PR після останньої звірки не перериває вже запущений прогін. Давність обмежує нову постановку;
наявна позначка відкритого PR з тим самим SHA сама лише через сплив 24 годин не скасовується.

Автоживий ставиться за новим штампом `build.txt` (40 hex SHA джерел), коли збірка вже з'явилася в main.
Злиття коду без нового штампу чекає. Ланцюг переглядає коміти першого батьківського ланцюга між проходами:
ключ позначки — штамп, ref — перший коміт main із цим штампом, навіть якщо після нього вже прийшла документація.
Перший запуск і перехід зі старого формату стану беруть наявний штамп як базову лінію без історичного прогону.
`live_stamps` і черга `live_pending` у `chain.json` записуються до постановки позначок; перезапуск і повтор
старого штампу не дублюють прогін. Поки моделі на локальному :1234 не видні через GET /api/v1/models,
кожна нова збірка лишається в черзі зі своїм точним SHA. Коли моделі доступні, ставиться
`автоживий-<штамп>/gpt-6.1-sol-high/1/p2-gpu`; дані наряду окремо називають SHA джерел і SHA готової збірки.
Узяття, квота та замок GPU — наявний механізм.
Доступність моделей не доводить справності Playwright чи достатності контексту: їх перевіряє сам живий наряд
після підготовки `живий-без-адміна`. Результат прогону залишається доказом, без автоматичного злиття.
Шаблони `аудит/наряди/автоперевірка.md` й `автоживий.md` постійні; довільний текст API в промпт не додається.

Сталі позначки створюються з lease «ref ще не існує», тож повтор після рестарту не перепише взяту спробу.
Рушій автоперевірки й автоживого обирається за квотами, які смуги вже ведуть: Codex — `codex` у `heartbeat.json`
(пише `gemini_run.ps1`), Claude — `quota-claude.json` (пише `claude_run.ps1`, тека `claude-run` поруч із `gemini-publish`),
`agy` — `pools.json` (пише `gemini_run.ps1`; на квоті — коли на 0 % усі групи саме обраної моделі, як
`QUOTA0_<група>` смуги: `Get-ModelGroups` у `wrapper_health.ps1`). Постачальник на квоті, коли скидання ще
попереду (скидання невідоме — година від відмови); файл не прочитано — доступний, як до цього. Рецензент PR — інший
постачальник, ніж автор, і не `claude -p` на ноутбуці (власник 26.10, 29.10): автор Claude (`claude/`, `cc-*`, `agy` з
моделлю Claude) → `agy` (`agy` у `ланцюг.json`), потім Codex; автор GPT (`codex/`, `gpt-*`) → `agy`, потім хмарний
Claude; автор Gemini чи невідомий → Codex, потім хмарний Claude. Хмарний Claude — без позначки: рядок
`GEMINI ОБГОРТКА: ПОТРІБНА ПЕРЕВІРКА CLAUDE #<PR> <SHA40>` диспетчерові (будить, один раз на голову), диспетчер запускає
хмарну сесію перевірки; чисте злиття `main` у таку голову нового рядка не дає. Обидва для автора Claude на квоті — перший
за порядком: позначка чекає скидання. `claude` у `ланцюг.json` — лише автоживий (GPU ноутбука). Позначки
`автоперевірка-*/cc-…`, що лишились від старого вибору, ланцюг знімає й ставить рецензента наново; кількість знятих за
прохід — рядок `ЗНЯТО ПОЗНАЧОК ПЕРЕВІРКИ <N>` у зведенні (не будить).
Позначка, що чекає вичерпаного постачальника, коли доступний інший, знімається (`git push origin :<ref>`) і ставиться
позначка доступного, один раз; опублікований звіт перевірки цієї голови нової позначки не породжує.
Збої ланцюга дають `GEMINI ОБГОРТКА: ЛАНЦЮГ CHAIN_<КОД>` щонайбільше раз за UTC-годину та повторюються
наступним проходом; збій не з кодом `CHAIN_*` — `CHAIN_FAILED <тип винятку> <скрипт>:<рядок>`, повний текст
винятку й стек — у `publish.log`. Самооновлення, створення PR, перевірка та постановка живого не чекають диспетчера.
Диспетчер перевіряє докази й зливає; червоний CI та договір незалежної перевірки зберігаються.
Добове мірило підтверджується окремо після застосування й одноразового встановлення; стенд з підмінами його не замінює.

Джерело контракту каталогу: [LM Studio — GET /api/v1/models](https://lmstudio.ai/docs/developer/rest/list).
Список містить доступні моделі, включно з незавантаженими; поле `key` звіряється з конфігурацією.
На 404 читається сумісний `/api/v0/models`, далі `/v1/models`; 401/403 не запускає обхід і не вимагає нового секрету.
[OpenAI-сумісний список](https://lmstudio.ai/docs/developer/openai-compat/models) може залежати від JIT,
тому він останній сумісний варіант. Вивід каталогу не є доказом достатності контексту під час живого прогону.


## Одна перевірка й спільний живий прогін

`Get-ReviewModels` вибирає одного іншого постачальника для `gemini/*`: фактичний `gpt-*`
з опублікованого стану/рядка ГОТОВО → Claude з `ланцюг.json`; Gemini/`cc-*`/невідомий → Codex.
`Get-ChainBranchWork` відкладає перевірку активної смуги: Gemini/Codex — `heartbeat.json/lanes/busy`,
Claude — зайнятий замок слота, `state/branch-<hash>.txt` та HEAD робочої копії. Відкладена голова
лишається придатною в `heads`; після кінця перевіряється один раз. Пропуск і шлях без активної
смуги видно в журналі ланцюга.
`Test-ReviewBranch` виключає `*/перевірка-*`, `*/pachka-*` й автозвіти.
Після опублікованого вердикту `Test-ReviewedMerge` порівнює повний diff проти merge-base:
чисте злиття main без зміни diff не створює нового наряду; звичайний коміт створює.
Стан старого формату відновлює fingerprint із відомого SHA для того самого PR.

`Get-LatestLivePending` згортає штампи до останньої готової збірки й журналює пропущені.
Поки активний прогін не опублікував кінець, наступна позначка не створюється; після кінця —
одна позначка останнього штампу. `chain.json` зберігає активну роботу й чергу до мережі.
Е1 бере той самий шаблон автоживого, `Get-AutoLivePlan` і замок GPU; датована позначка
не створює дубля, якщо той самий штамп уже має автоживий наряд.
План — публічний GitHub GET, PR лише `mightyrochy` з цього репозиторію, main.
Межа — `ПЕРЕВІРЕНО ЗБІРКУ: <SHA>` у звіті або штамп у назві автоживого старого формату;
нічний звіт без SHA не звужує план. Враховуються лише предки призначеної збірки.
`merge_commit_sha` PR має входити у нову збірку й не входити у вже перевірену;
час створення звіту й `merged_at` не відсікають злиття під час прогону.
Одна сцена об'єднує всі її рядки `ЖИВИЙ ПІСЛЯ:`.
CI й ноутбук запускають один повний перелік через `аудит/проби/доробка_менше_прогонів.py`:
усі shell-стенди, самостійні PowerShell-стенди, нічний стенд поза текою перевірки та хеші.
Зауваження Codex додаються до наряду перевірки через пагіновані публічні GET reviews/comments:
лише бот, відповідь чужому відкидається; збій входу повертає роботу в чекання.

`Test-DispatcherAction` — спільне рішення для хмари, повтору та резервного каналу: диспетчера будить лише закритий
перелік станів, після яких без нього нічого не зрушить: вердикти перевірки/пачки, звіти живого, ТРИВОГА, ЛАНЦЮГ і
ЗАБЛОКОВАНО з кодом, на який обгортка сама не відновлюється (невідомий код будить). Без пробудження лишаються
ЗАБЛОКОВАНО `QUOTA0_*` (позначка чекає скидання квоти, ту саму бере та сама смуга), `STALE` (PR уже закрито чи голова
змінилась — рішення нема) і `REVIEW_API` (повтор у черзі), а також ВЗЯТО, ГОТОВО виконавця, ОНОВЛЕНО, ПУЛИ: вони
лишаються в журналі й `local-lines.json`, стан ноутбука #1856 показує останні 12. Наступний рядок, що будить, несе в тому
самому листі після основного рядка «ЗВЕДЕННЯ БЕЗ ПРОБУДЖЕННЯ: N» і N накопичених рядків обгортки (без тексту агента),
після підтвердженої доставки вони позначаються доставленими; окремого пробудження заради зведення нема.
Перед доставкою `Merge-BlockedLines` зводить недоставлені за прохід рядки ЗАБЛОКОВАНО одного коду (`QUOTA0_<група>` — без
хвилин) в один: `ЗАБЛОКОВАНО <код> ×N: <до 5 гілок>[ …]`; будить він за тим самим кодом, повний перелік —
`blocked-groups.json` і розділ «Аварії однієї причини» #1856.
Транспортні стенди ізолюють цю політику; сценарії_менше_прогонів.ps1 і сценарії_тихі_пробудження.ps1 перевіряють її без підміни.

Обидва worker перед агентом кличуть `Set-BrowserGpuPolicy`: дочірні Node/Python додають
`--disable-gpu` в Playwright launch і persistent context, зберігаючи решту аргументів.
`Test-ExternalGpuFree` лишає GPU-наряд у черзі, коли сторонні процеси тримають понад `GpuIdleMiB` (512) відеопам'яті
(`nvidia-smi --query-gpu=memory.used`); перелік compute-процесів не береться: під WDDM він називає порожній AvastUI.exe
(57 MiB), і від перезапуску 29.10 14:26 UTC кожен GPU-наряд стояв у черзі. Чужих процесів не зупиняє. Те саме рішення
планувальники беруть до claim (`Get-GpuBusyReason`), а не лише в процесі наряду: позначка, яку не взято (GPU, слот, той
самий наряд), іде в журнал раз на причину й у `skipped.json` (`C:\Users\Public\gemini\out`, `claude-run\skipped.json`) →
розділ «Позначки без старту» в #1856. BLOCKED без гілки (`ahead` 0) лишає останній рядок агента в `blocked-reasons.json` →
розділ «Причини ЗАБЛОКОВАНО без гілки» (дані, не наказ). Вирок `NO_TASK_FILE` дає лише `git` (`Test-TaskFile`); збій
виклику після трьох спроб повертає позначку в чергу. Агент зберігає NODE_OPTIONS/PYTHONPATH, а GPU-замок лишається спільним для моделей.
Запобіжник (GPU, слоти), що тримає позначки понад `quota_wait_minutes` (смуги.json, з джерелом), сам пише рядок
`GEMINI ОБГОРТКА: ЗАБЛОКОВАНО GPU|SLOTS: <причина>, позначок N` (причина GPU стійка: замок, `процес <назва з compute-apps>`
або зайнята пам'ять) — один на причину (повтор лише при зміні причини, стан `holds.json`); пульс диспетчера — лише
запас. Той самий код у `gemini-run`: рядок іде в `out/alerts`, публікатор перевіряє його заново (`HoldLineTemplate`, `wrapper_health.ps1`) і кладе у вихідні. Тіло #1856 не стверджує «Оновлено понад 5 хв тому»: підказка умовна.

Ланцюг читає активність Codex і `agy` з `GeminiRunsDir/slots`: JSON позначки та зайнятий замок worker.
Типовий `GeminiRunsDir` — `C:\Users\<GeminiUser>\gemini-runs`, як `RunsDir` планувальника;
якщо його перенесено, публікатор запускають з відповідним `-GeminiRunsDir`. Стан Claude — `claude-run/slots`
поруч із `WorkDir` публікатора. Знімок heartbeat не визначає активність жодної смуги.
