# Gemini без руки — разове налаштування власника (М.2)

Після цього наряд Gemini йде сам: диспетчер ставить позначку черги, ноутбук проганяє `agy` під `gemini`, публікує гілку
`gemini/<наряд>` і пише диспетчерові рядок. Рук на прогін — 0. Час — 40–60 хв, з них ~20 — проба наприкінці.
Ноутбук має бути ввімкнений; кроки 3–5 — у «PowerShell (від імені адміністратора)» під твоїм обліковим записом.

## Як це працює (прочитати, 3 хв)

| хто | що робить | ключі |
|---|---|---|
| диспетчер (хмара) | гілка-позначка `gemini-queue/<наряд>/<модель>/<спроба>` на коміт `main`; текст наряду — `аудит/наряди/<наряд>.md` у `main` | свої |
| задача `gemini-run`, користувач `gemini`, раз на 15 хв | перевірка ізоляції → `git fetch` без входу → один наряд → `agy` до звіту (догонка тієї самої розмови) → бандл і стан у `C:\Users\Public\gemini\out\` | **нема** |
| задача `gemini-publish`, ти, раз на 1 хв | бандл → перевірки (лише `gemini/*`, без `.github/` і файлів обгортки, fast-forward) → `git push` → `claude -p … --cloud <диспетчер>` | git і Claude — твої |

Межі (18.10): повні права — лише під `gemini`; під `gemini` нема входу ні в GitHub, ні в Claude; обгортка ізоляції не
створює й не змінює. Задача під тобою з теки `gemini` лише читає файли, нічого звідти не запускає; її скрипт лежить у
твоєму профілі, а не в клоні: злиття в `main` його не міняє, оновлюєш рукою (крок 2).

## 0. Що вже має бути (перевір, 2 хв)

  `C:\Users\gemini\kod-shi-data` нема (23.10 обгортка падала з кодом 1) — під `gemini`, без входу в GitHub:

  ```powershell
  if (-not (git config --global user.email)) { git config --global user.name 'gemini'; git config --global user.email "gemini@$env:COMPUTERNAME" }
  ```
- Під тобою: `git push` у `mightyrochy/kod-shi-data` працює (так ти пушив гілки Gemini).
- `git --version` під обома — 2.30 чи новіший.

## 1. Claude CLI під тобою (5 хв; варіант В4 М.6)

## 2. Файли обгортки (5 хв)

Той самий PowerShell під тобою (не від адміністратора):

```powershell
$base = 'https://raw.githubusercontent.com/mightyrochy/kod-shi-data/main/аудит/адаптери/gemini'
$pub = "$env:USERPROFILE\gemini-publish"; New-Item -ItemType Directory -Force $pub | Out-Null
Invoke-WebRequest "$base/gemini_publish.ps1" -OutFile "$pub\gemini_publish.ps1" -UseBasicParsing
Invoke-WebRequest "$base/gemini_run.ps1" -OutFile "$env:TEMP\gemini_run.ps1" -UseBasicParsing
Get-FileHash "$pub\gemini_publish.ps1", "$env:TEMP\gemini_run.ps1" | Format-List Hash, Path
```

Хеші мають збігтися з таблицею внизу цього файлу (у PR — так само). Не збіглися — зупинись і напиши диспетчерові.
Оновлення обгортки згодом — той самий крок і крок 3 (копія `gemini_run.ps1`).

## 3. Тека обгортки `gemini` лише для читання (5 хв, від адміністратора)

`gemini` запускає свою копію, але змінити її не може — інакше агент міг би вимкнути межі часу.

```powershell
$run = 'C:\ProgramData\gemini-wrapper'
New-Item -ItemType Directory -Force $run | Out-Null
Copy-Item "$env:TEMP\gemini_run.ps1" "$run\gemini_run.ps1" -Force
icacls $run /inheritance:r /grant:r "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F" "${env:USERNAME}:(OI)(CI)F" "gemini:(OI)(CI)RX"
```

Теку обміну `C:\Users\Public\gemini\out` створить сама обгортка під `gemini` (крок 4) — тоді вона її власниця.

## 4. Перевірка під `gemini` (10 хв)

Зміна користувача (Win+L → `gemini`; так, як ти робив 19.10), звичайний PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\ProgramData\gemini-wrapper\gemini_run.ps1
Get-Content C:\Users\Public\gemini\out\heartbeat.json      # має бути "isolation":"OK"
Add-Content C:\ProgramData\gemini-wrapper\gemini_run.ps1 '#' # має бути відмова в доступі
agy models                                                  # список моделей (диспетчерові не треба — обгортка сама)
```

- `isolation` не `OK` — код скаже, що не так: `WHOAMI` (не той користувач), `NET_SESSION` (у `gemini` права
  адміністратора), `PROFILES` (бачить твій профіль), `DRIVES` (бачить інший диск), `ENV` (змінна з KEY/TOKEN/SECRET/
  PASSWORD). Виправ ізоляцію за описом 19.10, далі не йди.
- Помилка `origin клону … не https://github.com/mightyrochy/kod-shi-data` у `C:\Users\gemini\gemini-runs\wrapper.log`
  — клон не той; клон за `GEMINI.md`.
- У `gemini` нема пароля (входить без нього) — задай його тут же: Ctrl+Alt+Del → «Змінити пароль». Саме так, а не
  `net user` з твого облікового запису: скидання пароля адміністратором стирає збережений вхід `agy`.

Повернись до свого користувача й перевір, що задача під тобою прочитає теку обміну:

```powershell
Get-Content C:\Users\Public\gemini\out\heartbeat.json
```

Відмова в доступі — від адміністратора: `icacls C:\Users\Public\gemini /grant "${env:USERNAME}:(OI)(CI)RX" /T`.

## 5. Дві задачі планувальника (10 хв, від адміністратора)

```powershell
$set = @{ MultipleInstances = 'IgnoreNew'; AllowStartIfOnBatteries = $true; DontStopIfGoingOnBatteries = $true; StartWhenAvailable = $true }

# право «Вхід як пакетне завдання» для gemini: без нього задача не стартує (0x80070569); на Windows Home нема secpol.msc
$sid = ([System.Security.Principal.NTAccount]"$env:COMPUTERNAME\gemini").Translate([System.Security.Principal.SecurityIdentifier]).Value
$d = "$env:TEMP\batchright"; New-Item -ItemType Directory -Force $d | Out-Null
secedit /export /cfg "$d\cur.inf" /areas USER_RIGHTS | Out-Null
$line = Get-Content "$d\cur.inf" | Where-Object { $_ -match '^SeBatchLogonRight' }
$old = if ($line) { ($line -split '=', 2)[1].Trim() } else { '' }
$new = if (-not $old) { "*$sid" } elseif ($old -match [regex]::Escape($sid)) { $old } else { "$old,*$sid" }
'[Unicode]','Unicode=yes','[Version]','signature="$CHICAGO$"','Revision=1','[Privilege Rights]',"SeBatchLogonRight = $new" | Set-Content -Encoding Unicode "$d\new.inf"
secedit /configure /db "$d\new.sdb" /cfg "$d\new.inf" /areas USER_RIGHTS

# під gemini: раз на 15 хв, до 4 год (сама обгортка зупиняє прогін на 3 год)
$a = New-ScheduledTaskAction -Execute 'powershell.exe' -Argument '-NoProfile -NonInteractive -ExecutionPolicy Bypass -File C:\ProgramData\gemini-wrapper\gemini_run.ps1'
$t = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(2) -RepetitionInterval (New-TimeSpan -Minutes 15)
$s = New-ScheduledTaskSettingsSet @set -ExecutionTimeLimit (New-TimeSpan -Hours 4)
$c = Get-Credential -UserName "$env:COMPUTERNAME\gemini" -Message 'Пароль користувача gemini'
Register-ScheduledTask -TaskName 'gemini-run' -Action $a -Trigger $t -Settings $s -User $c.UserName -Password $c.GetNetworkCredential().Password -RunLevel Limited

# під тобою: раз на 1 хв (кінець прогону доходить за ≤ 2 хв), до 30 хв, поки ти увійшов у Windows (блокування екрана не заважає): задача з паролем
# акаунта Microsoft не приймає (0x8007052E); conhost --headless ховає вікно
$a2 = New-ScheduledTaskAction -Execute 'conhost.exe' -Argument "--headless powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File `"$env:USERPROFILE\gemini-publish\gemini_publish.ps1`""
$t2 = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(2) -RepetitionInterval (New-TimeSpan -Minutes 1)
$s2 = New-ScheduledTaskSettingsSet @set -ExecutionTimeLimit (New-TimeSpan -Minutes 30)
$p2 = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType Interactive -RunLevel Limited
Register-ScheduledTask -TaskName 'gemini-publish' -Action $a2 -Trigger $t2 -Settings $s2 -Principal $p2

Get-ScheduledTask gemini-run, gemini-publish | ForEach-Object { $_.TaskName, $_.Principal.LogonType, $_.Triggers[0].Repetition.Interval, $_.Triggers[0].Repetition.Duration }
```

Очікувано: `Password` і `Interactive`, `PT15M`/`PT5M`, тривалість порожня («безстроково»). Тривалість не порожня —
у «Планувальнику завдань» відкрий задачу → «Тригери» → «Змінити» → «протягом: Безстроково». Пароль задачі —
локальний (зберігає Windows), не секрет сесій.

## Рушії черги (М.9-В)

Рушій обирає **назва моделі в позначці** `gemini-queue/<наряд>/<модель>/<спроба>` (дозволені літери, цифри, `.`, `-`):

| модель у позначці | рушій | запуск (кожен хід — окремий процес; текст ходу — файл `turnN.md`) |
|---|---|---|
| `gpt-<модель>[-low\|-medium\|-high\|-xhigh]`, напр. `gpt-6.1-sol-high` | локальний Codex | `codex exec -C <клон> -m <модель> [-c model_reasoning_effort=<рівень>] --json -o <файл> --dangerously-bypass-approvals-and-sandbox "<прочитай файл…>"` |
| інша, напр. `gemini-3.8-flash-high` | `agy` (як було) | без змін |

Gemini CLI не ставимо (рішення диспетчера 25.10: для Google One його замінено Antigravity CLI з 18.06.2026; другий рушій Gemini — наявний `agy`).

- Codex — під тим самим ізольованим користувачем `gemini`, той самий клон, ті самі перевірки перед пушем (`gemini_publish.ps1`
  не змінювався по суті): гілка `gemini/<наряд>`, без `.github/` і `аудит/адаптери/`, fast-forward. Звіт — той самий рядок
  `НОУТБУК ГОТОВО gemini/<наряд> <SHA40>`. Догонка несе повний текст наряду (нової розмови рушій не пам'ятає).
- `--dangerously-bypass-approvals-and-sandbox` у Codex — лише тому, що ізоляція ОС (користувач без прав і входів, перевірка
  `Test-Isolation` перед кожним прогоном) уже стоїть; документація Codex дозволяє цей прапор лише в ізольованому середовищі.
- **Вибір за квотою.** Параметр `-CodexFallbackModel <gpt-модель[-зусилля]>` (за замовчуванням порожній — вимкнено): коли група
  моделі `agy` на 0 %, наряд іде в Codex з цією моделлю (`engine=codex` у стані, рядок «рушій: …» у журналі). Квоту Codex без ходу
  не прочитати, тож його 429 ловить обгортка (`QUOTA`); обидва недоступні — `QUOTA_ZERO`/`QUOTA`, позначка лишається. Моделі
  Codex — `аудит/МОДЕЛІ.md`; хмарний Codex з GitHub — лише GPT-5.6 Sol, локальний — gpt-6.1-sol чи Astra.
- Рушія нема на ноутбуці — код `ENGINE_MISSING` (рядок `ЗАБЛОКОВАНО … ENGINE_MISSING`), а не збій обгортки.
- Нові коди помилок: `QUOTA` (429, `usage limit`, `rate limit`), `AUTH` (`not logged in`, `please log in`).

### Межа довіри наряду

До сесій Claude — лише рядки, які обгортка обчислила сама: номери, SHA, стани, коди причин, адреси. Вільного тексту агента,
коментаря чи файлу — ні (урок 8940: текст агента пройшов через `models` стану). Тека вихідних — у профілі власника, не
`C:\Users\Public`: ізольовані користувачі в неї не пишуть. Пуш — лише в `refs/heads/gemini/*` і `refs/heads/codex/*`;
`.github/` і `аудит/адаптери/` у диффі — відмова, як у М.2. Нових секретів нема: `gh` і `claude` — наявні входи власника на
ноутбуці. Знахідки — `аудит/дошка/<гілка>.md`, номери — від диспетчера.

### Джерела форматів

- Codex: `exec`, `-C -m -c --json -o --dangerously-bypass-approvals-and-sandbox` — https://learn.chatgpt.com/docs/developer-commands?surface=cli .

### Тільки на ноутбуці (стенд заглушок цього не доводить)

1. Імена моделей `gpt-6.1-sol`/Astra (`аудит/МОДЕЛІ.md`) і чи приймає їх `codex exec -m`; запис `model_reasoning_effort`.
2. Події `codex exec --json`, код виходу при 429 і при виході з ChatGPT (`AUTH`); що `-o` пише лише останню відповідь.
3. Що `codex` знаходиться в PATH користувача `gemini` (після `2_під_gemini.ps1`).
4. Чи є спосіб прочитати залишок квоти Codex без ходу (тоді `Select-Engine` отримає її замість «невідомо»).

Проба Codex (крок 6): позначка `gpt-<модель>-<зусилля>` на наряді проби.

## Тека вихідних і квота (М.9-А)

**Тека вихідних** — `%USERPROFILE%\gemini-outbox` (поруч із `gemini-publish`, у профілі власника; не `C:\Users\Public`).
Один файл — один рядок, UTF-8 без BOM, ім'я `<yyyyMMdd-HHmmss>-<12 hex>.txt`. Писати лише так: тимчасове ім'я з крапкою
спереду, потім перейменування:

```powershell
$n = '{0}-{1}.txt' -f (Get-Date -Format 'yyyyMMdd-HHmmss'), ([guid]::NewGuid().ToString('N').Substring(0,12))
$f = Join-Path "$env:USERPROFILE\gemini-outbox" $n
[IO.File]::WriteAllText("$f.tmp", "$line`n", (New-Object Text.UTF8Encoding $false)); Rename-Item "$f.tmp" $n
```

`gemini-publish` щохвилини доставляє файли через `claude -p --cloud` (3 спроби за прохід, до 60 за все; стан
«надіслано / спроби» — `state\o-<id>.json`) і переносить у `done\`. Пересилається лише рядок, що повністю збігся з
шаблоном (мітка великими літерами; гілка й наряд — за `SlugPattern` обгортки; код — `[A-Z0-9_]{2,40}`):
`GEMINI ОБГОРТКА: ГОТОВО <гілка> <SHA40>( КВОТА <ГРУПА> <0-100>)?`, `GEMINI ОБГОРТКА: ЗАБЛОКОВАНО <гілка> <КОД>`, `СПОСТЕРІГАЧ КОМЕНТАР|CI|ПЕРЕНЕСЕНО|НЕ ПЕРЕНЕСЕНО …`. Інше йде в `quarantine\`, а
диспетчер бачить лише `GEMINI ОБГОРТКА: КАРАНТИН ВИХІДНИХ <id> <код>` (до 3 на добу; тексту файлу там нема).

Кінець прогону обгортка пише в теку сама: `ГОТОВО <гілка> <SHA>` для опублікованого, інакше
`ЗАБЛОКОВАНО <гілка> <КОД>` (`NOT_FF`, `PUSH_FAILED`, `NO_REPORT`, `MODEL_INVALID`, `INTERRUPTED_PUBLISHED`, `QUOTA`, `ISOLATION_FAILED`, `STATE_INVALID` — для двох останніх гілка `gemini/невідомо` —, …).

**Квота.** Перед нарядом `gemini-run` викликає `agy -p "/usage" --output-format json` (0 ходів). Група моделі наряду з 0 % —
наряд не береться, диспетчер отримує `ЗАБЛОКОВАНО <гілка> QUOTA0_<ГРУПА>_M<хв до скидання>`; позначка споживається, нову
ставить диспетчер після скидання. Залишок групи після прогону — суфікс ` КВОТА <ГРУПА> <0-100>` рядка ГОТОВО й `publish.log`. Не розібрали вивід чи `agy` не відповів —
наряд іде, початок виводу — в `wrapper.log`.

## Якщо щось не так

| видно | що це | що зробити |
|---|---|---|
| `gemini-run` стоїть на `0x41303`, у журналі задачі `2147943785` (`0x80070569`) чи «не надано тип входу» | у `gemini` нема права «Вхід як пакетне завдання» | блок права з кроку 5 (`secedit`) |
| `gemini-publish`: `0x8007052E` | задача з паролем акаунта Microsoft | реєстрація `gemini-publish` з кроку 5 (`Interactive`) |
| `gemini-run`: `1`, у `wrapper.log` «збій обгортки: git remote get-url origin -> 128 … cannot change to» | нема клону під `gemini` | клон з кроку 0 |
| рядок «agy під gemini без входу» | `agy` не бачить збереженого входу поза інтерактивним сеансом | під `gemini` один раз `agy` інтерактивно; повторюється — диспетчерові: тоді задача `gemini-run` — «Лише коли користувач увійшов» |
| `agy` не знає `--print-timeout` у режимі stream (рядок «agy закінчився з помилкою», у `agy.stderr.txt` про цей прапорець) | прапорець лише для `-p` | у дію задачі `gemini-run` дописати ` -NoPrintTimeoutFlag` |
| stream-json не працює зовсім | режим не підтримується цією версією `agy` | у дію задачі `gemini-run` дописати ` -Mode print` (кожен хід — окремий `agy -p`, догонка — `--conversation`) |
| «пуш не вдавався годину» | вийшов строк входу git (Git Credential Manager) | під тобою `git -C <твій клон> push --dry-run` і увійти; далі `powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\gemini-publish\gemini_publish.ps1" -Retry <id з рядка>` |
| рядок не дійшов, у `publish.log` `claude --cloud … ok: false` | вхід Claude CLI чи адреса диспетчера | `claude auth status`; адреса — з `аудит/СТАН.md` на `main` (обгортка читає її сама) |

Вимкнути все: `Disable-ScheduledTask gemini-run; Disable-ScheduledTask gemini-publish` (від адміністратора).
