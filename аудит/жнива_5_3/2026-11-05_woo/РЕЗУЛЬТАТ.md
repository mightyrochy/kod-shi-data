## Що змінено

- `фід_власник_кадру.доказ_варіанта` — одна точка читання доказу для двох джерел: `shopify:variant_ids` і
  `woo:variations`. Вибір варіанта — з адреси запису: `?variant=`, `?attribute_<таксономія>=<слаг>` або, для
  одноколірного Shopify (`кольорів`=1), адреса без запиту. Кадр доведено, лише якщо його прив'язані id —
  підмножина варіацій вибраного варіанта.
- Woo (`жниварка.варіанти_woo`, `власник_варіанта_woo`, `адреса_варіанта_woo`; адаптер `woo_варіанти._запис`):
  кольоровий варіант пише доказ — сирі id товару й варіацій кольору, код таксономії, слаг і кадри, прив'язані до
  цих варіацій. Головне зображення товару доказом не стає: варіація без свого зображення віддає в Store API саме
  його. Кадри сестер класу (`кадри_класу`) доказу не мають. Одноколірний Woo параметра не отримує — читається як
  доти.
- Свіжі жнива Woo: адреса кольорового факту — з `?attribute_<таксономія>=<слаг>`, як в адаптері; до того всі
  кольори товару мали адресу сторінки, і `_одна_річ` відсіювала 2 619 з 3 797 кольорів sunwin як «дубль (url…)».
  Кадри нормуються до розподілу тим самим перетворенням, що `чисті_фото` (кирилиця в імені файла — 73 кадри).
- Shopify одноколірний (`shopify_варіанти.власник_варіанта`): доказ кадрів, прив'язаних `variant_ids` до варіацій
  товару; галерея без прив'язки — невідомо; варіант без жодної прив'язки пише «невідомо».
