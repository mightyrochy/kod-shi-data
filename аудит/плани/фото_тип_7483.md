# Кодований фото-тип: план джерела для 7483

Це план до рішення менеджера, без виконання моделей і без зміни продукту чи каталогу. Підстава: #960/6249633233, варіант Б, слово власника 15.10 «1 б» щодо #1028. Кроки 2.6 (#1429) і 2.8 (#1440/#1441, пачка #1445) зливаються разом із кодованим фото-джерелом. Незалежні 2.4/2.5/2.7/2.10 вже винесено в #1446.

## Що вже виміряно

Джерело: збережені фактичні каталоги й метадані 2.6, source `26679a436025a72b0ab36fc045ce1d1922c3dd88`. Інвентар — #1429/6249701558; це читання збережених JSON, не нові жнива й не перевірка доступності URL зараз.

Унікальні байтові зображення всього корпусу поки не пораховані:9486URL не дорівнює9486новим модельним викликам.

Є616R3-mask метаданих A, ATR2088/SAM1022у галереї, але label-map кодованого типу в JSON немає. Не можна оголошувати тип фото з `ATR-reason`/`тип_запиту`: вони залежать від переданого каталожного слота. Піксельну маску можна використати як crop лише з доведеною прив’язкою до фактичного кадру; сам її запит не є класифікацією.

## Модель і місце виконання

Пропозиція: наявна локальна `qwen3-vl-8b-instruct` у LM Studio, Windows-ноутбук власника, API localhost:1234. Саме цю модель і шлях підтверджують історичний `жнива_прогін.py` та звіти; контекст16384/parallel3 — історичні налаштування, не вимога пілота. Поточний сервер, завантаження моделі та GPU не перевірялися. Ноутбук вмикає власник; команду після рішення менеджера координатор передасть через #996. Чужі GPU/проксі/моделі не чіпати.

Хмарний платний VLM API не пропонується. Хмарний ChatGPT не підміняє фото-оцінку через403; незалежні очі — ноутбук, або Claude за чинним AGENTS. Модель читає конкретні пікселі, повертає закриті коди; Python не читає назви/описи. Наявні словесні VLM-описи самі по собі не створюють нового незалежного фотокоду.

## Мінімальний договір і місце читання

Модельний JSON: `target_state` = `unique|ambiguous|not_visible`, `item_type` = один із99канонічних кодів або null, `box` = числовий bbox або null, `reason` = закритий код причини. Enum будується з єдиного канону2.6 (99типів/25слотів), а не копіюється руками в промпт чи JavaScript. Слот є похідним тієї самої таблиці. Це кандидат схеми, а не вже запущений producer.

Довірена обгортка, не модель, додає SKU, image-bytesSHA, точний sourceURL/crop, model+revision, schemaSHA, promptSHA, taxonomySHA, час і зв’язок відповіді з фактичним image-input. Каталожні назва, опис, очікуваний type/slot не подаються VLM: не можна видати відлуння каталогу за фото-факт. Не припускаємо «найбільший предмет = SKU». За кількох предметів без незалежно вказаної цілі, недоступного кадру чи неоднозначності — явний unknown із причиною; bbox без такої цілі не є доказом.

Новий namespace — `visible_item_type`; `catalog_type` зберігається окремо, конфлікт не стирається. Producer: `жнива_запис.обробити` / `жнива_збагачення.описати`; читачі: `фід_збагачення` у місцях836/872, з проекцією через `ВМ.СЛОТ_ТИПУ`. Читач приймає лише валідний код і доведений кадр/ціль, не повертає словесний fallback. Класифікація не перейменовується на числове measured; договір знання2.10 не змінює колір, склад чи метал за самим типом.

## Пілот і приймання

Спершу пропонуємо дозвіл лише на пілот, не на9486кадрів. Початкова калібровка —40цільових кадрів: актуально отримати bytes за правильними SKU/URL на ноутбуці, перевіритиSHA і запустити type-only. Неприв’язані47JPG не вважаються готовими входами. Записати wall, model usage, errors, target ambiguity, фактичні prompt/schema, queue/parallel і пам’ять. Якщо схема/модель не змінюються, ці40входять у наступні120, а не дублюються.

Приймальний пілот120:100реальних +20негативних контролів. Пропоновані неперетинні страти:30старих підтверджень,30колізій,20catalog≠photo,20multiobject/ambiguous. Каталожні дані можна використати для вибірки, але не як VLM-вхід чи очну істину. Незалежна розмітка цільового предмета потрібна до оцінювання відповіді; нерозв’язні випадки відділяються, а не насильно кодуються.

Пропоновані критерії для рішення менеджера:0помилкових прийнятих кодів;0false-confirmation у негативних/неоднозначних;≥95%coverage серед незалежно розв’язних;100%збереження старих правильних підтверджень саме в пілоті. Це не статистичне доведення99%точності всієї популяції. Недосягнення зупиняє розширення, не послаблює unknown чи критерій. Колірне мірило38/40 сюди автоматично не переноситься.

8668 не є квотою, яку треба будь-як відновити: ДО містить словесні, не прийняті очима підтвердження. Потрібен paired ledger кожного SKU: old-confirmed→новий код/unknown+reason; окремо old-correct, old-false, new-recovered. Показати фактичне **8668→T**, деTвимірюється, а не задається наперед, та N=coded+unknown із причинами. Усі втрати старих підтверджень і розбіжності — окремий очний список. Масове unknown не є дозволом на release; рішення після фактичного пілота за менеджером.

## Час, вартість і масштабування

Опублікована історія18–19.09:15.6речі/хв, тобто3.85с wall/річ, уже приparallel3; основний12405/11.74год, повтор2431/2.55год. Це повний старий pipeline, **не ETA нового type-only**, ще раз на3не ділити. Довідковий масштаб9486/15.6≈608хв не є замовленням чи оцінкою нового завдання.

Після пілота: `T = Tload + Nnew / q_wall`, деq_wallвиміряно саме для цієї схеми й фактичного parallel; dedup — за перевіреним bytesSHA+model/schema/taxonomy. Нова відповідь потрібна лише там, де немає придатного типового коду з доведеним походженням. Початковий верхній корпусA —9486URL, або9612лише якщо менеджер окремо включить колірний кадр; первинний крок не перебудовує маски/колір/каталог. Ціну API на локальному сервері не нараховують; електрика, GPU-тариф і поточна доступність невідомі, доларової суми не вигадуємо.

Після120: звіт actualq_wall/coverage/8668→T, доступні кадри/unknown причини, оцінкаNnewі ресурсу. Лише тоді окреме рішення менеджера щодо масштабу; повний прогін зараз не авторизовано й не виконується.

## Атомарний випуск

Один зафіксований набір: producer + валідатор/читач + дані з provenance +2.6+2.8. Валідація не приймає підставлений каталог/опис, чужийhash, неправильну taxonomy, неоднозначну ціль чи невідповідну схему. Докладний ledger і gate не підміняють фото-очі. Точкові сімейні/каталожні мірило/0.2 на фактичному остаточному артефакті та exact-headCI — один раз за звичайними правилами; прийнятий старий код/архів/композицію наново не оглядають.7483закривається лише за фактичним джерелом і результатом, не цим планом.

Джерела чотирьох паралельних readonly-підзадач: #1429/6249701558 (корпус), #1434/6249693682 (договір), #1440/6249687004 (модель/історичний час), #1441/6249694554 (мірило). Нових модельних викликів, каталожного перерахунку, HTTP-фото чи фото-приймання не виконано.
