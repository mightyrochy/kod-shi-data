# Обгортка: залежності бандла

База: `1f1d5b4c257f1032f1feb777266878d006c3d761`.
Код змінюється лише в окремому тимчасовому дереві; у гілку подається латка.

Три початкові бандли доступні в `C:/Users/Public/gemini/out`; їхні заголовки та
`git bundle verify` у клоні виконавця — `початкові-бандли.txt`.
Кожен вимагає рівно свій `start`: `e60e6233…`, `6374e62e…`, `dfd49736…`.
Це локальні злиття гілок перевірки, а не гарантовано опублікована база.
У клоні виконавця ці об'єкти є, тому verify має код 0; історичне сховище
публікатора та його `inbox` із профілю власника під ізольованим `gemini` недоступні.
Ці результати не видаються за verify в історичному сховищі публікатора.

На локальному стенді справжні `Complete-Status` і `Publish-Bundle` відтворили
обидва механізми: приватний `start`, який уже містить злиття main, та злиття
новішого main після опублікованого `start`. В обох випадках публікатор має коміт
позначки, проте бракує виключеного коміту: verify = 1, `BUNDLE_INVALID`, гілку не
пересунуто. Точний вивід — `до.txt`. Перший випадок відповідає залежностям усіх
трьох наявних бандлів; другий перевіряє окремо гіпотезу наряду про свіжіший main.
