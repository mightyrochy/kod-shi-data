# Доробка 4: однаковий токен передумови й читача та доступ до теки .git

Повна `зміни.patch` — від `main@6278a702a55513a56646ca0ff3465dd7b0aa05eb`.
Вона включає попередні доробки; старі латки окремо не накладати.
Код змінено й перевіряється у тимчасовому дереві задачі поза репозиторієм.
У гілці немає прямих змін `.github/` або `аудит/адаптери/gemini/`.
Латку застосовує диспетчер; публікацію гілки й PR виконує обгортка.
Наряд збережено.

Windows-фікстура виконує передумову та весь виклик справжнього читача через
[WindowsIdentity.RunImpersonated](https://learn.microsoft.com/en-us/dotnet/api/system.security.principal.windowsidentity.runimpersonated?view=netframework-4.8.1).
Перед кожною файловою операцією трьох функцій читача стенд звіряє TokenId,
SID і привілеї з токеном передумови. Окреме твердження перевіряє, що читач
виконано й розбіжностей немає, навіть якщо його catch перехопив виняток.
Рядки `ACL ТОКЕН`, `ACL ЧИТАННЯ` та `ACL ЧИТАЧ` виходять у журнал
успішного CI через спільний раннер без правки workflow.

Deny ставиться явно на кожний об'єкт власної тимчасової фікстури. Це
усуває залежність від успадкування й явних дозволів дочірнього об'єкта.
У випадку батьківської теки `slots` спеціально має захищений DACL із
явними дозволами: попри це читання заборонено під токеном передумови й
читача. Діагностика читає обидва шляхи — `claude-run` і `claude-run/slots`.
Усі DACL знімаються до зміни; deny застосовується від дітей до батька,
відновлення — від батька до дітей. Змінюється лише DACL через WRITE_DAC;
SACL, власник, права робочих тек і токен процесу обгортки не змінюються.

Доведена вада читача: заборона ListDirectory для `.git` не обов'язково
забороняє пряме читання `HEAD`. GetAttributes також не доводить доступності
переліку. Старий читач у такому випадку вважав гілку активною без рядка
про недоступний стан. Тепер перед HEAD він читає перелік теки `.git`,
включно з текою, на яку вказує gitdir файла worktree. Відмова дає звичайну
перевірку голови й журнал; доступні Codex/agy далі відкладають свої голови.
