# Доробка перевірки після кінця роботи

База латки — свіжий `main`, `19624dd9e15c2ec4b2ecbe6999a18a0fd4d306bc`.
`зміни.patch` містить первісну реалізацію #2417, застосування #2423, зняття
успішного рядка «ПІДСУМОК: ✗ 0» з 3229e44a і доробку за перевіркою #2429.
Застосовує диспетчер; файли обгортки в гілці подання не змінюються.

`Get-ChainBusySlots` читає зайнятий замок та JSON слота для всіх трьох смуг.
Для Codex і agy шлях задає `GeminiRunsDir` публікатора: типово
`C:\Users\<GeminiUser>\gemini-runs`, як `RunsDir` планувальника. Для перенесеного
`RunsDir` треба передати відповідний `-GeminiRunsDir`. Для Claude збережено
`claude-run` поруч із `WorkDir`, файл гілки продовження та HEAD робочої копії.
Heartbeat не визначає активність. `heads` зберігає придатність пропущеної голови.

Джерело стану: `gemini_run.ps1:1196–1210` бере замок, записує позначку й slug у JSON;
`:1221–1227` прибирає JSON та звільняє замок. `claude_run.ps1:976–989` використовує
той самий порядок. Гілка `gemini/<slug>` — `gemini_run.ps1:524,584`.
Новий читач і місце пропуску наведені в останньому коміті з точними рядками латки.

Відтворення перевірки до правки — незмінений
`аудит/перевірки/автоперевірка-2423-3229e44aebad16c3d5f41d7b0b0404c702fec6b2/heartbeat.ps1`
на дереві 3229e44a. Його код 0 означає, що обидва дефекти відтворено.
`heartbeat-fixed.ps1` повторює цю зовнішню пробу з очікуваннями інваріанта;
`heartbeat-template.ps1` — старий синтетичний стенд без застарілих тверджень,
які вважали heartbeat джерелом активності. Реалізація функцій береться з `SourceDir`.
Оновлений основний стенд у латці містить обидва випадки для обох смуг.

Команди на чистому тимчасовому дереві `main` з LF. Для повної батареї потрібен
Git-клон зі справжнім деревом та об’єктами архівів: `сценарії_копії.ps1` перевіряє
економію місця на цьому дереві. Експорту лише теки обгортки для нього недостатньо.
Можна створити `git clone --shared --no-checkout` усередині теки задачі, викласти
через sparse-checkout `AGENTS.md`, теку обгортки та `.github/workflows/obhortka.yml`,
і перейти на зафіксований коміт бази. Для нічного стенда потрібен також
`аудит/проби/перевірити_нічний_маркер.ps1`.

```powershell
git -C <дерево-main> apply --check <ця-тека>/зміни.patch
git -C <дерево-main> apply <ця-тека>/зміни.patch
git -C <дерево-main> add аудит/адаптери/gemini
python <дерево-main>/аудит/адаптери/gemini/перевірка/перевірити_хеші.py
powershell -NoProfile -ExecutionPolicy Bypass -File <ця-тека>/heartbeat-fixed.ps1 -SourceDir <обгортка-з-латкою> -Template <ця-тека>/heartbeat-template.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File <обгортка-з-латкою>/перевірка/сценарії_кінець_роботи.ps1 -SourceDir <вихідна-обгортка-main> -Before
powershell -NoProfile -ExecutionPolicy Bypass -File <обгортка-з-латкою>/перевірка/сценарії_кінець_роботи.ps1 -SourceDir <обгортка-з-латкою>
python аудит/проби/доробка_менше_прогонів.py --дерево <дерево-main-з-латкою> --журнали <тека-ASCII-в-TEMP>
```

Повна батарея — 14 shell-стендів, 7 самостійних PowerShell-стендів, нічний маркер
і хеші. Команди, коди й журнали збережені поруч. Це перевірка виконавця;
добове мірило наживо після застосування диспетчером ще не виконано.

Початковий прогін збережено окремо: читач `DONE` спершу захопив службовий
JSON-масив, а стенд копій не мав повного дерева. Після виправлення читача й
підготовки shared-клону виконано повні повтори обох стендів. Зведення останніх
результатів — `результати-батареї.json`; первісні результати й повтор — окремі JSON
та журнали `сценарії_смуг.перший.log` і `сценарії_копії.перший.log`.
