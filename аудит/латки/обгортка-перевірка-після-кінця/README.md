# Доробка 3: справжня ACL-фікстура та незалежне читання слотів

Повна `зміни.patch` — від `main@744f9b8edc5176ef521d1c5d6769bc9e11be10f5`.
Вона включає попередні доробки 1–2 та нову доробку 3; старі латки окремо
не накладати. Код змінено в тимчасовому дереві поза робочим репозиторієм.
У гілці немає прямих змін `.github/` чи `аудит/адаптери/gemini/`.
Латку застосовує диспетчер; пуш і PR виконує обгортка. Наряд збережено.

Windows-фікстура встановлює deny тільки у власній тимчасовій теці. Читання
відбувається з обмеженим токеном потоку того самого користувача, створеним
через `CreateRestrictedToken(DISABLE_MAX_PRIVILEGE)`; стенд перевіряє відсутність
SeBackupPrivilege/SeRestorePrivilege. `finally` відновлює токен та ACL.
Токен процесу обгортки, робочі права й установлені копії не змінювалися.
Контракт API: [Microsoft CreateRestrictedToken](https://learn.microsoft.com/windows/win32/api/securitybaseapi/nf-securitybaseapi-createrestrictedtoken).

Стенд друкує для каталогів SID, impersonation, elevationType/elevated, перелік
привілеїв із прапорцями та фактичний результат Get-ChildItem і Directory.GetFiles
перед обмеженням токена й після нього. Спільний раннер
`аудит/проби/доробка_менше_прогонів.py` передає ці рядки в stdout також при успіху:
їх буде видно в журналі CI та GITHUB_STEP_SUMMARY без зміни workflow.

Вимір на цьому ноутбуці: вихідний токен без backup/restore, elevated=0;
Get-ChildItem по deny-каталогах дає UnauthorizedAccessException, код Windows 5.
Обмежений токен має тільки SeChangeNotifyPrivilege й також отримує відмову.
Причину відмінності саме на раннері ще не виміряно: гіпотеза про його
SeBackupPrivilege не перетворюється на висновок. Наступний CI покаже обидва
токени й результати читання; доступу до раннера ця сесія не отримувала.

`Get-ChainBusySlots` читає каталог напряму, без Test-Path, і обробляє помилки
окремого JSON/замка: відсутність допускається, інша помилка журналюється.
Справні слоти зберігаються незалежно від порядку недоступних. Branch-файл,
.git та HEAD також читаються без Test-Path; помилка обмежена одним слотом,
а не всією смугою. Для недоступного стану зберігається звичайна перевірка
голови; доступні активні смуги далі відкладають її.

Джерело зв'язку незмінне: `gemini_run.ps1:1208–1210` і
