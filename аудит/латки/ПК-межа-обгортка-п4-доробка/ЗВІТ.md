## Застосування диспетчером

`обгортка.patch` містить тільки 24 файли `аудит/адаптери/gemini/`; `.github/` не змінюється. Інші потрібні записи #2685 — дев'ять відомих рядків дошки — перенесено у фрагмент цієї гілки. Нові рядки — 12243–12245. Паспорт кореня доповнено тут окремо, тому латка його не перезаписує. Наряд кореня лишається: весь корінь ще не має 0.

```powershell
git apply --check аудит/латки/ПК-межа-обгортка-п4-доробка/обгортка.patch
git apply аудит/латки/ПК-межа-обгортка-п4-доробка/обгортка.patch
git add аудит/адаптери/gemini/
python -X utf8 аудит/проби/доробка_менше_прогонів.py --дерево . --журнали <ASCII-тека-всередині-задачі>
```

Перед стендом хешів потрібен `git add`: він читає блоби індексу. ДО виконано з початковим `core.autocrlf=true` (робочі файли CRLF, блоби LF). Для прицільних прогонів і ПІСЛЯ файли приведено до LF та задано `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=core.autocrlf`, `GIT_CONFIG_VALUE_0=false`, щоб синтетичні репозиторії відтворювали блоби без зміни завершень рядків; нормалізація незмінених файлів не додає їх до латки. `NODE_OPTIONS`/`PYTHONPATH` не змінювалися. Шлях TMPDIR має бути ASCII — це контракт заглушок `.cmd` у `середовище.sh`. Початковий запуск із кириличним TMPDIR зупинено деревом процесів і не зараховано. Жодного фонового прогону не лишено.

Латка перевірена `git apply --check` проти бази. [Скрипт відтворення](перевірити_латку.py) застосував її в окремому індексі git, звірив SHA-256 24 файлів і отримав дерево обгортки `bd67ddf6b1419864903682ec87cb7d00ce1e96e1`, тотожне дереву стендів; [вивід](відтворення.txt). `.gitattributes` зберігає точні LF-байти латки й після checkout у Windows. SHA-256: `cf64c82d540c075942546877699c34a509c445d58884f39b6ea4fda2615c5333`; точні хеші 24 файлів — [файли.json](файли.json). Вміст після повного зеленого набору звірено з цими хешами.
