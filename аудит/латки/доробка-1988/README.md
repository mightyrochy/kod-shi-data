# Доробка #1988: відсутній обліковий запис gemini

База латки — `3dd2079d6ee5c0a5ec46456fdb4afd91251cc746`, голова
`origin/claude/e0-zastosuvannia` під час виконання наряду.

Файл: `01-облік-gemini.patch`.
SHA-256: `AC76CD62F73EE1E9D8EE3CDD57BFD572E433B437E2AB1F1EF616CC6EEEF63BCB`.

Латка змінює п'ять файлів:

- `аудит/адаптери/gemini/wrapper_update.ps1`;
- `аудит/адаптери/gemini/перевірка/сценарії_самооновлення.ps1`;
- `аудит/адаптери/gemini/перевірка/сценарії_самооновлення.sh`;
- `аудит/адаптери/gemini/m9v/хеші.psd1`;
- `аудит/адаптери/gemini/НАЛАШТУВАННЯ.md`.

`Test-UpdateRoot` повертає `false`, якщо обліковий запис чи учасника ACL неможливо
перекласти в SID або ACL неможливо прочитати. `Invoke-WrapperUpdate` обробляє це
наявною відмовою `UPDATE_ACL`: чинна версія зберігається, створюється рядок тривоги.
Перелік дозволених авторів запису та заборонені права залишаються попередніми.

Параметр `GeminiIdentity` дозволяє стенду передати синтетичний SID у справжній
алгоритм ACL; робочий виклик за замовчуванням визначає локальний облік
`$GeminiUser`. Стенд перевіряє RX загальної групи, відмову запису для загальної й
невідомої груп та gemini, дозвіл запису для SYSTEM, адміністратора й власника,
відмову для неперекладних обліків і повний шлях тривоги при відсутньому обліку.
Нові облікові записи й права ОС стенд не створює.

Відбиток `wrapper_update.ps1` у маніфесті та таблиці:
`4156307A17BDAE3AF7249E532947F659E99AA1349D159239159FAE60CA7E4F2B`.

Застосування диспетчером у дереві зазначеної бази:

```bash
git apply --check /шлях/до/01-облік-gemini.patch
git apply --index /шлях/до/01-облік-gemini.patch
python3 аудит/адаптери/gemini/перевірка/перевірити_хеші.py
H=аудит/адаптери/gemini/перевірка
for f in "$H"/сценарії_*.sh; do
  bash "$H/запустити_стенд.sh" "${f##*/}" || exit 1
done
GEMINI_TEST_USER=e0-no-gemini-1988 bash "$H/запустити_стенд.sh" сценарії_самооновлення.sh
```

Середовище перевірки — Windows PowerShell 5.1 через Git Bash. На заданій базі є
11 файлів `сценарії_*.sh`; разом із перевіркою хешів це 12 перевірок. Повтор
самооновлення з неіснуючим іменем задається через `GEMINI_TEST_USER`, що передає
параметр `-GeminiUser` до стенда й публікатора. Результати та вимір ДО → ПІСЛЯ —
у [стенди.txt](стенди.txt).
