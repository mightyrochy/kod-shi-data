# Латка: сцени гілки звіту

База: `4411f70673afbfb20e780bd4f3764e830c51a582`. Латка `зміни.patch` змінює читання реєстру публікації та додає розділ 7 стенда; автоживий не змінено. Реєстр main доповнюється повними рядками, доданими гілкою проти спільної бази, з id, відсутнім у main і базі. Порожнє поле всередині повного рядка допустиме за форматом реєстру.

## Перевірка

На ноутбуці Windows PowerShell 5.1 стенд запущено на тимчасовій копії файлів обгортки і реєстру:

```powershell
& "$source/перевірка/сценарії_живий_до_pr.ps1" -SourceDir $source -Phase ПІСЛЯ
```

ДО: нова сцена гілки давала `LIVE_AFTER_INVALID` (нове твердження стенда червоне); решта тверджень зелені. ПІСЛЯ: нова сцена дійсна, відсутня й неповна недійсні, режим наявної не змінюється, зміна сцени спільної бази, видаленої з main, не повертає її; усі розділи зелені. Стенд підміняє джерело байтів git і мережу, не викликає модель чи GitHub.

Перевірка застосування з кореня базової робочої копії:

```powershell
git apply --check аудит/латки/обгортка-реєстр-сцен-гілки/зміни.patch
```

Диспетчер застосовує латку до обгортки; для повтору стенда потрібні файли обгортки, реєстр і `.github/workflows/obhortka.yml` у їхніх звичних відносних шляхах.
