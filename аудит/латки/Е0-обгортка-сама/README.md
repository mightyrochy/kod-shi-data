Захищені файли робочої гілки не змінюються; встановлені копії й задачі ноутбука не змінювалися.

  Замість початкової `01-здоровя-обгортки.patch` застосувати тутешню `00-1949-узгоджені-хеші.patch`.

Причина узгодження: початкова #1949 не застосовується після #1945 у `m9v/хеші.psd1` та `НАЛАШТУВАННЯ.md`:

в контексті обох файлів з `CEBCDD8FFEAFCDF29D9B4F5F624F00E8C8AE9A3811B49E87D3EB6B9B992C24ED`
на `3550085176F339BA00B1D1C28391AC585B0959128335D193601734261D00085B`.
Виробнича поведінка #1949 збережена. SHA-256 узгодженої латки:
`42d5ea38eb98b32c8615de1f58df93c4db066dbd1dbc6877f8f7b036587af15a`.
Дерево після залежностей: `c4ff3884ebe0dcf8a48c96b8bdc212d29e0e8c3a`.

Перед кожним застосуванням — `git apply --check`, потім `git apply --index`.
Робоча копія має LF (`core.autocrlf=false` до checkout); `.gitattributes` поруч зберігає точні байти латок.
Після залежностей застосовується `01-самооновлення-й-ланцюг.patch`. Хеші в ній перераховано для стану після всіх трьох нарядів.

Два постійні шаблони `аудит/наряди/автоперевірка.md` та `автоживий.md` доставляються звичайними файлами цього PR.
Їх треба зберегти в main перед увімкненням ланцюга. Власний одноразовий наряд Е0 прибирається після виконання.

Латки застосовує сесія Claude після перевірки іншим постачальником. Потім та сама сесія під обліковим записом
власника один раз запускає `m9v/3_самооновлення.ps1` з перевіреного main. Він використовує наявне право запису
в ProgramData, не змінює ACL чи задач і не потребує адміністратора, пароля або нового входу.
Попередні встановлені скрипти не містять механізму оновлення: без цього одноразового переходу вони не зможуть
підхопити першу версію. Далі оновлення після злиття виконує сама обгортка.

## Зміна поведінки й докази

ДО після #1945 та #1949: механізмів самооновлення й автоматичного наступного кроку — 0 і 0 (`стенди.txt`).
ПІСЛЯ: окремі версії, хеші й проба до атомарного перемикання; невдала проба чи хеш зберігають старий pointer
і дають закритий рядок тривоги. Старі процеси читають власну теку. Встановлені копії під gemini не змінювалися.

Підтверджений DONE сам породжує PR-чернетку; PR рушія — незалежну перевірку конкретного SHA;
злитий продукт — очікування живого й GPU-позначку після появи моделей. Перезапуск не дублює постановку,
новий SHA отримує нову перевірку, кілька злиттів під час очікування об’єднуються. Злиття виконує лише диспетчер.

11 стендів: **279 ✓ / 0 ✗**. Окремий перевірник: **9 хешів ✓ / 0 ✗**; маніфест = таблиця = блоби індексу з LF.
Стенди — локальні git origin та підробні CLI; перевірка алгоритму ACL використовує синтетичні правила без Set-Acl.
Дві позитивні версії й відмови хешу/проби виконано справжніми git archive, PowerShell та File.Replace.
Перший червоний прогін здоров’я й виправлений повтор збережені; причиною була відповідь фікстури на відсутній конфіг.

- `стенди.txt`, `результати.json`, `журнали/` — команди, підсумки й повний вивід усіх початкових і повторних прогонів.
- `застосування.txt` — послідовні чисті apply, відбитки файлів та точний збіг відтвореного дерева
  `a853143e2055b50614d5637af5bc0bc34112fa75`.
- `хеші.txt`, `синтаксис.txt` — незалежні від журналу стендів перевірники хешів і синтаксису.
- `моделі.txt` — HTTP 200 живого локального каталогу: обидва точні ключі й Test-LiveModels=True,
  коли Qwen не завантажена у VRAM. Моделі не завантажувалися й не вивантажувалися.

Після повторного застосування на базі ще раз пройшов m9v; зафіксовано синтаксис 20 PowerShell-файлів,
13 Bash-файлів і YAML. Суто переведення рядків незмінених файлів у власну латку не включено.

## Межі приймання

Незалежну перевірку й застосування виконує наступна сесія за нарядом, не автор цієї реалізації.
Добове мірило не видається за виконане стендом: потрібен встановлений механізм та спостереження після застосування.
Час у рядку оновлення — від останнього коміту першого батьківського ланцюга main, що змінив обгортку;
точну мить натискання Merge API не вимірює. Локальний каталог підтверджує доступ, достатність контексту й
Playwright перевіряє живий наряд після підготовки `живий-без-адміна`.

ЖИВИЙ ПІСЛЯ: доба Е0 — кожен немержевий перехід без пульсу диспетчера; новий злитий SHA обгортки
з’являється у рядку ОНОВЛЕНО без дій власника, а відмова проби лишає чинну версію.
Вад поза мірилом наряду не знайдено.
