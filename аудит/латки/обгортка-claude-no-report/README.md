## Що змінено проти спроби 3

1. **11574 (P1).** `Protect-ClaudeText` знеособлює значення секретного поля за класом: ім'я — будь-яке, що містить
   слово секрету (token, secret, password/passwd, pwd, api-key, authorization, credential, cookie, private-key), далі
   необов'язкові закривальні лапки імені, `:`/`=`, значення в `"…"`, `'…'` або до кінця рядка. Форми: JSON у лапках,
   YAML, `ключ=значення`, заголовок `Authorization: …` (і в `-H "…"`), окремий `Bearer <токен>`. Візерунки
   `SecretContentPattern` (`gemini_publish.ps1`, рядок 61) лишаються: `eyJ…`, `sk-…`, `gh?_…`, `github_pat_…`,
   `refresh_token`, приватний ключ. Знеособлення — до запису у файл, журнал і публічний стан (шлях без змін:
   `Save-ClaudeNoReport` усе тіло до обрізання хвоста, `Get-ClaudeNoReportLines` повторно).
2. **11608.** Блокер лічиться лише як `НОУТБУК ЗАБЛОКОВАНО …` — як у `main` до латки. Рядок `ЗАБЛОКОВАНО: …` без
   префікса знову дає `NO_REPORT` з публікованим хвостом, а не `BLOCKED`: наряд вимагає префікс (`Get-Prompt`), а
   вільний текст, що починається зі слова, не є каналом результату. Стенд: `блокер-без-префікса` → `NO_REPORT`.
3. Стенд `сценарії_no_report.ps1`: вісім форм секретних значень (три — з проби Codex), перевірка файлу, журналу й
