# Доробка #1969

**Наряд заблоковано:** причина збою ізоляції ENV у CI не доведена; готова латка усуває склеювання рядків Claude.

База латки: `3812283728eeed1adc39a44dd2daabb3e242d677`. Захищені файли робочої гілки не змінено.

`01-рядки-вихідних.patch` додає завершальний LF у `claude_run.ps1:148` і посилює наявну перевірку
`сценарії_claude.sh:37`: кількість LF має дорівнювати кількості файлів, крім точного набору повідомлень.
`wrapper_health.ps1:40` уже записує LF. Без виправлення конкатенація «підсумок, тривога» дає
`ENGINE_MISSINGGEMINI`, а зворотний порядок — два рядки. UUID імен файлів роблять провал випадковим;
це не доказ відмінності між CI й ноутбуком. SHA-256 Claude перераховано у маніфесті й таблиці.

```bash
git apply --check аудит/латки/доробка-1969/01-рядки-вихідних.patch
git apply --index аудит/латки/доробка-1969/01-рядки-вихідних.patch
python аудит/адаптери/gemini/перевірка/перевірити_хеші.py
```

Застосовувати в копії з `core.autocrlf=false`; власна латка містить лише LF.
Повторне застосування на чистій базі перевірено, чотири результуючі файли тотожні тестовій копії.

Другий збій, ізоляція ENV у CI, наразі не відтворено: початковий сценарій на точних LF-блобах,
Windows PowerShell 5.1 і Python 3.11.9 доставляє рівно два очікувані повідомлення та проходить старе очікування.
Окремий прогін із підміною лише Get-Date на UTC також проходить; це перевірка гіпотези про часовий пояс,
не зміна часового поясу ОС і не приймання CI. Код ізоляції та його очікування без доведеної причини не змінено.

API GitHub підтверджує failure кроків 7 і 14 job `122406308522` (run `40565717855`).
`gh run view --job 122406308522 --log` не працює без авторизації; API `/actions/jobs/122406308522/logs`
повертає HTTP 403. Журналу CI з фактичним `claude.log` у цій сесії немає; причину саме того провалу не встановлено.

Перша копія через git archive успадкувала `core.autocrlf=true`; її зелені результати не є доказом LF-прогону.
Копію перезібрано командою `git -c core.autocrlf=false archive <база>`, збережено BOM PowerShell.

Сумісність Е0: `git apply --check` для `01-самооновлення-й-ланцюг.patch` із
`origin/gemini/Е0-обгортка-сама@76776983c92338fa2d069b08bfc5d33e29230ab1` повертає 1:
конфліктують лише `m9v/хеші.psd1:1` і `НАЛАШТУВАННЯ.md:409` через змінений SHA Claude.
Диспетчерові потрібно перенести зміни Е0 й перерахувати маніфест і таблицю для сумарного дерева;
старі хеші з Е0 переносити не можна. Повний stderr — `сумісність-Е0.txt`.

На повторно застосованій латці в окремому LF-дереві Windows PowerShell 5.1 і Python 3.11.9:

| Перевірка | ✓ | ✗ | Код |
|---|---:|---:|---:|
| `сценарії_claude.sh` | 43 | 0 | 0 |
| `сценарії_m9v.sh` | 7 | 0 | 0 |
| `перевірити_хеші.py` | 6 | 0 | 0 |

Команди з кореня тимчасової копії, з `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`, `PWSH=''`,
Python 3.11.9 першим у PATH, ASCII TMPDIR і `core.autocrlf=false` для батьківського й дочірніх git:

```bash
bash аудит/адаптери/gemini/перевірка/запустити_стенд.sh сценарії_claude.sh
bash аудит/адаптери/gemini/перевірка/запустити_стенд.sh сценарії_m9v.sh
python аудит/адаптери/gemini/перевірка/перевірити_хеші.py
```

Повні журнали цих двох стендів — у `журнали/`, коди й тривалість — у `результати.json`.
Шість інших незмінених Bash-стендів після латки не запускалися: повне мірило наряду не виконано.
Сценарій ізоляції 6 на початковій версії перевірено окремо; його зелений результат не видається за
відтворення або усунення червоного CI. Потрібен журнал від диспетчера, особливо фактичний JSON-файл
`gemini-obhortka/r6/claude.log` з того виконання та значення кількості рядків у перевірці.

Нові записи дошки: 10371 — виправлення запису LF (ЧАСТКОВО до застосування),
10372 — недоведена причина провалу ізоляції (ВІДКРИТО). Наряд видалено за прямою вказівкою;
незавершену частину збережено тут, у дошці та в тілі підсумкового коміту.

Відтворення першої причини: `проба-рядка.ps1` підвантажує точний код бази або код після латки,
викликає справжні Add-Line і Add-HealthAlert в окремій теці та не запускає Main.
`до-після-рядок.json`: завершальних LF у парі файлів **[0, 1] → [1, 1]**;
конкатенація з підсумком першим дає **1 → 2** рядки. Код PowerShell в обох випадках 0;
помилка є у змісті вихідних, а не у коді завершення цієї вимірювальної проби.

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File аудит/латки/доробка-1969/проба-рядка.ps1 -InputScript <копія_бази_або_після_латки>/claude_run.ps1 -ProbeOut <нова_порожня_тека>
```
