## Дозвіл повтору: доробка З1

Джерело події — Power-Troubleshooter 1 з `SleepTime`/`WakeTime`. За нового завантаження Windows (`Win32_OperatingSystem.LastBootUpTime`) початок перерви береться з останнього heartbeat публікатора, кінець — з boot. Сама тривала пауза публікатора події сну й дозволу повтору не створює. Без доступу і до системних подій, і до часу завантаження факт переривання не доведений; автоматичного повтору немає. `SetThreadExecutionState` не додається.

Публікатор тримає `sleep-events.json` і лічильник дозволів у власному профілі. На виміряну подію він пише один рядок `GEMINI ОБГОРТКА: СОН <з UTC> → <до UTC>, нарядів N`; ключ події й стале ім’я вихідного файла зберігають дедуплікацію після перезапуску.

Спільний фінал зберігає `started_utc`, `ended_utc`, `sleep_parent`. Для сну потрібен повний перетин початку/кінця прогону з подією; для reboot — початок до boot і фінал після нього. Якщо є коміти, дозвіл видається після успішної перевірки та публікації бандла. Без нових комітів основа — наявна опублікована гілка, або `main`, якщо гілки немає. Відмова запобіжника публікації дозволу не дає.

**Перед запуском** планувальник читає дозвіл лише з `C:\ProgramData\gemini-wrapper\sleep-retry-<id>.json`, куди публікатор має наявний запис, а `gemini` — RX за кроком 3 налаштування. Публікатор перед записом викликає чинний `Test-UpdateRoot`. Планувальник перевіряє ACL кореня й файла, їхню власність та відсутність reparse point у шляху. Власність або право запису користувача агента чи будь-якої його групи відхиляє канал; сторонній писач або власник окремого файла теж відхиляється. Нових прав, ACL чи секретів не потрібно. Для перенесеної інсталяції обидві сторони отримують однаковий `-UpdateRoot`.

`OutDir` більше не є джерелом дозволів. Перевіряються також ключ сну, точна позначка, попередній ID, кінцевий код класу переривання та опублікована голова після fetch. Успішний `DONE` повтору не підлягає. DONE → WAIT проходить один раз; звичайний планувальник бере повтор у вільний слот. Квота не стирає дозвіл сну. Повтор, перерваний знову, завершується ЗАБЛОКОВАНО. Власний запис публікатора дозволяє відновити запит після збою між публікацією і його створенням лише для того самого результату.

Самодостатню негативну пробу З1 зі звіту перевірки відтворено на старій і новій реалізаціях з підміною процесу моделі: **ДО — WAIT і 1 запуск; ПІСЛЯ — DONE і 0 запусків**. Виводи — `підробка-ДО.log`, `підробка-ПІСЛЯ.log`. У новому стенді також є підробка зі STALL, відхилення доступного агенту ACL та відмова повторювати успішний DONE навіть за наявності дозволу каналу.

Інтеграційний стенд запускається однією особою: після справжньої негативної перевірки ACL він підміняє лише межу перевірки ACL тимчасового довіреного каналу. Вибір теки, розбір дозволу, перевірка коду, перехід WAIT і планувальник виконуються справжніми функціями. Системні події, ref і процес моделі підмінені; фізичний сон та моделі не запускаються. Це не перевірка двох облікових записів установленої обгортки.

## Числа: доробка З2

Дві нові копії межі 65536 замінено режимом `Get-Line -StatusOnly`: він використовує незмінену наявну межу читача `Get-Line` з бази `main` і повертає лише розібраний стан до публікації та зміни seen. Помилка в цьому режимі не споживає повідомлення STATE_INVALID; це окремо перевіряє стенд. Захист читання недовірених результатів не послаблюється. Межу 4096 для довіреного дозволу прибрано. Довільний поріг паузи 5 прибрано разом із недоведеним висновком про сон. Суфікс із 12 hex береться регулярним виразом чинного формату `OutboxNamePattern`, без нового числового обмеження чи зрізу. Прилад і його вердикти не змінено.

Команда для обох повних обсягів: `python -X utf8 джерела/прилади/корінь_пк_межа.py --корінь <дерево> --усі`. ДО `main`: **місць: 96**; ПІСЛЯ застосування: **місць: 96**; коди обох запусків 0 (`межі.log`). У попередній спробі перевірка виміряла 96 → 101; у цій латці росту немає.

## Процесне живе мірило: доробка З3

Формат CI продуктового живого рядка вимагає ID з реєстру продуктових сцен. Для обгортки не підставляється стороння сцена й не змінюється парсер. Процесне приймання записується в README, дошці та тілі PR окремим абзацом без цього машинного префікса. Запропонований дослівний абзац для PR:

> Процесний живий вимір після встановлення: наступне відключення світла має дати один рядок СОН із правильними UTC та кількістю нарядів, один автоматичний повтор перерваних нарядів від опублікованих голів без нової позначки диспетчера, а наступне переривання повтору — ЗАБЛОКОВАНО. Доказ — журнал публікатора, heartbeat, дозвіл у ProgramData та голови повторів; до цього 12283–12284 — ЧАСТКОВО.

Цей абзац перевіряється незміненим `перевірити_тіло_pr.ps1` через `PR_BODY`; відсутність продуктового рядка дозволена його договором. Це дозволяє зафіксувати процесне приймання, але не ставить обгортку в автоматичну продуктову чергу живих сцен. Після застосування та штатного самооновлення процесне мірило має перевірити наступний фактичний цикл живлення; його ще не було в межах цього наряду.

Вад поза мірилом не знайдено. Застосування латки й живий вимір лишаються наступним кроком диспетчера; цей виконавець захищених файлів не встановлює.
