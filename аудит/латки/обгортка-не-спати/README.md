## Як відновлюється прогін

Публікатор зберігає `sleep-events.json` у власному профілі. Power-Troubleshooter 1 дає `SleepTime`/`WakeTime`; для вимкнення без події використовується останній heartbeat і час поточного завантаження Windows (`Win32_OperatingSystem.LastBootUpTime`). Навіть коротке вимкнення дає подію `heartbeat/boot`. Якщо зміни завантаження не видно, запасне джерело — понад 5 пропущених щохвилинних heartbeat; кінець такої паузи обмежено першою доступною ознакою роботи після неї, щоб уже закритий після ввімкнення наряд потрапив у вимір. Джерело записується в журнал. Пауза heartbeat без системної події чи зміни завантаження — наближена межа; сама вона не доводить фізичного сну.

На подію пишеться один рядок `GEMINI ОБГОРТКА: СОН <з UTC> → <до UTC>, нарядів N`. Стале ім'я вихідного файла й збережений ключ події захищають від дублювання при повторі проходу або перезапуску публікатора. `N` — унікальні позначки, що перетнули межу перерви, за heartbeat смуг та результатами прогонів; для зміни завантаження це прогони попередньої Windows із фіналом після boot.

Спільний фінал прогону зберігає `started_utc`, `ended_utc` і `sleep_parent`. Для точної події сну потрібен повний перетин: наряд почався не пізніше початку сну, а закінчився не раніше пробудження. При доведеній зміні завантаження початок до boot і фінал після boot також доводять переривання: це охоплює наряд, який стартував між останнім heartbeat і втратою живлення. Клас — `STALL`, `AGY_ERROR`, `BLOCKED` (у публікації отримують `_PUBLISHED`) і `INTERRUPTED` після ввімкнення. Усі його місця йдуть через одну точку `Request-SleepRetry` публікатора.

Якщо є коміти, публікатор спершу застосовує чинні перевірки й публікує бандл. Після успіху він записує у своєму профілі дозвіл і в обміні — запит повтору. Без нових комітів початком є наявна опублікована гілка, а за її відсутності — опублікований `main`. Відмова перевірок публікації дозволу не дає.

Планувальник після fetch звіряє ту саму позначку й SHA, кінець старого прогону та опубліковану голову. Він переводить DONE → WAIT; звичайний планувальник смуг бере її у вільний слот. Нова позначка диспетчера не потрібна. Дозвіл сну зберігається окремо від повторів за квотою, тому квота його не стирає. Другий перерваний прогін лишається кінцевим ЗАБЛОКОВАНО; дозвіл на його публікацію походить із власного стану публікатора, а саме поле `sleep_parent` без такого дозволу нічого не відкриває. Власний запис публікації містить ID результату: після збою між публікацією й створенням запиту його відновлює лише той самий результат, без повторного пушу.

Історичні результати без явного UTC початку/кінця не доводять перетину й автоматично не переграються. Стенд підміняє годинник, XML подій, ref та межу процесу моделі; фізичний сон ноутбука й модель у ньому не запускаються.

## Перевірено локально

Команди від кореня дерева зі застосованою латкою:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File аудит/адаптери/gemini/перевірка/сценарії_сну.ps1
python -X utf8 аудит/адаптери/gemini/перевірка/перевірити_хеші.py --диск
python -X utf8 аудит/проби/доробка_менше_прогонів.py --дерево . --журнали <тека-журналів> --лише сценарії_сну.ps1 сценарії_звіту.sh сценарії_прогону.sh сценарії_доставки.sh сценарії_кінця_позначки.ps1
```

ДО: той самий стенд із `-Before -SourceDir <незмінена-обгортка-main>`: рядків СОН 0, запитів повтору 0, STALL одразу дає ЗАБЛОКОВАНО. ПІСЛЯ: рядків СОН 1, запусків повтору 1 від опублікованої голови; другий сон — ЗАБЛОКОВАНО. Повні виводи — `стенд-ДО.log`, `стенд-ПІСЛЯ.log`; підсумки суміжних стендів — `результати.json`.

Окремий `латка-перевірка.log` підтверджує застосування латки до копії бази, побайтову відповідність шести файлів перевіреному дереву, одноразове включення стенда до CI та збіг дев'яти хешів із маніфестом і таблицею. Для побайтової звірки використано `git -c core.autocrlf=false apply`; звичайна Windows-конфігурація CRLF нормалізується при записі в git.

## Що лишається після злиття

Диспетчер застосовує латки до захищених файлів за своїм договором, потім штатне самооновлення доставляє обгортку. Рядки 12283–12284 — ЧАСТКОВО до живого виміру, який не підміняється локальним стендом.

ЖИВИЙ ПІСЛЯ: наступне відключення світла — чи є один рядок СОН з правильними UTC і N та чи перервані наряди повторилися від опублікованих голів без нової позначки диспетчера?

Вад поза мірилом не знайдено. Брак живого виміру після встановлення — залишок цього наряду, уже відображений у його двох рядках дошки.
