Кожна латка пройшла `git apply --check` у тимчасовій копії названої бази в цьому порядку;
обидва workflow розібрано PyYAML. Повторна команда: `python аудит/проби/Е1-докази/перевірити_латки.py`;
доказ — `аудит/проби/Е1-докази/латки-5.json`.
Нічний стенд — 8/8; спільні хеші — 5/5 після додавання файлів тимчасового дерева до індексу.
Команда: `powershell.exe -NoProfile -File аудит/проби/перевірити_нічний_маркер.ps1 -WrapperRoot <тека обгортки>`.

У CI кожна частина має 40 хвилин, кожен повтор сцени — 10 хвилин. Приймання бере останній датований запис
кожного id з `аудит/проби/нічні/**/повтор.json` та його `база.json`. Серія 2 доступна через `REPLAY_ARCHIVE=1`,
у блокувальний набір не входить. Порожні частини матриці мають явний порожній підсумок.
Записане підставляється на межі моделі; сторінка, воркер і міст виконуються в Chromium/Pyodide.

Відома червона звірка бази мусить мати номер дошки. Нова червона замість зеленої, зникла зелена звірка,
незавершена сцена чи таймаут — регрес. Зміна входу моделі зупиняє повтор на першому відсутньому запиті:
стенд повертає rc=3, приймання явно пише «запис застарів на виклику N» та `ЖИВИЙ ПІСЛЯ:` у підсумок CI.
Уже побачені регресії звірок цей стан не приховує. Залишок невикористаних відповідей після завершення — провал.

Старі записи мають іншу нумерацію заяв. Архівну розмітку переводять функції `мовний_шар` самого продукту;
для окремого виклику зіставляється JSON тієї самої заяви без її локального `key`. Тексти відповіді лишаються дослівними;
відповідь про іншу річ не створюється. Це перехід старого набору; нові записи зберігають повний обмін без перетворення.

Живе встановлення захищених копій і CI на навмисно зламаному PR не виконуються цими латками самі по собі.
