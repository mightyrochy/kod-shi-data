Колишню `00-1945-на-базі.patch` вилучено: вона повторювала вже встановлені зміни.
Нова 00 переносить сюди покриття шляхів з колишньої 01. Остаточний сценарний стенд зберігає
режим диму чинного main; записаний живий шлях блокує збірку й публікацію.

Повторна перевірка: `python аудит/проби/Е1-докази/перевірити_латки.py`.
Вона створює чисте тимчасове Git-дерево `origin/main`, для кожної латки виконує
`git apply --check` та `git apply`, додає захищені файли до індексу тимчасового дерева
та запускає `python аудит/адаптери/gemini/перевірка/перевірити_хеші.py`.
Перевіряються всі дев'ять хешів обгортки й десять умов нічної черги, включно зі збереженням
шляхів автоперевірки та автоживого Е0. Доказ — `аудит/проби/Е1-докази/доробка-латки.json`.

Після 02:00 UTC обгортка ставить одну позначку на добу, з окремою датованою гілкою,
звичайним слотом та замком GPU. Зміна main та перезапуск не змінюють ключ уже поставленої позначки.
Ніч читає `аудит/проби/нічний_наряд.md`; звичайні й автоматичні наряди зберігають шляхи Е0.

Приймання бере останній датований запис кожного id з `аудит/проби/нічні/**/повтор.json`
та його `база.json`. Серія 2 доступна через `REPLAY_ARCHIVE=1` як архів.
Кожна частина має 40 хвилин; один повтор сцени — 10 хвилин. Порожня частина пише `[]`.
Записані відповіді підставляються лише на межі моделі; сторінка, воркер і міст працюють у Chromium/Pyodide.

Червона звірка бази мусить мати номер дошки. Нова червона, колишня зелена, що стала червоною,
зникла зелена, незавершена сцена чи таймаут — регрес. Відома червона 10231 не блокує.
Коли опис наявної звірки змінюється, четвертий аргумент `ф` зберігає її сталу назву:
стенд друкує `ІД ЗВІРКИ:` окремо від опису. Знімок рахує ідентифікатор зі сталої назви
та номера повтору, тому старі записи сумісні. Зміна результату такої звірки й далі є регресом.
Затягування на коді базового main зберігає виправлені зелені звірки; записи з базового дерева
не зникають із перевірки, коли PR додає наступну ніч.

Зміна входу моделі зупиняє повтор на першому відсутньому запиті: стенд повертає 3,
приймання явно пише «запис застарів на виклику N» та `ЖИВИЙ ПІСЛЯ:`. Уже виявлений регрес
при цьому блокує крок. Окрема команда цього самого кроку `живий_після_CI.js` читає підсумок
та опис PR із `GITHUB_EVENT_PATH`: для застарілого запису без непорожнього рядка
`ЖИВИЙ ПІСЛЯ: <сцена> — <питання>` завершується кодом 1. Точна база й порожня частина
цього рядка не потребують. Опис PR обробляється як дані, без підстановки в shell.

Локальний браузерний доказ кроку CI: `аудит/проби/Е1-докази/перевірити_CI.py`
з аргументами `--збірка <збірка записаного концерту> --кеш <Pyodide 0.26.4> --вихід <нова тека>`.
Стенд читає текст кроку з перевірених латок та виконує його в Bash з Chromium/Pyodide.
ДО — код приймання перед перевіркою опису; ПІСЛЯ — код цілого кроку. Артефакт і кеш — передумови
кроку; збирання базового main окремим кроком job цим стендом не виконується.
Справжній GitHub CI та встановлення латок залишаються перевірці й диспетчерові.
