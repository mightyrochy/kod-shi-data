# Запасний рецензент і збереження ручних позначок

Модель автора: `gpt-6.1-sol-high`

База латки: `8cdc95bada08cda172f631fe8b19e4d4eaf73d0c` (`origin/main`).
Мірило ДО виконано на `425aa0450034f61d4e1f585b385ca5fa8fb75af7` з наряду;
дерево `аудит/адаптери/gemini/` у цих двох комітах тотожне (`git diff --exit-code`).
Модель автора підтверджена полем `model` файла `worker.json` прогону
`20261103-162852-3860263b7cc7`.

Застосовує диспетчер після огляду. У гілці виконавця захищених файлів не змінено.
Порядок: лише `01-запасний-рецензент.patch`, один раз на базі; попередніх латок не накладати.
SHA-256 латки та точний перелік восьми файлів — у `джерела-виміру.json`.
Латка містить реалізацію, опис у `НАЛАШТУВАННЯ.md`, маніфест і стенди.

Для роботи GPT першим кандидатом лишається agy. На його квоті Sol перевіряє Terra,
Terra — Sol; хмарний Claude обирається, коли обидва постачальники на квоті.
Різний effort не робить ту саму модель незалежним рецензентом.
Автор латки, застосованої Claude, визначається з рядка `Модель автора:` її README
або прийнятого ГОТОВО первісної гілки. Назва гілки застосування не підміняє автора.
Непідтверджену модель GPT конфігом не вгадуємо: на квоті agy за доступного Codex
це `CHAIN_AUTHOR`; якщо обидва постачальники на квоті, можлива хмарна перевірка.

Наявність позначки визначають віддалені refs, включно з ручними p1 без локального `seen`.
Спільний `Test-ReviewMarkerProtected` захищає TAKEN та доступні NEW/WAIT.
Застарілі голови, закриті PR та кінцеві/недоступні дублікати очищуються як раніше;
доступні незавершені позначки поточної голови залишаються.

Перелік класу за нарядом:

| місце | вирок | що перевірено й змінено |
|---|---|---|
| `Get-ReviewModels` | правлю | модель автора, Sol ↔ Terra, порядок agy → інший Codex → хмара |
| `Select-ReviewModel` | правлю | відсікання базової моделі автора незалежно від effort |
| `Request-CloudReview` | правлю | захист доступної/узятої позначки й при прямому виклику |
| `Test-CloudMove` | правлю | спільний захист до рішення про перенесення в хмару |
| `Move-BlockedMarkers` | правлю | спільний захист до створення заміни та зняття refs |
| `Remove-DeadReviewMarkers` | правлю | доступна незавершена ручна позначка не стає видаленим дублем |
| `Invoke-WrapperChain` | правлю | фактичні віддалені позначки замість лише локальної історії |
| `Test-ModelQuota`, GPU-ворота | не той клас | не змінено: це джерела доступності й допуску прогону |

Усі чотири входи захисту зняття/перенесення викликають одну функцію:
`Move-BlockedMarkers`, `Test-CloudMove`, `Request-CloudReview`, `Remove-DeadReviewMarkers`.
Входів поза цим захистом: ДО 4 → ПІСЛЯ 0 (огляд цих функцій у diff).
Визначення автора й нормалізація моделі також винесені в спільних читачів;
рішення про кандидатів приймається в `Get-ReviewModels`.

Команда кожного стенда — `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass
-File <стенд> -SourceDir <обгортка>`; для коду збірки — `-WrapperRoot <обгортка> -Phase ПІСЛЯ`.
Повні фінальні журнали та машинний підсумок — у `докази/`.
Заглушки API в двох синтетичних стендах тепер віддають список файлів для читача автора;
вибір стану, квоти та локальні refs основного мірила виконуються справжнім кодом.
Повтор позначок перевіряє числовий вибір серед недоступних дублів, доступні зберігає.

Відтворення на окремій копії дерева бази з LF:

```powershell
git -C $дерево apply --check $латка
git -C $дерево apply $латка
git -C $дерево add -- аудит/адаптери/gemini
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File "$дерево/аудит/адаптери/gemini/перевірка/сценарії_ланцюга.ps1" -SourceDir "$дерево/аудит/адаптери/gemini"
python -X utf8 "$дерево/аудит/адаптери/gemini/перевірка/перевірити_хеші.py"
```

PS1 збережені у UTF-8 BOM, як на базі, для Windows PowerShell 5.1; хеші рахуються
за точними git-блобами з LF. Байти виконуваних PS1 у фінальній латці тотожні прогону.
Перевірка дев'яти хешів і формату смуг — код 0. `git apply --check` — код 0;
після застосування всі вісім файлів побайтово збігаються з реалізацією.
