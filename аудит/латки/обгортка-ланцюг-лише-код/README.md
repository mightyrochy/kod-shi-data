# Автоперевірка коду й один автоживий на штамп

База: `main` на `76dfb40392ed9f3208f8986e1595553fd7046d45`.
Застосування виконує окрема сесія після незалежної перевірки; ця гілка містить лише латки.

| Порядок | Файл | SHA-256 байтів латки |
|---|---|---|
| 1 | `0001-ланцюг.patch` | `D4E4803A8C4FCD876BC439F38F81E679A32478990B1E46420D9A415730D37B55` |

Усі десять файлів застосовуються разом: ланцюг, передача SHA збірки в обох планувальниках,
сценарії, маніфест дев'яти хешів і його таблиця в документації. PS1 зберігають UTF-8 BOM і LF.
Локальні атрибути зберігають байти `.patch` та виключають його службові пробіли контексту з перевірки;
`git diff --check` самого застосованого коду проходить без винятків.

Скопіювати цю папку до такого самого шляху в чистому тимчасовому дереві бази.
З кореня цього дерева, у PowerShell:

```powershell
$patch = 'аудит/латки/обгортка-ланцюг-лише-код/0001-ланцюг.patch'
(Get-FileHash -Algorithm SHA256 -LiteralPath $patch).Hash
git apply --check $patch
git apply --index $patch
python аудит/адаптери/gemini/перевірка/перевірити_хеші.py
```

Перед `git apply` порівняти SHA-256 із таблицею. `--index` потрібен: перевірка хешів читає блоби індексу.
На новішій базі спочатку перевірити застосовність усієї латки; встановлені копії обгортки ці команди не змінюють.

PR із `[НЕ ЗЛИВАТИ]` пропускаються до API файлів. Решта читає всі сторінки `pulls/<PR>/files`;
лише шляхи `аудит/` поза `адаптери/` й `проби/` є документними. Перейменування враховує обидва шляхи.
Неповна чи порожня відповідь не створює позначки й не фіксує успіх: наступний прохід повторює запит.

Автоживий має ключ зі штампу `build.txt`, а ref — SHA першого коміту main, де з'явилася ця збірка.
`live_stamps` і черга `live_pending` зберігаються до постановки позначки. Кілька збірок між проходами
не губляться; повтор штампу та перезапуск не створюють дубля. Злиття джерел без нового штампу чекає.
Дані наряду розрізняють штамп джерел і SHA дерева готової збірки для живого прогону.
Перший запуск або міграція старого `chain.json` бере штамп останнього спостереженого main як базову лінію;
старе поле `pending` із довільним SHA main більше не є підставою запуску. Історичних прогонів не додає.

Мірило ДО → ПІСЛЯ й команди відтворення — у `ПЕРЕВІРКА.md` поруч.
Стенди використовують відокремлені локальні Git-репозиторії та підміни API/моделей.
Застосування до діючої обгортки й незалежна перевірка залишаються наступним кроком.
