# Робота з кодом — додаток до ролі

Читають виконавець і перевірка, коли наряд змінює або оцінює код. Процесний документний наряд цього файла,
каталогу й знімка продукту не потребує — його доказом є зміна процесу за мірилом наряду.

- Стандарт — `аудит/СТАНДАРТ_КОДУ.md`; пункти продукту — за нарядом. Правки показу лише в межах свого рядка дошки
  (п.7). Корінь із наряду — названий пункт «Корені вад» картини, не вся картина.
- Зміна AST модуля — запис у `джерела/проби/поділ_очікувані.d/рядок-<N>.txt` у тому самому PR; для функції, якої нема
  в базі (`pipeline.py@ac8c2ca`), запис зайвий: «не справдився» теж червонить CI. Перевірка дописує відсутній запис у
  найнижчій пачці зі зміною. Для історичних баз потрібен повний клон (`git fetch --unshallow`, якщо неглибокий).
- Батарея — раз до PR виконавця й раз на голові пачки, фоном до кінця (з тестом показу), без `sleep`-циклів.
  Далі — проби сім'ї виконавця; у перевірки ще сусідні сім'ї (`проби/<префікс>_*.py`, крім `pal_вердикт.py`,
  `pal_вимір.py`). Підготовка середовища — job `perevirka` у `.github/workflows/zbirka.yml`. Нема середовища —
  досить зеленого CI голови: там ті самі команди.

  ```
  cd джерела && python3 стенд_знімок.py --дим && python3 тест_живого_шляху.py && python3 тест_протоколу.py \
    && python3 прилади/розділи_гейтів.py && python3 audit_contracts.py && NODE_PATH=node_modules node тест_показу.js
  ```

Зелена батарея — дим; приймання, каталог, очі та живий прогін визначає `аудит/ПЕРЕВІРКА.md`.
