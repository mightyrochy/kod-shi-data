## 1. М.3: що досі правда, що змінилось

Досі правда (не повторюю, лише звірено):

- Застосунок Gemini: імпорт GitHub — знімок без історії й PR, запису в репозиторій нема (Д). Tasks — фоном, з
  браузером і кодом на віддаленому комп'ютері, за розкладом чи подією; GitHub не згадано, програмного запуску нема (Д).
- Antigravity `agy -p`: кешований вхід, типовий тайм-аут 5 хв (`--print-timeout`), `--continue`/`--conversation`;
  інструмент без дозволу — «soft-deny» з кодом виходу 0 (Д). Це підтверджує правило «догонка тієї самої розмови».
- Gemini CLI `gemini` зі споживчим входом Google — припинено з 18.06 (М3). Codex GitHub Action — лише ключ OpenAI API
  (Д) — заборонено («платних API і нових секретів нема»).
- Claude scheduled tasks (колишні routines) — дослідне прев'ю; тригери: розклад, API, GitHub (лише `pull_request` і
  `release`); кожна подія — нова сесія; погодинні межі, понадлімітні події відкидаються; зелений запуск не означає
  виконаної роботи (Д).
- Атомарного взяття (claim/lease) не треба: М.3 сам не знайшов доведеного дубля виконання (§3 М.3); черга одна —
  диспетчер, «ВЗЯТО» в #960.

Змінилось після М.3 (20.10):

- Координатора ChatGPT нема (власник 20.10 ~10:29, Ж): кожну задачу Codex веде окрема сесія, яку запускає власник.
  Канал #963 і сторож звітів лишились без ролі; `аудит/CHATGPT.md` ще описує координатора (прибирає М.5, #1492).
- М.4 злито (#1490): код PR більше не біжить із правом запису — непрямий шлях §7 М.3 закрито.
- Нове в документації, чого М.3 не мав: scheduled tasks Codex із тригером «активність PR у GitHub» (Д); `claude -p
  "<текст>" --cloud <id сесії>` — повідомлення в хмарну сесію Claude з будь-якої машини з входом Claude (Д);

## 2. Що кожен агент уміє тепер

### Claude (Claude Code, хмара й міст ноутбука)

- Запуск: сесію запускає власник (claude.ai/code, застосунок, `claude --cloud`) або інша сесія (`create_session`);
  scheduled task — за розкладом, API чи подією PR (Д). Модель і зусилля — явно (`CLAUDE.md` п.5).
- GitHub: читає й пише через MCP GitHub і git-проксі; ключ поза контейнером (Д); пушить свої гілки `claude/…`, PR —
  чернетки; злиття — лише диспетчер (Р, `AGENTS.md`).
- Листи: лише сесіям Claude — `send_message`, `create_trigger`+`fire_trigger` (`CLAUDE.md` п.6); події PR —
  `subscribe_pr_activity` (CI, рецензії). Писати ChatGPT чи Gemini не може: у них нема адреси (Д, Р).
- Рецензії: власної автоматичної рецензії в репозиторії нема; рецензує перевірка пачки (Р).
- Ноутбук: міст DESKTOP-6N11SA4 (запускач); хмарна сесія створювати сесії на мосту не може —
  `elevated_session_untrusted_device` (Ж 18.10, `аудит/ЗАПУСКАЧ.md`).
- Ліміти: підписка, спільна для всіх сесій і scheduled tasks (Д); скинуто 22.10 00:00 (Ж). Вікна п'ятигодинне й
  тижневе — `get_session.rate_limit_info` (Р).

## 4. Схема: хто кому що передає і де спільний стан

```text
власник ──слово──> менеджер (Claude) ──наряди `аудит/наряди/`, картина──> main
   │                                                                      │
   │ руки: запуск Codex (К2), пуш Gemini (К5), ноутбук       диспетчер (Claude): черга, «ВЗЯТО» у #960,
   │                                                         виконавці й перевірка Claude (К1)
   ▼                                                                      │
ChatGPT/Codex ──> PR codex/* (звіт у тілі) ───────┐                       │
Gemini agy ──> бандл ──> пуш власника ──> PR gemini/* ──┤<── PR claude/* ──────┘
                                                  ▼
             GitHub: PR-чернетки → пачка → перевірка → рецензія Codex (не-чернетка, К6)
                                                  ▼
             CI голови (zbirka.yml) → злиття диспетчером з повним SHA → main → зведення менеджерові
```

Спільний стан — лише в `main` і GitHub: наряди (`аудит/наряди/`), адреси й очікування (`аудит/СТАН.md`), симптоми
(дошка), результат і робоча переписка — PR, узяте — #960. Ноутбук тримає лише проміжне (бандли, логи) — те, що
власник не запушив, для решти не існує. Пам'ять сесій — не стан: губиться при передачі й стисненні (`CLAUDE.md` п.11).

**Рішення 1 — «М.1 у тіні».** Так, тінь потрібна, але не після хмарного пілоту, а зараз і вужче. Тінь — нове

команда, що будить сесію, коли завершилась (`run_in_background`). Пілот М.3 (Codex/Claude cloud, Gemini Tasks) для
цього нічого не додає.

**Рішення 2 — «А–Ж після пілоту».** Пілоту як окремого етапу не треба; кожне рішення має відповідь уже тепер:

- Б (публікація окремим сервісом) — **лише як обгортка М.2** поза ізоляцією, що пушить після роботи (дозволено словом
  18.10); окремого брокера з власним ключем — ні.
- В (програмне чекання) — **так**, це новий М.1 (рішення 1).
- Г (актуальна перевірка, новий SHA знімає допуск) — **уже діє**: злиття з `expectedHeadSha`, «голова змінилась —

- Д (сила й квота окремо для продуктів) — **так, у М.7**: застосунок, `agy` і Claude в `agy` — різні квоти (Ж 19.10);

- Ж (новий ресурс чи ключ) — **ні зараз**: усе потрібне для М.1 і М.2 є; варіанти з дією власника — §8.

**М.1 — лишити, переписати вужче, «після: —».** Ціль та сама: модель не чекає. Зміст: чекання CI голови — фонова
команда тієї сесії, що чекає (диспетчер для пачки), один раз будить її з висновком «зелений/червоний, SHA»; тінь на
трьох пачках, потім сторожі CI зникають; сторож звітів ChatGPT — прибрати. Мірило: сесій-сторожів за добу
(`list_sessions`) ДО → 0 після тіні, затримка події не гірша за сторожа. Сила — Sonnet medium, ризик Р1.

**М.2 — лишити спосіб і ціль, переписати під планувальник.** Застосунок Gemini код-виконавцем не стане (не пише в

власником — забрати бандл (`git fetch` бандла, без запуску коду з тек `gemini`), дифф без `.github/`, пуш `gemini/*` і
(К9) рядок диспетчерові. Ризик лишається Р3: межі М.3 §7 (обгортка не виконує коду агента). Потребує разового
налаштування власником — §8, В3.

## 8. Варіанти, що потребують дії власника

На рішення власника, не прохання. Ціна — дія власника й ліміт; виграш — відома втрата, яку знімає.

- **В1. Scheduled task Codex із тригером «активність PR»** (ChatGPT веб, Scheduled → подія GitHub, фільтр за міткою чи
  автором). Ціна: ~10 хв раз; «відповідний тариф» — **Н**; ліміт Codex на кожен запуск; чи пушить веб-задача код —
  **Н**, спершу одна проба на документному наряді. Виграш: наряд Codex стартує без власника — знімає простій К2
  (Ф0 — ~31 год).
- **В2. Scheduled task Claude з тригером PR** (claude.ai/code/routines, фільтр гілки `codex/` чи `gemini/`, «не
  чернетка»). Ціна: ~5 хв раз; кожна подія — нова сесія з холодним стартом; погодинні межі, понадлімітні події
  відкидаються (Д). Виграш малий: пульс і так бачить PR щогодини; має сенс лише для злиття без затримки.
- **В3. Налаштування М.2: дві задачі планувальника Windows** (під `gemini` і під власником). Ціна: 30–60 хв раз;
  пароль користувача `gemini` зберігає планувальник (локально, не секрет сесій); ноутбук має бути ввімкнений. Виграш:
  0 рук на прогін Gemini замість двох фаз — знімає простої на кшталт #1483.
- **В4. Вхід Claude CLI на ноутбуці під власником** (`claude auth login`; CLI вже є, якщо міст працює — **Н**). Ціна:
  хвилина. Виграш: обгортка В3 пише диспетчерові `claude -p "<рядок>" --cloud <id з СТАН.md>` без моделі й запускача —
  результат Gemini доходить сам (К9).
- **В5. Remote Control для `agy`** (демон під `gemini`). Ціна: на Windows автозапуск — лише встановлення
  адміністратором (Д), тобто дія власника в ізольованому профілі; рука лишається, але з телефона. Виграш: запуск і
  відповідь на питання `agy` без ноутбука поруч; без В3 — найдешевший крок.
- **В6. Перевірити статус Gemini Code Assist** (GitHub Settings → Applications: споживча чи підприємницька версія)
  і за потреби пробний PR не-чернетку з кодом і навмисною вадою HIGH. Ціна: кілька хвилин і одна проба. Виграш: знати,
  чи є друга родина рецензії; споживча й мовчить — видалити застосунок; потрібна рецензія — підписка
  Standard/Enterprise (платна, ціну не перевірено — **Н**).
- **В7. Claude Projects для диспетчера.** Ціна: доступ — поступове розгортання бети Pro/Max (**Н**, чи є в акаунті);
  проєкт «витрачає ліміт швидше» (Д); переписати роль диспетчера — велика зміна, не раніше М.7. Виграш: потоки самі
  звітують у розмову проєкту, а вона не передається — знімає адресні втрати листів (10 з 15 розкладених).
- **В8. Обмеження взаємодії GitHub** (власник 18.10) — продовжувати що 6 місяців; без нього рецензенти й сесії мусять
  розрізняти чужі коментарі самі (`AGENTS.md`, «Безпека»).
