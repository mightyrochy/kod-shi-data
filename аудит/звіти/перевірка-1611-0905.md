(«відмова / пропуск» — хибний файл / добрий.) Звичайний шлях і сусідні форми на голові — так само «відмова / пропуск»:
`git add <файл> && git commit -m x`, `git commit -m "$(cat <<'EOF' … Пам'ять … EOF )"`, `<<EOF` без лапок і `git push`
після, `<<-EOF` з табом, два heredoc у команді, `cd <дерево> && git commit -F - <<'EOF'`, heredoc без обмежника,
тут-рядок `<<< "пам'ять"`. Стенд голови `python3 аудит/проби/хук_дошка_поля.py` (після `git fetch` чотирьох голів):
**20 з 20 ✔**, зокрема 15931 а–д.

**Нова форма на звичайному шляху — 15933.** `коміти` зшиває рядки команди « ; » і розбирає `shlex` з типовим
`commenters='#'`: коментар оболонки з'їдає решту команди разом із `git commit`.

```
коміти('# коментар\ngit commit -m x', '/r')       → []     (891a319d — так само [])
коміти('git add -A # усе\ngit commit -m x', '/r') → []
                                                         голова 39c66cde    main b3fd2771
# крок 3: коміт⏎git add <файл> && git commit -m x     пропуск / пропуск   відмова / пропуск
git add -A  # усе⏎git commit -m x                     пропуск / пропуск   відмова / пропуск
# коміт і пуш⏎git commit -m x && git push …         пропуск / пропуск   відмова / пропуск
```

Коментар рядком у багаторядковій команді — звичайна форма команди сесії, а на `main` такий коміт відхилено: мовчазний
пропуск звірки на звичайному шляху, регресія проти `main`. Це друга «ДОРОБИТИ» того самого наряду (перша — 07:44, 15931),
тож за договором — **КОЛО**. Механізм спільний для 15931, 15932 і 15933: хук розбирає команду власним лексером, що не
повторює лексики bash (рядки, коментарі, лапки навколо `<<`), і кожна невідповідність дає `[]` — пропуск; `main`
помиляється в бік відмови. Рішення, як далі (консервативний запасний шлях «є `git … commit` у тексті — звіряти індекс»
замість `[]`, чи інший підхід), — диспетчерові.

хибне впізнання маркера `<<EOF` у лапках, яке прибирає справжній рядок коду. Відтворено:
