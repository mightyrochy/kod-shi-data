## 4. Спосіб: одна шина, один поштар, квитанції

### 4.1 Принципи

1. Шина одна — git у GitHub. Чого нема в git, того для інших не існує.
2. Повідомлення — не текст у чаті, а запис зі станом. Файл наряду несе зміст, позначка — адресу, рушій, модель,
   пріоритет, строк і спробу.
3. Доставляє код без моделі. Моделі не чекають, не опитують і не пересилають.
4. Кожен перехід стану лишає в шині квитанцію, видиму без пробудження сесії: ВЗЯТО, ЙДЕ, ГОТОВО чи ЗАБЛОКОВАНО.
5. Будять лише кінцеві події й тривоги — одним каналом, з повтором і запасним шляхом.
6. Лист іде прямо тому, хто діятиме. Адресу беруть за роллю з `аудит/СТАН.md` у мить надсилання.
7. Рушій обирають за видимою квотою. Квота 0 — заміна без людини.
8. Кожен збій має код і автоматичну реакцію. Мовчання — теж збій: на нього стоїть тайм-аут.

### 4.2 Формат повідомлення

- **Наряд** — `аудит/наряди/<назва>.md` у `main`, самодостатній, як зараз. Нове поле в шапці — «відповідь: <роль>» (за
  замовчуванням диспетчер). Обгортка шукає адресу цієї ролі в `аудит/СТАН.md` і нікуди інде не пише.
- **Позначка** — гілка `gemini-queue/<назва>/<рушій-модель-зусилля>/<спроба>` із пріоритетом і строком (формат задає
  М.9-Е). Створення гілки атомарне, тож дубля не буде. Ставить позначки лише диспетчер — черга одна.
- **Консультація посеред роботи** (за рішенням менеджера). Виконавець ставить позначку
  `консультація-<наряд>-<n>` на іншу родину, не більше двох на наряд, з «відповідь: виконавець #<PR>». Відповідь — гілка
  й рядок обгортки за 15–30 хв, без пересилання через третю сесію (пересилання губило листи, `AGENTS.md`).

### 4.3 Життєвий цикл і квитанції

| стан | хто пише | де | як видно з хмари | тайм-аут → реакція |
|---|---|---|---|---|
| ПОСТАВЛЕНО | диспетчер | гілка-позначка | `git ls-remote` | 10 хв без ВЗЯТО на вільному слоті → перевірити вік стану ноутбука |
| ВЗЯТО | обгортка | стан ноутбука: слот, позначка, рушій, модель, час | читання стану без пробудження | — |
| ЙДЕ | обгортка | серцебиття слота в стані щохвилини | вік стану | стан старший за 15 хв → тривога «ноутбук»; наряд довший за свою межу → зупинка, ЗАБЛОКОВАНО TIMEOUT |
| ГОТОВО / ЗАБЛОКОВАНО `<код>` | обгортка | гілка `gemini/<назва>` і рядок адресатові | рядок будить сесію | 10 хв без `ok:true` → той самий рядок коментарем у #1690 |
| ПРИЙНЯТО | диспетчер | PR-чернетка чи вердикт | PR | — |
| ЗАКРИТО | диспетчер | позначку видалено | — | — |

ВЗЯТО й ЙДЕ лише пишуть у стан і нікого не будять: рядок будить сесію, а кожне пробудження перечитує весь її контекст —
це більшість витрат (`AGENTS.md`, «Контекст»).

| ноутбук → хмарна | `claude -p --cloud`, текст stdin, мітка першою | коментар у #1690 через `gh` власника | `"ok":true` у журналі; коментар бачить пульс |

### 4.5 Оперативність: цілі

| що | зараз | ціль | чим |
|---|---|---|---|
| позначка → ВЗЯТО | ≤ 15 хв плюс черга за іншим рушієм (медіана до гілки ≤ 2 год) | ≤ 5 хв на вільному слоті | опитування ≤ 5 хв і слоти (М.9-Е) |
| кінець прогону → рядок у сесії | 2–3 хв | ≤ 2 хв; гарантовано ≤ 15 хв | повтор і запасний коментар |
| тиша ноутбука → тривога | не видно | ≤ 20 хв | стан у хмарі й перевірка віку на пульсі |
| 429 → інший рушій чи модель | не відбувається (4 доби) | ≤ 1 прохід | заміна моделі в рушії, далі — рушія |
| рядок → дія диспетчера | хвилини (рядок будить) | без змін | пульс — лише сітка безпеки, рідше |

### 4.6 Збої й автоматична реакція

| збій | як видно | реакція |
|---|---|---|
| мережа | код git чи `gh` ≠ 0 | повтор наступним проходом (уже є) |
| сон чи перезавантаження | INTERRUPTED | докат із гілки (є); ноутбук без сну — дія власника (§7) |
| квота 0 | 429, `remaining_fraction = 0` | спробу не спалювати (М.9-Е); той самий рушій іншою моделлю за таблицею заміни, інакше — інший рушій; рядок QUOTA0 з часом скидання в UTC |
| вхід рушія чи `claude` відкликано (401) | текст помилки | рядок «ТРИВОГА ВХІД <рушій>» запасним коментарем: це саме та дія, яку робить власник |
| адреса застаріла чи сесію заархівовано | `ok:false` «not found», «archived» | перечитати `аудит/СТАН.md` зі свіжого `main`, інакше — запасний коментар |
| агент завис | вік серцебиття слота більший за межу | зупинка, ЗАБЛОКОВАНО TIMEOUT, нова спроба з гілки |
| агент ЗАБЛОКОВАНО | рядок | диспетчер того ж такту: доробка тим самим рушієм або наряд іншому |
| хибний SECRET | рядок SECRET | нова спроба; повторився — знахідка на шаблони фільтра, не послаблення стелі |

### 5.2 Розподіл за квотою — правило диспетчера

1. **Черга не порожня.** На кожну вільну смугу — щонайменше одна готова позначка, інакше ліміт згорає без роботи.
   Мірило — простій смуги при порожній черзі.
2. **Порядок рушіїв для нової роботи:**
   - Codex і `agy` (спершу пул Gemini, потім «Claude and GPT»);
   - далі Claude Code на ноутбуці;
   - далі хмарний Claude (слово власника 25.10, 26.10).
3. **Квота групи нижча за 10 %** — нові позначки йдуть іншій моделі чи рушію. Час скидання — зі стану ноутбука.
4. **Перевірку робить інша родина, ніж автор.** Codex ↔ Gemini; роботу Claude перевіряють Codex або Gemini.
5. **Ліміт Claude**, спільний для всіх сесій і scheduled tasks, тримають для менеджера, диспетчера й того, що можуть
   лише Claude.

### 5.3 Квота застосунку Gemini

Програмного входу до неї нема (Д). Це остаточна відповідь, а не «знайдемо згодом». Найближче:

- **Пул Antigravity «Claude and GPT».** Opus 5.5 і Sonnet 5.5 на квоті Google (Д); використано 0 % (власник 24.10).
  - Єдиний прогін Claude через `agy` (`claude-opus-5-5-high`, 23.10 17:27) скінчився QUOTA (В), хоча 24.10 пул
    показував 0 % (власник).
  - Отже, ймовірно, моделі Claude на акаунті `gemini` недоступні, бо підписка пробна чи інша — Н. Список моделей у
    `pools.json` обгортка фільтрує, тож звідти цього не видно.
  - Перевірка — `agy models` під `gemini` (§7).
- **Colab AI через Colab MCP з відкритою вкладкою.** Проба за рішенням власника:
  1. Власник один раз відкриває в браузері ноутбука ноутбук Colab, підключений до Colab MCP, і лишає вкладку відкритою.
  2. Клієнтом MCP стає `agy` у смузі Gemini (Google → Google), не Claude і не Codex: інакше діє межа умов Google з §3.
  3. Агент виконує клітинки з `google.colab.ai`.

  Мірило: N запитів без людини за 2 год і CU до та після. Ризики:
  - закрита вкладка зупиняє смугу (це видно в стані);
  - чи вважає Google це автоматизацією акаунта — Н;
  - квота Colab AI для AI Pro не опублікована — Н.
- **Застосунок Gemini** — лише власні питання власника, не потік нарядів.
