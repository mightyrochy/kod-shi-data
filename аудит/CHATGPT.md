# Адаптер ChatGPT (Codex)

Ядро — `AGENTS.md`; договір — файл призначеної ролі. Тут лише GitHub-механіка (п.22), без координатора.

- Префікс гілки — `codex/`. Гілка, тип PR і зміст звіту — за договором ролі; створення через наявний GitHub-інструмент
  або `gh pr create --base main --draft --head <гілка> --body-file <файл>`. Для PR пачки `--draft` не додають.
  Багаторядкове тіло — файлом або структурованим аргументом. Тіло містить наряд чи посилання на нього.
- Робоча переписка, звіт виконавця з повним SHA й виправлення — у PR наряду. Для звіту менеджерові за окремим
  дорученням достатньо вказаної в ньому PR-чернетки. Новий стан — новим коментарем: правки коментарів не сповіщають.
- Канали Claude: #960 — рішення й відмітки зайнятої роботи; #963 — звіт диспетчерові; #996 — команди ноутбуку.
  У #963 лише три форми: `ДЛЯ CLAUDE: ПЕРЕВІРЕНО ПАЧКА …`, `ДЛЯ CLAUDE: РІШЕННЯ: …`,
  `ДЛЯ CLAUDE: ПРОБЛЕМА: …`. Це обгортка звіту ролі, не окрема процедура приймання.
- Команди призначеній сесії ChatGPT на ноутбуці — коментарі `НОУТБУК:` у #996; вона читає їх лише за постійним
  дорученням у своєму чаті. Сам коментар не створює сесію й не доводить доставку.
- Хмара ChatGPT отримувала 403 на фото крамниць. Потрібні фото — передати запит на очне приймання через ноутбук;
  недоступний і він — блокер адресатові ролі. Поріг приймання не змінюється через транспорт.
- Ліміт/контекст — повідомлені платформою числа чи повідомлення про вичерпання; недоступне число не оцінювати.
  Доступних інструментів постійного листування й підписки може не бути: вихід — PR і кінцева відповідь сесії,
  а не обіцянка автоматично прокинутися. Дії на ліміті — п.11 ядра.
