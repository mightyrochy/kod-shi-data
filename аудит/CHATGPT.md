# Адаптер ChatGPT (Codex)

Ядро — `AGENTS.md`; договір — файл призначеної ролі. Тут лише механіка запуску (п.22).

- Codex працює лише в хмарі: «Кодекс ми тепер даємо тільки в хмару. На ноутбуці Gemini та відеокарта» (власник 27.11) —
  позначок `gpt-…` у чергу обгортки диспетчер не ставить, смуга Codex на ноутбуці порожня. Наряд, доробку й оцінку
  прогону Codex отримує хмарною задачею (нижче); агент — виконавець за `AGENTS.md` і `аудит/ВИКОНАВЕЦЬ.md`. Модель — з
  `аудит/МОДЕЛІ.md`; розмір і вид наряду не обмежені: код, оцінка прогону (наряд зі звітом у коміті), батарея — «тут
  ніяких обмежень ні по моделях ні по розміру задач немає і бути не може» (власник 26.10). Координатора ChatGPT нема
  (власник 20.10): окрема сесія виконує призначене, не бере черги й не чекає пробуджень.
- Легасі-канал Codex заборонено, бо там доступні лише старі моделі, а хмарний Codex не заборонено: хмарна задача Codex —
  дозволений канал, коли її фактична модель — з таблиці `аудит/МОДЕЛІ.md`; модель і шлях запуску перевіряє перший наряд
  (менеджер 19.11 за словом власника 19.11). Наявні носії з міткою `codex-cloud`, їхнє продовження, зупинку, CI,
  перевірку й злиття веде диспетчер (`аудит/ДИСПЕТЧЕР.md`): роль диспетчера на стороні Codex, дану сесії «Dot» 19.11,
  знято — «Дот кодексу не справляється з роботою деспетчера» (власник 24.11). Широку роботу диспетчер дає Codex:
  «Запускай широку роботу в кодекс» (власник 24.11); хмарні задачі запускає окрема сесія Codex у ChatGPT — лише зв'язок
  і запуск: «Вчора разом працювали тимчасовий менеджер кодекс та деспетчер клод», «це не обов'язково має бути менеджер.
  Просто окрема сесія кодексу для зв'язку та запуску. Диспетчер на стороні кодекс» (власник 26.11). Диспетчер дає їй
  наряд носієм з міткою `codex-cloud` і говорить з нею текстом носія чи PR; вона запускає й супроводжує хмарні задачі, а
  CI, перевірку й злиття їхніх PR, розподіл і стан веде диспетчер. Нарядів вона не пише й не приймає. Власника про
  запуск окремої задачі не просять: «Це ручний запуск окремої роботи на кодекс, а не налаштування автоматичної
  взаємодії»; обгорткою ноутбука (`codex cloud`) задач у хмару не ставлять: «це дурна ідея» (власник 26.11).
- «@codex» у GitHub — легасі: нарядів, доробок і перевірок ним не запускають (менеджер 26.10 за словом власника 26.10);
  документація OpenAI відносить інтеграцію GitHub до «Codex Cloud (Legacy)», і проба 19.11 згадкою в issue відповіді не
  дала. Лишається рецензія PR — `аудит/ПЕРЕВІРКА.md`. Хмарну задачу запускає сесія на стороні Codex (вище).
- Команд коментарями в GitHub сесіям ChatGPT нема: коментар не створює сесію й не доводить доставку.
- Фото крамниць хмарі ChatGPT — 403: запит на очне приймання — через ноутбук; недоступний і він — блокер адресатові
  ролі. Поріг приймання транспорт не змінює.
- Вимірник ліміту й контексту — числа платформи чи її повідомлення про вичерпання.
