# Адаптер ChatGPT (Codex)

Ядро — `AGENTS.md`; договір — файл призначеної ролі. Тут лише GitHub-механіка (п.22).

- Наряд коду й доробку PR Codex запускає диспетчер без власника (власник 23.10: «Я не буду нічого робити сам»). Наряд —
  PR з гілки `codex/<наряд>` (порожній коміт від `main`; тіло — посилання на наряд із повним SHA `main`), доробка — той
  самий PR; коментар: «@codex Виконай наряд з опису PR (доробка — що виправити) за `AGENTS.md` з `main`. Пушу в тебе
  нема: кінцева відповідь — повний `git diff <SHA голови PR>` блоком diff, без скорочень, і `git hash-object` кожного
  зміненого файлу». Codex не пушить (у задачі нема `origin`, #1621), тож diff з відповіді `chatgpt-codex-connector[bot]`
  переносить сесія Claude сили «код»: U+FFFD (кирилиця ламається в дорозі, #1558) у контексті й «−» — з голови, тоді
  `git apply --3way --recount`, у «+» — за змістом, доки `git hash-object` файлів не збіжиться з відповіддю; коміт із
  посиланням на відповідь, пуш у гілку PR; далі — як PR виконавця. Година без відповіді — спершу причина за
  «Призначенням» `аудит/ДИСПЕТЧЕР.md` («взяв і мовчить» — ще не причина); не усунено чи diff не ліг — наряд бере Claude
  чи `agy` з того ж рядка `аудит/МОДЕЛІ.md`; хеш не збігся чи його нема (AST цього не доводить) — доробляє Claude, у
  коміті «дороблено Claude».
- Модель і зусилля — у кожному коментарі запуску й доробки, з `аудит/МОДЕЛІ.md` (власник 24.10: «продовжуй задавати»);
  це намір, не налаштування — там же.
- Перевірка — розділ «Наряд Codex» в описі PR, що перевіряють (SHA, ризик, пункти `аудит/ПЕРЕВІРКА.md`); коментар:
  «@codex Виконай розділ «Наряд Codex» з опису PR за `AGENTS.md` з `main`. Модель — …, зусилля — …. Пушу в тебе
  нема й правок коду не треба: кінцева відповідь — список знахідок за пунктами розділу з номерами рядків і доказом».
  Слова «перевір», «перевірка», «review», «огляд» — і в коментарі, і в тексті розділу — Codex бере як вбудований огляд
  без доказів (#1625; #1818, #1832: розділ починався з «Перевірка…») — це рецензент; розділ ставить задачу дієсловами
  «знайди», «звір», «доведи». Знову лише огляд — перевірку бере Claude чи `agy` з рядка `аудит/МОДЕЛІ.md`. Пачки він не
  збирає: за «ПЕРЕВІРЕНО» PR зливає диспетчер.
- Наряд коду — механіка з diff до ~20 КіБ (`-U1`), більший — Claude; цілість від розміру не залежить (#1650 обрізано,
  #1655 — 71 КБ цілий). Важке Codex бере й не відповідає: 3 з 4 німих запусків 25–26.10 (з 29) — перевірка PR на
  ~3,6 тис. рядків (#1773), повна батарея (#1815), доробка на ~73 КіБ (#1834); тож батарея й наряд понад межу — одразу
  Claude чи `agy` з рядка `аудит/МОДЕЛІ.md`.
- Префікс гілки — `codex/`. Гілка, тип PR і зміст звіту — за договором ролі; PR — наявним GitHub-інструментом або `gh pr
  create --base main --draft --head <гілка> --body-file <файл>` (PR пачки — без `--draft`); тіло містить наряд чи
  посилання на нього.
- Сесіям Claude Codex не пише: звіт ролі («ГОТОВО», «ПЕРЕВІРЕНО», «ЗАБЛОКОВАНО», «ЗНАХІДКА») з повним SHA, робоча
  переписка й виправлення — у своєму PR; його бачить пульс диспетчера. Новий стан — новим коментарем: правки
  коментарів не сповіщають. Підписки й самопробудження нема: вихід — PR і кінцева відповідь сесії.
- Сесія ChatGPT на ноутбуці бере команди — коментарі `НОУТБУК:` у #996 — лише за постійним дорученням власника у своєму
  чаті (власник): це виняток із «не бере черги». Сам коментар не створює сесію й не доводить доставку.
- Фото крамниць хмарі ChatGPT — 403: запит на очне приймання — через ноутбук; недоступний і він — блокер адресатові
  ролі. Поріг приймання транспорт не змінює.
- Вимірник ліміту й контексту — числа платформи чи її повідомлення про вичерпання.
