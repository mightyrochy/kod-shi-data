стан 10826: **ЧАСТКОВО** · Копія задачі — `git worktree` клону зі sparse-checkout без тек-архівів `аудит/` (від третього рівня, ≥ 8 МіБ, `Get-ArchiveDirs`). Повтор з 04.11 17:06 UTC до 19.11 (журнал обгортки): ~700 копій поспіль «тек-архівів не викладено — 0» (до того 49–56), прибрана копія в середньому 5,9 ГБ, `аудит/` живої копії 6,2 ГБ (29.10 — 247 МБ уся копія), `git reset --hard` копії — середнє за день 256–531 с, 19.11 — 836 с, до 1776 с. Причина: клон обгортки частковий, а `Get-ArchiveDirs` у частковому клоні мовчки повертав порожньо (звіт латки `обгортка-ланцюг-стан-доступ` 05.11: стенд копії в копії під `gemini` — 0 тек, з `remote.origin.promisor=false` — 53). Тепер розміри — з наявних blob-об'єктів через `--no-lazy-fetch` (без довантаження), відсутні в суму не йдуть, а рядок журналу копії каже, чому тек менше чи нема (частковий клон і скільки blob-об'єктів без розміру, код і stderr `ls-tree`, sparse-checkout, git до 2.36); стенд `сценарії_копії.ps1` має випадок часткового клону. Закриває лише живий рядок журналу з N > 0 після оновлення обгортки. <!-- дошка: механізм=інше; закриття=корінь; доказ=проба; дата-закриття=2026-11-19 -->
