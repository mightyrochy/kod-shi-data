# Проба: задача нового хмарного Codex, поставлена з ноутбука командою `codex cloud`

Виконавець — наглядова сесія ноутбука: лише там є Codex CLI із входом у ChatGPT. Уточнення 19.11 15:40 UTC: CLI
Codex стоїть у профілі обгортки, а не наглядової сесії, і та просила запуску в власника (зведення диспетчера 15:34
UTC). Власника не чекаємо: частину Codex бере Codex через чергу обгортки — його робота й є кроки 1–5 цього наряду
командами `codex cloud` у своєму профілі; позначку ставить диспетчер. Частина `agy --remote-agent` стоїть: запуск із
пропуском дозволів відхилив класифікатор, відмову не обходять. Правило — `аудит/CHATGPT.md`; картина
— `аудит/КАРТИНА.md`, §4, «Робота без ноутбука й хмарний Codex»; перша проба (згадкою в GitHub, не стартувала) —
`аудит/проби/хмарний-codex-1/ЗВІТ.md`.

**Проблема.** Наряд Codex запускає обгортка на ноутбуці, і виконується він теж там: нема світла — стоїть і запуск, і
робота. Новий хмарний Codex за документацією OpenAI запускається з застосунку ChatGPT чи з CLI (`codex cloud`: «submit
work to a configured environment», «apply the result to your local repository»). Хмарні сесії Claude цього не можуть:
CLI й входу в ChatGPT у них нема, а вхід — новий секрет (вимір диспетчера 19.11 12:13 UTC). На ноутбуці вхід уже є.
Наживо `codex cloud` у нас ніхто не запускав.

**Ціль.** Дізнатись однією справжньою задачею: чи стартує хмарна задача Codex з ноутбука, на якій моделі, чи доходить
її результат у PR без ноутбука — і що для цього бракує.

**Крок.**
1. Що вміє CLI на ноутбуці: версія, `codex cloud --help` і довідка його підкоманд — дослівно у звіт. Команди нема —
   потрібна версія й чи оновлення CLI безпечне для обгортки; оновлюєш — за своїм договором.
2. Середовища: які бачить CLI. Нема жодного для `mightyrochy/kod-shi-data` — спробуй типове (документація: «If the
   default environment is available, you can start without choosing a repository»); не виходить — точний текст відмови
   і стоп: створення середовища — дія власника в ChatGPT (Settings → Codex Cloud → Environments), просить менеджер.
3. Одна задача: частина `силует_реєстр.py` наряду `аудит/наряди/Е3-сила-правила-вага.md` (диспетчер її тримає). Текст
   задачі — файл наряду, роль ВИКОНАВЕЦЬ за `AGENTS.md` і `аудит/ВИКОНАВЕЦЬ.md`, окрема гілка й PR-чернетка в
   репозиторії, у тілі PR — модель і зусилля. Модель — найновіша Sol зі списку, якщо CLI дає вибір. Номер задачі — у
   звіт одразу.
4. Що сталось далі, без втручання: статус, час до кінця, чи задача сама запушила гілку й відкрила PR, чи результат
   лежить у хмарі й чекає `apply` на ноутбуці. Другий випадок — застосуй і опублікуй звичним шляхом обгортки, і так і
   запиши: без ноутбука результат не дійшов би.
5. PR — звичним шляхом: CI й перевірка іншим постачальником (ставить диспетчер).

**Друга задача тієї самої проби — Gemini в хмарі (додано 19.11).** За оглядами (офіційної сторінки
`antigravity.google/docs/remote-agents/` менеджер не відкривав), `agy --remote-agent` (версія від 1.4.12) ставить
задачу у хмарну машину Google у підписці Google AI Pro: репозиторій GitHub під'єднується через OAuth, задача йде далі
із закритим ноутбуком. Ті самі кроки 1–5 для `agy`: що вміє CLI (версія, довідка прапорця), чи під'єднано
репозиторій (нема — точний текст і стоп: під'єднання GitHub у Google — дія власника), одна задача на
`gemini-4-neon-high` — мала частина наряду коду в межі «малі наряди» (`аудит/МОДЕЛІ.md`), яку дасть диспетчер, — і що
сталось далі без втручання. Мірила — ті самі рядки окремим розділом звіту, пул — GEMINIMODELS до й після.

**Мірило — рядками `аудит/проби/хмарний-codex-2/ЗВІТ.md`.**
- стартувала: так / ні; час від команди до старту й до кінця; номер задачі;
- фактична модель і зусилля: що показує CLI чи сторінка задачі і що назвав Codex; не з таблиці `аудит/МОДЕЛІ.md` —
  стоп і рядок менеджерові;
- з якої квоти списалось і скільки (тижневий запас Codex до й після);
- PR: відкрив сам чи через `apply` на ноутбуці; CI першої голови; вердикт перевірки й число вад;
- чого бракувало (середовище, доступ до репозиторію, мережа, фото крамниць) — точними текстами відмов;
- поруч — ті самі числа останнього подібного наряду Codex через обгортку.

**Не робиш.** Нових входів і секретів, змін у налаштуваннях ChatGPT і GitHub; більше однієї задачі до висновку
менеджера; змін в обгортці під хмарний запуск — це наступний наряд, за звітом.

**Далі.** Менеджер за звітом вирішує: чи обгортка ставить наряди Codex у хмару (тоді взяте переживає відключення
світла) і що потрібно, щоб запуск теж не залежав від ноутбука, — це вже питання власникові з ціною для безпеки.
