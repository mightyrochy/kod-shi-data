# Прилад «ЖИВИЙ ПІСЛЯ: заплановано / прогнано»

## Проблема

`аудит/ДИСПЕТЧЕР.md`, «Прогони» (#3669, менеджер 13.11 за словом власника 13.11): питання `ЖИВИЙ ПІСЛЯ` злитого, яких не
взяв жоден прогін, — прострочене, а у зведенні — «прогнано N з M». Нині це тримає лише пам'ять диспетчера: за тиждень із
221 питання злитого прогнано один нічний набір, і ніхто цього не бачив, доки не порахував менеджер. Правило без приладу
відстає від слова (ядро, «Пам'ять»).

## Крок

1. Знайди, звідки план прогону вже бере ці дані: `аудит/адаптери/gemini/ЧЕРГА.md`, «Спільний тестовий прогін»
   (`Get-LatestLivePending`, межа — `ПЕРЕВІРЕНО ЗБІРКУ: <SHA>` у звіті прогону; рядки `ЖИВИЙ ПІСЛЯ:` злитих PR), розбір
   рядка — `.github/workflows/zhyvyi-ryadok.yml` і його скрипт. Не дублюй розбір: один розбирач рядка й одне визначення
   «прогнано» (злиття — предок збірки звіту з `ПЕРЕВІРЕНО ЗБІРКУ`, і сцену рядка звіт згадує).
2. Прилад `джерела/прилади/живий_після_прогнано.py` (назву можна іншу): з `git` `main` і звітів прогонів у репозиторії —
   для злитих PR за вікно (типово 7 діб, ключ `--діб`) з рядком `ЖИВИЙ ПІСЛЯ` (крім «не потрібен»): M питань, N прогнаних,
   перелік непрогнаних (PR, дата злиття, сцена, години від злиття). Без мережі; що не з `git` — «не виміряно» з причиною.
3. Звір на тижні 05–13.11 із числом менеджера (221 питання, один нічний набір); розбіжність — поясни в PR.
4. Тест приладу: штучна історія (злиття до й після збірки звіту, «не потрібен», сцена в кількох PR).

## Мірило

Прилад на свіжому `main` дає M, N і перелік; число тижня збігається з виміром менеджера або різницю пояснено по PR;
тест — OK. Прилад — інструмент такту диспетчера, не гейт CI: злиття не блокує.
