# Імпорти й чужі імена: ядро без циклів

**Проблема.** К-4 (`аудит/КАРТИНА.md`, таблиця коренів): модулі ядра залежать «усі від усіх». Оцінка коду #1387
(`аудит/огляд_коду/ОЦІНКА.md`, розд. 4; `аудит/огляд_коду/карта_системи.md`, рядки 63–100 і 308–314; `main` 17.10):
граф імпортів — 1 168 ребер, 492 з них — імпорти в тілах функцій; через них одна сильна компонента охоплює 126 зі 156
модулів, а без них циклів нема. Цикли замикають 129 функційних ребер «угору чи вбік»: `сценарій` кличе
`паспорт_нагоди` у `з_показу`, а той імпортує `сценарій` угорі файла; `colorspace` → `колір_простір_риси` →
`face_contrast` → `colorspace`; `feed` → `фід_збагачення` → `суд_блиск` → `feed`. Ядро звертається до 564 чужих
приватних імен (`from X import _y`, `X._y`); `__import__("…")` (`фід_каталог` — до приладу `чистка_каталогу`,
`outfit`, `pipeline`, `річ_з_фото`) ховає ребра навіть від лічильника. Наслідок: правка модуля зачіпає будь-який
інший, а латку кладуть у місці симптому (К-5). Рядків дошки, які закрило б розбиття, Д.1 не знайшов — мірило тут
сама зв'язність, поведінка не міняється.

**Ціль.** Граф імпортів ядра (`status.МОДУЛІ_ПРОДУКТУ`) разом з імпортами в тілах функцій і прихованими — без
циклів: спільне переїжджає вниз, до модуля, від якого залежать обидва, або йде параметром, а не новим обхідним
імпортом. Чуже приватне ім'я в ядрі — 0: потрібне іншим стає публічним у своєму модулі, потрібне одному — переїжджає
до нього. Імпорт стоїть угорі модуля; в тілі функції лишається лише лінивий, з причиною. Поведінка та сама.

**Підказка.**
- Лічильник — `аудит/огляд_коду/скрипти/карта/граф.py` (компоненти Тар'яна) і `приватні.py`, команди —
  `карта_системи.md`, «Як відтворити». `граф.py` переходить у теку ядра до запису: вихідний файл — абсолютний шлях
  поза репозиторієм. `__import__` він ребром не рахує — заміни звичайним імпортом або дорахуй у тому ж PR. Нового
  гейта в CI нема (п.3): числа — у тілі PR.
- Порядок: цикли (мірило плану) → чужі імена → підняття імпортів. Сесія вичерпується — PR на межі пункту з числами,
  решта — «лишилось» у тілі PR (п.11).
- Почни з ребер «угору»: для кожного циклу — що саме спільне і куди воно переїжджає; підняти імпорт без цього не
  можна (цикл під час завантаження). Нічого нового — ні правила, ні тексту, ні порогу; вада по дорозі — «ЗНАХІДКА».
- Фасади поділу реекспортують 399 приватних імен для проб (`карта_системи.md`, рядки 115–118): перейменування —
  разом із реекспортом і пробами; проба може читати приватне свого модуля (мірило — лише ядро).
- Зміна AST старої функції — запис у `джерела/проби/поділ_очікувані.d/` (`аудит/КОД.md`; форма — `_як-додавати.txt`).
  Файл — `рядок-<N>.txt`: N дає диспетчер у призначенні; той самий рядок «зв'язність імпортів ядра (К-4)» з ДО/ПІСЛЯ
  йде в `аудит/дошка/<гілка>.md` («виявлено: менеджер; внесено: давнє» — оцінка коду #1387).
- Гілка чіпає десятки модулів ядра; 3.1-Б, 3.2 і 2.9 переписують ті самі (`міст_відповіді`, `оцінка_образу`,
  `мовний_шар`, `паспорт_нагоди`, `сценарій`, `правило_руки2`) — тому ДО міряй на `main` після них.

**Мірило.** ДО на `main` старту → ПІСЛЯ на голові гілки (17.10 — 156 модулів, 22.10 — 159):

- чужих приватних імен у ядрі: 564 → 0 або перелік із причиною; імпортів у тілах функцій: 492 → лише ліниві з
  причиною (перелік у PR);
