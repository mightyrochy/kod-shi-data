закривати LM studio якщо вона якраз і використовується для прогонів?» — LM Studio закривати не треба, а її модель —

**Інваріант ПІСЛЯ:** (власник 31.10 ~21:33 UTC: «я так і не зрозумів навіщо вивантажувати модель, якщо її знову
потрібно завантажувати для прогону» — обгортка моделей не вивантажує; модель LM Studio — інструмент прогонів, а не
сторонній процес.)
1. Зайнятість для запобіжника — відеопам'ять лише сторонніх процесів, що справді навантажують карту: не робочий стіл,
   оверлей і оболонка Windows (ShellHost, CrossDeviceResume, NVIDIA Overlay тощо) і не LM Studio з його моделями. Джерело
   — те, що дає MiB кожного процесу під WDDM (наприклад, лічильник Windows `\GPU Process Memory(*)\Dedicated Usage` з
   PID; `--query-compute-apps` під WDDM дає N/A і буває порожнім). Як відрізнити — з виміру на ноутбуці чи документації,
   з посиланням у PR; поріг без джерела не вигадуєш.
2. Модель, що лишилась у LM Studio, GPU-позначку не тримає: наряд, якому потрібна інша модель чи інші параметри,
   перевантажує її сам за `аудит/НОУТБУК.md`. Обгортка моделей не вивантажує й LM Studio не закриває.
3. Карта зайнята стороннім процесом — причина містить назву процесу й MiB.
4. Таблиця «Позначки без старту» в #1856 показує позначку, час і причину (31.10 — порожні клітинки; `Read-NoteRows` /
