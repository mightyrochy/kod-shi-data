# Проба: наряд хмарному агентові GitHub Copilot на MAI Code 2 — без ноутбука, без квот Claude й Codex

Картина — `аудит/КАРТИНА.md`, §4, «Хмарних виконавців бракує». Власник оформив Copilot Pro на акаунті `mightyrochy`
(слово 19.11 21:38 UTC, журнал): $10 на місяць, використання на $15, 1 кредит — $0,01; агент, що бере задачу й відкриває
PR, у Pro є; моделі списують кредити кожна за своєю ціною.

**Проблема.** Квоти Claude й Codex кінчаються до скидання, а механічну роботу роблять ті самі сильні моделі. Чи тягне її
дешева модель іншої родини в готовому хмарному агенті, ніхто не міряв.

**Ціль.** Одним справжнім механічним нарядом дізнатись: чи доходить задача до агента Copilot без руки власника, чи
вертається PR, чи проходить він мірило наряду й скільки це коштує кредитів.

**Крок.**

1. Задача — на вибір диспетчера: один готовий наряд механічної роботи без відеокарти, без `.github/` і без спільних
   файлів із тим, що йде, чиє мірило цілком міряє CI чи прилад без моделі (Р0 чи Р1 без сесії, `аудит/ПЕРЕВІРКА.md`). Не
   частина ваги й не крок зупиненого кореня (`аудит/ПЛАН.md`, «Зупинено»).
2. Запуск — issue від `mightyrochy` українською: шлях файлу наряду, роль ВИКОНАВЕЦЬ за `AGENTS.md` і
   `аудит/ВИКОНАВЕЦЬ.md`, мірило дослівно; issue призначити агентові Copilot з моделлю MAI Code 2. Чим призначається
   агент і чи обирається модель інструментом GitHub хмарної сесії — перевір; не призначається — точний текст відмови
   менеджерові, і стоп; призначається, але модель не обирається — запускай як є й запиши, яка модель працювала. У тексті
   issue нема згадок зі знаком @ (ядро, «Нікому»).
3. Далі без втручання й без доробок: що агент зробив сам — те й результат. PR агента GitHub записує на того, хто
   призначив задачу, — автор `mightyrochy`, гілка `copilot/…` (вимір 19.11, #4470), тож правило ядра про чужий PR його
   не стосується; документний PR із такої гілки самозлиття не зливає (#4484). CI на PR агента не стартує, доки власник
   не натисне «Approve and run workflows»: рядок у зведенні з посиланням на PR. Після зеленого CI звіряєш числа мірила
   й межі диффа (Р1 без моделі) і зливаєш; переносити коміти агента у PR сесії не можна — запобіжник платформи
   відмовив 19.11, і перемикача «Require approval for workflow runs» сесія не чіпає.

**Мірило — рядками зведення диспетчера (окремого звіту не треба).**

- стартував: так / ні; час від призначення до першої ознаки (гілка, PR, коментар) і до готового PR;
- модель, що працювала (з PR чи сторінки сесії агента);
- CI: стартував сам чи чекає дозволу; зелений чи червоний, який крок;
- мірило наряду: числа ДО → ПІСЛЯ з CI чи приладу; пройдено чи ні;
- межі: файли поза нарядом у диффі; чи є файл дошки й запис паспорта, де наряд їх вимагає; мова PR;
- чого диспетчер не бачить: витрату кредитів — її дивиться власник (Settings → Billing), просить менеджер.

**Далі.** Менеджер читає дифф і каже власникові результат із числами. Вдалось — питання власникові про правило злиття PR
від агента й потік механічних нарядів; не вдалось — другий кандидат із картини (Kiro чи Hydrogen в Actions) лише за його
словом.
