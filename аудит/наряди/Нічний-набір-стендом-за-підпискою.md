# Свіжі записи нічного набору на моделі продукту без ноутбука: стенд у хмарі, модель — `claude -p` за підпискою

Наряд диспетчера (проба й прилад) за рішенням менеджера 20.11 04:43 UTC. Договір — `аудит/ВИКОНАВЕЦЬ.md`, код —
`аудит/КОД.md`, порядок прогонів — `аудит/проби/живі_порядок.md`.

**Що відомо.** Відтворення записаних сцен у CI (`аудит/проби/приймання_записів.js`, `храповик_записів.js`, джоб
відтворення в `.github/workflows/zbirka.yml`) читає лише `аудит/проби/нічні/<РРРРММДД>[TГГХХ]/<сцена>/повтор.json`
(`версія` 1, `жінка`, `змінні`, цілий `сід`) з відповідями моделі в `VIDPOVIDI/обмін/NNNNN.json` — формат стенда
`аудит/проби/рв6_стенд.js`. Найсвіжіший набір на `main` — 14.11 (рядок дошки 16792): записи застаріли, тому мірила
#4457 (`Відповідь-моделі-наново`) і #4449 (`Код-помилки-готовим-перевіряльником`) стоять — у їхніх тілах названо
12 сцен набору, у #4457 ще `ж1_оціни_образ_6б`, `ж3_зима`, `ж8_зима`. Нічний набір на ноутбуці стоїть у черзі за
автоживим, що йде понад шість годин (16826). Записи прогону через справжній міст (#4488) мають інший формат і сцени —
відтворення їх не бачить. У пробі #4407 (`аудит/проби/модель-текст-claude/`) `скрипти/стенд_моста.js` уже жене
сторінку через код `джерела/worker_джерело.js` у тому ж процесі, підмінивши лише `api.anthropic.com`, а
`скрипти/повтор.py` кличе `claude -p --model claude-sonnet-5-5 --effort low` з фото base64 — за підпискою, без ключа
API. **Чого не виміряно:** чи `рв6_стенд.js` приймає таку підміну без правки самого стенда; скільки триває сцена
через `claude -p` (у пробі — по шість викликів одночасно); чи запис, знятий так, приймає `приймання_записів.js`.

**Чому це вада.** Перебудова (чотири наряди за #4457) чекає записів, які дає лише ноутбук; модель у них — не модель
продукту. Шлях без ноутбука, кредитів API й Codex зняв би це чекання і дав би дешеве приймання правок сторінки на
моделі продукту.

**Ціль.** З'єднати два готові шматки: стенд `рв6_стенд.js` жене сцену, виклик моделі йде через код моста, а підміна
`api.anthropic.com` відповідає через `claude -p --model claude-sonnet-5-5` з малим рівнем зусилля. Крок 1 — одна
сцена набору (`ж4_робота`) від початку до `повтор.json`, який приймає `приймання_записів.js` на свіжому `main`.
Пройшла — крок 2: решта сцен набору з тіл #4457 і #4449 і три сцени #4457, по одному проходу, у
`аудит/проби/нічні/<дата>/`. У кожному записі й у звіті названо модель і шлях (підписка, `claude -p`, рівень
зусилля): мислення через CLI не тотожне API (16747).

**Мірило — числами без моделі, у PR і звіті `аудит/проби/нічний-набір-за-підпискою/ЗВІТ.md`.**

- крок 1: `node аудит/проби/приймання_записів.js` (команда — як у джобі відтворення `zbirka.yml`) на записі
  `ж4_робота` — код виходу 0, сцену порівняно (порівняних сцен 0 — не пройдено); секунд на сцену, викликів моделі,
  не-200 і повторів;
- крок 2: таблиця «сцена — прийнято / застаріла (rc=3) / не дійшла — викликів — секунд»; свіжих записів N з M;
- сусідні входи, які мірило однієї сцени не покриває, — рядком на кожен, пройшов чи ні: сцена з фото у вході
  (`ж1_оціни_образ_6б`); найдовша розмова набору; виклик, на який `claude -p` не відповів чи відповів не JSON
  (стенд не має писати такий обмін у запис як відповідь моделі); шість викликів одночасно проти одного — чи порядок
  файлів `VIDPOVIDI/обмін` той, що читає відтворення; повторний запуск тієї самої сцени — запис не дописується поверх
  старого;
- CI голови PR зелений; джоб відтворення на голові показує свіжі сцени, а не «застарілі 12 з 12».

Крок 1 не пройшов за два підходи — диспетчерові «ЗАБЛОКОВАНО» з рядком, на чому стала (стенд не приймає підміни,
формат обміну, час, межа підписки): тоді лишається ноутбук.
