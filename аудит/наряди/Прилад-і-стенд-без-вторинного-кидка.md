# Прилад кореня і стенд архівного чату кінчають з першою причиною, а не з вторинною помилкою

Дві вади вимірників із дошки (`аудит/БЕКЛОГ.md`, рядки 16426 і 16425), обидві — «інструмент падає на порожньому
результаті й ховає справжню причину». Продукту вони не чіпають.

**16426.** `python джерела/прилади/храповик_кореня.py --база origin/main` на Windows (PYTHONUTF8=1,
PYTHONIOENCODING=utf-8) обривається в приладі `Річ-колір-межі`: `AttributeError: 'NoneType' object has no attribute
'strip'` у читанні `вих.stdout`, `джерела/прилади/корінь_річ_колір_межі.py:1295–1298`. Виміряне виконавцем 18.11:
батьківський Python має utf8_mode=1, дочірній запущено з `-I` — у нього utf8_mode=0 і stdout.encoding=cp1251; код
дочірнього 0, байти читаються як CP1251, UTF-8 падає на 0xf7, `text=True` дає `stdout=None` після
UnicodeDecodeError у потоці читання. Лічби кореня на Windows нема: 24 прилади, код 1, два червоні пункти цього кореня.

**16425.** Стенд `node аудит/перевірки/дані-4161/заглушка.js . --чат <кеш Pyodide>` з `ZNIMKY`: після збою збору
(`build · failed: worker: мовчить 300 с, виклик запити`; `2б. чотири картки за 742.0 с · розклад рук: null · пул:
null`) стенд друкує дев'ять падінь і обривається на `page.evaluate: TypeError: Cannot read properties of null
(reading 'картки')` — читає `П.картки` за порожнього `П`.

**Ціль.**
1. Відтвори 16426 на ноутбуці тією самою командою на свіжому `main` і назви в PR вивід ДО. Виправ причину, а не
   місце: дочірній Python приладу пише, а батьківський читає в одному, явно названому кодуванні (UTF-8) незалежно
   від `-I`, змінних середовища й кодової сторінки Windows. Знайди всі місця в `джерела/прилади/*.py`, де прилад
   запускає дочірній Python і читає його текстовий вивід (число місць — у PR), і зведи їх до одного способу запуску
   з одним кодуванням; дочірній, що впав чи нічого не надрукував, дає помилку з його кодом виходу й stderr, а не
   `NoneType`.
2. 16425: стенд, чий збір не дав карток, кінчає одним рядком з початковою причиною збору (`build · failed: …`) і
   ненульовим кодом виходу — без дев'яти похідних падінь і без вторинного кидка на порожньому `П`. Відтвори
   підкладеним порожнім результатом збору (без моделі й без 300 с чекання) і назви вивід ДО й ПІСЛЯ.
3. Число жодного приладу кореня на `main` від правки не міняється: `храповик_кореня.py --база origin/main` на
   Windows доходить до кінця й друкує лічбу всіх 24 приладів; числа збігаються з CI Linux тієї самої бази (у PR —
   таблиця «прилад · Windows · CI»; розбіжність — «ЗНАХІДКА», не підгонка).

**Мірило.** На голові гілки на ноутбуці: повний храповик доходить до кінця, пунктів «прилад обірвався» — 0 (ДО — 2);
стенд із підкладеним порожнім збором кінчає одним рядком причини й кодом ≠ 0; CI голови зелений. Перевірок і
храповика не послаблюєш, паспортів коренів не правиш.

**Межі.** Лише `джерела/прилади/**` і `аудит/перевірки/дані-4161/заглушка.js`; `.github/` і
`аудит/адаптери/gemini/` не чіпаєш (потрібна зміна там — латка в `аудит/латки/Прилад-і-стенд-без-вторинного-кидка/`).
Коду продукту не правиш. Прогону з моделлю крок не потребує — рядка прогону в тілі PR не пиши.
