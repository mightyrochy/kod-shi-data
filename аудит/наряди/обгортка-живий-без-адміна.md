Без цього GPU-наряди після відставки запускача не мають рушія. Рішення менеджера 27.10 ~07:52: прав адміністратора не
брати й ізоляції М.9-Г не послаблювати. Переносні node і Playwright — у профілі `gemini`. Модель — запитами HTTP до
LM Studio власника на `127.0.0.1:1234`, без `lms`.

**Що зробити.**
1. Переносний node (LTS, zip) і Playwright з Chromium — у профілі `gemini` (`%USERPROFILE%`), без інсталятора й без змін
   системних змінних. Шлях і версії — у звіт. Запуск стенда бере їх через змінні процесу (`NODE_PATH` і шлях до
   `node`), а не з `C:\Users\Admin`.
2. Проксі `аудит/ноутбук_стенд_2/проксі_почергове.js` вантажить моделі через `lms` (`LMS_BIN`, рядки 13–23). Додай
   режим HTTP і вмикай його змінною, а режим `lms` для `Admin` лиши незмінним:
   - вивантаження й завантаження — через REST API запущеного сервера LM Studio;
   - контекст і `parallel 1` — як зараз (`CTX`).
   Ендпоїнти й поля спершу встанови на живому сервері: версія, `GET` переліку моделей, відповідь на завантаження. Не
   вгадуй. Якщо API не дає задати контекст, JIT із 4096 не годиться: промпт складання ~48 тис. токенів. Тоді —
   «ЗАБЛОКОВАНО» з відповідями сервера. Тест — `тест_проксі.js` на підробному сервері HTTP, поряд з наявним
   підробним `lms`.
3. Доказ — один прогін, перший рядок серії 2 з `аудит/проби/б1_доречність.md` (`OTSINKA=0`, без `FOTO`):
   - під обгорткою, моделями `аудит/НОУТБУК.md` («Моделі»), через проксі в режимі HTTP;
   - перед стартом — `nvidia-smi`: GPU тримає інший процес (запускач веде серію 2) — чекай до 30 хв, далі стоп;
   - результат — запис прогону й знімки карток. Вихід — у `аудит/проби/обгортка-живий/` (не в `б1/`: це доказ
     середовища, не мірило).
4. Сервер LM Studio не слухає 1234 (застосунок власника закрито) — запустити його `gemini` не може. Тоді у звіт —
   рядок дії власникові з точними кроками, наприклад автозапуск сервера LM Studio при вході в Windows. Будь-що інше,
   що все ж вимагає адміністратора, — так само одним рядком із кроками, без обходу.
