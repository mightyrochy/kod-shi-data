# Перевірки PR моделлю Gemini у Colab — на квоті поза `agy`

Роль — НОУТБУЧНА СЕСІЯ (`аудит/НОУТБУК.md`), ядро — `AGENTS.md`, адаптер — `CLAUDE.md`. Наряд самодостатній. Заміняє

**Навіщо.** Власник 26.10: ліміт Gemini поза `agy` не використано (06:35), а вибір кодів речей уже робить локальна
модель, і великого корисного виходу він не дає (08:14). Без ключа, покупки й браузера людини до Gemini плану AI Pro,
крім `agy`, веде лише Colab (`google-colab-cli`, Gemini у VM через `google.colab.ai`). Брак — у виконавцях і перевірках:
коли `agy` на 429, перевірки стоять (25.10 — шість), а роботу Claude за `аудит/МОДЕЛІ.md` перевіряє Gemini. Мета —

**Межі (диспетчер).**
- Відеокарту ноутбука й чергу GPU не чіпаєш.
- Лише Colab CLI (`colab …`) і код у рантаймі. Браузерну автоматизацію акаунта власника не робиш.
- WSL і CLI ставиш під користувачем власника, не під `gemini`: там `agy` читає тексти крамниць. WSL нема → ставити
  не вночі (потрібні адмін і перезавантаження; уночі ноутбук розбирає каталог): «НОУТБУК ЗАБЛОКОВАНО: WSL, чекаю
  власника» запускачеві.
- Вхід Colab CLI — токен Google-акаунта власника (правило 9738). Вхід робить власник руками; кодом пристрою — якщо CLI
  його вміє. Усе, що можна без входу, готуєш до нього: WSL є, CLI стоїть, скрипт перевірки лежить готовий. Потім
  стоп: «НОУТБУК ЗАБЛОКОВАНО: вхід Colab CLI, чекаю власника» запускачеві. Якщо CLI дає код пристрою (адреса й код
  без повернення коду на ноутбук), то адресу, код і строк дії одразу листом диспетчерові: `claude -p --cloud`, мітка
  «НОУТБУК COLAB ВХІД:». Вхід чекаєш до кінця строку коду.
- Тексти крамниць сесія сама не читає: лише запускає скрипти й читає числа. Модель у Colab інструментів не має.
- Тунелю з ноутбука в Colab нема. Токена GitHub у Colab нема: результат забираєш `colab download` на ноутбук, комітиш
  сам.
- Оплати по факту нема. Бюджет — ≤ 8 CU, рантайм лише CPU. `colab stop` — після кожного кроку з рантаймом: CU горять
  і на простої.
- Першим кроком — `colab usage`. 0 CU чи пробний період → стоп, доказ у #1690.

**Кроки.**
1. `colab usage` (залишок CU) → `colab new` без GPU → `colab exec`: `from google.colab import ai; ai.list_models()`.
   Перелік — дослівно. Не працює з `colab exec`, а лише в браузері → доказ у #1690, `colab stop`, «НОУТБУК ГОТОВО» з цим
   доказом: шлях закрито.
2. Пілот — 3 PR, які вже перевірено і чиї вади відомі; номери й SHA дає диспетчер у запуску (щонайменше один — з
   блокувальною вадою, один — без вад). У VM — `git clone` (репозиторій відкритий), голова PR на перевіреному SHA,
   команди тестів і мірила з наряду PR. Скрипт перевірки фіксований: модель отримує текст наряду, `аудит/ПЕРЕВІРКА.md`,
   diff проти бази й виводи команд і повертає вердикт і вади з `шлях:рядок`. Інструментів модель не має й команд не
   обирає. Модель — найсильніша Gemini з переліку п.1.
3. Суд — звіт наявної перевірки кожного PR: відомі вади знайдено / пропущено, хибні; не-JSON окремо; час і виклики на
   одну перевірку. Числа — лише з виводу команд, команда й вивід поруч.
4. Ліміти `google.colab.ai`: скільки викликів до відмови за годину й за добу (тексти відмов — дослівно) і скільки CU
   списує одна перевірка (`colab usage` до й після). Висновок числом — перевірок на добу. Межу шукаєш лише в межах
   бюджету 8 CU: дійшов до 8 — стоп, межу записуєш як «не досягнуто при N викликах».
5. `colab stop`; `colab usage` наприкінці.
