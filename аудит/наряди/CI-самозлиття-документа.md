# Крок CI, що сам зливає документ без коду на зеленій голові

Роль — ВИКОНАВЕЦЬ (`аудит/ВИКОНАВЕЦЬ.md`), ядро — `AGENTS.md`, адаптер — твій. Наряд дає диспетчер; гілка —
`claude/CI-самозлиття-документа` від свіжого `main`; PR-чернетка. Код продукту не чіпаєш.

**Правило (ядро, «Документ без коду зливається сам», #3582; слово власника 12.11 17:12 і 17:39 у чаті менеджера).**
PR від `mightyrochy` з гілки цього репозиторію, не чернетку, що несе лише стан, дошку, наряди, журнал, передачі чи звіт
із його даними й скриптами проби й не чіпає ні коду (усе, що виконує продукт, CI, хук чи обгортка), ні файлів правил,
CI зливає сам на зеленій голові — без диспетчера й без перевірки до злиття. Чого CI не злив, зливає диспетчер. Правило
називає клас; точний перелік шляхів — у приладі, який пишеш ти.

**Факти (менеджер 12.11 17:45, вимір 12.11).** Вбудоване автозлиття GitHub у репозиторії вимкнене (`enable_pr_auto_merge`
→ «Auto-merge is not enabled for this repository»); сесії його не вмикають — заборона ядра чинна, вмикати його кроком
теж не можна. Репозиторій відкритий. Нових секретів (PAT, ключів застосунку) нема й про них не просять;
`workflow_dispatch` не запускають ні сесії, ні цей крок.

1. **Прилад класу.** `джерела/прилади/документ_без_коду.py`: на вході — список змінених шляхів PR (і статус кожного:
   додано, змінено, видалено, перейменовано — обидва імені), на виході — «документ» чи «ні» з першим шляхом-причиною.
   Перелік дозволених шляхів — з правила й наявного поділу в `.github/workflows/zbirka.yml` (крок «які шляхи змінено»,
   `produkt`/`pravyla`) і `джерела/прилади/журнал_і_розмір_правил.py`: файли правил (ядро, адаптери, договори ролей,
   `аудит/*.md` верхнього рівня, крім стану й журналу, якщо правило їх дозволяє) — «ні»; усе, що виконується (`джерела/`,
   `.github/`, `.claude/`, хуки, обгортка, `index.html`, каталог) — «ні»; невідомий шлях — «ні». Скрипти проби в звіті
   дозволені лише там, де правило їх називає (тека звіту), і ніде їх не виконуєш. Тест приладу — на історії: щонайменше
   30 злитих PR за 10–12.11 (документні, кодові, з правилами менеджера), вердикт приладу проти класу з тіла й файлів PR;
   розбіжність — 0 або кожна пояснена й виправлена.
2. **Крок CI.** Новий робочий процес у `.github/workflows/`: після завершення CI голови PR (`workflow_run` чи
   `check_suite` — що вимірно надійніше; кілька робочих процесів на PR — злиття лише коли завершені всі перевірки
   голови, кожна `success` чи `skipped`, крім самого кроку) зливає PR, якщо одночасно: автор і `head.repo` —
   `mightyrochy/kod-shi-data` (не форк), база `main`, не чернетка, прилад п.1 каже «документ» на файлах PR з API, голова
   досі та сама, що пройшла (злиття squash з `sha` голови). Безпека: робочий процес із правом запису не робить checkout і
   не виконує коду з гілки PR — прилад береш із `main`, файли PR — лише списком з API; права — найменші (`contents:
   write`, `pull-requests: write` лише на job злиття); `concurrency` — одне злиття за раз. Конфлікт, червоний CI,
   чернетка, «ні» приладу — нічого не робить, пише причину в підсумок job; ці PR лишаються диспетчерові.
3. **Робочі процеси `main` після злиття.** Перевір виміром, які робочі процеси `main` запускає злиття документа диспетчером
   (`push` на `main`: згортання дошки й публікація в `zbirka.yml`, інші) і що з них не стартує, коли зливає токен CI
   (`GITHUB_TOKEN` не породжує нових запусків, крім `workflow_dispatch` і `repository_dispatch`, — звір із документацією
   й виміром). Те, що мусить відбутися після злиття (згорнута дошка на `main`, опублікований показ), має відбутися й
   тепер — без нових секретів і без `workflow_dispatch`: напр. крок злиття сам виконує потрібні job `main` після злиття
   (повторне використання через `workflow_call`) чи робочі процеси `main` слухають завершення кроку злиття. Обраний шлях
   і вимір — у PR.
4. **Мірило.** (а) Прилад п.1 на історії — розбіжностей 0 з N ≥ 30, таблиця в PR. (б) Логіка рішення кроку п.2 — тест на
   записаних подіях (документний PR зелений → злити; код, файл правил, чернетка, форк, інший автор, червона чи незавершена
   перевірка, голова змінилась → не зливати), усі випадки зелені. (в) Шлях п.3 — доказ виміром (документація й запуск
   у гілці чи на історії запусків). Живе мірило після злиття — диспетчерове: перший документний PR злито CI на зеленій
   голові, і робочі процеси `main` після нього пройшли.
5. **Дошка.** Знахідки — `аудит/дошка/claude/CI-самозлиття-документа.md`, номери 14811–14813, за шапкою
   `джерела/прилади/згорнути_дошку.py` і полями `джерела/прилади/дошка_поля.py`; перевірка — `python3
   джерела/прилади/згорнути_дошку.py --лише-перевірити` (0 помилок).
