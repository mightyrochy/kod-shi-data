# Текст картки — про склад, який код уже вирішив

Корінь — `аудит/корені/Е3-заміна-з-перевіркою.md` («Рішення менеджера 16.11 — клас неповний», «Прилад доповнено»),
етап Е3; `аудит/ПРОДУКТ.md` — п.17 (заміни нема — пояснення), п.12.

**Проблема.** Жінка читає під образом «Я замінюю сукню, бо її срібний відтінок надто близький до кольору нареченої», а
на картці — та сама сукня, і «Як це носити» радить пасок поверх неї (четвертий живий прогін, с5, дошка 15983). Заміну
модель пропонує в тій самій відповіді, що й текст картки; коли код заміни не застосував (відмова, нема запасної, модель
лишила річ, виклик упав), текст цієї відповіді йде на картку як написаний. Окремо: опис поля підстави для моделі не
називає слів, які приймає схема, — модель пише підставу реченням, і код відмовляє за формою.

**Ціль.** Картка не каже про заміну, якої на ній нема. Текст під образом пишеться для складу, який код уже вирішив:
після застосованої заміни — про образ із нею; коли заміни не буде — про образ, який лишився, і чого йому бракує для
цієї нагоди. Пропозиція з підставою, яку модель справді має, не губиться на формі поля.

**Підказка.** Будовою, а не ще одним зняттям поля: проза відповіді, що несла пропозицію, не є текстом картки, доки
рішення коду невідоме; для підстави `day` шлях «заміни нема — картка каже, чого бракує» вже є — зроби його спільним
для всіх рішень «не застосовано». Опис поля підстави називає слова переліку схеми. Код не шукає в тексті слів про
заміну (п.12); схему під речення в полі підстави не розширюй.
