  `Write-Pools` питає `agy` на кожному проході, навіть без позначки (`G/gemini_run.ps1:916`).

**Ціль.**

1. Смуга на рушій — Codex, `agy`, Claude Code — і смуги йдуть водночас. У смузі — до N нарядів водночас; N і межі часу —
   у файлі даних у `G/`, який обгортка читає з `origin/main`, не з клону агента; стелі — в коді під хешем, дані їх не
   перевищать. Кожен наряд — своя робоча копія й тека запуску; узяття позначки атомарне: дві смуги чи два слоти одну
   не візьмуть.
2. Порядок задає диспетчер: пріоритет і строк — у назві позначки (формат — у `G/ЧЕРГА.md`), рівні — за часом постановки.
3. Відмова за квотою спроби не спалює: після скидання позначку бере та сама смуга, без нової від диспетчера.
4. Стан ноутбука (#1856, той самий, що пише #1858) показує по смугах узяті позначки, вільні слоти й квоту кожної групи
   моделей з часом скидання в UTC і часом зчитування; для Codex і Claude — останню відмову за квотою і скидання, якщо
   CLI його дає (перевір, що дає).
5. GPU-наряд — один на ноутбуці через замок, спільний для обох облікових записів.
6. Опитування в кожній смузі — не рідше ніж раз на 5 хв; `/usage` — не частіше, ніж треба для стану.

**Підказка.** Облікові записи розведено жорстко (`agy` і Codex — `gemini`, Claude — власник: `Test-Isolation`,
`Test-OwnerUser`), тож планувальників щонайменше два, а слоти й замок GPU — у спільній теці. Розбір позначок і стан уже
є двічі (`gemini_run.ps1`, `claude_run.ps1`): спільне — одним модулем під хешем, третьої копії не роби. Межа задачі — не
коротша за межу наряду. Таблицю хешів (`G/m9v/хеші.psd1`) рахуєш від своєї голови після злиття `main` з #1852 і #1858.

**Мірило.** Стенд (`G/перевірка/`, сценарії з підробленими CLI): шість позначок на одному коміті — по дві Codex, `agy` і
Claude Code, одна з них GPU, пріоритети різні, одна `agy` — на нульовій квоті. ДО — по одній, за абеткою, квотна —
`DONE`. ПІСЛЯ — смуги водночас, у кожній до N зі слотів даних і за пріоритетом; GPU — по одному; квотну взято після
«скидання» без нової позначки; у стані — смуги, слоти й квота з UTC; зміна N у файлі даних міняє паралельність без
перевстановлення.
