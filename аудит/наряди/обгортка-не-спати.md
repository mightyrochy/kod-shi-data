# Обгортка: ноутбук не засинає, поки йде наряд

Роль — ВИКОНАВЕЦЬ (`аудит/ВИКОНАВЕЦЬ.md`); код — `аудит/КОД.md`; обгортка — `аудит/адаптери/gemini/НАЛАШТУВАННЯ.md`,
черга — `аудит/адаптери/gemini/ЧЕРГА.md`.

**Що видно (#1856, 02.11).** Стан ноутбука мовчав з 00:55 до ~07:00 UTC, потім з 07:10 до ~11:40. Посеред цього
`живий-c71cc075-продовження` закомітив звіт о 00:53, а рядок ГОТОВО дійшов лише о 07:03. Чотири наряди Codex
(`лічба-проб-ізоляція`, `розбір-заміна-руки-2-c71cc075-доробка`, `Е3-поле-без-писача`, `Е3-сила-правила`) і
`автоживий-99157d45…` скінчились STALL / STALL_PUBLISHED і пішли на повтор. Власник у ці години не працював за
ноутбуком; гіпотеза: Windows присипляє систему за таймером простою, бо фонові процеси нарядів не тримають її
бодрою (не виміряно: журнал живлення `powercfg /systemsleepdiagnostics`, події Kernel-Power 42/107).

**Ціль.**
1. Перший вимір: подія сну й пробудження за 01–02.11 (`Get-WinEvent` System, Kernel-Power 42 і 107,
   Power-Troubleshooter 1) з часом UTC проти мовчання #1856 — підтверди чи спростуй гіпотезу в README латки.
2. Поки в обгортці йде хоч один процес наряду (смуги codex, agy, claude), система не засинає за таймером простою:
   `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` у кожному процесі наряду (`-WorkerFile` у
   `gemini_run.ps1`; процес наряду в `claude_run.ps1`) від старту до кінця, з поверненням `ES_CONTINUOUS` у `finally`.
   Без прав адміністратора й без змін плану живлення; дисплей не тримати (`ES_DISPLAY_REQUIRED` не ставити). Знайди всі
   точки старту процесу наряду в обгортці (той самий клас) і перелічи їх у README з рядками.
3. Сон, який система все ж узяла (кришка, кнопка, батарея), не губить наряд мовчки: після пробудження обгортка пише
   рядок «GEMINI ОБГОРТКА: СОН <з UTC> → <до UTC>, нарядів N» — один на подію.

**Мірило.** Стенд Windows PowerShell 5.1 у CI обгортки: процес наряду викликає встановлення й зняття стану (підміна
P/Invoke у стенді), виняток посеред наряду знімає стан; новий стенд — у переліку частин `.github/workflows/obhortka.yml`
(інакше збирач: «запусків 0, очікується 1»). На ноутбуці після злиття — `powercfg /requests` під час наряду показує
процес обгортки в SYSTEM.
