# Обгортка: ноутбук не засинає, поки йде наряд

Роль — ВИКОНАВЕЦЬ (`аудит/ВИКОНАВЕЦЬ.md`); код — `аудит/КОД.md`; обгортка — `аудит/адаптери/gemini/НАЛАШТУВАННЯ.md`,
черга — `аудит/адаптери/gemini/ЧЕРГА.md`.

**Що видно (#1856, 02.11).** Стан ноутбука мовчав з 00:55 до ~07:00 UTC, потім з 07:10 до ~11:40. Посеред цього
`живий-c71cc075-продовження` закомітив звіт о 00:53, а рядок ГОТОВО дійшов лише о 07:03. Чотири наряди Codex
(`лічба-проб-ізоляція`, `розбір-заміна-руки-2-c71cc075-доробка`, `Е3-поле-без-писача`, `Е3-сила-правила`) і
`автоживий-99157d45…` скінчились STALL / STALL_PUBLISHED і пішли на повтор. Власник у ці години не працював за
ноутбуком; гіпотеза: Windows присипляє систему за таймером простою, бо фонові процеси нарядів не тримають її
бодрою (не виміряно: журнал живлення `powercfg /systemsleepdiagnostics`, події Kernel-Power 42/107).

**Спроба 1 (gemini/обгортка-не-спати fbe7fef7).** Вимір: сон 02.11 01:05:03 → 06:52:10 і 07:09:31 → 11:42:28 UTC,
Kernel-Power 42 з причиною «Application API», не таймер простою. Власник 02.11 12:08: «Ноутбук вимикається бо
пропадає світло» — сон за викликом програми при втраті живлення бажаний (батарея), його не блокуємо.

**Ціль (спроба 2).**
1. Назви програму, що викликала сон: події Kernel-Power 42 / 506 / 507, Power-Troubleshooter 1, `powercfg
   /systemsleepdiagnostics` чи `/sleepstudy` (без адміністратора — що доступне), журнал ASUS/Armoury Crate, якщо є, і
   чи збігся сон із переходом на батарею (Kernel-Power 105 чи подібна подія). Висновок — у README латки; невиміряне —
   «гіпотеза: …».
2. `SetThreadExecutionState` не додаєш: сон від втрати світла не прибираємо.
3. Після пробудження чи ввімкнення обгортка пише рядок «GEMINI ОБГОРТКА: СОН <з UTC> → <до UTC>, нарядів N» — один на
   подію (джерело — подія Power-Troubleshooter 1 чи час останнього heartbeat).
4. Наряд, перерваний сном чи вимкненням (STALL, STALL_PUBLISHED, AGY_ERROR чи BLOCKED_PUBLISHED, що почались до сну й
   скінчились після нього), обгортка ставить на повтор сама, від опублікованої голови, без нової позначки диспетчера —
   один повтор на сон; повтор, перерваний знову, — рядок ЗАБЛОКОВАНО, як зараз. Знайди всі місця, де закривається
   прогін з цими кодами (той самий клас), і перелічи їх у README з рядками.

**Мірило.** Стенд Windows PowerShell 5.1 у CI обгортки: сон посеред наряду (підміна часу подій у стенді) дає один рядок СОН і
один повтор від опублікованої голови, другий сон — ЗАБЛОКОВАНО; новий стенд — у переліку частин `.github/workflows/obhortka.yml`
(інакше збирач: «запусків 0, очікується 1»). На ноутбуці після злиття — наступне відключення світла дає рядок СОН і
повтор перерваних нарядів без позначки диспетчера.
