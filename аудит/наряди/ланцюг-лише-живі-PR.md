**Факти.** Після першого самооновлення (ОНОВЛЕНО 3f020079, 28.10 ~03:20 UTC) `Invoke-WrapperChain`
(`wrapper_chain.ps1`) за один прохід поставив 44 позначки `автоперевірка-<PR>-<SHA>` (24 `gpt-6.1-sol-high`, 20
`cc-claude-opus-5-5-high`) на **всі** відкриті PR з гілок `gemini|claude|codex/`, зокрема мертві чернетки звітів 15–26.10
(#963, #991, #1028, #1460, #1860–#1879). Звіти автоперевірок обгортка публікує PR-чернетками з гілок
`gemini/автоперевірка-*` (#2002–#2004 — звіти про вже закриті PR), а ланцюг бере й ці гілки — автоперевірка звіту

**Що зробити.**
1. Гілка `gemini/ланцюг-лише-живі-PR` від `main` без змін `аудит/адаптери/gemini/` і `.github/` у ній; код — тимчасовим
   деревом поза репозиторієм (`git worktree add <тека> origin/main`), латка — `git diff` там, потім `git worktree remove`.
2. Перед запуском рушія на позначці `автоперевірка-<N>-<SHA>` (усі три смуги) обгортка сама, без моделі, звіряє через
   API: PR відкритий і голова = SHA позначки. Ні — позначка закривається власним кодом (напр. `STALE`) одним рядком
   `ЗАБЛОКОВАНО <гілка> STALE`, без витрати квоти; вже поставлені 44 позначки підпадають під це правило.
3. Ланцюг не ставить автоперевірку на PR без руху: лише на PR, чия голова з'явилась після встановлення ланцюга чи
   оновилась за останні N годин (N — у `ланцюг.json`, типово 24); вибір і межу обґрунтуй у README латки. Гілки
   `*/автоперевірка-*` ланцюг не бере ніколи.
4. Проба ДО → ПІСЛЯ на стенді: закритий PR, змінена голова, давній PR без руху, PR звіту автоперевірки, живий PR — запуск моделі
   5/5 → 1/5.
5. Усі 12 `перевірка/сценарії_*.sh` — 0 ✗; хеші змінених файлів — у `m9v/хеші.psd1` і таблиці `НАЛАШТУВАННЯ.md` тією
   самою латкою; `перевірити_хеші.py` — 0 ✗; `git apply --check` на `main` — код 0.
6. Нові вади — `аудит/дошка/gemini-lancjug-zhyvi-pr.md` за шапкою `джерела/прилади/згорнути_дошку.py`, новим форматом
