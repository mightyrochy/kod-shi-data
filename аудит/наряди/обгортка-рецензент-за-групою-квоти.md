# Рецензент ланцюга: квоту `agy` судити за групою обраної моделі, а не за будь-якою групою

Роль — ВИКОНАВЕЦЬ (`аудит/ВИКОНАВЕЦЬ.md`), ядро — `AGENTS.md`; обгортка — `аудит/адаптери/gemini/ЧЕРГА.md`,
`НАЛАШТУВАННЯ.md` («Самооновлення», вибір рецензента).

**Чому (етап Е0 — координація механізмом, `аудит/ПЛАН.md`, зміна 4).** 29.10 ~15:00–19:00 жодна автоперевірка
claude-PR не пішла в роботу: #2226, #2239, #2242, #2245, #2246, #2249 отримали позначки
`автоперевірка-…/gemini-3.8-flash-high/…`, і всі одразу — `ЗАБЛОКОВАНО … QUOTA0_GEMINIMODELS` до 02.11 (тіло #1856 о
18:58: `agy · GEMINIMODELS WEEK 0 %`, `CLAUDEANDGPTMODE WEEK 1 %`; Codex — остання відмова 15:18, понад годину тому,
тобто доступний за `Test-QuotaRefused`). Диспетчер ставив хмарні перевірки вручну.

Причина в коді (`аудит/адаптери/gemini/wrapper_chain.ps1`): `Test-ProviderQuota 'agy'` повертає «на квоті» лише коли
**всі** групи `pools.json` на 0 %. Група CLAUDEANDGPTMODE з 1 % робить `agy` «доступним», `Select-ReviewModel` бере
перший кандидат — модель `agy` з `ланцюг.json` (`gemini-3.8-flash-high`), чия група GEMINIMODELS на 0 %, і запасний
Codex не обирається ніколи. Та сама перевірка, ймовірно, тримає й заміну позначки, що чекає вичерпаного постачальника,
на доступного (`НАЛАШТУВАННЯ.md`: «знімається … і ставиться позначка доступного») — звір.

**Що зробити.** Квота `agy` для рецензента — за групою саме тієї моделі, яку ланцюг ставить (відповідність модель →
група вже є там, де `gemini_run.ps1` пише `QUOTA0_<ГРУПА>`; одне джерело, без нової таблиці). Усі місця, що питають
`Test-ProviderQuota 'agy'` для конкретної моделі, — через ту саму перевірку. Інших змін поведінки нема.
