# GPU-запобіжник: навантаження карти — лише в причину й журнал, не умова запуску (рішення менеджера 01.11, #2731)

**Факт.** Після #2718 (обгортка d11ad0d2, 14:42 UTC) `Get-GpuLoad` (`queue_lanes.ps1`) блокує кожен GPU-наряд, бо
`$script:GpuIdlePercent = 0`, а стіл на RTX 4090 дає 43–45 % (`nvidia-smi utilization.gpu`); 5 GPU-позначок стоять.
**Рішення менеджера 01.11** (`аудит/корені/ПК-межа-без-джерела.md`, розділ «навантаження GPU як умова запуску», #2731):
0 % — запас без джерела (виміряно, коли стіл малювала Intel); межі нема, доки нема виміру столу на дискретній карті.
Запобіжник тримає вільну VRAM проти виміряної потреби прогону (`GpuRunMiB`), а навантаження лише записує в причину й
журнал.

**Що зробити.**
1. **Рішення (12256).** `Get-GpuLoad`, `Test-ExternalGpuFree`, `Get-GpuBusyReason` і будь-яка копія в `claude_run.ps1` /
   `gemini_run.ps1`: умова запуску — лише телеметрія без помилки й вільна VRAM ≥ залишкової потреби (зарахування
   неактивної LM Studio — як зараз, незалежно від навантаження). Навантаження `Percent` — у причину відмови за пам'яттю й у
   журнал взяття, не окрема причина. `GpuIdlePercent` прибираєш; нового числа не вводиш.
2. **Стенди (12257).** Стіл 45 % + браузер 1,2 ГБ при вільних ≥ `GpuRunMiB` — вільна; гра чи чужа модель, що забрала VRAM
