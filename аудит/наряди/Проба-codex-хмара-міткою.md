# Проба: наряд хмарному Codex міткою на PR — без ноутбука й без руки власника

Картина — `аудит/КАРТИНА.md`, §4, «Робота без ноутбука й хмарний Codex»; попередні проби —
`аудит/проби/хмарний-codex-1/ЗВІТ.md` (згадка в GitHub, не стартувала) і `аудит/наряди/Проба-codex-cloud-з-ноутбука.md`
(команда `codex cloud` через обгортку — потребує ноутбука).

**Проблема.** Наряд Codex запускає обгортка на ноутбуці й виконується там само: нема світла — стоїть і запуск, і
робота. Хмарна сесія Codex на нашому репозиторії стартує з заданими моделлю й зусиллям (знімок екрана застосунку
Codex у чаті менеджера 19.11), але запускав її власник рукою. Помічник застосунку (dot) відповів, що вміє запускати
хмарну сесію на подію GitHub у PR, без ноутбука; сигналом пропонує окрему мітку. Наживо цього ніхто не робив.

**Ціль.** Однією справжньою правкою коду дізнатись, чи доходить наряд від диспетчера до хмарного Codex міткою на PR і
чи вертається результат PR-чернеткою — коли ноутбук участі не бере.

**Крок.**
1. Запуск — робота диспетчера: мітка `codex-cloud` на PR від `mightyrochy` з гілки цього репозиторію, у тілі якого —
   шлях файлу наряду, модель і зусилля. Який це PR і чим ставиться мітка — механіка диспетчера; перевір, чи
   інструмент GitHub хмарної сесії ставить мітку й чи створює її, коли такої ще нема. Не ставить — точний текст
   відмови менеджерові, і стоп.
2. Задача — одна частина наряду коду без відеокарти й без спільних файлів із тим, що йде, на вибір диспетчера; роль
   ВИКОНАВЕЦЬ за `AGENTS.md`, `аудит/ВИКОНАВЕЦЬ.md` і `аудит/CHATGPT.md`.
3. Далі без втручання: чи з'явилась PR-чернетка, чия вона, що в її тілі про модель і зусилля. Потім — звичний шлях:
   CI й перевірка іншим постачальником.
4. За змогою мітку поставити, коли ноутбук вимкнено чи спить; інакше — записати, що він був увімкнений, і чи щось на
   ньому при цьому запускалось (стан ноутбука).

**Мірило — рядками зведення диспетчера (окремого звіту не треба).**
- стартувала: так / ні; час від мітки до першої ознаки (гілка, PR, коментар) і до PR-чернетки;
- модель і зусилля: що просили в тілі PR і що назвав Codex у своєму PR;
- квота Codex до й після (стан ноутбука, коли він є);
- PR: відкрито без ноутбука — так / ні; CI першої голови; вердикт перевірки й число вад;
- чи був другий запуск на ту саму мітку або запуск на PR-результат (кола бути не має);
- чого бракувало — точними текстами.

**Не робиш.** Нових входів і секретів; другої мітки до рядків мірила; мітки на PR не від `mightyrochy` чи з форка;
змін в обгортці й правилах під цей шлях — це за результатом, менеджер.

**Далі.** Вдалось — менеджер вносить канал «диспетчер → хмарний Codex» у ядро й `аудит/CHATGPT.md`, і диспетчер
ставить наряди Codex міткою, коли ноутбука нема. Не вдалось — рядок «чого бракувало» менеджерові; шлях через обгортку
ноутбука лишається.
