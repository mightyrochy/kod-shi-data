# П'ять образів батареї не будять своїх цілей: причина кожного

Батарея (`джерела/батарея_труба.py`) проганяє кожен навмисний образ і поруч ставить його ціль — правило, яке образ має
розбудити (`_перевірка_гілок`, поле «ожила»). Після #4249 `python3 gate_reach.py --образи` (у `джерела/`) повертає 1,
коли ціль не ожила. На `main` 90a8ba88 не оживають п'ять образів із 28 (рядок дошки 16457 — читай лише його; повні
пари образ–ціль і всі 14 сцен — `аудит/проби/Батарея-ціль-образу-червонить/гілки-main.json`):

| ціль | образ |
|---|---|
| K-CLR-05 | срібло на теплому оливковому підтоні — гасить правило металу |
| K-CLR-05 | золота каблучка на оливковому підтоні, елісітація дана — рішення УТРИМАНО |
| K-COL-02 | три гучні хроми (C* ≥ 40) — понад бюджет акцентів |
| K-SIL-07 | тотальна теракота під відкритим кардиганом — колона свідома, не площинна |
| K-CRA-09 | усе з одного реєстру: воркер від сорочки до черевиків (анти-костюм) |

Через це латку CI з #4249 (`аудит/латки/Батарея-ціль-образу-червонить/ci.patch`, крок `gate_reach.py --образи` у
`zbirka.yml`) застосувати не можна: CI `main` став би червоним. Причину виконавець #4249 не встановлював.

**Ціль.** Для кожного з п'яти образів — встановлена причина, чому ціль мовчить, з доказом із коду й прогону, одного з
трьох родів: (а) образ батареї не дає правилу його входу (образ застарів чи складений не так, як читає правило сьогодні);
(б) правило чи його вхід змінено навмисно — назви PR і рядок, що зняв умову, — і ціль образу в батареї лишилась стара;
(в) правило чи його вхід зламано: на вході, який за текстом правила (`аудит/ПРОДУКТ.md`, його пункт) має його будити,
воно мовчить. Історію шукай тим, що вже є: `git log -S` за ID цілі, `git bisect` з `gate_reach.py --образи` від
останнього `main`, де ціль жила (якщо жила).

**Що правиш.** Рід (а) і (б) — батарея: образ чи його названу ціль у `джерела/батарея_образи.py` /
`джерела/батарея_входи.py` приводиш до чинного правила так, щоб образ перевіряв те саме правило по суті, а не
будь-що, що оживає; ціль не глушиш, образу не викидаєш, винятків у `gate_reach.py` не додаєш. Рід (в) — правил
продукту й їхніх входів не правиш: «ЗНАХІДКА» рядком дошки (номери наряду) з образом, входом, пунктом правила, комітом,
що зламав, і виводом прогону — це крок кореня продукту, його дає менеджер.

**Мірило ДО → ПІСЛЯ** (числа — у звіт і в повідомлення коміту).
- Причин встановлено: 0 з 5 → 5 з 5, кожна з родом і доказом.
- `python3 gate_reach.py --образи` на голові: образів 28, True 22, False 5, None 1, код 1 → False лише роду (в), їх
  число й ID; коли роду (в) нема — False 0, код 0.
- Стандартна батарея з `аудит/КОД.md` — як на базі.

**Межі.** `.github/` не чіпаєш (латку CI застосовує диспетчер, коли False — 0). Нових гейтів, запускачів і workflow
нема. Звіт — `аудит/проби/Батарея-цілі-неживі-причини/ЗВІТ.md`: таблиця «образ — ціль — рід — причина — доказ — що
зроблено». Гілка, PR і рядок кінця — за адаптером рушія (`аудит/CHATGPT.md`); файл наряду видали тим самим PR.
