# Час від пушу до зеленого CI: виміряти чергу й виконання по джобах на всіх запусках і скоротити

Роль — ВИКОНАВЕЦЬ (`аудит/ВИКОНАВЕЦЬ.md`), ядро — `AGENTS.md`, адаптер — `CLAUDE.md`, код — `аудит/КОД.md`. Наряд ставить
диспетчер (CI — його ділянка, `аудит/ДИСПЕТЧЕР.md`); гілка — `claude/CI-час-злиття` від свіжого `main`, PR-чернетка.

**Що видно (менеджер 08.11 за питанням власника 08.11 18:03 UTC «чи злиття все ще по пів години»).** Вимір менеджера
08.11: 99 злитих PR, 82 зіставлено із запусками `zbirka.yml`. Від PR до злиття медіана — документ 48 хв, код 140 (01.11 —
19 і 47); CI від останнього пушу — документ 21, код 97 (48–241); зелений → злиття 7–11 хв. На #3399: PR 15:38, перший джоб
15:52, «перевірка джерел» стартувала 16:11 і йшла 39 хв (01.11 — 14–25). Гіпотеза менеджера: черга на машину — по всіх
запусках не міряно. Наряд 01.11 на CI, що ганяє лише зачеплене зміною, файлом не з'явився: `zbirka.yml` з 01.11 мінявся
лише checkout (04.11) і шрифтами (05.11).

1. **Вимір усього обсягу.** Усі запуски всіх workflow (`.github/workflows/*.yml`) за 01.11–08.11 через публічний API
   GitHub (`actions/runs`, `runs/<id>/jobs`): на кожен джоб — очікування в черзі (`started_at − created_at` джоба й
   запуску), виконання (`completed_at − started_at`), висновок, подія (push/PR), чи PR документний (лише `аудит/**`,
   `*.md`) чи кодовий. Таблиця й скрипт — `аудит/перевірка/ci_час_0811/` (скрипт — щоб вимір повторювався). Підсумок:
   медіана й p90 черги та виконання по джобу й по дню; частка часу PR, яку дає черга, а яку — виконання; скільки
   одночасних запусків стоїть (паралельність, ліміт раннерів); які джоби йдуть на документних PR, хоча документ
   їх не зачіпає. Частковий вимір — «гіпотеза: <що не виміряно>», не висновок (ядро, «Причини»).
2. **Скорочення за виміром.** Те, що дає найбільшу частку часу, — правкою будови CI, а не латкою на джоб: зокрема
   документний PR не ганяє джобів, яких документ не зачіпає (умова за зміненими шляхами там, де вона вже є в `zbirka.yml`,
   чи нова); застарілий запуск попередньої голови скасовується (`concurrency` з `cancel-in-progress` там, де його нема);
   Pyodide-джоби (10 шардів) і «перевірка джерел» — лише коли зачеплено те, що вони перевіряють. Жоден гейт не
   вимикається для кодового PR, і на `main` після злиття CI ганяє повний набір: охоплення не губиться, губиться лише
   повтор. `workflow_dispatch` не запускаєш (ядро).
3. **Мірило.** Той самий скрипт на PR цієї гілки й на 3+ PR, злитих після неї (диспетчер дасть номери): CI від
   останнього пушу — документ ≤ 10 хв, код — медіана нижче 97 хв на числі з виміру; на кодовому PR склад джобів той
   самий, що до правки. У PR — до/після числами й список джобів, що тепер не йдуть на документі.
