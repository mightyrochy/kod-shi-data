# PR коду зливається сам на зеленій голові з розібраними рецензіями — без диспетчера

Наряд менеджера 28.11 за словом власника 28.11 ~02:30 і ~02:44 UTC: «чому цим займається дорогий деспетчер?» і «так» на
те, щоб PR коду CI зливав сам (`аудит/РІШЕННЯ_ВЛАСНИКА.md`). Файли — `.github/workflows/samozlyttia.yml`,
`джерела/прилади/документ_без_коду.py` і його тест. Правило, яке втілюєш, — `аудит/ДИСПЕТЧЕР.md`, «Злиття», перші два
пункти, і `AGENTS.md`, «Документ без коду». Договір — `аудит/ВИКОНАВЕЦЬ.md`.

**Проблема.** Кожен PR коду чекає пробудження диспетчера на сильній моделі: той читає доказ у PR і ставить мітку
«злити». Це перевірка окремою сесією під іншою назвою — її знято (власник 28.11), а злиття досі стоїть за нею.

**Головне правило.** PR, що не документ, крок самозлиття зливає без мітки, коли виконано все разом:

1. умови, спільні з документом (`_умови_pr`: від `mightyrochy`, гілка цього репозиторію, база `main`, не чернетка), і
   гілка не `copilot/…`;
2. усі перевірки голови завершені й `success` чи `skipped` — як у документа;
3. жоден файл PR не лежить у закритих місцях: `.github/**`, `.claude/**`, `аудит/адаптери/gemini/**`, файли правил
   (`ФАЙЛИ_ПРАВИЛ`), сам `джерела/прилади/документ_без_коду.py` з тестом і записами — такі PR лишаються мітці
   диспетчера;
4. на поточній голові є рецензія `copilot-pull-request-reviewer[bot]` (`commit_id` рецензії — SHA голови);
5. у кожному треді рецензії, який почав `chatgpt-codex-connector[bot]` чи `copilot-pull-request-reviewer[bot]`,
   зауваження розібране: тред закрито (resolved) або останній коментар у ньому — від `mightyrochy`. Треди інших акаунтів
   на рішення не впливають ні в який бік: репозиторій відкритий (`AGENTS.md`, «Безпека»).

**Що робиш.**

1. Рішення — у приладі, з `main`, за відповідями API (рецензії й треди — теж списком з API); коду гілки PR крок злиття
   не бере й не виконує, як тепер. Причина кожного незлитого PR — у підсумку job одним рядком («нема рецензії Copilot на
   голові», «тред Copilot без відповіді: <посилання>», «закрите місце: <файл>»).
2. Рішення будять і події рецензії: рецензія чи відповідь у треді часто приходить після зеленого CI, і завершення CI
   нового рішення вже не дасть. Спосіб — той самий, що з міткою: подія запускає процес із `main` чи порожній процес,
   завершення якого ловить `workflow_run`; код гілки при цьому не виконується. Знята чернетка — так само.
3. Мітка «злити» лишається як є — нею диспетчер зливає закриті місця, файли правил і голову, на яку рецензія Copilot не
   прийшла.
4. Шапку `samozlyttia.yml` і докстрінг приладу переписуєш під нову поведінку; старий опис «решту лишає диспетчерові»
   видаляєш.

**Мірило.** (а) Тест приладу на записаних відповідях API, у CI зелений; у PR — його вивід ДО (на `main`) і ПІСЛЯ.
Випадки: зелена голова з рецензією Copilot без тредів — злити; рецензія Copilot лише на попередній голові — ні; тред
бота без відповіді — ні; тред бота з останнім коментарем `mightyrochy` — злити; закритий тред — злити; тред чужого
акаунта без відповіді — злити; файл у закритому місці — ні без мітки й так із міткою; чернетка — ні; червона перевірка —
ні; гілка `copilot/…` — ні. (б) Документ без коду й мітка «злити» поводяться як до правки — їхні чинні тести зелені без
змін у записах. (в) Наживо, після злиття: перший PR коду, що зливається без мітки, — номер запуску й рядок підсумку job
диспетчер дописує коментарем у PR цього наряду; не злився на виконаних умовах — «ЗНАХІДКА» диспетчерові з підсумком job.

**Чого не робиш.** Auto-merge GitHub не вмикаєш і `workflow_dispatch` не запускаєш (`AGENTS.md`, «Нікому»); прав токена
понад потрібні для читання рецензій не додаєш; звірок CI не знімаєш і не послаблюєш; шляху документа не міняєш; нових
приладів не додаєш.

**PR.** Чернетка від `main`, одна гілка; чіпає `.github/`, тож зливає диспетчер міткою на зеленому CI. Нотатки для себе
— в PR з кожним комітом. Кінець — «ГОТОВО #PR <SHA>» диспетчерові.
