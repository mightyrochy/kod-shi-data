# Сервер LM Studio на 127.0.0.1:1234 запускається при вході у Windows

Ти — виконавець на ноутбуці (`аудит/НОУТБУК.md`), обліковий запис `Admin`; ядро — `AGENTS.md`.

**Навіщо.** Смуга Codex (`gemini`) живих прогонів не веде, коли сервер LM Studio закрито: запустити його вона не може
(`аудит/наряди/обгортка-живий-без-адміна.md`, п.4). 01.11 ~12:04 UTC нічний Е1 на Codex скінчився
`ЗАБЛОКОВАНО: LM Studio не слухає 127.0.0.1:1234` (гілка `gemini/Е1-нічний-живий-20261101`). Сервер має бути живий після
кожного входу у Windows, без руки власника.

**Що зробити.**
1. Стан: версія LM Studio й `lms`; чи слухає 1234 (`GET http://127.0.0.1:1234/v1/models`) — код і перелік моделей.
2. Увімкни запуск сервера LM Studio на 1234 при вході у Windows штатним засобом LM Studio (налаштування застосунку чи
   `lms`; назву ключа й спосіб встанови з `lms --help` і самої LM Studio, не вгадуй). Порт, `parallel` і контекст
   моделей не міняй; моделей не вантаж. Штатного засобу нема — задача Планувальника від `Admin` при вході з
   `lms server start`, без прав адміністратора системи. Потрібні права адміністратора чи дія в інтерфейсі — у звіт один
   рядок дії власникові з точними кроками, без обходу.
3. Запусти сервер зараз (`lms server start`) і перевір `GET /v1/models` з облікового запису `gemini`, якщо можеш
   (інакше — з `Admin`).
4. Нічого іншого не змінюєш: Avast, інші програми автозапуску, права, обгортку.

**Звіт.** `аудит/проби/lmstudio-автозапуск/ЗВІТ.md`: що було (п.1), що змінено (п.2, де саме), перевірка (п.3). Мірило —
сервер відповідає на 1234 зараз, і є записаний засіб, що піднімає його при вході. Кінець — рядок `НОУТБУК ГОТОВО <гілка>
<SHA>` чи `ЗАБЛОКОВАНО: …`.
