## 3. Architecture decision — chained FitDiT on the SOURCE; QIE dropped

We considered a two-stage QIE-holistic (composer) → FitDiT-refine (tailor) pipeline. Owner challenge:
**if we build the layer graph + occlusion masks ourselves — and we can, because the layer order is
KNOWN from the outfit definition — then QIE adds nothing essential** and only brings its ~9 % body slim.

**Decision: drop QIE from V1.** The concrete mechanism is a chained FitDiT on the SOURCE photo:
```
canvas = source photo (real body, original clothes)
for garment in layer order (bottom-up):     # order from the outfit definition
    M = agnostic mask for this garment (FitDiT parsing + occlusion from the layer graph;
        upper-garment mask extends over the lower garment's waistband at the seam)
    canvas = FitDiT(canvas, M, precise_reference)
→ accessories (OmniTry / inpaint)
```
**Outfit logic = pass order + mask overlap at seams** (a later pass drawn into a mask that covers the
earlier layer ⇒ "over"). FitDiT only edits inside the mask, so source body/face and previously-placed
garments are preserved. **QIE/holistic is only needed when outfit logic is UNKNOWN (V2/V3, stylist-
invented outfits), not for a manually-defined V1 outfit.**

## 4. What the FitDiT stack already provides (vision mapping)

Already loaded inside FitDiT: **garment encoder** (`transformer_garm`), **human-parsing**
(`parsing_*.onnx` → agnostic regions), **pose** (`dwpose` + `pose_guider`). Plus our **FashionSigLIP**
eval encoder (loaded, uncalibrated). **Missing / to wire:** layer-graph + occlusion orchestration (the
chaining above), **OmniTry** (accessories), **DISTS** + calibration set, **SMPL body-shape** (secondary).
So the build is mostly **orchestration of present pieces + accessories**, not from scratch.

## 5. Better analogs to FitDiT (for our needs)

- **Garment detail (axis #1):** FitDiT is the **strongest open model** (beats IDM-VTON/CatVTON on
  VITON-HD/DressCode). No better analog on detail — keep it as the per-garment core.
- **Multi-item one-pass + composable:** **AnyDressing** — parallel multi-garment in one pass + plug-in
  with ControlNet/IP-Adapter/LoRA (so body/identity control can be folded in). The strongest analog for
  OUR multi-item architecture, BUT **academic-only (non-commercial)**, detail-vs-FitDiT unverified,
  ~SDXL VRAM. Alternatives: OmniVTON++ (training-free multi-garment, NC), MuGa-VTON (DiT).
- **Accessories (FitDiT can't):** **OmniTry** — mask-free, jewelry/belts/shoes, **CC-BY-SA
  (commercial-OK)**; release + VRAM unverified. A **complement**, not a replacement.
- **Commercial-OK licenses are scarce:** only **Leffa (MIT)** and **OmniTry (CC-BY-SA)**;
  FitDiT / AnyDressing / IDM-VTON / CatVTON / OmniVTON are prototype-only (verify FitDiT's license).
- **The slit-skirt failure is masking/category, NOT model choice** — fixed by our occlusion masks or a
  dress-category, not by switching models.

| need | best |
|---|---|
| per-garment detail | **FitDiT** |
| full outfit in one pass + composable controls | **AnyDressing** (NC) |
| accessories | **OmniTry** (commercial-OK; verify release) |
