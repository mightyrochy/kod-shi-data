# E-018 — бенч-оф шляхів візуалізації образу «Код Ші»

**СТАН: НЕ ЗАПУЩЕНО. Потребує В-3 (бюджет) і відповідей В-1, В-2.** Чернетка 18.09.2026
за `research/ДОСЛІДЖЕННЯ_ВІЗУАЛІЗАЦІЯ_2026-09.md`; протокол пишеться ДО запуску
(`METHODOLOGY.md` §2). Зведено координатором із протоколів двох прогонів сесії-дослідника
та інвентарю ноутбука.

## Питання

Чи існує шлях візуалізації, що переносить конкретні речі каталогу «Код Ші» на людину або
її двійника зі збереженням крою, фактури й фурнітури під планку власника — у межах 16 ГБ
VRAM, без нових завантажень, і за ціною хмари не вище стелі В-3?

## Рішення, яке це інформує

В-4 (доля локального конвеєра OSS) і вибір двигуна для режиму Б або В у V1 «Код Ші».
Якщо В-2 = А (колаж), E-018 не потрібен.

## Заморожені входи

- (а) **Три образи, зібрані продуктом** із речей каталогу (фото крамниць публічні): по
  5–7 речей зі взуттям і сумкою. ID речей: Образ-1 `[____]`, Образ-2 `[____]`, Образ-3 `[____]`
  — заповнює власник (чекпойнт 1). Для кожної речі — найкраще фото і маска ATR з v2
  (`джерела/аудит/фото_v2/`, `збагачення_v2_вибірка.json`), тобто плитка речі без тла.
- (б) **Людина**: приватне фото власника `assets/person/person_front.png` — лише локально,
  ніколи в хмару без В-1 = так; для хмарних кандидатів — синтетичний двійник (MakeHuman /
  MPFB CC0 або Anny з топологією SOMA), якого ще нема: збудувати як передкрок або
  відкласти хмарних кандидатів до В-1.
- Дошка: комбінована (маска + зріз), як у E-016/E-017; одноплиткова дошка давала
  ідентичність 0.40 (H-PIPELINE-2026-06-21) — не використовувати.
- Одна мінімальна інструкція для всіх двигунів, сід 42, ~1 МП; налаштування кожного
  двигуна — з `experiments/017_editor_fidelity_benchoff/_payload_*.json` як стартові.

## Кандидати (не більше трьох)

1. **Qwen-Image-Edit-2511 fp8mixed, локально** — на диску (`unet\qwen_image_edit_2511_fp8mixed`,
   19.1 ГБ), Apache-2.0, у E-017 переніс повний образ з ідентичністю 0.95. Два варіанти:
   20 кроків (як E-017) і Lightning 4 кроки (LoRA на диску) — щоб зміряти ціну швидкості.
2. **FLUX.2-klein-4B, локально** — на диску (7.2 ГБ), Apache-2.0, ~13 ГБ VRAM за карткою;
   у E-017 переніс лише блузу, ідентичність 0.60. Дешевий, бо вже стоїть.
3. **Nano Banana Pro (Gemini 3 Pro Image), хмара** — $0.134 за зображення, Україна в списку
   регіонів; на двійнику, або на фото при В-1 = так.

Резерв (не запускати без окремого слова): Seedream 4.5 / 5.0 (ціни лише з офіційних
сторінок), FASHN Try-On Max (одна річ за виклик, ≈ $2.25 на набір), Z-Image-Edit (ваги Edit
не на диску; Turbo є). Вилучені: OmniGen2 (ідентичність 0.13–0.21 в E-017), FLUX.1-Kontext
(одне зображення, не переносить), OmniTry (28 ГБ), HiDream-O1 (прогін E-017 недійсний —
повернути лише після виправлення графа, якщо В-3 виділяє на це час), Voost / klein-9B /
FLUX.2 dev (некомерційні).

## Що міряємо (кожне зображення)

- **Ідентичність** (режим В): ArcFace buffalo_l, косинус до вхідного фото, поріг 0.57
  (V-ID-001). Для двійника (режим Б) — вимикається; замість неї пропорції (шир. плечей /
  стегон до вхідного двійника) і кольори шкіри та волосся в Lab проти паспорта.
- **Кожна річ окремо**: маска речі на виході (ATR за регіоном слота) → середній Lab проти
  еталона з v2 (ΔE CIEDE2000, орієнтир PASS ≤ 3 / WARN 3–5 з V-COLOR-001, не правило);
  FashionSigLIP sim і DISTS проти плитки речі; AnomalyDINO (структура) де маска надійна.
- **VLM-суддя** (Qwen3-VL у LM Studio, локально): по кожній речі три прапорці — річ
  присутня / крій і деталі відповідають / шарування вірне; плюс перелік помилок словами.
  Спостереження, не вердикт.
- **Ціна і час**: секунд на зображення (локально — з логів ComfyUI; хмара — з відповіді),
  доларів на зображення, VRAM пік (`/system_stats`).
- Контактний аркуш усіх виходів з підписами — як `results/_sheet_e017_all.png`.

## Правило рішення

Кандидат проходить, якщо на ≥ 2 з 3 образів усі речі мають прапорець «річ присутня» від
VLM-судді, ідентичність або пропорції в межах порогів, І власник підтверджує візуально на
аркуші. Одне зображення — Observation (`METHODOLOGY.md` §1). Якщо не проходить жоден
локальний кандидат і хмара заборонена (В-1 = ні), спрацьовує критерій зупинки
`BUILD_PLAN.md` для режиму В.

## Чекпойнти власника

1. Затвердити ID трьох образів і рішення про двійник (будувати чи відкласти хмару).
2. Переглянути контактний аркуш після першого прогону всіх кандидатів.
3. Фінальна візуальна оцінка по формі (рядок на зображення, як `E017_РОЗСУД.md`).
4. В-3 (перед стартом), В-4 (після).

## Гілки за рішеннями

- В-1 = ні → кандидат 3 лише на двійнику; без двійника — лише кандидати 1–2.
- В-2 = А → E-018 не потрібен. В-2 = Б → ArcFace вимкнено, пропорції й кольори увімкнено.
  В-2 = В → ArcFace обов'язковий.

## Бюджет (для В-3)

Диск: 0 нових ГБ. Хмара: 3 образи × 2 ітерації × $0.134 ≈ $0.80 (кандидат 3); резерв
FASHN ≈ $2.25. Час GPU: не оцінено, міряється тут же. Заборонено: будь-які завантаження
ваг і вузлів без окремого слова власника.

## Димові прогони

Не робились. Дозволено ≤ 3 на вже встановлених двигунах, коли ComfyUI працює; результат —
Observation для аркуша, не доказ.
