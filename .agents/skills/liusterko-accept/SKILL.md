# Приймання результату Люстерка

Прочитай доручення, `AGENTS.md`, `CLAUDE.md`, пов'язаний рядок єдиного
`аудит/БЕКЛОГ.md` і фактичні докази. Claude Opus 5.5 max лишається головним
керівником; dot координує OpenAI під ним. Уточни, хто призначений приймальником:
виконавець не приймає свою роботу через повідомлення «ГОТОВО».

Звір робочу копію, baseline і фактичний SHA/незакомічений diff. Прочитай зміни,
включно нові файли; перевір дозволені шляхи, критерії, результати потрібних
перевірок і зупинку фонових робіт. Відсутній доказ — відкрита перевірка,
а не успіх. Доказ має відповідати версії, яку приймаєш.

Для продуктової зміни виконай ручне приймання за `CLAUDE.md` п.10 і п.15:

- відкрий зібрану сторінку на 390×844 у справжньому браузері;
- пройди знайомство → сценарій → палітра → «Зібрати образи» → картки;
- збережи й сам переглянь екрани та кожну картку, прочитай питання,
  пояснення й тексти, відкрий вивантажений файл вердиктів;
- переглянь фото речей, яких стосується зміна. Для модельної поведінки
  використовуй живий Claude через підписку за підтвердженої квоти;
  дрібні суміжні зміни можна перевіряти групою. Для зміни без моделі
  перевір справжню функцію у Chromium на зібраній сторінці.

Саме збереження знімків, заглушка та зелені гейти не замінюють огляду.
За відсутності потрібного живого прогону/доступу зафіксуй межу й наступний
крок; не приймай продукт як перевірений. Перед злиттям і після фактично
погодженого злиття потрібен ручний прохід відповідної збірки. Приймання
доручення не дає дозволу на merge і не запускає його автоматично.

Для суто інфраструктурної зміни перевір її поведінку вузькою пробою; не
вимагай продуктову матрицю без причини. Cloud, GitHub-конектор, dot та Code
review вважай налаштованими лише за фактичними доказами у відповідному
сервісі. Локальна навичка, JSON або `передача.ps1` цього не доводять.

Якщо використовується локальний `джерела/передача.ps1`, приймальник із
`actor=controller` викликає `Accept` лише після огляду, з `checks_passed: true`,
`evidence[]` і `next_step`. Скрипт не виконує `checks[]` і не перевіряє зміст
доказів за людину. Невиконані критерії — `Reject` з доказами й наступним
кроком (`review → blocked`); продовження невдалого наряду — новий явно
погоджений ID. Не підміняй `controller`, щоб обійти приймання.

Знахідки записуй тільки в `аудит/БЕКЛОГ.md` в межах дозволених файлів або
передавай координатору для запису, з тим, що видно, де та як відтворити.
Не публікуй `.agent-runs/`, секрети чи локальні логи. Не витрачай невідому
квоту й не купуй доступ/платний API заради приймання. Підсумок: прийнято або
повернуто, фактична версія, докази, обмеження та наступний крок.
