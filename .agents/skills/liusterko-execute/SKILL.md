# Виконання доручення Люстерка

Прочитай `AGENTS.md`, `CLAUDE.md` і зазначений рядок `аудит/БЕКЛОГ.md`
у призначеній копії. Звір джерело погодження, роль виконавця, приймальника,
дозволені файли, baseline SHA, гілку й критерії. Якщо істотної межі бракує,
передай конкретну прогалину координатору, не розширюй доручення сам.

Починай новий наряд у чистій окремій копії. Збережи чужі незакомічені зміни;
не скидай і не чисть їх, не використовуй основну копію для виконання. Нове
продуктове рішення передай Claude Opus 5.5 max. Dot — координатор OpenAI
під Claude; він не замінює керівника.

Виконай тільки погоджену зміну. Дозволені файли є межею доручення і перевірки
після роботи; сам перелік не створює файлову пісочницю. Для Codex модель,
effort і швидкість бери з `AGENTS.md` та явного доручення. Не запускай
додаткові моделі, GPU чи хмарні роботи «для впевненості» поза його межами.

Для локального `джерела/передача.ps1`:

- `Run` — один явний запуск Codex за свіжою підтвердженою квотою саме Codex,
  чистою копією й точним baseline; відсутня, невідома або прострочена квота
  Codex блокує цей запуск;
- Claude, LM Studio та ComfyUI використовують `Export` і ручний наявний
  клієнт; результат записують через `Result`, скрипт їх не запускає;
- `checks[]` виконай свідомо в межах доручення: скрипт їх не виконує.

Для інфраструктури достатні вузькі перевірки; невідома квота Claude не
блокує роботу, яка не викликає Claude. Для продуктової зміни виконай
перевірки за `CLAUDE.md` п.10 і п.15: ручний прохід та живий Claude там, де
змінюється модельна поведінка. Не видавай заглушку або CI за доказ якості.
Якщо потрібної квоти/середовища немає, здай зроблене з конкретним обмеженням;
приймання лишається відкритим. Невідомі квоти не вигадуй, токени CLI тримай
окремо від відсотків Claude/ChatGPT. Без покупок і платного API.

Перечитай diff і перевір усі змінені, включно нові, файли проти меж доручення.
Нову знахідку прив'яжи до єдиного беклогу; якщо він поза дозволеними файлами,
передай координатору доказ для запису. Після двох невдалих цілеспрямованих
спроб передай проблему з доказами; без автоматичних повторів, самонагадувань,
`workflow_dispatch` чи автоматичного merge.

Зупини свої фонові процеси. Збережи результат відповідно до явного доручення:
заборона commit/push має пріоритет над типовим правилом негайного push після
commit. `.agent-runs/` і секрети не публікуй. Здай SHA/гілку/PR або статус
«не закомічено», перелік файлів, перевірки й обмеження, докази та наступний
крок. Завершення виконавця — `review`, а не `accepted`.

У Codex/Cloud здавай результат відповіддю в поточному чаті або файлом/PR
за явною авторизацією. Не імітуй Claude `create_trigger`/`fire_trigger`;
не повідомляй інші сесії без людського дозволу.
