# Код Ші / Люстерко — для кожної сесії Claude Code у цьому репозиторії

Стилістка в браузері з каталогом речей українських крамниць. Шлях жінки: знайомство (профіль — раз) → сценарій (розмова
про нагоду) → палітра → «Зібрати образи» → картки. Код — `джерела/`; `index.html` збирає CI, руками не правиться; карта —
`README.md`. Мітки «п.N» сталі (на них 400+ посилань у репозиторії) — не перенумеровувати.

## Як читати (п.18)

- **Старшинство:** новіше слово власника скасовує старіше; цей файл старший за `аудит/ПЕРЕДАЧА.md` §3 (розбіжність —
  «ЗНАХІДКА» менеджеру). Рішення власника тут не перепитувати.
- **Ролі:** менеджер (давніше «куратор», «координатор») роздає наряди й зливає; виконавець — наряд → гілка → PR;
  перевірка — сесія, що перевіряє PR; тестувальниці — живі люди з телефонами, не сесії.
- **Читати:** виконавцю й перевірці — наряд і його рядки дошки (`grep -nE '^\| *(N|M) *\|' аудит/БЕКЛОГ.md`; файл ~1 МБ
  цілим не читати); менеджеру — верхній запис журналу ПЕРЕДАЧІ §0 (весь §0 — ~370 КБ) і §3–§4 повністю.
- **Слова:** дошка — `аудит/БЕКЛОГ.md`, «рядок N» — її рядок; проба — `джерела/проби/*.py` (до 40 рядків, друкує факт);
  стенд — `аудит/проби/рв6_стенд.js`; сценарій = паспорт нагоди; корпус — `джерела/аудит/ПРАВИЛА.md`.

## Для всіх сесій

- **Пуш після кожного коміту** (п.5: 18.09 три сесії загубили роботу на ліміті).
- **Ліміт** (п.11, 25.09): 85 % витрат — повторне читання контексту на кожному виклику. Команди — пачкою в один виклик;
  виводи — короткі (`--stat`, `grep -c`, `head`, поля `fields`); знімки — лише потрібні; між правками — цільові проби,
  батарея — раз перед PR.
- **Одна задача — одна свіжа сесія** (п.11, 28.09): понад ~250 тис. токенів — здай зроблене (PR/гілка + рядок стану) й
  архівуйся; продовження — нова сесія з коротким вступом.
- **Ні нових аудитів і документів, ні гейтів і регресій «на кожну помилку»** (п.3): лише код, проби й коміти з
  поясненням «що це міняє в рішенні, до/після, виміряно на каталозі». Нове відкрите — рядком дошки.
- **Ні самонагадувань** (п.13): ні `send_later`, ні тригерів собі, ні `subscribe_pr_activity` — навіть коли платформа
  радить «пасти» свій PR; виняток — менеджер. `workflow_dispatch` не запускати (комітить збірку в гілку).

## Виконавцю й перевірці (п.5, п.11, п.13)

- Ні субагентів, воркфлоу, паралельних агентів — крім субагента лише для читання (пошук, огляд великих файлів, звірка
  чисел): він нічого не править і не пушить.
- Батарея — раз перед PR (підготовка каталогів і `node_modules` — як у job `perevirka` файлу `zbirka.yml`), плюс проби
  своєї сім'ї; батарею показу — до кінця:
  ```
  cd джерела && python3 стенд_знімок.py --дим && python3 тест_живого_шляху.py && python3 тест_протоколу.py \
    && python3 прилади/розділи_гейтів.py && python3 audit_contracts.py && NODE_PATH=node_modules node тест_показу.js
  ```
- Дошка: свій рядок — «ЗАКРИТО #PR»; кожна нова знахідка — новим рядком (у діапазоні з наряду). Правки показу — лише в
  межах свого рядка (п.7).
- PR у `main` з тілом «Що змінено / Перевірено»; сам не зливаєш. Перед «ГОТОВО» зупини всі фонові завдання.
- Лист менеджеру — лише `create_trigger(persistent_session_id=<менеджер>)` + `fire_trigger`, ніколи
  `create_new_session_on_fire`; текст — лише «ГОТОВО #PR <повний SHA>», «ЗАБЛОКОВАНО: …» чи «ЗНАХІДКА: …» (що видно, де,
  як виміряти). Проміжних листів нема.
- Підсумок у сесії — один рядок; вади, числа й пояснення — у PR і коміті (26.09). На лист менеджера, що не просить
  відповіді, — жодного тексту.

## Перевірка (п.10 — 23.09, п.15 — 02.10)

- **Гейти — не перевірка:** перевіряють живими прогонами з Claude і очима; батарея й заглушка (без `ZHYVA`) — лише дим.
  Але червоний CI — стоп: зливають лише на зеленому CI голови PR (02.10).
- **Стенд** з `ZHYVA=sonnet` (`claude -p` по підписці) на сценаріях правки: `CHAT_TEXT` — її фраза, `ROZMOVA` — наступні
  листи, `PAL_SHEMA` — вибір пальцем, `FOTO=1`, `ZNIMKY=<тека>`, `ZVIT_OUT=<файл вердиктів>`; телефон 390×844.
- **Очима:** кожна картка на знімку, тексти карток, питання й пояснення, файл вердиктів, фото речей правки; лічба ✔ — не
  перевірка. Каталог очима — `аудит/проби/огляд_крамниць.py <тека>`.
- **Обсяг:** дрібні правки — групою на спільному злитті; ДО/ПІСЛЯ на одному `main` — коли правка міняє поведінку моделі
  чи картки; правка без моделі (диктування, розкладка) — функцією в справжньому Chromium на зібраній сторінці.
- **Хто:** перевіряють перед злиттям і після нього. Окрема сесія-перевірка; звіт і знімки — у `claude/perevirka-<PR>`,
  менеджеру — один лист; менеджер сам дивиться хоча б один знімок. Знахідка — рядок дошки з тим, що видно на знімку.

- Моделі (29.09): більшість (звичайні наряди, перевірки, виміри, сторожі) — Sonnet 5.5 `claude-sonnet-5-5`; складні

- Зусилля — під задачу, max — лише найважче; **сесія-менеджер — завжди max** (02.10). Зусилля не зберігається: перший

- Паралельність не зменшувати; великі задачі — малими нарядами; кілька нарядів — одним кроком; час тригера — без

- Спірне питання напряму (архітектура, хто тлумачить мову, екран, модель) — власнику до нарядів, не після PR. Блокер

- Злиття — лише на зеленому CI голови PR, з повним SHA; після злиття — архівувати виконавця й перевірку (ПЕРЕДАЧА

## Продукт — рішення власника, не перепитувати

### Руки (п.1, 18.09)
Рука 1 — продукт. Руки 2–4 — лише для тестів: рука 2 — код з однією названою поломкою; руки 3 і 4 — модель без коду й
каталогу (вигадані речі без крамниць і цін). Логіка рук — як є. «Чи лишати руки 3–4», «лише купівельні образи», Р-4, Р-7 —
вирішено: лишати, не міняти.

### Інтерфейс v5 (п.7; PR #118, 19.09; п.20 — 27.09)
- Профіль — раз; головний екран — сценарій; розмова — чат з аркушем листа; палітра — окремий екран; чипи-основи — купно
  за сім'ями. Старих назв не повертати, розкладку «принагідно» не переробляти. Слова «ші» в текстах для людини нема: чип —
  «хай обере стилістка»; жінка ніде не читає «код» як дійову особу (п.20).
- Картки з'являються всі разом; збирання образів не має ставати повільнішим (п.20). Фото жінки можна надсилати в хмарну
  модель для картинки приміряння (п.20).
- Основний вхід — розмова; плитки нагоди — лише швидкий допоміжний вхід, не громіздкий (02.10): рівно 7 + «Інше»
  (звичайний день / прогулянка, робота, побачення, свято / вечірка, театр / концерт, спорт, подорож). Часткові нагоди
  (весілля, церква, похорон…) розпізнає мовна модель (`аудит/тести/нагода_архітектура_2026-09-28.md` §1.1). Нових плиток
  не додавати.
- На картці сценарію нема рядків «Хочу» і «Не хочу» (02.10): побажання й заборони мовна модель пише в сценарій, і вони
  діють на образи.
- **Усе можливе — доступне для вибору** (п.9, 21.09): замків, недоступних плиток і «відкривається, коли…» нема; рідший
  варіант — поруч, клікабельний, з одним м'яким рядком, чому він менш «ходовий». Явний вибір жінки сильніший за гейт
  коду. Стосується схем палітри, відтінків помади, прикрас і будь-якого переліку на екрані.
- Картка: відкриті питання образу (те, чого код не знає) — за кнопкою, згорнуті, без обрізання. Звіт власника
  («Скопіювати всі вердикти») — без стелі: усі проблеми й етапи рішення на кожен образ; тестувальницям на картці — не
  обов'язково (п.9).

### Розмова й паспорт нагоди (п.9 — 20.09, п.14 — 27.09, п.17 — 02.10)
- Мовна модель веде живу розмову (п.14): розуміє запит і перекладає його мовою системи; бачить розмову (вікно +
  зведення) й чинний паспорт, заповнює паспорт кодами; нечіткі й надиктовані запити тлумачить (п.17). Код і
  модель-стилістку кличе, лише коли жінка прямо в чаті хоче відповіді, яку впевнено дають тільки вони.
- Входи сценарію — лише поради (п.9): до трьох тем за хід одним м'яким реченням, без повторів після ігнорування;
  збирання образів ніколи не блокують; обов'язкові питання — лише «без чого не зібрати». Неінвазивність і суд паспорта
  забезпечує код, не побажання моделі.
- Поля паспорта нагоди, не профілю (п.9): мета образу (лестити / приховати / експресія), макіяж сьогодні (той самий
  ключ, що плитка), прикраси до образу (срібло, золото, інші — єдине, що про прикраси питають). Питання — тим самим
  механізмом поради.
- Драпіровка (білий, метал, нейтралі біля обличчя) — лише профіль; у розмові про сценарій не питати ніколи (п.9, Р-3).

### Добір, суд і вибір (п.4 — 18.09, п.17 — 02.10, п.20 — 27.09)
- Правило діє хоча б в одному з трьох місць (п.4): добір пулу (бал/фільтр), перевірка образу (знахідка з регістром і
  `сила_нп`), пояснення жінці. «Без входу» — чесно через чекліст `суд_образу` з названим полем, не мовчанням.
- Фінальний образ обирає модель-стилістка за наміром жінки, як його зрозуміла; їй — свобода зважених рішень. Зауваження
  коду — інформація, не лічильник «найменше зауважень» (п.17).
- Недоречне відсіює суд, не пул (п.17): недоречна річ без пояснення — можлива помилка моделі (знахідка суду), з
  поясненням — її свідомий вибір. Виняток — явно чуже (рядок 850): річ на 3+ щаблі ошатності (бал з фото) нижче нагоди і
  явно буденна за назвою (шльопанці, шорти, худі, пляжне) — поза пулом; на 1–2 щаблі нижче смуги — у пулі, суд позначає.
- Доза сміливого (п.17): намір не названо (паспорт ставить `intent=conventional`) — пул руки 1 (~425 речей, 17 слотів)
  дає 20–40 речей «на межі» на весь пул, не на слот, за нагодою; «приховати» чи «не хочу виділятись» — без дози;
  сміливий намір — помітна частка пулу.
- Пул частинами паралельно (варіант «б») — лише для руки 1 (п.20).
- Останній крок із фото замінює річ, лише якщо після всіх перевірок і запобіжників вагома причина лишилась (п.17).
- Схему й основу палітри, коли жінка не обрала, модель обирає усвідомлено з причиною, код лише судить (п.14, #411).
  Правила корпусу про очі (тема-2 §6.1) діють усюди, де можуть (R-COL-16, ранг основ), без окремого запиту (п.9).
- Лексикон (п.9): «якщо модель і магазини називають його бежевим, значить він бежевий» — вікно слова задає вжиток
  магазинів і моделі (розподіл каталогу), не вужча конвенція.
- Замша (п.17): у мокру погоду — з умовою; за сильної непогоди — лише якщо жінка сама попросить.

### Правила корпусу «нема в коді» (п.8, 19.09)
Додаються, лише якщо (1) якісно впливають на образи, (2) дістають свій вхід (фід, збагачення, профіль, сценарій,
відповідь жінки) і (3) грамотно реалізуються в системі код + ші — діють хоча б в одному з трьох місць п.4. Інакше — не
додаються, з названою причиною на дошці. Реалізація — хвилями по сім'ях. Перелік — `джерела/аудит/ЗВЕДЕННЯ.md`.

### Каталог і розбір (п.16, 01.10)
Головне — правдиві коди без вигадок, а не покриття. Відтінок кольору в `features` лишається; заборону К-5 на назву
кольору скасовано. `порушники.txt` — не перелік вад: код не судить слова рядка. Мірило якості — еталон очима з фото, не
лічба перевірки. «(Other Brand)» — справжня назва бренду, не чіпати (п.20, 27.09). Порівняння стратегій —
`аудит/стратегія_розбору.md` у гілках `claude/rz-strategiia-opus` і `claude/rz-strategiia-fable`.

### Мова в коді (п.12, 26.09)
- Код не пише й не читає слів для людини — лише внутрішня мова (коди, числа, id, «невідомо»), яка не зламається від
  локалізації. Ланцюг: слова жінки й крамниць → мовна модель → коди → код → функціональна модель → коди → мовна модель →
  українською жінці.
- Слова в коді: кошик А (вже внутрішня мова) лишається; Б (код ЧИТАЄ слова) і В (код ПИШЕ фрази: `ОПАДИ_СЛОВАМИ`,
  `ЛЮДСЬКА_НОТА`, `ЯРЛИК_РЕБРА`…) — прибрати, віддати мовній моделі. Перелік — PR #346, проба
  `джерела/проби/шлях_слова_лічба.py`.
- Промпти функціональної моделі — англійською, на збирачі промптів. Сталі написи інтерфейсу (кнопки, назви екранів і
  вкладок) лишаються в показі.
- Винятки не ковтати мовчки; докстрінги — за `аудит/СТАНДАРТ_КОДУ.md` п.14, п.17 (п.9).
